## 配置与隔离

所有调用使用 v3 配置引用的 `deepseek-v4.1-flash` 及锁定推理参数。前九组关闭思考。Base-think 与 Ours-think 开启思考，其余参数原样保留。Base-think 的首请求使用归档的原 A0 检查器提示。凭据仅取 `OPENCODE_GO_API_KEY`。首个 Base-think 请求作为能力核验并计入试运行。模型或思考模式如被明确拒绝，停止，保留错误。只使用 API 生成契约、修订、区分序列和 Python 参考模型。评测输入及输出只在 eval 环节使用，不回流。

| 配置 | 方法 |
| --- | --- |
| Base | 原 v3 A0 检查器，零新增调用 |
| CoT | 非结构化详细推理后直接生成检查器，按同批 Ours 平均实际 token 对齐 |
| VS | Veri-Sure B.1 的五个顶层字段，含每输出 latency_cycles，从契约生成检查器，无审查 |
| Ours | 详尽契约、两轮独立审查、工具裁决、检查 A 和 B |
| Ours-R0 | 零审查 |
| Ours-R1 | 一轮审查 |
| Ours-noTrace | 两轮审查，只传文字问题 |
| Ours-noA | 共用 Ours 检查 A 前首个可执行模型，跳过检查 A |
| Ours-noB | 使用二轮结束时编写者版本，跳过检查 B |
| Base-think | 原 A0 提示开启思考 |
| Ours-think | 完整机制开启思考 |

VS 使用与本文同名的原版 B.1。schema 包含 `module_name`、`io`、`clocking`、`timing.outputs`、`functional_summary`，并允许 v3 组合接口没有物理时钟或复位。参考模型始终遵守 v3 `reference(vectors)` 与位宽完整性。[Veri-Sure](https://arxiv.org/abs/2601.19747v1)

每题种子分别生成初始契约。相同单元、思考设置和处理此前完全相同的消融分支共享节点，含第 1 轮审查。每次独立审查只见该次契约和带句号索引的原 spec。确定性 JSON 与语义 schema 校验最多重新生成两次。每条规则有 2–4 拍示例、规则 ID 和输出，缺少逐字 spec 引文时必须给 uncertain 候选。审查覆盖每个编号句段、核对引文与内部一致性，逐条输出问题。每条歧义各生成两份可执行模型，工具在审查者给出的区分输入上比较完整输出，等同才自动关闭。无法执行的裁决保持问题开放并单列。修订以逐问题、可还原的结构编辑归档，接受必须改动，反驳须引用原文。

最终分歧和显式 uncertain 先保留编写者基准，再最多展开三个替代组合，总共至多四个。只有冻结 spec 解析器抽出的可执行、具有明确输入和期望输出的例子用于检查 B。若基准与替代都满足例子，取基准。例子缺失或所有版本不符时标 `unresolved_no_example` 并使用编写者版本。符号状态表如缺少外部状态编码，作为可审查的非执行例子保留。检查 A 独立执行所有最终契约规则例子，允许固定契约最多两次重新生成。仍不符时保留最后一个可执行模型及失败标志。可执行性检查仍沿用 v3 完整输出。凡使用失败模型的配置，保留计划样本并按 v3 处理。

审查精确率对每条接受编辑比较编辑之前和之后的契约。归档逐编辑生成的诊断模型，仅由 eval 比较这两份模型与 golden 的不一致周期数。共享节点只算一次，思考组独立统计。这些诊断调用单列成本，排除在 CoT 对齐所用方法预算之外。检查 A 记录每次例子不一致及重新生成，并比较首次可用候选与最终模型的评测。检查 B 记录可执行 spec 例子对每个候选的拦截、选中方案及和 noB 的成对差异。

CoT 的目标为该批 Ours 的平均实际总 token，包括契约、审查、可执行裁决、修订、检查 A/B 相关的模型调用。使用同一锁定上限，用自然语言推理与独立复核消耗预算，最后直接生成参考模型。报告实测偏差。试运行 CoT 用该批三份 Ours 得到的目标，全量使用 85 份 Ours 的目标重新生成全量 CoT，试运行记录独立归档。

## 指标与假设

v3 评分采用原主边沿、评分时屏蔽 golden 的 X/Z 位及原 H 清单。误报率使用确有执行结果的 golden 作分母，检查器不可执行单列。golden 条件检错按通过 golden 且在 H 失败计数，并沿用 v3 的计划 H 分母。另报告逐轮问题及类型、no_effect、接受/反驳、审查精确率三类、两项检查的拦截和误报变化、未决比例、用量和费用。先在题内合并五个种子，再作题级宏平均与配对；另报 pooled。配对使用双侧 Wilcoxon 精确符号翻转及 20,000 次题级配对 bootstrap 百分位区间，无观测配对单列。预定义所有 Ours 对前八组其余配置的比较，以及 Ours-think vs Base-think，两种主指标联合做 Holm，同时报告未校正 p。2×2 采用全部 17 题的相同设置。

- H1。Ours 对 Base 和 CoT 分别降低误报，且 golden 条件检错不下降。对后者同时报告点估计和区间，非显著差异不解读为不下降。
- H2。Ours 相比 Ours-R0 误报更低。
- H3。Ours 相比 Ours-noTrace 误报更低。
- H4。Ours-think 相比 Base-think 误报更低。

## 执行顺序

提交预注册后才执行确定性 spec 抽取。先跑 `edgecapture`、`circuit9`、`fsm3s` 各首个固定种子的全部十一组，分别覆盖独立复位、时序波形和符号状态表。验证输入隔离、各阶段产物、沙箱执行和 v3 Base 对照。试运行通过才启动 85 次的全量矩阵。同一节点可重用已归档的试运行结果，CoT 按前述规则单独匹配。
