The reset behavior is the most consequential part of this specification for the checker, because it is the one place where the normal "sample at posedge, then update" rhythm is deliberately broken. Reset is positive-edge-triggered and asynchronous: asserting it forces the machine into its initial state and drives the initial output immediately, without waiting for a clock edge. The checker must therefore treat the reset row as a special case. On that row, `z` is the initial output regardless of `x`, and the state is forced to the initial state. It must not require a clock edge to establish the reset state, and it must not let the `x` value on the reset row influence either the output or the state.

After reset is released, the machine resumes normal synchronous operation. The first posedge after release samples the first input bit and moves the machine out of the initial state. From that point on, each row's `x` is driven before the sampled posedge and held stable across that edge. Optional mid-cycle changes to `x` occur after sampling and before the next edge, and are carried forward to the start of the next row. The checker should therefore evaluate each row at its posedge using the `x` value valid at that edge, not any mid-cycle value. This matters because a mid-cycle change belongs to the next row's setup, not to the row being sampled.

Because the output is state-only, the checker cannot compute `z` combinationally from the current `x`. It must maintain the state variable, read `z` from the state-output table at the sampling edge, and then update the state from (`state`, `x`). A common checker bug is to compute the 2's-complement bit directly from `x` and the "seen a 1" flag in the same cycle; that produces a Mealy-like result and will disagree with the Moore machine by one cycle at the transition where the first 1 is encountered.

Worked example: input stream `0, 1, 0` (LSB first), starting from reset. At the first posedge after reset release, `x=0`; the pre-edge state is the initial state, so `z` is the initial output (0), and the state stays "no 1 seen." At the second posedge, `x=1`; `z` is still the initial-state output (0), and the state transitions to "seen a 1." At the third posedge, `x=0`; `z` is now the "seen a 1" output (1), and the state remains "seen a 1." The sampled output sequence is `0, 0, 1`, which is the 2's-complement result delayed by one cycle relative to the input — exactly what a Moore realization produces. A checker that instead emitted `0, 1, 1` on the same edges would be modeling a Mealy machine and would fail against this specification.

The final checker should therefore key `z` to the pre-edge state, apply the transition with the edge-stable `x`, and handle the asynchronous reset row without requiring a clock edge. It should also confirm that the reset row's `x` is ignored entirely, since the specification makes the reset state and output unconditional.
