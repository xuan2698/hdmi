The machine is a Moore 2's-complementer: output depends only on state, and state encodes whether a 1 has already been seen in the LSB-first stream. Two states suffice. In the initial state (call it S0, "no 1 seen yet"), the output is 0. In the second state (S1, "a 1 has been seen"), the output is 1. The transition rule is: from S0, x=0 keeps S0 and x=1 moves to S1; from S1, any x keeps S1. This is the standard "copy bits until the first 1, then invert every subsequent bit" behavior, realized as a Moore machine so the output lags the input by one sampled edge.

Reset is asynchronous and positive-edge triggered. When `areset` is asserted, the machine is forced to S0 and `z` is forced to 0 regardless of `clk` or `x`. The reset row must be handled without requiring a clock edge, and `x` on that row is ignored entirely. Conversion begins only after reset is released; the first sampled posedge after release uses the pre-edge state S0.

For each non-reset row, the checker must sample at the posedge using the `x` value stable at that edge. The output `z` is read from the pre-edge state's output table, then the state is updated from (`state`, `x`). Mid-cycle changes to `x` occur after sampling and belong to the next row's setup; they must not affect the current row's sampled `x` or `z`. This ordering is the key correctness point: read `z` from the old state, then transition.

A frequent checker error is to compute `z` combinationally from the current `x` and the "seen a 1" flag in the same cycle. That yields a Mealy-like result and disagrees with the Moore machine by one cycle at the transition where the first 1 appears. The checker must instead key `z` to the pre-edge state only.

Worked example: input stream `0, 1, 0` (LSB first), starting from reset. First posedge after release: `x=0`, pre-edge state S0, so `z=0`, state stays S0. Second posedge: `x=1`, pre-edge state S0, so `z=0`, state moves to S1. Third posedge: `x=0`, pre-edge state S1, so `z=1`, state stays S1. Sampled output sequence is `0, 0, 1`, the 2's-complement result delayed one cycle — exactly the Moore behavior. A checker emitting `0, 1, 1` on those edges would be modeling a Mealy machine and would fail.

The final checker should therefore: handle the asynchronous reset row unconditionally (force S0, `z=0`, ignore `x`); for each clocked row, sample edge-stable `x`, emit `z` from the pre-edge state, then apply the transition; and carry any mid-cycle `x` change forward to the next row rather than applying it to the current sample.
