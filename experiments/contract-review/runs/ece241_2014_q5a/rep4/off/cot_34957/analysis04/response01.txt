The public specification defines a one-input, one-output serial 2's complementer as a Moore machine: the output depends only on the current state, not directly on the input. The input `x` is one bit per clock cycle, presented least-significant bit first, and the output `z` is one bit per cycle. Both ports are one bit wide. `areset` is a one-bit positive-edge-triggered asynchronous reset. The conversion begins when reset is released and stops when reset is asserted. The machine must accept numbers of arbitrary length, so the state set must be finite and independent of input length; the natural Moore realization uses two states: a "copy" state (output 0) and a "complement" state (output 1), with the transition determined by whether a 1 has already been seen.

The critical boundary issue for the final Python checker is the distinction between the sampled edge and mid-cycle input changes. Each row's values are driven before the sampled edge. Optional mid input changes occur after sampling, before the other edge, and are carried to the start of the next row. Therefore, for a given row, the checker must use the `x` value present at the sampled edge to compute the next state, and must use the current state (before that transition) to produce the output. The checker must not compute `z` from `x` directly, because this is a Moore machine: output is a function of state only. The checker must also not let a mid-cycle change in `x` affect either the current row's output or the current row's next state; that change belongs to the next row.

Reset handling is equally important. Because `areset` is asynchronous, the checker must apply reset immediately when `areset` is asserted, without waiting for a clock edge. While reset is asserted, the machine must hold the reset state and the corresponding output, and conversion must not advance. When reset is released, the first sampled edge must use the initial state established by reset release, not a state carried over from before reset. The checker should therefore treat reset as an immediate override: if `areset` is asserted in a row, set the state to the reset state and compare the expected output for that reset state; do not perform the normal transition for that row.

A short worked example illustrates the required ordering. Suppose the reset state is S0 with output 0, and the transition table says S0 with x=1 goes to S1. For a row where `areset` is deasserted and sampled x=1, the checker must output 0 (from S0) and set the next state to S1. If x then changes mid-cycle to 0, that change is carried to the next row. On the next row, the checker uses state S1 and sampled x=0; if S1 has output 1 and S1 with x=0 stays S1, the checker outputs 1 and keeps S1. The mid-cycle 0 did not alter the first row's output or next state.

For the final Python checker, the useful focus is therefore: model the machine as a transition table keyed by state and sampled `x`, with output attached to the current state; process each row by first applying asynchronous reset immediately if asserted, otherwise emit the output of the pre-transition state, compute the next state from the sampled `x`, and then advance the state; carry any mid-cycle `x` change to the next row; and ensure the first sampled edge after reset release starts from the reset-release initial state. The checker must never derive `z` combinationally from `x`, and must never advance conversion while reset is asserted.
