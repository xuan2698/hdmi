The public interface is deliberately minimal: one 1-bit input `x`, one 1-bit output `z`, one clock `clk`, and one asynchronous active-high reset `areset`. All declared widths are exactly 1, so there are no multi-bit packing, endianness, or truncation concerns. The only meaningful boundary values are logic 0 and logic 1 on `x`, `z`, and `areset`; `clk` is a timing signal rather than a data value. Because the machine accepts numbers of arbitrary length, there is no fixed input width, no terminal count, and no “last bit” flag. The checker must not assume a bounded number of cycles or a fixed word length.

The behavioral boundary that matters most is the reset boundary. `areset` is asynchronous and positive-edge triggered: assertion forces the state to S0 and `z` to 0 independently of `clk`, and `x` is ignored on that row. Conversion starts only after reset is released. The first sampled posedge after release therefore evaluates the pre-edge state S0, not any state implied by the first input bit. This is a boundary between “reset domain” and “conversion domain,” and the checker must treat the reset row as unconditional rather than as an ordinary clocked transition.

The second boundary is the Moore output boundary. `z` is a function of the pre-edge state only. On every non-reset row the checker must read `z` from the state that existed before the posedge, then update the state from (`state`, sampled `x`). The input `x` must be the value stable at the sampling edge. Any mid-cycle change to `x` occurs after sampling and belongs to the next row; it must be carried forward, not applied retroactively. This ordering—emit `z` from old state, then transition—is the single most useful point for the final Python checker, because the common failure is to derive `z` combinationally from current `x` and a “seen a 1” flag, producing a Mealy-like output that lags incorrectly by one cycle at the first 1.

A short worked example fixes the boundary. With LSB-first input `0, 1, 0` after reset release: first posedge has `x=0`, pre-edge S0, so `z=0` and state stays S0; second posedge has `x=1`, pre-edge S0, so `z=0` and state becomes S1; third posedge has `x=0`, pre-edge S1, so `z=1` and state stays S1. The sampled output is `0, 0, 1`, the 2's-complement result delayed one cycle. A checker producing `0, 1, 1` would be wrong.

In prose, the final checker should therefore enforce three things: reset rows force S0 and `z=0` while ignoring `x`; clocked rows sample edge-stable `x`, emit `z` from the pre-edge state, then transition; and mid-cycle `x` changes are deferred to the next row. No other port-width or numeric-boundary handling is needed beyond 1-bit logic values and arbitrary-length sequencing.
