**Reset and power-up behavior.** The public specification defines a positive-edge-triggered asynchronous reset (`areset`, active high) for a one-input, one-output serial 2's complementer. The machine is a Moore machine: its output `z` is a function of the current state only, and the state set is effectively {Copy, Complement}. In Copy, `z=0` and incoming bits are passed through unchanged in the sense that the machine stays in Copy while `x=0`; the first `x=1` moves it to Complement. In Complement, `z=1` and every subsequent bit is inverted (state stays in Complement regardless of `x`). This is the standard "scan from LSB, copy until first 1, then invert" algorithm for two's complement.

Power-up is not separately specified beyond the asynchronous reset. Because reset is asynchronous, asserting `areset` at any time must force the machine into the Copy state and drive `z=0` without waiting for a clock edge. Releasing `areset` does not itself define a conversion start edge in the sense of consuming an input bit; conversion "begins when Reset is released," meaning the next sampled positive edges are treated as the LSB-first input stream. The specification does not require a fixed number of idle cycles after release, nor does it constrain `x` while reset is asserted. A correct checker should therefore treat reset as a level-sensitive override: while `areset=1`, force the reference state to Copy and require `z=0`; while `areset=0`, advance on each positive edge.

**The alignment point that matters most for the final Python checker.** The phrase "sample after the posedge edge has settled" and "each row's values are driven before the sampled edge" means input sampling, state transition, and output observation are aligned to the same edge. The sampled `z` on a given positive edge must be the Moore output of the **next** state—the state entered by that edge—not the output of the pre-edge state. A checker that compares `z` against the pre-edge state's output will be off by one cycle and will reject a correct implementation. This is most visible at the first `1` after reset: the machine is in Copy (`z=0`); when the first sampled `x=1` arrives, the transition is Copy → Complement, and because Complement has Moore output `1`, the sampled `z` on that same edge must be `1`. A checker expecting `z=0` on that edge and `z=1` only on the next edge is modeling a delayed or Mealy-like output and will fail a correct Moore design.

**Short worked example.** Suppose the sampled input after reset release is `x = 0, 0, 1, 0, 1`. The expected sampled output is `z = 0, 0, 1, 1, 0`. The first two zeros keep the machine in Copy with `z=0`. The first `1` moves to Complement and must produce `z=1` on that very edge. The following `0` and `1` are inverted to `1` and `0`. A checker that shifts the output stream right by one cycle would produce `0, 0, 0, 1, 1` and mismatch at the third sample.

**Useful discipline for the final Python checker.** Keep a single reference state variable initialized to Copy. On each positive edge when `areset` is deasserted, update the reference state from the sampled `x`, then compare the sampled `z` to the Moore output of the updated state on that same edge. When `areset` is asserted, force the reference state to Copy and require `z=0`, without imposing a fixed number of idle cycles before or after release. Allow `x` to change arbitrarily while reset is asserted, since the specification does not constrain input behavior during reset. Do not assume any particular state encoding or state count; only the Copy/Complement distinction and same-edge output alignment matter. The essential invariant is that input sampling, state transition, and Moore output observation all occur on the same positive edge.
