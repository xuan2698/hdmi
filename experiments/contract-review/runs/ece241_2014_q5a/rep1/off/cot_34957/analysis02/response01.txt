**Reset and power-up analysis**

The machine has one asynchronous control input, `areset`, and one synchronous data input, `x`. The public timing convention is that each row’s values are driven before the sampled positive edge, and the checker samples after that edge has settled. Optional mid-input changes occur after sampling and before the next edge, and are carried into the next row. This distinction matters because the Moore output `z` belongs to the state present at the sampled edge, not to any mid-cycle change in `x`.

On power-up, before any reset is applied, the state is not specified by the public interface. The checker should therefore not require a particular `z` value until `areset` has been asserted. The asynchronous reset is the only defined initialization mechanism. When `areset` is asserted, the machine must be forced to the initial “before first one” state without waiting for a clock edge. In that state the Moore output must be defined; for the standard serial 2’s complementer, the natural initial output is `0`, since no first `1` has yet been seen and the copied-bit mode has not ended. The checker should treat reset assertion as immediately establishing both the initial state and its associated output, subject only to the stated sampling convention after the edge has settled.

When `areset` is released, conversion begins. The first sampled positive edge after release uses the current `x` value as the least-significant bit of the input number. Because the machine is Moore, the sampled `z` at that edge is determined by the state before the edge, not by the new `x` alone. The state transition then records whether the first `1` has been observed. In the initial mode, zeros are copied and the machine remains “before first one.” When the first `1` is sampled, the output for that sampled edge is `1` and the machine moves to “after first one.” From then on, the output is the complement of the input bit associated with the state, and the machine remains in the inverted mode until reset is asserted again.

A useful point for the final Python checker is to keep three things separate: the asynchronous reset effect, the sampled edge values, and the mid-input carry-forward. Reset assertion should be allowed to change state and `z` without a clock edge. At each sampled posedge, the checker should capture settled `areset`, `x`, and `z`, and should verify that `z` is consistent with the Moore state alone. Any mid-input change to `x` after sampling must affect only the next row’s input, never the current row’s `z`. The checker should also confirm that reset release starts conversion at the next sampled edge and that reset assertion stops conversion immediately, returning the machine to the defined initial output.

Short worked example: input bits LSB-first `0, 0, 1`. After reset release, the first two sampled zeros produce `z = 0` while the machine remains “before first one.” The sampled `1` produces `z = 1` and moves the machine to “after first one.” If `x` changes mid-cycle after that sample, the change is used only for the next row; the `z` captured at the first-one edge remains `1`.
