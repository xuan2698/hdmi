The public spec describes a one-input, one-output serial 2's complementer as a Moore machine: output `z` depends only on the current state, not directly on `x`. Input `x` arrives least-significant bit first, one bit per clock, and the machine must handle arbitrary-length numbers. Reset is positive-edge-triggered and asynchronous; conversion begins when reset is released and stops when reset is asserted. The checker samples after the posedge has settled, with each row's values driven before the sampled edge. Optional mid-input changes occur after sampling, before the other edge, and carry to the start of the next row.

The key timing distinction is between the sampled edge and the mid-cycle interval. At a sampled posedge, the checker observes the settled values of `areset`, `x`, and `z` that were driven before that edge. The Moore output `z` must therefore be consistent with the state that the machine has already entered, not with a combinational function of the just-sampled `x`. In particular, if `x` changes after the sampled edge, that change must not retroactively alter the `z` observed at that edge. The mid-input change is explicitly allowed to occur after sampling and before the other edge, and it is carried forward to the start of the next row. This means the checker should treat the post-sample `x` value as the input for the next sampled edge, while the `z` captured at the current edge belongs to the current state.

For a serial 2's complementer, the usual state interpretation is: scan from the LSB upward, copy bits until the first `1` is seen, then invert every subsequent bit. A Moore implementation can encode this with states such as "before first one" and "after first one." In the "before first one" state, output equals the input bit only if that bit is 0; when the first 1 arrives, the output is 1 and the machine transitions to "after first one." Thereafter output is the complement of `x`. Because the output is Moore, the state must be updated at the sampled edge so that the next sampled `z` reflects the new mode. The asynchronous reset must force the machine to the initial "before first one" state and a defined output, and release of reset starts conversion.

A useful point for the final Python checker is to separate the edge sample from the mid-input update. At each sampled posedge, record `areset`, `x`, and `z` as settled. Then apply any optional mid-input change to `x` for the next row, but do not re-evaluate `z` for the current row. The checker should also verify that `z` is a function of state alone: for the same state and reset condition, `z` must be identical regardless of the mid-input value. Finally, because reset is asynchronous and positive-edge-triggered, the checker should allow reset assertion to take effect without waiting for a clock edge, while still sampling the post-release behavior at the next settled posedge.

Short worked example: suppose the number is `100` (binary, LSB first: `0,0,1`). Before the first 1, output copies `0` and `0`. When the first `1` is sampled, output is `1` and the state moves to "after first one." If a mid-input change supplies the next bit after that sample, it is used only for the next row; the `z` at the first-one edge remains `1`. The final complement bits are then inverted relative to subsequent inputs.
