**Reset and power-up analysis (public spec only)**

The public interface makes `areset` an asynchronous, active-high override. That has two consequences a checker must respect. First, while `areset` is asserted, the machine must be forced to its initial Moore state and `z` must be `0` independently of `clk`; a checker should not require a posedge before the reset value appears, nor should it require `z` to remain at whatever value the previous conversion had produced. Second, power-up is not separately specified beyond this: the only guaranteed observable is that with `areset` held asserted the output is the initial-state output `z=0`, and the first conversion begins only after release. A checker should therefore treat "reset asserted" as a stable expected-output region (`z=0`) and should not attempt to predict internal state or output during the release edge itself.

The subtle point for the final Python checker is the interaction between asynchronous reset and the Moore output delay. Because `z` is a function of state, and reset asynchronously forces the initial state, `z` may change to `0` at an arbitrary time relative to `clk` when `areset` is asserted. Sampling only after posedges has settled is correct for normal operation, but the checker must also allow the reset-induced `z=0` to appear without a preceding sampled edge. Conversely, on release, the first posedge after release samples the first `x` bit; the output visible after that edge is still the initial state's `z=0` (the machine has not yet consumed a `1`), and only the following edge reflects the first-one transition. A checker that compares `z` to a function of the current `x` sample, or that expects the complement to appear on the same edge as the first sampled `1`, will fail on alignment and on reset-release timing.

Worked example (short): hold `areset=1`; `z` must read `0` asynchronously. Release reset; sampled `x` sequence LSB-first is `0,0,1,0,1`. After the first two posedges, state is still initial, so sampled `z=0,0`. At the edge sampling the first `1`, the machine enters the first-one state; sampled `z` after that edge is `1`. Next sampled `x=0` gives `z=1`; next sampled `x=1` gives `z=0`. The checker should derive expected `z` from the Moore state implied by prior sampled `x`, permit the one-step latency, and treat `areset` as an asynchronous override that forces `z=0` without requiring a clock edge. It should not constrain state encoding or count, only the public `x`/`z`/`areset` relation.
