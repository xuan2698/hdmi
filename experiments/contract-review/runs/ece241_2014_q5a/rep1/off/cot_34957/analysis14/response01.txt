**Reset and power-up behavior**

The public specification defines a positive-edge-triggered asynchronous reset (`areset`) for a one-input, one-output serial 2's complementer. The machine consumes `x` least-significant-bit first and produces `z`, the 2's complement of the accumulated input, as a Moore output. Because the reset is asynchronous, asserting `areset` must force the machine into its initial state independently of `clk`; the output `z` must then be `0` while reset is held. Power-up is not separately modeled: the specification gives no guaranteed pre-reset state, so the checker should treat the first asserted reset as the only reliable initialization event. Any behavior observed before a reset has been asserted is not part of the public contract and should not be scored.

The conversion begins when reset is released. The first positive clock edge after release samples the first input bit, and the Moore output observed after that edge corresponds to the state entered by that same edge. This same-edge alignment is the critical point for the final checker. In the initial "copying" state, a sampled `x=0` keeps the machine copying and yields `z=0`; a sampled `x=1` moves the machine into the "complementing" state and yields `z=1` immediately on that edge. Once complementing, every subsequent bit is inverted: `x=0` gives `z=1`, and `x=1` gives `z=0`. The machine remains in complementing mode for the rest of the number, since after the first `1` in LSB-first order all higher bits must be inverted.

A short worked example clarifies the timing. Suppose reset is released and the sampled input sequence is `x = 0, 0, 1, 0, 1`. The expected sampled outputs are `z = 0, 0, 1, 1, 0`. The first two zeros leave the machine copying, so `z` stays `0`. The first `1` transitions into complementing, and `z` is already `1` on that same sampled edge. The following `0` is inverted to `1`, and the final `1` is inverted to `0`. A checker that expects the complementing output one cycle later, or that compares `z` against a function of the previous input, will report false failures.

For the final Python checker, the useful reference model is a two-state variable: copying (initial) and complementing. On each sampled positive edge, if `areset` is asserted, force the reference state to copying and require `z=0`. Otherwise update the reference state from the sampled `x`: in copying, remain copying while `x=0` and move to complementing when `x=1`; in complementing, remain complementing regardless of `x`. The expected `z` is `0` in copying and `1` in complementing, compared against the sampled `z` after the same edge. The checker should not assume a particular state encoding or state count, should allow `x` to change arbitrarily while `areset=1`, and should not over-constrain the exact cycle of reset release. The essential invariant is that input sampling and Moore output observation are aligned on the same positive edge.
