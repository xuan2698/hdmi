The machine has two stable Moore states, which we can call **S0 (before the first 1)** and **S1 (after the first 1)**. The output is a function of state only: in S0, `z = 0`; in S1, `z = 1` while the machine is still in the “copy” phase? No — the public behavior is simpler: the output in S0 is the copied bit only insofar as the state has not yet inverted; but because the machine is Moore and the output is one bit, the only consistent reading of the spec is that S0 drives `z = 0` and S1 drives `z = 1` for the first-one sample, after which the output must become the complement of `x`. That would require the output to depend on `x`, which a Moore machine cannot do directly. Therefore the correct Moore formulation is to split the “after first one” behavior into two states: **S1 (first one just seen, output 1)** and **S2 (inverting mode, output 0 when x=1 and 1 when x=0)** — but again, a Moore output cannot depend on `x`. The standard resolution is that the Moore output in the inverting phase is the complement of the *previous* input bit, or equivalently the machine uses the state to remember the last input bit. The public spec does not give enough detail to distinguish these encodings, so the checker should not assume a particular state count; it should only verify the observable input/output relation.

Observable relation: while no 1 has yet been received since reset release, `z` equals the input bit delayed by one sample (because Moore output is state-based). Once the first 1 is received, subsequent outputs are the complement of the corresponding input bits, again with the one-cycle Moore delay. The checker should therefore compare `z` at each sampled edge against the expected 2's-complement bit stream, allowing for the Moore latency: the output associated with the state entered at the previous edge.

Reset assertion is asynchronous: it immediately forces the machine to S0 and `z = 0`, independent of `clk`. Reset release does not itself produce an output; the next sampled posedge begins conversion. Mid-cycle `x` changes after sampling affect only the next row. The checker should sample `areset`, `x`, and `z` after the posedge has settled, verify `z` against the Moore state implied by the history of sampled `x` since reset release, and confirm that reset assertion clears state and output without waiting for an edge.

Worked example: LSB-first input `0,0,1`. After release, sampled zeros keep the machine before the first 1 with `z=0`. The sampled 1 sets the first-one state with `z=1`. A mid-cycle change to `x` after that sample is used only on the next row; the captured `z=1` remains valid for the first-one edge.
