The machine has two states, `COPY` and `INVERT`, with `COPY` as the reset state. In `COPY`, the output is `z = 0` and the machine stays in `COPY` while `x = 0`; on the first `x = 1` it must output `z = 1` on that same row and move to `INVERT`. In `INVERT`, the output is `z = 1` and the machine remains in `INVERT` for all subsequent inputs, since after the least-significant `1` has been found every remaining bit is complemented. Thus the output is a function of the current state alone (Moore), and the only state transition that depends on `x` is `COPY --x=1--> INVERT`; all other transitions are self-loops.

The subtlety is the ordering of output and transition on the boundary row. The output must be derived from the pre-edge state, so on the row where the sampled state is `COPY` and `x = 1`, `z` is still `0`? No — the specification requires `z = 1` on that row. The correct reading is that the Moore output for `COPY` is `0`, but the boundary row is the row on which the machine has already committed to `INVERT` for output purposes while the state register still holds `COPY` before the edge. Concretely, the intended behavior for input bits `0,1,0,0` (LSB first) is `z = 0,1,1,1`: the first `1` produces `z = 1` immediately, and the next state becomes `INVERT`. A design that transitions first and outputs from the new state would give `0,0,1,1`, which is wrong. The checker must therefore assert, on any row whose pre-edge state is `COPY` and whose sampled `x = 1`, that `z = 1` and that the next state is `INVERT`. This single boundary assertion is the most valuable check, because it distinguishes the correct output-before-transition ordering from the plausible but incorrect transition-before-output ordering, and it cannot be masked by later rows that happen to be `1`.

Reset dominates everything. On every row where sampled `areset = 1`, the state must be forced to `COPY` and `z` must be `0`, regardless of `x` or the prior state. The checker must verify both the output and the next state on reset rows; checking only `z = 0` would pass a design that gates the output but still advances the state, whose error surfaces one row later. Mid-row input changes occur after sampling and apply only to the next row; they must not alter the just-sampled `z` or the transition taken on the current row. The checker should sample `x` and `areset` before the edge, compute `z` from the pre-edge state, then apply the `x`-driven transition to obtain the next state, carrying any mid-row change forward. The initial state may be left unconstrained or required to be `COPY` via an initial reset row.
