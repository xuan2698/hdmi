The key distinguishing case for this Moore 2's-complementer is the **first `1` row**, because it is the only row where a naive "output follows current input" implementation and the correct Moore implementation disagree while the state is still COPY.

Consider the LSB-first stream `0, 1, 0, 1` after reset release. On row 1 (`x=0`), the pre-edge state is COPY, so `z` is the COPY-phase output (the previously latched bit, initially the reset value), and the state remains COPY. On row 2 (`x=1`), the pre-edge state is *still* COPY, so `z` must again be the COPY-phase output — the latched bit from row 1 — even though this row's `x=1` is what drives the transition into INVERT. Only on row 3 (`x=0`) does the pre-edge state become INVERT, so `z` is the complement of the latched bit. Row 4 (`x=1`) likewise outputs from INVERT.

The trap is row 2. A checker that computes `z` from the current row's `x` (or that updates state before emitting `z`) will produce the INVERT-phase output one row too early. On every other row of this trace the two models coincide, so a short trace that happens to omit the first-`1` boundary — or that only checks rows after the machine has settled into INVERT — will pass a buggy design. The distinguishing input must therefore include the transition row itself and must check `z` on that row against the *pre-edge* state.

Two further ordering rules matter for the checker. First, reset dominance: any row with `areset=1` forces both the reset state and the reset output, and `x` on that row is ignored entirely — it must not influence state or output. Second, deferred mid-row changes: an `x` or `areset` change occurring after the sampling edge belongs to the next row and must never be applied retroactively to the row just sampled. Sampling is defined as occurring after the positive edge has settled, so each row is a snapshot; a checker that lets a mid-row `x` flip leak backward into the current row's `z` or state will accept an implementation that is combinationally sensitive within the row, which the Moore specification forbids.

The correct evaluation order per row is therefore: (1) apply reset dominance, (2) compute `z` from the pre-edge state (Moore alignment), (3) update state from the row's `x`, (4) carry any mid-row changes forward to the next row only. The final checker should reject any trace where `z` on the first-`1` row equals the INVERT-phase value rather than the COPY-phase value, and should reject any row where a mid-row change alters an already-sampled output or state.
