The public interface is a single-bit synchronous machine: one input `x`, one output `z`, one clock `clk`, and one asynchronous reset `areset`. All ports are width 1, so there are no multi-bit packing or endianness concerns at the port boundary; the only ordering convention that matters is temporal. The input stream is LSB-first, meaning the first sampled `x` after reset release is the least-significant bit of the operand, and the output stream is produced in the same order. Because the machine accepts arbitrary-length operands, the checker must not assume a fixed row count or a terminal framing bit. The meaningful boundary values are therefore per-row Boolean values: `x ∈ {0,1}`, `z ∈ {0,1}`, and `areset ∈ {0,1}`. The state set is `{COPY, INVERT}`, with `COPY` as the reset state.

The subtle boundary is not numeric range but temporal alignment. The specification is Moore-style: `z` is a function of the state, and the sampled output on a row corresponds to the pre-edge state, not the state after applying that row’s `x`. Reset is asynchronous and dominant: whenever `areset` is sampled high, the state is forced to `COPY` and the output is the `COPY` output for that row. Since `COPY` with no prior inversion history copies the input, the reset-row output is `z = 0` under the stated convention. A checker must treat reset as overriding both the next-state function and the output function; gating only `z` while still advancing state, or advancing state unconditionally, is a divergence.

When `areset = 0`, the checker should evaluate `z` from the pre-edge state first: in `COPY`, `z = x`; in `INVERT`, `z = ~x`. Only then should it apply the transition: `COPY` with `x = 1` goes to `INVERT`; `COPY` with `x = 0` stays `COPY`; `INVERT` stays `INVERT`. Mid-row changes to `x` or `areset` occur after sampling and belong only to the next row; they must not retroactively alter the just-sampled `z` or the transition taken on that row.

The highest-value checker assertion is the first-1 boundary. On the first row where `x = 1` while the pre-edge state is `COPY`, the output must be `z = 1` (the copied bit), and the next state must be `INVERT`. A design that computes `z` from the post-transition state would emit `z = 0` on exactly that row. Because later rows in a typical trace also produce `1`, a checker that omits this boundary can still pass a broken design, so the first-1 row must be asserted explicitly.

Worked example: LSB-first input `0100` represents value 2. Row 1: reset released, state `COPY`, `x = 0` → `z = 0`, next `COPY`. Row 2: `x = 1` → `z = 1` (boundary), next `INVERT`. Row 3: `x = 0`, `INVERT` → `z = 1`. Row 4: `x = 0`, `INVERT` → `z = 1`. Output `0011` LSB-first is 3, the two’s complement of 2. The boundary row is where a post-transition-output bug shows `z = 0` instead of `1`.

For the final checker, the useful focus is: require an initial reset row or leave the first state unconstrained, enforce reset dominance on every `areset = 1` row, compute `z` from the pre-edge state before applying the `x`-driven transition, carry mid-row changes forward only, and explicitly assert the first-1 boundary row.
