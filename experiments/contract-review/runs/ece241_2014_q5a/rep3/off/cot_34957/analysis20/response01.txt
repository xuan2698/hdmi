**Reset and power-up analysis**

The public specification defines a positive-edge-triggered asynchronous reset, with `areset` sampled alongside `x` at each rising edge. The phrase "conversion begins when Reset is released and stops when Reset is asserted" is the key behavioral anchor. It means the machine's conversion phase is not merely paused during reset; it is reinitialized so that the next conversion starts from the least-significant bit with the correct 2's-complement boundary condition. For a 2's-complementer processing LSB-first, that boundary condition is the "copy until first 1, then invert" rule. The natural reset state is therefore the copy phase, which we can call `COPY`, with output `z = 0`.

The checker should treat reset as a sampled, edge-aligned event, not as a level that can be applied at arbitrary times within a row. On any row where the pre-edge sampled `areset` is 1, the required behavior is: the pre-edge output `z` is 0, and the next state is `COPY`, independent of `x` and of the prior state. Asserting only `z = 0` on reset rows is a classic under-check. A faulty machine could hold `z` low during reset while still advancing its internal phase, then emerge from reset in `INVERT` and produce wrong outputs on the first bits of the next number. The checker must therefore assert both the reset-row output and the reset-row next-state transition. This is the single most valuable reset assertion because it catches state-retention faults that output-only checks miss.

Power-up behavior is deliberately less constrained by the public spec. The spec says conversion begins when reset is released, which implies that a well-formed stimulus will include at least one reset row before meaningful data. The checker may either force the initial state to `COPY` via an initial reset row, or leave the pre-first-reset state unconstrained. If it leaves it unconstrained, it must not assume `COPY` before the first sampled reset. The safer checker policy is to require an initial reset row in the stimulus and then treat the post-reset state as `COPY`; this removes ambiguity without over-constraining the design. If the checker instead assumes `COPY` at time zero and the design powers up in an arbitrary state, a correct design could be failed for behavior the spec never required.

A second reset subtlety is the interaction with mid-row input changes. Because `areset` is sampled at the positive edge, a mid-row change of `areset` after sampling belongs to the next row. The checker must not let a mid-row reset assertion retroactively zero the just-sampled `z` or alter the transition just taken. Conversely, a mid-row release of reset must not be treated as releasing the machine until the next sampled edge. This is the same edge-boundary discipline required for `x`, and it matters for reset because a checker that samples reset after the edge can mis-time the first post-reset conversion row.

**Worked example.** Suppose the stimulus has a reset row with `areset = 1`, `x = 0`, pre-edge state `INVERT`. The required sampled behavior is `z = 0` and next state `COPY`. The next row has `areset = 0`, `x = 0`, pre-edge state `COPY`; required `z = 0`, next state `COPY`. The following row has `x = 1`, pre-edge `COPY`; required `z = 1`, next state `INVERT`. A machine that only zeroes `z` on reset but keeps `INVERT` would output `z = 1` on the second row and fail the boundary check immediately.

**Focus for the final checker.** Pin the reset row as a joint assertion on `z` and next state, and pin the first post-reset `1` as the transition from `COPY` to `INVERT` with `z = 1`. These two boundary assertions, evaluated strictly from pre-edge state and sampled inputs, catch the dominant reset-retention and off-by-one-phase faults.
