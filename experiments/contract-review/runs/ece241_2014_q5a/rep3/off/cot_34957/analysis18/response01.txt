The most useful implementation mistake to target is an off-by-one in the **first `1` boundary** — the row where the machine must both emit `z = 1` and transition from `COPY` to `INVERT`. A common buggy design treats the transition as "detect `1`, then invert on the *next* cycle," producing `z = 0` on that boundary row and only asserting `z = 1` afterward. This is easy to miss because every later row still outputs `1`, so the machine looks correct in steady state.

Concretely, the correct Moore behavior is: in `COPY`, `z = x`; if `x = 1`, next state is `INVERT`. In `INVERT`, `z = 1` always, and the state stays `INVERT`. The buggy variant instead keeps `z = 0` on the first `1` and enters `INVERT` one row late, so the output stream is shifted by one at exactly the boundary. Since the spec is LSB-first, the first `1` after the least-significant run of zeros is the only row that distinguishes the two designs; all subsequent bits are `1` under both.

This matters because later `1` bits do not re-expose the error. Once the machine has entered `INVERT`, every subsequent bit produces `z = 1` under either ordering, so a design that delays the first `1` by one row will still look correct on all rows after the boundary. Only the first `1` bit after the least-significant run of zeros reveals the ordering. A checker that samples only steady-state behavior, or that compares outputs after the state has already flipped, will pass the wrong machine. The boundary assertion is therefore the highest-value check and should be verified directly from the pre-edge state and the sampled `x`.

Reset is the other boundary the checker must pin down. On every row where the sampled `areset` is `1`, the next state must be `COPY` and `z` must be `0`, regardless of `x` and regardless of the prior state. Checking only `z = 0` is insufficient: a design could suppress the output on the reset row while still advancing state, and the error would only surface one row later when the machine fails to behave as if it had restarted in `COPY`. Both the output and the next state must be asserted on reset rows.

The sampling discipline also needs to be explicit. The checker should use the pre-edge `x` and `areset`, compute `z` from the pre-edge state, then apply the transition to obtain the next state. Mid-row input changes occur after sampling and belong only to the next row; they must not retroactively alter the just-sampled `z` or the transition taken on the current row. The initial state may be left unconstrained or forced to `COPY` by an initial reset row, but if it is left unconstrained the checker should not assume `COPY` before the first reset.

Worked example: for LSB-first `0,1,0,0`, the first row has pre-edge `COPY`, `x = 0`, so `z = 0` and the state stays `COPY`. The second row has pre-edge `COPY`, `x = 1`, so the boundary rule requires `z = 1` and next state `INVERT`. The remaining rows output `1,1`. The checker's key assertion is that second-row boundary: `z = 1` with next state `INVERT`, not `z = 0`.
