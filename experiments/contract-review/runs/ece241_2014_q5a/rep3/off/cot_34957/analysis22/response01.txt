The design is a two-state Moore machine. State `COPY` means no `1` has yet been seen in the LSB-first stream, so the current bit passes through unchanged (`z = x`). State `INVERT` means a `1` has already been seen, so all higher bits are complemented (`z = ~x`). The transition is: from `COPY`, `x = 0` stays in `COPY` and `x = 1` goes to `INVERT`; from `INVERT`, any `x` stays in `INVERT`. Output depends only on state and current input, which is the standard Moore-with-input form used here.

Port widths are minimal: `areset`, `x`, and `z` are each 1 bit; `clk` is the single clock. Because the machine accepts arbitrary-length numbers, there is no width parameter and no terminal state — the checker must not assume a fixed number of cycles. The only "boundary values" are therefore logic levels and edge timing, not numeric ranges. `z` is always exactly one bit, so the checker compares against 0 or 1, never against a multi-bit encoding.

Reset is positive-edge-triggered and asynchronous. When `areset` is asserted, state is forced to `COPY` and `z` to 0 independent of `clk`. When released, conversion begins from `COPY` at the next sampled positive edge. The checker must treat the sampled `areset` at each positive edge as authoritative: mid-row assertion or release takes effect only at the next sampled edge and must not retroactively alter the `z` or next state already committed at the previous edge. The same edge-boundary discipline applies to `x`.

The critical checker points are the reset row and the first post-reset `1`. On a reset row (`areset = 1`), regardless of prior state and `x`, sampled `z` must be 0 and next state must be `COPY`. On the first row after reset with `areset = 0` and `x = 1`, the pre-edge state is `COPY`, so `z` must be 1 and next state must be `INVERT`. A design that clears `z` on reset but fails to force `COPY` will output `z = 1` on an early `x = 0` row (since `INVERT` complements 0 to 1) and fail immediately. A design that forces `COPY` but mishandles the first `1` will either stay in `COPY` (outputting 1 but never inverting later bits) or invert the first `1` itself (outputting 0 where 1 is required). Both faults are caught by pinning the reset row as a joint `z`/next-state assertion and pinning the first post-reset `1` as the `COPY → INVERT` transition with `z = 1`.

The checker should require an initial reset row so the post-reset state is unambiguously `COPY`, avoiding any assumption about power-up state. It should evaluate all assertions from the pre-edge state and sampled inputs at the positive edge, and must not let mid-row `areset` or `x` changes affect the just-sampled outputs or transitions.

Worked example: reset row with `areset = 1`, `x = 0` → `z = 0`, next state `COPY`. Next row `areset = 0`, `x = 1` → `z = 1`, next state `INVERT`. Next row `x = 0` → `z = 1` (complement of 0), state stays `INVERT`. This three-row sequence pins both the reset boundary and the first-`1` transition.
