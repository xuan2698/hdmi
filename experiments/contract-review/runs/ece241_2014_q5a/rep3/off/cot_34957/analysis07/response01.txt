The public spec fixes a Moore machine, so the output is a function of the pre-edge state only. The input stream is LSB-first, and the 2's complement rule is: copy bits until and including the first `1`, then invert every subsequent bit. That makes the first `1` the pivot. The state transition COPY→INVERT is triggered by `x=1`, but the output on that same row must still be the COPY-phase value, because the machine has not yet entered INVERT at sampling time.

Edge and mid-input timing matter here. Each row's values are driven before the sampled posedge. The checker should sample `x`, `areset`, and the current state at that edge, compute `z` from the pre-edge state, then update the state from `x`. Optional mid-input changes occur after sampling and before the other edge; they belong to the next row and must not retroactively affect the just-sampled `z` or state. This is the key timing discipline: the Moore output is aligned to the state that existed before the edge, not to the state that results from the edge.

Reset is positive-edge-triggered and asynchronous. A row with `areset=1` forces both the reset state and the reset output; `x` on that row is ignored and must not leak into state or `z`. Conversion begins when Reset is released and stops when Reset is asserted. The checker should therefore apply reset dominance first, then emit `z` from the pre-edge state, then update state from `x`, then carry mid-row changes forward.

A useful worked example is the 4-bit number `0100` (value 4), sent LSB-first as `x = 0, 0, 1, 0`. Its 2's complement is `1100`, so the output bits LSB-first are `0, 0, 1, 1`. On row 3, the pre-edge state is COPY and `x=1`, so `z=1` (the copied pivot bit), and the next state is INVERT. A buggy design that outputs from the post-transition state would put `z=0` on row 3. On this trace row 4 also happens to be `1`, so a careless checker comparing only rows 1, 2, and 4 would miss the error entirely.

For the final Python checker, the most valuable assertion is the first-`1` boundary check: on the row where `x=1` first appears while the pre-edge state is COPY, `z` must equal `1`, not the INVERT-phase complement. This is the only row where pre- and post-transition output models diverge on a minimal trace. The checker should also enforce Moore alignment generally, reset dominance, and no retroactive mid-row changes. The evaluation order per row is: apply reset dominance → emit `z` from pre-edge state → update state from `x` → carry mid-row changes forward. That ordering captures the public spec's timing intent and catches the most likely implementation error.
