The public spec fixes a Moore machine whose output depends only on the current state, with the input stream arriving least-significant bit first. The natural state set is `COPY` and `INVERT`: in `COPY`, the machine has seen only zeros so far and passes each bit through unchanged; in `INVERT`, the machine has already seen the first `1` and must complement every subsequent bit. The transition is simple: from `COPY`, `x = 0` keeps `COPY` and `x = 1` moves to `INVERT`; from `INVERT`, any `x` stays in `INVERT`. The output is `z = x` in `COPY` and `z = ~x` in `INVERT`, which is why the output cannot be read from the state alone — it is a function of both state and sampled input, even though the machine is Moore in form because the state itself encodes the conversion phase.

The edge and mid-input timing is where the checker earns its keep. Each row's values are driven before the sampled positive edge. The checker must take the pre-edge `x` and `areset`, evaluate `z` from the pre-edge state, and then apply the transition to obtain the next state. Mid-row input changes occur after sampling and before the next edge; they belong to the next row and must not retroactively change the just-sampled `z` or the transition just taken. If the checker instead samples after the edge or lets a mid-row change leak backward, it will mis-attribute the boundary behavior and can pass a machine that is off by one row.

The highest-value assertion is the first `1` after the least-significant run of zeros. Consider LSB-first `0,1,0,0`. Row one: pre-edge state `COPY`, `x = 0`, so `z = 0` and the state remains `COPY`. Row two: pre-edge state `COPY`, `x = 1`, so the boundary rule requires `z = 1` and next state `INVERT`. Rows three and four output `1,1`. A wrong machine that delays the first `1` by one row still produces `z = 1` on every later row, because once in `INVERT` all subsequent bits output `1` under either ordering. Only that second-row boundary exposes the error. The checker should therefore assert directly, from the pre-edge state and sampled `x`, that the first `1` yields `z = 1` and next state `INVERT`, not `z = 0`.

Reset is the other boundary to pin down. On every row where sampled `areset` is `1`, the next state must be `COPY` and `z` must be `0`, regardless of `x` and prior state. Checking only `z = 0` is insufficient: a design could suppress output on the reset row while still advancing state, and the fault would surface one row later when the machine fails to behave as if restarted in `COPY`. Both output and next state must be asserted on reset rows. The initial state may be left unconstrained or forced to `COPY` by an initial reset row; if unconstrained, the checker must not assume `COPY` before the first reset.
