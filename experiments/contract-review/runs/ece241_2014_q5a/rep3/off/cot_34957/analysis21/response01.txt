The machine has two states, `COPY` and `INVERT`, and one output `z` that is a function of the current state only (Moore). The input `x` arrives least-significant bit first, so the conversion rule is: while no `1` has yet been seen, the 2's-complement output equals the input bit (copy phase); after the first `1` is seen, every subsequent output bit is the complement of the input bit (invert phase). This is the standard "scan from LSB, copy up to and including the first 1, then invert the rest" algorithm.

State transitions: from `COPY`, if `x = 0` the machine stays in `COPY` (still no 1 seen); if `x = 1` it moves to `INVERT` (first 1 encountered, and that bit is copied, not inverted). From `INVERT`, the machine stays in `INVERT` regardless of `x`, because once the first 1 has passed, all remaining higher bits are complemented. Output: in `COPY`, `z = x`; in `INVERT`, `z = ~x`. Equivalently, `z` is the current input bit in the copy phase and its complement in the invert phase, which is exactly the 2's-complement bit stream.

Reset is positive-edge-triggered and asynchronous. When `areset` is asserted, the state is forced to `COPY` and `z` is forced to 0, independent of `clk`. When `areset` is released, conversion begins from `COPY` on the next sampled positive edge. Because reset is asynchronous, the checker must treat the sampled `areset` value at each positive edge as authoritative: a mid-row assertion or release of `areset` takes effect only at the next sampled edge, and must not retroactively change the `z` or next state already committed at the previous edge. This edge-boundary discipline is the same one applied to `x`.

The key boundary behavior for the checker is the reset row and the first post-reset `1`. On a reset row (`areset = 1`), regardless of prior state and `x`, the sampled `z` must be 0 and the next state must be `COPY`. On the first row after reset with `areset = 0` and `x = 1`, the pre-edge state is `COPY`, so `z` must be 1 and the next state must be `INVERT`. A design that clears `z` on reset but fails to force the state to `COPY` will output `z = 1` on an early `x = 0` row (since `INVERT` complements 0 to 1) and fail immediately; a design that forces `COPY` but mishandles the first `1` will either stay in `COPY` (outputting 1 but never inverting later bits) or invert the first 1 itself (outputting 0 where 1 is required). Both faults are caught by pinning the reset row as a joint `z`/next-state assertion and pinning the first post-reset `1` as the `COPY → INVERT` transition with `z = 1`.

The checker should require an initial reset row so the post-reset state is unambiguously `COPY`, avoiding any assumption about the power-up state. It should evaluate all assertions from the pre-edge state and the sampled inputs at the positive edge, and it should not let mid-row `areset` or `x` changes affect the just-sampled outputs or transitions.
