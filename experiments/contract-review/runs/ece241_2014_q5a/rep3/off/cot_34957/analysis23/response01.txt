The most useful point for the final Python checker is that the reset row and the first post-reset `1` row together form a single, tightly coupled assertion pair, and the checker should treat them as such rather than as independent checks. The public spec makes the reset behavior joint: on a sampled reset row, `z` must be 0 and the next state must be `COPY`, simultaneously. Splitting these into two separate assertions weakens the check, because a design that clears `z` on reset but leaves the state in `INVERT` would pass a `z`-only assertion on the reset row and only fail later, on an `x = 0` row where `INVERT` wrongly produces `z = 1`. Conversely, a design that forces `COPY` but mishandles the first `1` passes the reset row entirely and fails only at the transition row. The checker should therefore assert the reset row as a joint `(z = 0, next_state = COPY)` predicate, and assert the first post-reset `1` row as a joint `(z = 1, next_state = INVERT)` predicate, both evaluated from the pre-edge state and the sampled inputs at the positive edge.

A second useful point is the edge-boundary discipline. The spec says mid-row changes to `areset` or `x` occur after sampling and are carried to the start of the next row; they must not retroactively alter the `z` or next state already committed at the previous edge. The checker should sample `areset` and `x` at the positive edge, compute the expected `z` and next state from the pre-edge state and those sampled values, and compare against the sampled `z` and the state observed at the next sampled edge. Any mid-row activity is irrelevant to the current row's assertions.

A third point is the requirement of an initial reset row. Without it, the checker cannot assume the post-reset state is `COPY`, since power-up state is unspecified. Requiring an initial reset row makes the post-reset state unambiguous and lets the checker pin the first post-reset `1` transition reliably.

Worked example: reset row with `areset = 1`, `x = 0` → `z = 0`, next state `COPY`. Next row `areset = 0`, `x = 1` → `z = 1`, next state `INVERT`. Next row `x = 0` → `z = 1`, state stays `INVERT`. This three-row sequence pins both the reset boundary and the first-`1` transition, and the checker should encode it as two joint assertions plus the initial-reset precondition.
