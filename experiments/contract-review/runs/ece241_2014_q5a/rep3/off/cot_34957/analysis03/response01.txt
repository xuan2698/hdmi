The machine has two Moore states: **COPY** and **INVERT**. In COPY, the output is the bit most recently latched into the state (the previous input bit); in INVERT, the output is the complement of that latched bit. Reset forces the machine into COPY with the output corresponding to a zero latched bit (i.e., output 0), and while reset is asserted the state and output are held there regardless of `x`. The first `1` seen in the input causes the transition from COPY to INVERT; once in INVERT the machine stays there for the remainder of the number, since after the first `1` every subsequent bit is complemented. A `0` in COPY leaves the machine in COPY. In INVERT, both `0` and `1` leave the machine in INVERT.

The essential timing property is Moore alignment. The output sampled on a given clock edge is a function of the state *before* that edge, not of the input presented on that same row. The state update, by contrast, consumes that row's `x`. This means the transition row — the row in which the first `1` arrives — is the one place a careless checker breaks: the output on that row still belongs to COPY (it reflects the previously latched bit), even though the state is about to move to INVERT. A checker that derives `z` from the current row's `x` will produce the wrong value on exactly that row, and only there in the common case, making the bug easy to miss in short traces.

Mid-row input changes are deferred. If `x` changes after the sampling edge but before the next edge, that change is carried forward and applied as the next row's pre-edge input; it must never be applied retroactively to the row already sampled. The same deferral applies to reset: a mid-row assertion of `areset` affects only the next sampled row and cannot rewrite an already-sampled output or state. The checker should therefore treat each row as a snapshot taken after the positive edge has settled, with all changes between edges belonging to the following row.

Worked example: release reset, then feed LSB-first `0, 1, 0, 1`. Row 1 (`x=0`): pre-edge state COPY, output is the COPY output, state remains COPY. Row 2 (`x=1`): pre-edge state still COPY, so output is again the COPY output, but the state updates to INVERT. Row 3 (`x=0`): pre-edge state INVERT, output is the complement of the latched bit, state stays INVERT. Row 4 (`x=1`): output is again the INVERT-phase output. Any row with `areset=1` instead forces reset state and reset output and ignores `x`.

For the final checker, enforce three invariants in strict order: reset dominance first (asserted reset overrides state and output and ignores `x`), then Moore alignment (compute expected `z` from the pre-edge state, then update state from the row's `x`), then deferred mid-row changes (apply `x` and reset changes only to the next row). Sampling must occur after the positive edge has settled, so any output that would only be correct if `z` tracked `x` combinationally within the same row must be rejected.
