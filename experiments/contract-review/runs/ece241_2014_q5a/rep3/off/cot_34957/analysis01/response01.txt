The key timing point for the final checker is that this is a **Moore** machine sampled on the positive clock edge, with an **asynchronous active-high reset**, and the input stream is LSB-first. Because the output is Moore, `z` in any sampled row must depend only on the state reached *before* that edge, not on the `x` value presented in the same row. The checker should therefore compare `z` against the state-implied output for the pre-edge state, while using the row's `x` only to determine the next state.

Edge timing: each row's `areset` and `x` values are driven before the positive edge and are stable at the sampling instant. After the edge settles, the machine has consumed that row's `x` (unless reset dominates) and the sampled `z` reflects the new state. Mid-input changes occur after sampling and before the next edge; they are carried into the start of the next row. Thus a mid-row change of `x` must not affect the `z` sampled in the current row, and a mid-row change of `areset` must not retroactively alter the current row's sampled output. The checker should treat the sampled edge as the only evaluation point and should not infer behavior from values that appear only mid-cycle.

Reset timing is the subtle part. Since reset is asynchronous and positive-edge triggered in the sense that the machine is clocked on the positive edge, an asserted `areset` before the edge forces the state to the reset state independently of `clk`. The conversion begins when reset is released and stops when reset is asserted. For checker purposes, any row with `areset=1` at the sampling edge should be treated as forcing the reset state and the corresponding reset output, regardless of `x`. Rows after release should begin conversion from the reset state using the LSB-first input. A mid-row assertion of reset after sampling should affect the next sampled row, not the already-sampled one.

For a 2's complementer processing LSB-first, the natural Moore state distinction is whether a `1` has already been seen. Before the first `1`, output equals input (copy phase); after the first `1`, output is the complement of input (invert phase). The reset state is the copy phase. The checker can validate `z` from the pre-edge phase: in copy phase `z=x_previous` semantics apply only through state, so the Moore output must be consistent with the phase, not with the current row's `x` transition. This is the most common place a naive checker fails: it may compute `z` from the same row's `x` rather than from the state before the edge.

Short worked example: suppose reset is released, and the LSB-first input sequence is `0, 1, 0, 1`. In the copy phase, the first `0` leaves the machine in copy phase and the Moore output for that sampled row is the copy-phase output. The next `1` moves the machine to invert phase; the output sampled on that edge still corresponds to the pre-edge copy phase, while the following rows output the complement phase. The checker must align output with the pre-edge state, then update state using the row's `x`. If a row has `areset=1`, the checker should override both state and output to reset values and ignore `x` for that sample.

Finally, the checker should be strict about sampling after the positive edge has settled: it should not accept outputs that would only be valid if `z` changed combinationally with `x` in the same row. It should also ensure that mid-input changes are applied only to the next row's pre-edge values. This makes the Moore requirement, asynchronous reset dominance, and LSB-first conversion order the three invariants to enforce.
