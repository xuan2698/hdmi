One implementation mistake worth flagging: treating the reset row's `z = 0` and `next_state = COPY` as independent checks. The spec makes them joint — on a sampled reset row both must hold simultaneously. A design that clears `z` on reset but leaves the state in `INVERT` would pass a `z`-only assertion on the reset row and only fail later, on an `x = 0` row where `INVERT` wrongly emits `z = 1`. Conversely, forcing `COPY` but mishandling the first `1` passes the reset row and fails only at the transition row. The checker should assert the reset row as a joint `(z = 0, next_state = COPY)` predicate, and the first post-reset `1` row as a joint `(z = 1, next_state = INVERT)` predicate, both evaluated from the pre-edge state and sampled inputs at the positive edge.
