**Reset and power-up analysis**

The machine is specified as a Moore machine, so the output `z` is a function of the stored state alone, not of the current input `x`. That single fact drives nearly every reset and power-up subtlety in this design.

At power-up, before any clock edge has been sampled, the state is undefined in the abstract specification. The only defined entry point is the asynchronous reset: whenever `areset=1` is present at a sampling edge, the machine must be forced into the reset state and must present the reset output, independent of `x`. Because reset is asynchronous and positive-edge triggered in the sense that it is recognized at the sampling edge, the checker should treat any row whose sampled `areset` is 1 as authoritative: state becomes the reset state, output becomes the reset output, and the row's `x` is irrelevant for that sample. This is the cleanest power-up story: the first meaningful sample is either a reset row (which establishes a known state) or, if reset was already released, a row that must be interpreted as beginning conversion from the reset state.

The reset state is the "copy phase" — no `1` has yet been seen in the LSB-first stream. In copy phase the Moore output equals the input bit that was latched into the state on the previous edge; in invert phase (after the first `1`) the output is the complement. The critical checker consequence is alignment: the output sampled on a given edge reflects the state *before* that edge, while the state update uses that row's `x`. A naive checker that computes `z` from the same row's `x` will be wrong in exactly the transition row where the first `1` arrives, because the output still belongs to copy phase even though the state is about to flip to invert phase.

Mid-row input changes are explicitly deferred: a change after sampling but before the next edge is carried to the start of the next row. So the checker must apply `x` changes only to the next row's pre-edge values, never retroactively to the row just sampled. Likewise, a mid-row assertion of reset after sampling affects only the next sampled row; it must not rewrite the already-sampled output or state.

**Short worked example.** Release reset, then feed LSB-first `0, 1, 0, 1`. Row 1 (`x=0`): pre-edge state is copy phase, so `z` is the copy-phase output; state stays copy. Row 2 (`x=1`): pre-edge state is still copy phase, so `z` is again the copy-phase output, but the state updates to invert phase. Row 3 (`x=0`): pre-edge state is invert phase, so `z` is the complement of the previously latched bit; state stays invert. Row 4 (`x=1`): `z` is again invert-phase output. If any of these rows had `areset=1`, that row would instead force reset state and reset output and ignore `x`.

**Useful point for the final checker.** Enforce three invariants in order: (1) reset dominance — `areset=1` at the sample overrides state and output and ignores `x`; (2) Moore alignment — compute expected `z` from the pre-edge state, then update state from that row's `x`; (3) deferred mid-row changes — apply `x` and reset changes only to the next row. Sampling must occur after the positive edge has settled, so any output that would only be valid if `z` tracked `x` combinationally in the same row must be rejected.
