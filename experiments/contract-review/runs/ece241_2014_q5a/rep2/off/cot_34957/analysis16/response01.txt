The public interface is narrow: one 1-bit input `x`, one 1-bit output `z`, one clock `clk`, and one 1-bit asynchronous reset `areset`. All logic is single-bit; there are no buses, no signed encodings, and no multi-bit boundary values to interpret. The only "boundary" that matters is the reset boundary: `areset` is positive-edge triggered and asynchronous, but the checker samples it only after the posedge has settled. A sampled-high `areset` forces the machine to S0 with `z=0` for that row and does not consume the `x` bit on that row. Conversion begins on the first row where `areset` is sampled low. A reset asserted after the sampled edge takes effect on the next row. Mid-row `x` changes are staged and carried to the start of the next row, so they never affect the current row's sampled value.

The machine has two states. S0 means "no 1 has been seen yet"; its Moore output is `z=0`. S1 means "the first 1 has been seen"; its Moore output is `z=1`. From S0, `x=0` stays in S0, and `x=1` moves to S1. From S1, both `x=0` and `x=1` stay in S1. S1 is absorbing until reset. Because the output is Moore, `z` depends only on the installed state, not on the current `x`.

The crux for the final Python checker is the row where the first 1 is sampled while in S0. The machine transitions to S1 and the output for that same row must be 1, because the output is taken from the installed (next) state. A checker that emits `z` from the pre-state produces 0 on that row and is off by one for the rest of the number. This bug is invisible on all-zero inputs, which never leave S0, and it is exposed by any input with a leading 0 followed by a 1. The checker should therefore, per row: if sampled `areset` is high, force S0 and `z=0` and do not advance the input index; otherwise sample settled `x`, compute the next state, install it, and emit `z` from the installed state. The reference should be anchored at the first sampled-high reset row, not at time zero.

Worked example: LSB-first `x = 0,1,0,1` represents value 10; its two's complement is 0110, so the LSB-first output is `0,1,1,0`. Row 1: S0, `x=0` → S0, `z=0`. Row 2: S0, `x=1` → S1, `z=1` (the distinguishing row). Row 3: S1, `x=0` → S1, `z=1`. Row 4: S1, `x=1` → S1, `z=0`. A pre-state checker instead yields `0,0,1,1`, which is wrong from row 2 onward.
