The machine has two states, S0 and S1, with S0 as the reset state. S0 is the "no 1 seen yet" state: while the LSB-first stream has contained only zeros, the 2's complement output is identical to the input, so the machine must pass zeros through unchanged and remain in S0. S1 is the "a 1 has already been seen" state: once the first 1 of the number has been consumed, every subsequent output bit is the complement of the corresponding input bit, and the machine remains in S1 forever until reset. There is no path from S1 back to S0, because the first 1 in an LSB-first stream is the rightmost 1 of the number, and all bits to its left must be inverted regardless of their values.

The output Z is a Moore output, a function of the state alone. In S0, Z = 0. In S1, Z = 1. This is the crucial design choice: the output does not depend directly on x, only on which state the machine occupies after the sampling edge. Consequently the transition rule is: from S0, x = 0 keeps S0 and x = 1 moves to S1; from S1, any x keeps S1. The output for a row is read from the state the machine occupies after that row's transition, which is why the first 1 in the stream produces Z = 1 on the same row it is consumed rather than on the following row.

The asynchronous reset dominates everything. While areset is asserted, the state is forced to S0 and Z is forced to 0, independent of clk and independent of x. An asserted areset on a row is an override: it does not consume that row's x, and it does not advance the machine. Release of areset is not a sampling event; the first bit is consumed only at the first positive edge after release. The checker must therefore not treat the release row as consuming a bit, and must not let an x value present before release leak into the first post-release row.

At a normal sampling edge the order of operations matters. First, if areset is asserted, force S0 and Z = 0 and do not consume x. Otherwise, sample x at the settled positive edge, compute the next state from the current state and the sampled x, install that as the new state, and then set Z from the new state. Only after that may a mid-row change to x be accepted as the value staged for the next row; such a change must never retroactively alter the current row's transition or output. A checker that computes Z from the pre-edge state will lag by one row whenever the first 1 is not the final bit, and a checker that lets mid-row x changes affect the current row will produce spurious transitions.

Worked example, LSB-first x = 0,1,0,1. Row 1: S0, x=0, stay S0, Z=0. Row 2: S0, x=1, go to S1, Z=1. Row 3: S1, x=0, stay S1, Z=1. Row 4: S1, x=1, stay S1, Z=0. Output 0,1,1,0. A present-state-output checker instead yields 0,0,1,1, the one-row lag. This minimal case also catches a release-consumes-a-bit error and a mid-row-sensitive error, so it is a good regression seed for the checker.
