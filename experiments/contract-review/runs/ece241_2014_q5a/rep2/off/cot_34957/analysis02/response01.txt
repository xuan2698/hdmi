**Reset and power-up behavior.** The machine is a Moore machine, so `z` is a function of state alone; the state is updated only on the positive clock edge, except that `areset` is asynchronous and dominant. On power-up, before any clock edge and before reset is released, the state is indeterminate in real hardware, but the specification's reset contract makes the observable behavior well-defined: while `areset` is asserted, the machine must be forced into the "no 1 seen yet" state, and therefore `z` must be 0. Because reset is asynchronous, this forcing must not wait for `clk`; a checker should be prepared to see `z` go to 0 at any time `areset` is high, including between edges. When `areset` is released, the machine remains in the reset state until the first positive edge after release. Thus immediately after reset release and before that first edge, `z` is still 0. The first post-reset edge samples `x` and moves to the appropriate next state; only then may `z` become 1 (if the first sampled bit is 1). This ordering matters for the checker: it must not expect a conversion result on the same edge that releases reset, and it must not treat the pre-edge interval after release as having already consumed an input bit.

**Mid-row input changes.** The protocol note says optional mid input changes occur after sampling, before the other edge, and are carried to the start of the next row. For the checker this means the value of `x` used for a given row is the value present at that row's sampled positive edge. A change in `x` after that edge must not retroactively affect the `z` associated with that row. The checker should therefore latch `x` at the sampled edge, compute the next state from the current state and the latched `x`, and compare `z` against the Moore output of the resulting state. Any subsequent `x` transition before the next row's driven value is irrelevant to the current row and belongs to the next row's setup.

**Worked example.** Release reset; drive LSB-first `x = 0,1,0,1`. Row 1 samples 0: state stays "no 1 seen," `z=0`. Row 2 samples 1: state becomes "1 seen," `z=1`. Row 3 samples 0: state remains "1 seen," output inverts, `z=1`. Row 4 samples 1: output inverts, `z=0`. Output stream `0,1,1,0` is the 2's complement of the four-bit LSB-first input `0,1,0,1` (value 10), giving 6 (`0,1,1,0` LSB-first). A mid-row change after row 2's sample would be carried to row 3 and must not alter row 2's `z`.

**Useful point for the final Python checker.** Enforce asynchronous reset as a level-sensitive override: whenever `areset` is high, force the reset state and `z=0` regardless of clock; on release, hold that state until the next sampled positive edge; at each sampled edge, latch `x`, update state, then compare `z` to the Moore output of the updated state, ignoring mid-row `x` changes for the current row.
