The public interface is deliberately narrow: one 1-bit input `x`, one 1-bit output `z`, one clock `clk`, and one asynchronous reset `areset`. All four are single-bit signals, so there are no multi-bit boundary values to reason about; every sampled value is either 0 or 1. The only "width" concern for the checker is that `z` is a Moore output derived from state, not from `x`, and that `areset` is an override rather than a data input. There is no enable, no valid qualifier, and no length field: the machine accepts an arbitrary-length LSB-first bit stream and converts it to its two's complement by the standard "copy up to and including the first 1, then invert" rule, which the two-state machine implements implicitly.

Boundary behavior centers on reset and on the first 1. While `areset` is asserted, state is forced to S0 and `z` is forced to 0 regardless of `clk` and `x`; an asserted reset row consumes no bit and advances no state. Release of `areset` is not itself a sampling event, so the first post-release positive edge is the first bit-consuming edge, and any `x` value present before release must not leak into that first consumed row. At a normal edge the order is: check reset; if not asserted, sample settled `x`, compute next state from current state and sampled `x`, install it, then drive `z` from the new state. Mid-row `x` changes after sampling are staged for the next row only and must never retroactively change the current row's transition or output.

The transition rule is: from S0, `x=0` stays S0 and `x=1` goes to S1; from S1, any `x` stays S1. Output is read from the post-transition state, so the first 1 in the stream yields `z=1` on the same row it is consumed. This is the key point for the final Python checker: `z` must be computed from the state after the row's transition, not from the pre-edge state. A present-state-output checker lags by one row whenever the first 1 is not the final bit.

Worked example, LSB-first `x = 0,1,0,1`: row 1 S0, x=0, stay S0, z=0; row 2 S0, x=1, go S1, z=1; row 3 S1, x=0, stay S1, z=1; row 4 S1, x=1, stay S1, z=0. Output `0,1,1,0`. A pre-state checker gives `0,0,1,1`. This minimal case also exposes a release-consumes-a-bit error and a mid-row-sensitive error, making it a strong regression seed.
