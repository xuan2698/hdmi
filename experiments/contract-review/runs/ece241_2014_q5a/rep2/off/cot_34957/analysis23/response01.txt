The key point for the final Python checker is that the Moore output must be attributed to the **post-transition state**, not the pre-transition state. This is the single most likely source of silent disagreement between a reference model and a checker that otherwise looks correct.

Because `z` is a function of state only, the checker must decide which state the sampled `z` belongs to. The intended convention is: after the posedge settles, sample `areset` and `x`, compute the next state, install it, then emit `z` from the installed state. A checker that emits `z` from the pre-transition state agrees only on rows where the state does not change, and diverges at the first input `1`.

A short worked example makes this concrete. Take LSB-first `x = 0,1,0,1`, representing value 10; two's complement is 0110, so LSB-first output is `0,1,1,0`. Row 1: state S0, `x=0`, next S0, `z=0`. Row 2: S0, `x=1`, next S1, `z=1` — the distinguishing row. Row 3: S1, `x=0`, next S1, `z=1`. Row 4: S1, `x=1`, next S1, `z=0`. A pre-state checker yields `0,0,1,1`, wrong from row 2 onward.

Two invariants reinforce this. First, S1 is absorbing until reset: after the first `1`, every non-reset row outputs `z=1` regardless of `x`, so the checker must not recompute a per-bit complement or toggle on `x` alone. Second, reset anchoring must be exact: a sampled-high `areset` forces S0 and `z=0` for that row and must not consume the `x` bit; a reset asserted after the sampled edge takes effect on the following row; mid-row `x` changes are staged and carried to the next row and never affect the current sample. The input index advances only on rows where `areset` is sampled low.

The reference model is therefore: sample `areset` and `x` post-settle; if `areset` is high, force S0, emit `z=0`, do not advance the index; otherwise compute next state from current state and sampled `x`, install it, emit `z` from the installed state, and advance the index. Post-transition emission plus reset-gated index advancement are the two rules that close the main failure modes.
