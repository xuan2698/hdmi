The most useful implementation mistake to flag for the final Python checker is a **one-row state/output skew**: computing `z` from the *current* state before installing the next state, rather than from the *next* (installed) state. In a Moore machine the output is a function of the state the machine is in during that cycle. For a 2's complementer the intended encoding is typically S0 = "no 1 seen yet" (output 0) and S1 = "a 1 has been seen" (output 1), with the transition S0→S1 on the first `x=1`. The output on the row where that first 1 arrives must already be 1, because the machine has *entered* S1 by the end of that cycle. A checker that emits `z` from the pre-edge state will produce 0 on that row and then lag by one row for the remainder of the stream. Because the error is a pure shift, it is invisible on all-zero inputs and on inputs whose first bit is 1 only if the checker happens to align differently — so it needs a vector with a leading 0 followed by a 1 to expose it.

A short distinguishing input makes this concrete. Take LSB-first `x = 0,1,0,1`, which is the 4-bit value 10 (binary `1010`), whose two's complement in 4 bits is `0110`, i.e. LSB-first output `0,1,1,0`. Row 1: state S0, `x=0`, next state S0, `z=0`. Row 2: state S0, `x=1`, next state S1, `z=1` — this is the row that separates the two checker styles. Row 3: state S1, `x=0`, stay S1, `z=1`. Row 4: state S1, `x=1`, stay S1, `z=0`. Correct output stream is `0,1,1,0`. A pre-state checker produces `0,0,1,1`, lagging by one row from the first 1 onward. The same vector also catches two other common mistakes: a checker that treats reset release as consuming a bit will shift the whole stream, and a checker that lets a mid-row `x` change after sampling affect the current row will flip row 2 or row 3 depending on where the change is injected.

Two further details matter for the checker's row model. First, `areset` is an override, not a data input: while asserted, state is forced to S0 and `z` to 0, and no bit is consumed, so the checker must not advance its input index on reset rows. Second, the first post-release positive edge is the first bit-consuming edge; any `x` value present before release must not leak into that row. The checker should therefore model each row as: if `areset` sampled high, force S0 and `z=0` and do not consume `x`; otherwise sample settled `x`, compute next state, install it, then emit `z` from the installed state. Mid-row `x` changes after sampling are staged for the next row only.

Given the two-state structure, a compact regression set is enough: the vector above, a stream with no 1 at all (all zeros, output all zeros, state stays S0), a stream whose first bit is 1 (output starts with 1 immediately), and a reset-in-the-middle case to confirm no bit is consumed and `z` is forced to 0. The `0,1,0,1` vector remains the strongest single seed because it exercises the first-1 transition, the post-transition output rule, and the LSB-first ordering simultaneously.
