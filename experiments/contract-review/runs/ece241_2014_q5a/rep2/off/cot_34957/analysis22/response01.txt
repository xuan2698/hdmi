The public interface is narrow: one clock, one asynchronous active-high reset (`areset`, 1 bit), one serial input (`x`, 1 bit), and one serial output (`z`, 1 bit). All four are single-bit signals, so there are no multi-bit port-width or packing ambiguities to resolve; the only width question is temporal, namely how many clock cycles a given input bit occupies and when the corresponding output bit is considered valid. The spec fixes this: one input bit per clock cycle, LSB first, arbitrary length, with conversion starting when reset is released and stopping when reset is asserted. The checker should therefore treat each non-reset sampled row as consuming exactly one input bit and producing exactly one output bit, and should treat reset rows as consuming no input bit.

Boundary values are simple but easy to mishandle. `x` and `z` are binary, so the only legal values are 0 and 1; any other sampled value is a protocol violation rather than a meaningful state. `areset` is likewise binary, and its polarity is active-high: a sampled 1 forces the machine to the initial state and forces `z=0`. The interesting boundary is not numeric range but the reset boundary itself — the transition from reset-asserted rows to the first reset-released row. That first released row is where conversion begins, and it is the row most likely to be mis-scored if the checker advances the input index during reset or attributes `z` to the pre-transition state.

The critical correctness point for the final Python checker is Moore output timing. Because `z` depends only on state, the checker must fix a convention for which state the sampled `z` belongs to. The intended convention is post-transition: sample `areset` and `x` after the posedge settles, compute the next state, install it, then emit `z` from the installed state. A checker that emits `z` from the pre-transition state agrees only while the state is unchanged and diverges at the first input 1.

A short worked example makes the distinction concrete. Take LSB-first `x = 0,1,0,1`, representing value 10; two's complement is 0110, so LSB-first output is `0,1,1,0`. Row 1: state S0, `x=0`, next S0, `z=0`. Row 2: S0, `x=1`, next S1, `z=1` — the distinguishing row. Row 3: S1, `x=0`, next S1, `z=1`. Row 4: S1, `x=1`, next S1, `z=0`. A pre-state checker yields `0,0,1,1`, wrong from row 2 onward.

Two invariants reinforce this. First, S1 is absorbing until reset: after the first 1, every non-reset row outputs `z=1` regardless of `x`, so the checker must not recompute a per-bit complement or toggle on `x` alone. Second, reset anchoring must be exact: a sampled-high `areset` forces S0 and `z=0` for that row and must not consume the `x` bit; a reset asserted after the sampled edge takes effect on the following row; mid-row `x` changes are staged and carried to the next row and never affect the current sample. The input index advances only on rows where `areset` is sampled low.

The reference model is therefore: sample `areset` and `x` post-settle; if `areset` is high, force S0, emit `z=0`, do not advance the index; otherwise compute next state from current state and sampled `x`, install it, emit `z` from the installed state, and advance the index. Post-transition emission plus reset-gated index advancement are the two rules that close the main failure modes.
