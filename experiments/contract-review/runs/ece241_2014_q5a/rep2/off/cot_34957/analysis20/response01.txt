**Reset and power-up behavior**

The machine has a single state bit with two states: S0 (no `1` seen yet in the LSB-first stream) and S1 (a `1` has been seen, so every subsequent output bit is the complement of the input bit). The output `z` is a Moore output taken from the state register: `z=0` in S0 and `z=1` in S1. Because `areset` is positive-edge triggered and asynchronous, asserting it forces the state register to S0 independently of `clk`; releasing it lets the machine begin conversion from S0 on the next sampled edge.

Power-up is not the same as reset. Before any reset has been observed, the state register has no defined value in the specification, so the checker must not assume S0 at time zero. The meaningful anchor is the first row where `areset` is sampled high: that row establishes S0 and `z=0`, and it does not consume an input bit. Conversion starts on the first row where `areset` is sampled low. If reset is asserted after a sampled edge, the effect appears on the following row, because the checker samples `areset` only after the posedge has settled.

The subtle point for the final Python checker is the ordering of state update and output emission. The correct Moore invariant is: sample `x` and `areset`, compute the next state, install it, then emit `z` from the installed state. Equivalently, `z` on row *n* reflects the state after row *n*'s transition. A checker that computes `z` from the pre-transition state agrees only while the machine is in S0 (where the next state is also S0) and diverges from the first `1` onward.

A short worked example makes the failure concrete. Take LSB-first `x = 0,1,0,1`, representing 10; its two's complement is 0110, so the LSB-first output should be `0,1,1,0`. Row 1: state S0, `x=0`, next state S0, `z=0`. Row 2: state S0, `x=1`, next state S1, `z=1` — the distinguishing row. Row 3: state S1, `x=0`, next state S1, `z=1`. Row 4: state S1, `x=1`, next state S1, `z=0`. A pre-state checker instead yields `0,0,1,1`, wrong from row 2. Note also that S1 is absorbing until reset: once the first `1` is seen, every later row outputs `z=1` regardless of `x`, so the checker must not try to recompute the complement per bit or toggle on `x` alone.

The reset boundary compounds this if handled loosely. A sampled-high `areset` forces S0 with `z=0` for that row and must not consume the `x` bit; conversion begins on the first row where `areset` is sampled low. A reset asserted after the sampled edge takes effect on the next row. Mid-row `x` changes are staged and carried to the start of the next row, so they never affect the current row's sampled value. The reference should therefore be anchored at the first sampled-high reset row, not at time zero, and the input index should advance only on rows where `areset` is sampled low. Combined with the post-transition output rule, these two invariants — emit `z` after installing the next state, and advance the input index only on non-reset rows — cover the failure modes a naive checker is most likely to exhibit.
