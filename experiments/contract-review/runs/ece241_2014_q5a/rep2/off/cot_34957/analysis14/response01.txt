**Reset and power-up behavior**

The machine has one state bit, so power-up can only land in one of two states, and the specification does not define which. That is the first thing the checker must not assume. The only state the public spec pins down is the reset state: while `areset` is sampled high, the machine is forced to S0 and `z` is forced to 0. Everything before the first sampled high `areset` is therefore "don't care" for state, and the checker should treat the pre-reset interval as unconstrained rather than expecting S0. A checker that initializes its reference model to S0 and then compares against the DUT before any reset has been applied will produce spurious mismatches on any implementation that powers up in S1. The safe row model is: ignore state and `z` until the first row where `areset` is sampled high; from that row onward the reference is anchored.

The reset is asynchronous and positive-edge triggered, but the sampling protocol is what the checker actually sees: each row's values are driven before the sampled edge, and the sample is taken after the posedge has settled. So the checker should evaluate `areset` at the sampled edge, not at the moment it changes. A reset that is released mid-row and is high at the sampled edge forces S0/z=0 for that row; a reset that is asserted after the sampled edge takes effect on the next row. This matters because the spec says conversion begins when Reset is released and stops when Reset is asserted — the checker must not consume an input bit on a row where reset is sampled high, and must not let an `x` value present before release leak into the first post-release row.

The subtle point worth flagging for the final checker is the interaction between reset and the first-1 transition. The machine's job is to copy bits up to and including the first 1, then invert. If reset is released and the very first sampled `x` is 1, the output on that same row must already be 1 (state S1 installed, `z` emitted from the installed state). A checker that emits `z` from the pre-state will output 0 there and lag by one row from the first 1 onward — invisible on all-zero vectors and on first-bit-1 vectors only if the checker also mishandles the first row, but exposed by any vector with a leading 0 followed by a 1.

Worked example: LSB-first `x = 0,1,0,1` (value 10, two's complement 0110, LSB-first output 0,1,1,0). Row 1: S0, x=0 → S0, z=0. Row 2: S0, x=1 → S1, z=1 (the distinguishing row). Row 3: S1, x=0 → S1, z=1. Row 4: S1, x=1 → S1, z=0. A pre-state checker yields 0,0,1,1.

For the final checker: model each row as "if sampled `areset` high, force S0 and z=0 and do not advance the input index; else sample settled `x`, compute next state, install it, emit `z` from the installed state," and stage mid-row `x` changes for the next row only. Anchor the reference at the first sampled-high reset row, not at time zero.
