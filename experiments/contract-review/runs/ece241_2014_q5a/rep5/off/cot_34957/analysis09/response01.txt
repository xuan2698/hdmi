The machine has two states, `S0` and `S1`, with `S0` the reset state. The input `x` arrives least-significant bit first, and the output `z` is the two's-complement result bit for the same position. The conversion rule is the standard "copy until the first 1, then invert" rule: while no 1 has yet been seen, each input bit is passed through unchanged; after the first 1 has been seen, every subsequent input bit is complemented. `S0` encodes "no 1 seen yet," and `S1` encodes "a 1 has been seen, so invert from here on."

From `S0`, an input `x=0` keeps the machine in `S0` and outputs `z=0`, since a leading zero is copied. An input `x=1` moves the machine to `S1` and outputs `z=1`, since the first 1 is copied and simultaneously arms the inversion for later bits. From `S1`, the machine stays in `S1` regardless of `x`, because once inversion has begun it continues for the rest of the number. In `S1`, `x=0` produces `z=1` and `x=1` produces `z=0`, the complemented values. Thus the output is `0` in `S0` and `1` in `S1`; equivalently, `z` equals the current state bit. This is a Moore machine because `z` depends only on the state, not directly on `x`.

Reset is asynchronous and active-high, and it forces the state to `S0` immediately, independent of the clock. Asserting reset therefore clears any partial conversion: the next number starts fresh at `S0` when reset is released. The first sampled positive edge after release processes the first bit of the new number. A stream interrupted by reset and restarted is a new number, not a continuation. Power-up without reset is unspecified, so the checker should assert `areset` at time zero and depend on the asynchronous override rather than an assumed initial state.

The key sampling boundary is that `z` is read from the post-edge state, because the specification says to sample after the posedge has settled. This matters on the `S0`-to-`S1` transition: the pre-edge state gives `z=0`, the post-edge state gives `z=1`, and `1` is correct. A checker binding `z` to the pre-edge state is wrong on that row and stays off by one afterward.

Worked example: stream `0,1,0` (LSB-first value 2). Row 1: `x=0`, `S0`→`S0`, `z=0`. Row 2: `x=1`, `S0`→`S1`, `z=1`. Row 3: `x=0`, `S1`→`S1`, `z=1`. Output `0,1,1` = 3, the correct two's complement of 2. Row 2 is the discriminator.

Two further boundaries: the all-zero stream never leaves `S0`, so all outputs are `0`, correct for zero at any width, and the checker must not demand a `1` before accepting outputs. Also, mid-row `x` changes occur after sampling and carry to the next row; they must not alter the transition or output already committed at the sampled edge. The final checker must encode post-edge `z`, immediate asynchronous reset override, and deferred mid-row `x`.
