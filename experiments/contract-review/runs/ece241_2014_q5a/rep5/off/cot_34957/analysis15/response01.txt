The machine has two states, call them `S0` (no `1` seen yet) and `S1` (a `1` has been seen). The output is a Moore function of state only: `z=0` in `S0`, `z=1` in `S1`. The transition function is: in `S0`, `x=0` stays `S0` and `x=1` goes to `S1`; in `S1`, both `x=0` and `x=1` stay `S1`. Asynchronous reset forces `S0` immediately, independent of `clk`.

The reason this computes two's complement on an LSB-first stream is the standard "copy through the first 1, then invert" rule. Before the first `1`, output bits equal input bits (both zero). At the first `1`, the output is `1` (same as input). After that, every subsequent input bit is inverted. The state machine encodes exactly that: `S0` means "still copying," `S1` means "now inverting." Because `z` is registered in the state, the output for a given row reflects the state *after* that row's edge, i.e., the decision made using that row's `x`. So the first `1` in the input produces a `1` in the output on the same row, and the inversion begins on the following row.

For the checker, the key point is the sampling phase. Each row's `x` is driven before the sampled positive edge; `z` must be read after that edge has settled, so `z` corresponds to the post-edge state. A checker that reads `z` before the edge, or that computes `z` directly from the current `x`, will be correct while the stream is all zeros and then lag by one row once the first `1` appears. Concretely, for input `0,1,0`, the correct outputs are `0,1,1`; a combinational or pre-edge checker yields `0,0,1`.

Two further points matter. First, reset is asynchronous: asserting it must immediately drive the state to `S0` and clear any partial conversion, without waiting for a clock edge. Releasing reset starts a fresh conversion. Second, mid-row `x` changes occur after sampling and before the next edge; they are carried into the next row and must not alter the current row's already-settled `z`. Since the output is Moore, `z` is constant within a row after the edge settles, so any mid-row perturbation of `z` is a bug.

The checker should not assume a defined initial state before the first reset. The safe sequence is: assert reset, release it, then compare outputs row by row starting from the first post-release positive edge. The all-zero stream is the boundary case: the machine never leaves `S0`, so every output is `0`, and no transition to `S1` should ever be observed.
