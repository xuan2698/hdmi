The most useful implementation mistake to flag for the final checker is a **sampling-phase error**: reading `z` before the positive edge has settled, or deriving `z` combinationally from the current `x` rather than from the registered Moore state. This is the classic failure mode for a 2's-complementer, because the machine's whole job is to delay the "first 1" event by one state transition. A checker that samples too early, or that treats `z` as a function of `x` in the same row, will be correct on the leading zeros and then be permanently one row behind once the first `1` arrives.

The correct Moore behavior is: state `S0` means "no 1 seen yet, output 0"; state `S1` means "a 1 has been seen, output 1." On each sampled positive edge, if `x=0` stay put; if `x=1` move to `S1` (and stay there). The output `z` is the state's output, valid only after the edge settles. So the first `1` in the input produces `z=1` on that same row's post-edge sample, not on the following row, and not before the edge.

Worked example: LSB-first stream `0,1,0` (value 2). Row 1: `x=0`, state `S0`, post-edge `z=0`. Row 2: `x=1`, state becomes `S1`, post-edge `z=1`. Row 3: `x=0`, state stays `S1`, post-edge `z=1`. Output `0,1,1` = 3, the correct two's complement. A pre-edge or input-combinational checker would report `z=0` on row 2 (old state `S0`), yielding `0,0,1` and failing.

Two related traps the checker should also guard against, but which are secondary to the phase error: (1) treating asynchronous reset as synchronous, i.e., waiting for a clock edge before forcing `S0` — the spec requires immediate override and discarding any partial conversion; and (2) letting a mid-row `x` change retroactively alter the already-committed transition or output. Mid-row changes are deferred to the next sampling interval and must not perturb `z` within the current row, since Moore output is constant after the edge settles.

The final checker's central invariants should therefore be: sample `z` only after the positive edge settles; apply asynchronous reset as an immediate override to `S0`; and defer mid-row `x` changes to the next row. The all-zero stream is a useful boundary — it never leaves `S0`, so every output is `0`, and the checker must not demand a `1` appear.
