The public interface is narrow but the timing semantics carry all the risk. `areset` and `x` are each one bit wide; `z` is one bit wide; `clk` is the single sampling clock. There are no multi-bit buses, no enables, and no separate valid strobe, so every row in the stimulus is implicitly a conversion step once reset has been released. Boundary values are therefore trivial in width (only `0` and `1` per signal) but non-trivial in sequence: the meaningful boundaries are the all-zero stream, the first `1` in a stream, and the transition out of reset.

The machine has two conceptual states. `S0` means "no `1` has yet been seen in this conversion"; in `S0` the output is `0` and the next input bit is passed through unchanged in the sense that a `0` keeps the machine in `S0` while a `1` moves it to `S1`. `S1` means "the first `1` has been consumed"; from then on every input bit is inverted at the output, and the state remains `S1` for all subsequent bits. This is the standard LSB-first 2's-complement algorithm: copy bits up to and including the first `1`, then invert the rest. The all-zero stream is the boundary case that never leaves `S0`, so every output is `0` and no `S0→S1` transition should be observed. Conversely, a stream whose first bit is `1` enters `S1` on the very first sampled edge, so all outputs including the first are `1` for that bit position.

Reset is asynchronous and active-high. Asserting `areset` forces `S0` immediately, independent of `clk`, discarding any partial conversion and re-arming the "first `1` not yet seen" memory. Releasing `areset` starts a fresh conversion from `S0`. Power-up state is not specified publicly, so `z` is undefined until reset has been asserted and released; the checker must not sample or compare `z` before that.

The checker-critical point is phase alignment. Each row drives `x` before the sampled positive edge, and `z` is sampled after that edge has settled. Because the machine is Moore, `z` is a function of the post-edge state, and that state was updated using the `x` present at the same edge. Thus the `z` observed in a row corresponds to the edge that consumed that row's `x` — it is the registered output for that same edge, not a one-cycle-lagged function of `x`. A mid-row change on `x` occurs after sampling and belongs to the next row; it must not retroactively alter the current row's settled `z`. Since `z` is Moore, it must be constant within a row once the edge settles, so any mid-row change on `z` is a defect.

Worked example: LSB-first stream `0,1,0` yields `0,1,1`. Row 1: `x=0`, stay `S0`, `z=0`. Row 2: `x=1`, enter `S1`, `z=1`. Row 3: `x=0`, stay `S1`, `z=1`. A checker that reads `z` before the edge, or derives `z` combinationally from current `x`, produces `0,0,1` — an off-by-one error invisible on all-zero streams and appearing only after the first `1`. The final Python checker should compare each row's settled `z` against the state reached by consuming that row's `x`, and should ignore `z` entirely until reset has been asserted and released.
