**Reset and power-up behavior.** The machine has two states: `S0` (no `1` seen yet, `z=0`) and `S1` (a `1` has been seen, `z=1`). The 2's-complement rule for an LSB-first stream is simple: copy bits until the first `1` is encountered (inclusive), then invert every subsequent bit. `S0` is the "still copying" state; `S1` is the "inverting" state. Reset is positive-edge-triggered and asynchronous, so asserting `areset` forces the machine to `S0` with `z=0` immediately, independent of `clk`, and holds it there for as long as reset is asserted. Conversion begins only when reset is released; the first sampled edge after release is the first bit of the number. Because the state is forced to `S0` on assertion, any partial conversion is discarded, and a stream interrupted by reset and restarted is treated as a brand-new number rather than a continuation. Power-up without an explicit reset is not guaranteed by the specification; the checker should drive `areset` at time zero and rely on the asynchronous override rather than on any assumed initial state.

**The sampling boundary that matters most.** The output `z` is a Moore output, so it is a function of the current state alone. The critical question for the checker is *which* state — the state before the sampled clock edge or the state after it. The specification says to sample after the posedge has settled, so `z` must be read from the post-edge state. This distinction is invisible in `S0`-to-`S0` and `S1`-to-`S1` transitions but is decisive on the `S0`-to-`S1` transition, where the pre-edge state gives `z=0` and the post-edge state gives `z=1`. A checker that binds `z` to the pre-edge state will be wrong on exactly that row and then remain off by one for the rest of the stream.

**Worked example.** Stream `0,1,0` (LSB-first value 2). Row 1: `x=0`, state `S0`, next `S0`, sampled `z=0`. Row 2: `x=1`, state `S0`, next `S1`, sampled `z=1`. Row 3: `x=0`, state `S1`, next `S1`, sampled `z=1`. Output `0,1,1` = 3, the correct 3-bit two's complement of 2. Row 2 is the discriminator: pre-edge state `S0` would report `0`, post-edge state `S1` reports `1`, and `1` is correct.

**Two more boundaries for the checker.** The all-zero stream never leaves `S0`, so every output is `0` — correct for zero at any width; the checker must not require a `1` before accepting outputs. And mid-row `x` changes occur after sampling and are carried to the next row; they must not retroactively alter the transition or output already committed at the sampled edge. Together with immediate asynchronous reset override, these are the temporal rules the final checker must encode: post-edge `z`, immediate reset, deferred mid-row `x`.
