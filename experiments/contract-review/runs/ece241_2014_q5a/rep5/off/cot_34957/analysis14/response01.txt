**Reset and power-up analysis (public spec only).** The machine is a one-input, one-output Moore 2's-complementer. Input `x` arrives LSB-first; output `z` is the two's-complement result, also LSB-first, one bit per clock. Reset is positive-edge-triggered and asynchronous: asserting it forces the machine to its initial state immediately, independent of `clk`, and discards any partial conversion. Conversion begins only when reset is released; it stops when reset is asserted again. Because the output is Moore, `z` is a function of the registered state alone and is valid after the sampling edge has settled.

The essential state meaning is: `S0` = "no input `1` has yet been seen," output `0`; `S1` = "a `1` has been seen," output `1`. On each sampled positive edge, `x=0` holds the state, `x=1` moves to (or holds) `S1`. Thus the first `1` in the LSB-first stream causes the transition into `S1` on that same sampled edge, and the post-edge output becomes `1` on that row. Subsequent bits, whatever they are, keep the machine in `S1` and output `1`. The all-zero input never leaves `S0` and yields all-zero output; the checker must not require a `1` to appear.

**Power-up.** Before any reset is applied, the state is not specified by the public description. The checker should not assume `S0` at time zero; it should treat the first valid observation window as beginning after a reset assertion has been released and the first positive edge has settled. If the checker begins sampling before a reset has occurred, it may see an arbitrary initial state and must not flag that as a functional error. The safe convention is: assert reset, release it, then begin comparing outputs row by row.

**The central phase trap.** The most likely checker bug is to compute `z` combinationally from the current `x` rather than from the registered Moore state. That is the classic 2's-complementer failure: the machine's job is to delay the "first 1" event by one state transition, so a checker that samples too early, or treats `z` as a function of `x` in the same row, is correct on leading zeros and then permanently one row behind once the first `1` arrives.

**Worked example.** LSB-first stream `0,1,0` (value 2). Row 1: `x=0`, state `S0`, post-edge `z=0`. Row 2: `x=1`, state becomes `S1`, post-edge `z=1`. Row 3: `x=0`, state stays `S1`, post-edge `z=1`. Output `0,1,1` = 3, the correct two's complement. A pre-edge or input-combinational checker would report `z=0` on row 2 (old state `S0`), giving `0,0,1` and failing.

**Secondary traps.** (1) Treating asynchronous reset as synchronous — waiting for a clock edge before forcing `S0` — is wrong; reset must override immediately and discard partial conversion. (2) Letting a mid-row `x` change retroactively alter an already-committed transition or output is wrong; mid-row changes are deferred to the next sampling interval and must not perturb `z` within the current row, since Moore output is constant after the edge settles.

**Checker invariants.** Sample `z` only after the positive edge settles; apply asynchronous reset as an immediate override to `S0`; defer mid-row `x` changes to the next row; and do not assume a defined state before the first reset. The all-zero stream is the boundary case: it never leaves `S0`, so every output is `0`.
