The public interface is narrow but the timing semantics carry most of the risk. There is one clock, `clk`, one asynchronous active-high reset, `areset`, one serial input `x`, and one serial output `z`, each one bit wide. The machine consumes `x` least-significant bit first and emits the two's-complement result in the same order. Because the number length is arbitrary, there is no width parameter and no end-of-number handshake; the only framing signal is `areset`. Releasing reset begins a new conversion, and asserting reset terminates the current one. The checker should therefore treat reset as the sole delimiter between numbers and should not infer number boundaries from bit patterns.

The state set is `S0` and `S1`. `S0` means no `1` has yet been seen in the current number; `S1` means a `1` has been seen and all subsequent bits are to be inverted. In `S0`, `x=0` keeps the machine in `S0` and `x=1` moves it to `S1`. In `S1`, the machine remains in `S1` for either input. The output is purely state-determined: `z=0` in `S0` and `z=1` in `S1`. This is the Moore property that the checker must preserve; `z` must not be computed combinationally from the current `x` in a way that changes within a row.

The most important boundary for the final Python checker is post-edge sampling of `z`. The specification says to sample after the positive edge has settled. On the transition from `S0` to `S1`, the pre-edge state would report `z=0`, but the correct post-edge value is `z=1`. A checker that latches `z` before the edge, or that associates the output with the state that produced the transition rather than the state reached by it, will be wrong on that row and will remain offset for the rest of the number. The checker should drive `x` and `areset` before the edge, allow the edge to settle, then read `z` from the resulting state.

Reset is asynchronous and active-high. Asserting `areset` must force `S0` immediately, without waiting for a clock edge, and must discard any partial conversion. When reset is released, the next sampled positive edge processes the first bit of the new number. Power-up state without reset is unspecified, so the checker should assert reset at time zero and rely on the asynchronous override rather than assuming an initial state. A stream interrupted by reset and then restarted is a new number, not a continuation of the old one.

Mid-row input changes are explicitly deferred: they occur after sampling and before the other edge, and they carry to the start of the next row. They must not retroactively alter the transition or output already committed at the sampled edge. The checker should therefore apply `x` changes only for the next sampling interval, not as a same-row correction.

A short worked example clarifies the discriminator. For the LSB-first stream `0,1,0` (value 2), row 1 has `x=0`, stays in `S0`, and outputs `z=0`. Row 2 has `x=1`, moves to `S1`, and outputs `z=1` post-edge. Row 3 has `x=0`, stays in `S1`, and outputs `z=1`. The output stream `0,1,1` is 3, the correct two's complement of 2. Row 2 is the row that separates a correct post-edge checker from a pre-edge or input-combinational one.

Two additional boundaries matter. The all-zero stream never leaves `S0`, so every output is `0`, which is correct for zero at any width; the checker must not require a `1` to appear. Also, because the machine is Moore, `z` is constant throughout a row after the edge settles, so any mid-row change in `x` must not be allowed to perturb `z` before the next sampled edge. The final checker should encode post-edge `z`, immediate asynchronous reset override, and deferred mid-row `x` as its three central invariants.
