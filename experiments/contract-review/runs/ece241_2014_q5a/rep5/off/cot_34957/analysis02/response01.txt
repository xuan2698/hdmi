**Reset and power-up behavior**

The machine is specified as a positive-edge-triggered Moore machine with an asynchronous active-high reset (`areset`). Because the reset is asynchronous, it does not wait for a clock edge: whenever `areset` is asserted, the state must be forced to the designated reset state and the Moore output `z` must immediately reflect that reset state. This has two consequences for a checker.

First, power-up is not a separate behavioral mode in the public specification. There is no defined "unknown" or "initializing" interval that the checker must model. The only guaranteed entry condition is that asserting `areset` places the machine in its reset state. A checker should therefore treat reset assertion as authoritative at any row boundary (and, in the asynchronous sense, between edges), rather than requiring a posedge before the reset state becomes observable. If a row drives `areset = 1`, the expected post-edge state and output are the reset state and its output, independent of `x` and independent of the prior state.

Second, release of reset begins conversion. The specification says conversion begins when Reset is released and stops when Reset is asserted. So the checker should not expect meaningful 2's-complement conversion while `areset` is held; it should expect the reset-state output. Once `areset` is deasserted, the machine consumes `x` least-significant bit first and produces the 2's-complement output stream. The Moore property means `z` after a posedge is a function of the newly entered state, not of the current `x` combination after the edge.

The subtle point for the final Python checker is the interaction of asynchronous reset with the sampling discipline. The checker should evaluate at a stable post-edge moment: the edge has occurred, flops have updated, and the row's driven values are valid. At that moment, if `areset` is asserted, the reset state/output must win immediately; the checker should not require an additional clock edge to "latch" reset. If `areset` is not asserted, the checker updates state from the sampled `x` and then reads `z` from the resulting state. Optional mid-row changes to `x` occur after sampling and must be carried to the next row; they must not retroactively change the just-sampled transition or the output compared for the current row.

A short worked example: suppose the machine is in the state reached after seeing only zero bits, and the next sampled `x` is `1`. At the posedge, the machine transitions according to that `1`, and `z` is read from the new state. If `x` changes later in the same row, that change is queued for the next row and does not alter the transition or output already checked. If instead `areset` is asserted at that row boundary, the reset state and its output take precedence immediately, without waiting for a posedge.

The most useful implementation point is to make the sample function explicit: apply asynchronous reset first, then perform the edge transition only when reset is inactive, then read the Moore output from the post-edge state. Mid-input changes should be stored for the next row rather than applied to the current comparison.
