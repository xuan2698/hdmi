The public spec describes a Moore-style detector with a sticky output: once `1101` has been observed in the sampled bit stream, `start_shifting` is asserted and remains asserted until a synchronous active-high reset is sampled. The checker should model the input as a serial stream at positive clock edges, not as a parallel word. Each sampled row uses the `reset` and `data` values driven before that edge; optional mid-row changes belong to the next sampled row.

The important distinction is between the detector state and the output latch. The machine must remember how much of `1101` has been matched so far, including overlapping prefixes. For example, after seeing `11`, a later `0` does not necessarily discard all progress; after seeing `110`, the final `1` completes detection. The checker should not assume that every nonmatching bit returns the machine to a completely blank prefix state. It should also not require `start_shifting` to follow the current `data` bit after detection.

The output boundary is one-way until reset. Before detection, `start_shifting` should be 0. On the sampled row that completes `1101`, it should become 1. On every subsequent sampled row with `reset=0`, it must remain 1 regardless of `data`. Only a sampled `reset=1` clears it. Reset has priority over `data` and returns the machine to its initial state with `start_shifting=0`. A reset value that changes between edges does not retroactively affect the row already sampled; it is carried to the next sampled row.

A short worked example: suppose the machine has matched `110` and is waiting for the final `1`. On the completing sampled row, `reset=0`, `data=1`; the correct output is `start_shifting=1`. On the next sampled row, `reset=0`, `data=0`; the correct output is still `1`. A checker that recomputes the output from the current `data` bit would wrongly expect 0.

The useful focus for the final Python checker is therefore the registered, persistent nature of `start_shifting`: verify the 0-to-1 transition on the completing sampled row, verify that it stays 1 on every later non-reset row independent of `data`, and verify that only a sampled synchronous `reset=1` clears it.
