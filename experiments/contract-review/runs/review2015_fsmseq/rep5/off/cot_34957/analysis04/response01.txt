The public interface is deliberately narrow: one-bit synchronous active-high `reset`, one-bit serial `data`, one-bit registered output `start_shifting`, and a single `clk`. There are no multi-bit buses, no enables, and no separate valid qualifier. Consequently the boundary values for every input are exactly `0` and `1`; there is no intermediate or out-of-range encoding to reject. The output is likewise binary, but its meaning is asymmetric: `0` is the ordinary “sequence not yet observed since reset” value, while `1` is a sticky latched condition. Once `start_shifting` becomes `1`, it remains `1` on every subsequent sampled edge until a sampled `reset=1` clears it. The checker should therefore treat the output as a state-derived signal, not as a pulse or a one-cycle flag.

The machine’s observable behavior is defined at the positive clock edge. Each row supplies the values that are present before that edge; the row’s expected output and next state are determined from the state entering the row together with that row’s sampled `reset` and `data`. Reset has priority. If the sampled row has `reset=1`, the machine returns to the initial state and the row’s output is `0`, independent of `data` and independent of whether the machine had already found `1101`. If `reset=0`, the sequence recognizer advances normally: initial plus `1` goes to a one-bit prefix state; that state plus `1` goes to a two-bit `11` prefix; `11` plus `0` goes to `110`; `110` plus `1` completes the pattern and enters the found state, where the output becomes `1` and stays `1`. Non-progressing bits fall back according to the longest suffix that is still a prefix of `1101`; notably, from `11`, another `1` keeps the machine in `11`, and from `110`, a `0` returns to initial.

The most important checker point is the separation between sampled values and mid-row changes. A mid-row change occurs after the sampled edge and before the opposite edge, and it is carried into the start of the next row. It must not alter the current row’s transition or output. This is especially relevant at the completing transition: if a row is entered in the `110` state with sampled `data=1` and `reset=0`, that row’s output is `1` and the next state is found. If `data` later changes to `0` during the same row, the current row still outputs `1`; the carried `0` is merely the next row’s sampled input, where the machine is already found and remains found unless reset is sampled high. The checker should process each row as a fixed tuple, apply synchronous reset first, then the sequence transition, then the sticky output, and only afterward update any carried inputs for the following row.
