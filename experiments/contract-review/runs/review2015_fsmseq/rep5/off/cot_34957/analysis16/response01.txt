The public interface is narrow and entirely one-bit: `reset`, `data`, and `start_shifting` are each width 1, with a single clock `clk`. There are no multi-bit buses, no enable, and no separate valid signal. Consequently, boundary-value analysis is mostly about the two legal values of each one-bit signal and about timing relative to the sampled positive edge, not about numeric ranges. The meaningful “boundaries” are 0 versus 1 on `reset` and `data`, and the transition boundary of `start_shifting` from 0 to 1 and back to 0 only under reset.

Because all ports are one bit, there is no overflow, underflow, signedness, or truncation concern. The checker should not invent intermediate encodings or assume that `data` carries more than one bit per sampled row. Each sampled row contributes exactly one input bit to the sequence search. The sequence `1101` therefore spans four sampled rows in the normal case, although overlapping prefixes matter: after seeing `11`, a later `0` may still leave a useful suffix, and after seeing `110`, the final `1` completes detection. The checker should treat the input as a serial bit stream sampled at positive edges, not as a parallel word.

The key boundary for `start_shifting` is the one-way latch implied by “forever, until reset.” Before detection, the output is expected to be 0. On the sampled row that completes `1101`, the output should become 1. After that, for every sampled row with `reset=0`, the output must remain 1 regardless of `data`. The only way back to 0 is a sampled `reset=1`. This means the checker must distinguish “not yet found” from “found and holding.” It should not require the output to track the current bit, and it should not treat a later `0` or `1` as clearing the found condition.

Reset is active high and synchronous. A sampled `reset=1` has priority over `data` and must return the machine to its initial state with `start_shifting=0`. A reset value that changes between edges does not affect the row already sampled; it is carried to the next sampled row. The checker should therefore evaluate outputs only after the positive edge has settled, using the values driven before that edge. Mid-row changes are relevant only as the inputs for the following sampled row.

A short worked example illustrates the persistence boundary. Suppose the machine has matched `110` and is waiting for the final `1`. On the completing sampled row, `reset=0`, `data=1`; the correct output is `start_shifting=1`. On the next sampled row, `reset=0`, `data=0`; the correct output is still `1`. A checker that recomputes the output from the current `data` bit would wrongly expect 0. The useful focus for the final Python checker is therefore the registered, persistent nature of `start_shifting`: verify the 0-to-1 transition on the completing sampled row, then verify that it stays 1 on every later non-reset row independent of `data`, and that only a sampled synchronous `reset=1` clears it.
