The key point for the final checker is that the machine has two distinct behavioral regimes: prefix tracking before the first match, and an absorbing matched state afterward. In the prefix regime, the state advances according to the longest suffix of the sampled data stream that is also a prefix of `1101`. From the initial state, `data=1` moves toward the first bit of the pattern, while `data=0` keeps the machine at the initial state. Subsequent sampled bits refine the prefix: after seeing `1`, another `1` keeps the one-bit prefix; a `0` advances to the two-bit prefix `10`; a `1` from `10` advances to `110`; and a `1` from `110` completes the match and enters the absorbing state. Mismatches fall back to the longest valid suffix prefix, not necessarily to the initial state—for example, after `11`, a `0` yields prefix `10`, and after `110`, a `0` yields the initial state because no suffix of `1100` is a nonempty prefix of `1101`.

Once the match is detected, the machine enters the absorbing matched state. In that state, `start_shifting` is 1 and remains 1 for every subsequent sampled edge regardless of `data`. Only a sampled synchronous `reset=1` returns the machine to the initial state and clears `start_shifting`. The checker must therefore not recompute the output from a sliding window of recent bits after the first match; the output is latched, not pattern-derived.

Reset precedence is absolute at the sampled edge. If `reset=1` is sampled, the next state is the initial state and `start_shifting=0`, independent of `data` and independent of whether the machine was matched. Mid-cycle changes to `data` or `reset` do not affect the current sampled edge; they are carried into the next row. The checker should compare outputs after the sampled edge has settled, using inputs driven before that edge.

Worked example: sampled `data=1,1,0,1` reaches the matched state and sets `start_shifting=1`. A mid-cycle `data=0` before the next edge is the next row’s input; at that next sampled edge the machine stays matched and `start_shifting` remains 1. A checker expecting the output to clear because the recent window is now `1010` would be wrong.
