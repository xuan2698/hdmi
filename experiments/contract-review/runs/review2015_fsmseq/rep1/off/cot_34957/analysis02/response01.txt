The key point for the final Python checker is the separation of **input assignment** from **state update**, and the fact that only the rising edge is a sampling event. The public spec says each row’s values are driven before the sampled edge, and optional mid-input changes occur after sampling, before the other edge, and are carried to the start of the next row. That means a row can contain two distinct input moments: the pre-edge values that the FSM actually samples, and a later mid-cycle change that only becomes the starting input for the next row. The checker must not treat the mid change as a clock event or as an immediate transition trigger.

For reset and power-up, the prose should emphasize that reset is active high and synchronous. It is evaluated only when the rising edge samples it. A mid-cycle assertion of reset does not clear the machine immediately; it only matters if it is present at the next sampled rising edge. Likewise, deassertion of reset mid-cycle does not release the machine until the next rising edge samples reset low. Power-up behavior should be described as the machine beginning in its initial non-matching state with `start_shifting` low, and only the sampled synchronous reset can force that initial condition after power-up. The sticky nature of `start_shifting` means that once a sampled rising edge detects the 1101 sequence, the output becomes 1 after the edge settles and remains 1 forever unless a later sampled rising edge sees reset high. A mid-cycle data change cannot undo a match, and a mid-cycle reset cannot clear the sticky output until the next rising edge.

A short worked example is useful: suppose the FSM has already seen “110” and the next row drives `reset=0, data=1` before the rising edge. At that edge the machine samples the 1, reaches the terminal match state, and `start_shifting` becomes 1 after the edge settles. If a mid change then sets `data=0`, that does not undo the match; the next row simply begins with `data=0`, while `start_shifting` remains 1 unless reset is sampled high at a later rising edge.

The final checker should therefore compare `start_shifting` only after each sampled rising edge has settled, carry mid-cycle input changes into the next row’s starting inputs, and enforce that only a sampled synchronous reset can clear the sticky output. It should also avoid updating outputs on the falling edge or on mid-cycle input changes. This keeps the checker aligned with the public specification’s two-phase row model and prevents false failures caused by treating every input change as a clock event.
