The machine is a Moore-style recognizer for the bit pattern 1101, with a sticky success flag. Its state should represent how much of the target prefix has most recently been matched: no useful prefix, “1”, “11”, and “110”. A fifth terminal state represents having completed 1101; once entered, it is absorbing except for synchronous reset. The output `start_shifting` is low in all prefix states and high in the terminal state. Because the output depends only on the state, it changes only after a sampled rising edge causes a state transition, not in response to mid-cycle input changes.

On each rising edge, reset is evaluated first. If sampled `reset` is 1, the machine returns to the initial no-prefix state and `start_shifting` becomes 0 after the edge settles, regardless of the sampled data value. If sampled `reset` is 0, the machine advances according to the sampled `data` bit. From the initial state, data 1 moves to the “1” state and data 0 stays initial. From “1”, data 1 moves to “11” and data 0 returns to initial. From “11”, data 0 moves to “110” and data 1 stays in “11”, since the trailing 1 can begin a new attempt. From “110”, data 1 completes the sequence and moves to the terminal state, setting `start_shifting` high; data 0 returns to initial. From the terminal state, any data value keeps the machine in the terminal state, so `start_shifting` remains high. Only a sampled synchronous reset can leave the terminal state and clear the output.

The important checker point is the two-phase row model. Inputs are driven before the sampled rising edge; the checker must evaluate reset and data only at that edge and compare `start_shifting` only after the edge has settled. Optional mid-cycle input changes occur after sampling and before the other edge; they are not clock events and must not trigger transitions or output updates. They simply become the starting inputs for the next row. In particular, a mid-cycle reset assertion does not clear the machine immediately, and a mid-cycle reset deassertion does not release it until the next sampled rising edge. Power-up begins in the initial non-matching state with `start_shifting` low; only a sampled synchronous reset can force that condition afterward.

Worked example: if the machine is in “110” and the next row drives `reset=0, data=1` before the rising edge, that edge samples the 1, enters the terminal state, and `start_shifting` becomes 1 after settling. A subsequent mid-cycle change to `data=0` does not undo the match; the next row starts with data 0, while `start_shifting` stays 1 unless a later sampled rising edge sees reset high.
