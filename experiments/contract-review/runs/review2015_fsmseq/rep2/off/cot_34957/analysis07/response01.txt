The public specification defines a synchronous finite-state machine with a single-bit input `data`, a single-bit active-high synchronous `reset`, and a single-bit output `start_shifting`. The machine searches the serial input stream for the bit pattern `1101`. Once that pattern has been observed, `start_shifting` must become 1 and remain 1 indefinitely, until a synchronous reset returns the machine to its initial condition. The output is therefore sticky: after the first detection, later input bits do not clear it. Reset is sampled at the same edge as `data`, and reset has priority over the normal transition.

The timing discipline is central to the checker. Each row supplies the values that are driven before the sampled positive clock edge. The checker should sample those values at that edge, after the edge has settled, and compare the resulting output against the expected value for that row. Optional mid-cycle input changes occur after sampling and before the opposite edge; they are not part of the transition just sampled. Instead, they are carried forward as the starting inputs for the next row. Consequently, a mid-cycle change to `data` or `reset` must not retroactively alter the state or output computed for the preceding sampled edge. The checker should apply the row’s driven values at the sampled edge, compute the next state and output, compare them, and only afterward accept any mid-cycle values as the initial conditions for the following row.

Reset handling needs particular care. When `reset=1` is sampled, the machine must return to its initial state and produce `start_shifting=0` for that edge, regardless of `data`. That reset transition overrides the entire normal transition for that sampled edge. The checker should not allow the same row’s `data=1` to also advance the prefix matcher. In other words, reset is not merely an override on the output; it overrides the entire transition for that edge.

The prefix behavior also needs care around overlapping prefixes. The sequence `1101` has a nontrivial self-overlap: after seeing `11`, another `1` should keep the machine in the “seen 11” state rather than falling back to “seen 1” or initial. Similarly, after seeing `110`, a `0` should return to initial, because `1100` has no suffix that is a useful prefix of `1101`. The checker should encode these transitions directly rather than using a generic substring search over a history buffer, since the public spec describes a finite-state machine and the sticky terminal state changes the meaning of later bits.

Sampling discipline is the third point. Inputs are driven before the sampled posedge, and expected outputs are checked after that edge has settled. Optional mid-cycle input changes occur after sampling and before the opposite edge; they are carried to the start of the next row. Therefore the checker must not let a mid-cycle change affect the transition just sampled. It should apply the row’s driven values at the sampled edge, compute the next state and output, compare, and only then accept any mid-cycle values as the starting inputs for the following row.

A short worked example: assume the current state is “seen 11.” A sampled row has `reset=0, data=0`. The machine moves to “seen 110” and outputs 0. If `data` changes to 1 after sampling, that change is ignored for this edge. At the next posedge, with `reset=0, data=1`, the machine enters the terminal state and outputs 1. After that, with reset low, the output remains 1 for any data. This example captures the two main checker hazards: mid-cycle changes apply only to the next sampled row, and the sticky flag must persist after the match rather than being recomputed from the latest bit.
