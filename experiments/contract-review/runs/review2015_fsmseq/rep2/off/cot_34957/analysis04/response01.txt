The interface is deliberately narrow: one synchronous active-high `reset`, one serial `data` input, one `start_shifting` output, and a single clock. All ports are one bit wide, so there are no multi-bit boundary values to interpret. The meaningful boundary cases are therefore logical rather than numeric: `reset` high versus low, `data` high versus low, and the timing boundary between the sampled posedge and any later input change.

The public behavior describes a Moore-style detector whose output depends on the state reached after the sampled edge. The machine has five conceptual states: initial, seen `1`, seen `11`, seen `110`, and terminal/sticky. The terminal state is absorbing under normal operation because `start_shifting` must remain 1 forever until reset. Reset is synchronous and active high, and it overrides data. Thus a sampled row with `reset=1` must force the initial non-accepting state and `start_shifting=0`, even if `data=1` is also present. The checker should not let a reset row simultaneously count as the first bit of a new match.

The transition logic is a prefix matcher for `1101`. From initial, `0` stays initial and `1` goes to seen `1`. From seen `1`, `1` goes to seen `11` and `0` returns to initial. From seen `11`, `0` goes to seen `110` and `1` stays in seen `11`, since the trailing `11` remains a valid prefix. From seen `110`, `1` completes the sequence and enters the sticky terminal state; `0` returns to initial because `1100` has no useful suffix for this pattern. In the terminal state, any data value leaves the state unchanged and keeps `start_shifting=1` unless reset is sampled high.

The most important checker point is sampling discipline. Expected outputs should be evaluated after each sampled posedge has settled, using the state resulting from that edge. Inputs are driven before the sampled edge. Optional mid-cycle changes occur after sampling and before the opposite edge; they must be carried into the next row and must not retroactively affect the just-sampled transition. The checker should therefore maintain a current state, apply reset with priority, then data, then compare the resulting `start_shifting`. It should not expect the sticky flag to clear when later data bits fail to extend the pattern.

A short worked example: suppose the current state is seen `11`. A sampled row with `reset=0, data=0` moves to seen `110` and outputs 0. If `data` changes to 1 after sampling, that change is ignored for this edge. At the next posedge with `reset=0, data=1`, the machine enters the terminal state and outputs 1. Thereafter, with reset low, the output remains 1 regardless of data. This illustrates both the prefix-table behavior and the requirement that mid-cycle changes apply only to the next sampled row.
