One implementation mistake worth flagging for the checker is treating `reset` as an output-only override rather than a full transition override. In this spec, reset is active-high synchronous: when the sampled row has `reset=1`, the machine must return to its initial state and `start_shifting` must be 0 for that edge, regardless of `data`. The reset transition overrides the entire normal transition for that sampled edge. The checker should not allow the same row’s `data=1` to also advance the prefix matcher. In other words, reset is not merely an override on the output; it overrides the entire transition for that edge.

The prefix behavior also needs care around overlapping prefixes. The sequence `1101` has a nontrivial self-overlap: after seeing `11`, another `1` should keep the machine in the “seen 11” state rather than falling back to “seen 1” or initial. Similarly, after seeing `110`, a `0` should return to initial, because `1100` has no suffix that is a useful prefix of `1101`. The checker should encode these transitions directly rather than using a generic substring search over a history buffer, since the public spec describes a finite-state machine and the sticky terminal state changes the meaning of later bits.

Sampling discipline is the third point. Inputs are driven before the sampled posedge, and expected outputs are checked after that edge has settled. Optional mid-cycle input changes occur after sampling and before the opposite edge; they are carried to the start of the next row. Therefore the checker must not let a mid-cycle change affect the transition just sampled. It should apply the row’s driven values at the sampled edge, compute the next state and output, compare, and only then accept any mid-cycle values as the starting inputs for the following row.

A short worked example: assume the current state is “seen 11.” A sampled row has `reset=0, data=0`. The machine moves to “seen 110” and outputs 0. If `data` changes to 1 after sampling, that change is ignored for this edge. At the next posedge, with `reset=0, data=1`, the machine enters the terminal state and outputs 1. After that, with reset low, the output remains 1 for any data. This example captures the two main checker hazards: mid-cycle changes apply only to the next sampled row, and the sticky flag must persist after the match rather than being recomputed from the latest bit.
