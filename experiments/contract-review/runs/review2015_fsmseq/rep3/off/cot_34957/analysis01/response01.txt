The public spec defines a synchronous Moore-style recognizer: one input bit per clock, one output bit that latches high permanently once the pattern 1101 has been observed, cleared only by a synchronous active-high reset. Because the output is described as “forever, until reset,” the machine must include a sticky state (or equivalent flag) that is entered on pattern completion and never left except by reset. The reset is synchronous, so it is sampled on the same posedge as data; there is no asynchronous clear path to reason about.

The timing language is the important part for the checker. Each row’s values are “driven before the sampled edge,” and sampling occurs “after the posedge edge has settled.” That means the checker should treat the posedge as the sampling instant: inputs present just before that edge are the ones the FSM sees, and outputs are evaluated from the state that results from that edge (or, depending on convention, the state visible after settling). The phrase “sample after the posedge edge has settled” warns against evaluating outputs at the exact edge instant; the checker should allow the synchronous update to complete before comparing start_shifting.

Mid-input changes are explicitly allowed “AFTER sampling, before the other edge,” and are “carried to the start of the next row.” This is the subtle point. A mid-row change is not sampled by the current posedge; it becomes the input value for the next sampled edge. So the checker must not treat a mid-row data toggle as affecting the current row’s transition. Instead, it should model two phases per row: (1) pre-edge driven values, sampled at posedge; (2) optional post-sample changes that persist into the next row’s pre-edge value. If a mid change occurs, the next row’s effective data is the changed value unless the next row explicitly drives something else. The same applies to reset: a mid-row reset assertion after sampling does not reset the current state; it is seen at the next posedge.

A useful worked example: suppose the FSM is in the state representing prefix “11” and start_shifting=0. In a row, data=0 is driven before the posedge, so at the edge the machine sees 0 and moves to the state for suffix “10” (or equivalent), still start_shifting=0. After sampling, data changes to 1 mid-row. That 1 is carried to the next row. In the next row, before the posedge, data is therefore 1; the machine sees 1 and, from the “10” state, completes 1101, setting start_shifting=1 after that edge. The checker must not have completed the pattern in the first row just because a 1 appeared after the edge.

For the final Python checker, the key is to separate “edge-sampled inputs” from “mid-row carried inputs.” The checker should compute the next state only from the values driven before the posedge, then apply any mid-row changes to the input registers for the following row. Output comparison should use the settled post-edge state, and once start_shifting is 1 it must remain 1 across all subsequent rows until a synchronous reset is sampled at a posedge. Reset should be treated like any other synchronous input: a reset value driven before the edge clears the sticky flag and returns the FSM to its initial state at that edge; a reset asserted only mid-row takes effect at the next edge. This timing discipline is the main thing to encode, because the pattern detection itself is a straightforward five-state prefix automaton plus a terminal sticky state.
