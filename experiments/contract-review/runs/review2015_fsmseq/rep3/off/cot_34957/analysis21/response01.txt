The machine needs five meaningful states: an initial state with no useful suffix, a state for a matched “1,” a state for “11,” a state for “110,” and an absorbing accept state after “1101.” The output is 0 in the first four states and 1 in the accept state. Because the specification says the output must remain 1 forever until reset, the accept state should have no outgoing transition except reset. Equivalently, a separate latched flag can be set when the transition into accept occurs and cleared only by reset; either representation is acceptable as long as the checker compares the settled post-edge output.

Transitions should be evaluated from the pre-edge state and pre-edge inputs. Reset has priority: if reset is high, the next state is the initial state and the output is 0, regardless of data. If reset is low, data drives the sequence logic. From the initial state, data=0 stays initial and data=1 moves to the “1” state. From “1,” data=0 returns to initial and data=1 moves to “11.” From “11,” data=0 moves to “110” and data=1 stays in “11,” since the trailing two bits are still a valid prefix. From “110,” data=1 moves to accept and data=0 returns to initial, since “1100” has no useful suffix. From accept, every non-reset input stays in accept with output 1.

The important checker point is that the output must be taken from the settled post-edge state, not recomputed from the current input alone. Once accept is reached, later bits must not clear the output. A common bug is to let the state machine continue matching and then drive the output low when the state leaves the accepting pattern. Under this specification, accept is absorbing until reset, so the output remains high even if subsequent data would otherwise suggest a fallback.

Reset priority must also be applied before sequence logic. If the machine is in accept and the pre-edge inputs are reset=1 and data=1, the edge must produce the initial state and start_shifting=0. Data must not override reset. The checker should therefore sample reset and data before the edge, apply reset first, and only then evaluate the sequence transition when reset is low.

Fallback behavior is the other likely source of mismatches. From “11,” a 1 must remain in “11,” not reset or advance incorrectly. From “110,” a 0 must return to initial. A checker that merely counts matched bits without proper suffix fallback will diverge on overlapping prefixes.

Worked example: if the pre-edge state is “11,” reset=0, and data=0, the sampled edge moves to “110” and keeps start_shifting=0. If data changes to 1 after sampling, that 1 belongs to the next row; only the following posedge can complete 1101 and set start_shifting=1. The final checker should latch pre-edge inputs per sampled edge, apply reset priority first, update the absorbing or latched accept condition, and compare the settled post-edge output.
