The key point for the final Python checker is that this FSM is trivial structurally but easy to get wrong procedurally. The detector is a prefix automaton for “1101” with a sticky terminal state: once the full pattern has been observed at a sampled posedge, `start_shifting` becomes 1 and remains 1 until a synchronous reset is sampled high. The interesting behavior is not the state diagram; it is the exact boundary between “inputs that were present before the sampled edge” and “inputs that changed after the sampled edge.”

Reset is active high synchronous. That means reset is not an asynchronous clear. A high reset value that is driven before a posedge must force the next state to the initial state and force `start_shifting` to 0 at that edge. A reset that appears only after the posedge has already sampled must not retroactively affect the transition just taken. It is simply the reset value carried into the next row, where it will be sampled at the following posedge. The same rule applies to `data`: a mid-row change is not part of the current transition. It is carried forward and becomes the pre-edge value for the next sampled edge unless the next row explicitly drives a different value.

A short worked example makes the hazard concrete. Suppose the machine is in the state representing that it has seen “11”, with `start_shifting = 0`. Before a posedge, `data = 0` is driven. At the sampled edge, the machine moves to the initial state and leaves the output 0, because “110” does not end in a useful prefix of “1101”. After sampling, `data` changes to 1. That 1 is carried to the next row. At the next posedge, with `data = 1` present before the edge, the machine moves from the initial state to the state representing “1”, not to the terminal state. The earlier “11” was already broken by the sampled 0. A checker that used the post-edge 1 as though it belonged to the previous transition could incorrectly advance the prefix or even claim completion.

For the final Python checker, the useful focus is therefore procedural rather than structural. Evaluate next state and output from pre-edge driven inputs, then propagate mid-row changes into the next row’s pre-edge inputs. Reset is just another synchronous input under that model. Power-up may be treated as the documented initial state, with the first sampled reset providing the definitive known condition. The detector itself is a small prefix automaton plus a terminal sticky state; the timing discipline around sampling, mid-row changes, and synchronous reset is the part most likely to cause checker errors.
