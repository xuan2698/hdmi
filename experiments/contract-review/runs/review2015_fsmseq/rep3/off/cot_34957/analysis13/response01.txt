The public specification defines a synchronous finite-state machine sampled on the rising edge of `clk`. The key timing distinction is between values present before the sampled posedge and optional mid-row changes that occur after sampling but before the next edge. The checker must treat pre-edge `reset` and `data` as the inputs that determine the transition into the just-settled state and output. Mid-row changes are not retroactive: they are carried forward and become relevant only at the next sampled edge.

The FSM has five meaningful states. S0 is the initial or reset state, waiting for a 1. S1 records that a 1 has been seen. S2 records “11”. S3 records “110”. S4 is the latched-found state: `start_shifting` is 1 and remains 1 forever until synchronous reset. Reset is active high and synchronous, so `reset=1` before a sampled edge forces the next state to S0 and the output to 0, regardless of `data`. From S3, pre-edge `data=1` completes “1101” and moves to S4, so after that edge settles `start_shifting` must be 1. From S4, any pre-edge `data` keeps the machine in S4 and the output at 1 unless reset is asserted.

The main checker hazard is using a post-edge or end-of-row input value for the transition that was just sampled. A mid-row change after the posedge belongs to the next row. If the checker lets a post-edge `data` or `reset` influence the just-sampled transition, it can produce a one-cycle-early or one-cycle-late result. The output must be compared against the state implied by the pre-edge `reset` and `data`, not against any later value.

A short worked example clarifies the boundary between S2 and S3. Suppose the machine is in S2, meaning the recent suffix is “11”. Before the sampled posedge, `data=0` and `reset=0`. The edge must move S2 to S3, and after the edge settles `start_shifting` must still be 0. After sampling, `data` changes to 1 and is carried into the next row. At the following posedge, with `data=1` present before the edge, S3 moves to S4 and the output becomes 1. A checker that used the post-edge `data=1` for the earlier transition would incorrectly jump from S2 to S4 one cycle early, setting `start_shifting=1` too soon. Conversely, a checker that delayed the S3-to-S4 transition until after the next edge would set the output one cycle late.

Reset follows the same rule. If the machine is in S3 and pre-edge `data=1`, the normal transition would enter S4 and set the output to 1. But if pre-edge `reset=1` at that same edge, reset wins: the next state is S0 and the output must be 0. A post-edge reset change does not affect that transition; it is carried to the next row and sampled at the following posedge. Thus the final Python checker should evaluate each sampled edge using only the pre-edge `reset` and `data`, then compare the post-edge `start_shifting` against the resulting state. This is the principal place where a pattern-only model or a final-value sampler will diverge from the public specification.
