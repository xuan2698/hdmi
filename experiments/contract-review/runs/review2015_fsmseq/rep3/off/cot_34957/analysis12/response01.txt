One common implementation mistake is to let the checker’s notion of “the current input” come from the wrong side of the sampled clock edge. The public specification says each row’s values are driven before the sampled edge, and optional mid input changes occur after sampling and are carried to the start of the next row. A checker that reads `data` or `reset` at the end of a row, or that lets a post-edge change influence the just-sampled transition, can produce a one-cycle-early or one-cycle-late result.

The FSM itself is straightforward: S0 waits for a 1; S1 has seen “1”; S2 has seen “11”; S3 has seen “110”; S4 means the sequence has been found and the output is latched. From S3, a pre-edge `data=1` completes “1101” and moves to S4, so after the edge settles `start_shifting` must be 1. From S4, all data values keep the machine in S4 and the output stays 1 until a synchronous reset. Reset has priority: if `reset=1` before the sampled edge, the next state is S0 and `start_shifting` is 0, even if `data=1` would otherwise complete the pattern from S3.

A useful distinguishing example is the boundary between S2 and S3. Suppose the machine is in S2, meaning the recent input suffix is “11”. Before the sampled posedge, `data=0` and `reset=0`. The edge must move S2 to S3, and after the edge settles the output must still be 0. After sampling, `data` changes to 1 and is carried into the next row. At the following posedge, with `data=1` present before the edge, S3 moves to S4 and the output becomes 1. A checker that used the post-edge `data=1` for the earlier transition would incorrectly jump from S2 to S4 one cycle early, setting `start_shifting=1` too soon. Conversely, a checker that delayed the S3-to-S4 transition until after the next edge would set the output one cycle late.

The same timing rule applies to reset. If the machine is in S3 and pre-edge `data=1`, the normal transition would enter S4 and set the output to 1. But if pre-edge `reset=1` at that same edge, reset wins: the next state is S0 and the output must be 0. A post-edge reset change does not affect that transition; it is carried to the next row and sampled at the following posedge. Thus the checker should compare the post-edge output against the state implied by the pre-edge `reset` and `data`, not against any later input value. This is the main place where a pattern-only model or a final-value sampler will diverge from the public specification.
