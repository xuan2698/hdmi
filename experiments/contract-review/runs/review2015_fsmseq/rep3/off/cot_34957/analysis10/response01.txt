The public interface is small but the timing semantics matter. `reset` and `data` are each one bit wide; `start_shifting` is one bit wide. All are sampled with respect to `clk`, and the specification says to sample after the posedge has settled. Values shown in a row are driven before the sampled edge. Optional mid-cycle input changes occur after sampling and before the opposite edge, and those changes carry into the start of the next row. That carry rule is the main boundary condition for a checker: an input change after the sampled edge must not retroactively affect the transition just taken.

The state machine has five conceptual states: S0 (no useful prefix), S1 (suffix “1”), S2 (suffix “11”), S3 (suffix “110”), and S4 (pattern found / latched). From S0, data 1 goes to S1 and data 0 stays in S0. From S1, data 0 returns to S0 and data 1 goes to S2. From S2, data 0 goes to S3 and data 1 stays in S2. From S3, data 1 goes to S4 and data 0 returns to S0. From S4, every data value stays in S4. The output `start_shifting` is 0 in S0 through S3 and 1 in S4. Once S4 is reached, the output remains 1 forever until reset, independent of subsequent data.

Reset is active high and synchronous. If `reset` is high before a sampled posedge, the next state is S0 and `start_shifting` becomes 0 at that edge, regardless of current state or data. If `reset` is low before the edge, the normal transition applies. A reset or data value that changes only after the sampled edge is not part of that transition; it is carried into the next row and sampled at the following posedge.

The most useful checker point is output timing relative to the sampled edge. The output must reflect the state after the edge, not the pre-edge input combination. For example, if the machine is in S3 and pre-edge data is 1, the edge enters S4, so after the edge settles `start_shifting` should be 1. If reset is high at that same edge, the transition must go to S0 and the output must be 0 even though data would otherwise complete the pattern. Reset priority over pattern completion is the most likely source of mismatch in a checker that models only pattern matching.

Worked example: in S2 (“11”), pre-edge data 0 moves the machine to S3 with output 0. After sampling, data changes to 1 and is carried to the next row. At the next posedge, with data 1 present before the edge, S3 moves to S4 and output becomes 1. A checker using the post-edge 1 for the earlier transition would jump from S2 to S4 one cycle too early.
