The public specification defines a synchronous finite-state machine with a single-bit input `data`, a single-bit active-high synchronous `reset`, a clock `clk`, and a single-bit output `start_shifting`. The machine is intended to detect the bit sequence `1101` in the input stream. Once that sequence has been observed, `start_shifting` must become 1 and remain 1 forever, until a synchronous reset returns the machine to its initial state. The output is therefore a sticky “sequence seen” flag rather than a pulse or a per-window match indicator.

Because reset is synchronous and active high, it is sampled at the same posedge as `data`. When `reset=1` is present before a sampled clock edge, the next state is the initial state and the output after that edge must be 0, regardless of the current state or the value of `data`. When `reset=0`, the machine advances according to the input bit and the current state. The reset behavior is not asynchronous: a reset value that changes after the sampled edge does not retroactively affect the transition that was just taken. It is carried forward and becomes relevant only at the next sampled edge.

The natural state interpretation is a prefix-matching progression. The initial state represents no useful suffix of the target sequence. Subsequent states represent having most recently seen a prefix of `1101`: a leading `1`, then `11`, then `110`. A final state represents having completed `1101`; that state is absorbing with respect to the output, so `start_shifting` remains 1 for all non-reset edges thereafter. From the initial state, `data=1` advances toward the first prefix, while `data=0` keeps the machine in the initial state. From the one-`1` state, another `1` advances to the `11` state, while a `0` returns to the initial state. From the `11` state, a `0` advances to the `110` state, while a `1` keeps the machine in the `11` state because the trailing `11` is still a valid prefix. From the `110` state, a `1` completes the sequence and moves to the final state, setting the output to 1; a `0` returns to the initial state. From the final state, any pre-edge `data` keeps the machine in the final state and the output at 1 unless reset is asserted.

The main checker hazard is using a post-edge or end-of-row input value for the transition that was just sampled. A mid-row change after the posedge belongs to the next row. If the checker lets a post-edge `data` or `reset` influence the just-sampled transition, it can produce a one-cycle-early or one-cycle-late result. The output must be compared against the state implied by the pre-edge `reset` and `data`, not against any later value.

A short worked example clarifies the boundary between the `11` state and the `110` state. Suppose the machine is in the `11` state. Before the sampled posedge, `data=0` and `reset=0`. The edge must move the machine to the `110` state, and after the edge settles `start_shifting` must still be 0. After sampling, `data` changes to 1 and is carried into the next row. At the following posedge, with `data=1` present before the edge, the machine moves to the final state and the output becomes 1. A checker that used the post-edge `data=1` for the earlier transition would incorrectly jump from `11` to the final state one cycle early, setting `start_shifting=1` too soon. Conversely, a checker that delayed the `110`-to-final transition until after the next edge would set the output one cycle late.

Reset follows the same rule. If the machine is in the `110` state and pre-edge `data=1`, the normal transition would enter the final state and set the output to 1. But if pre-edge `reset=1` at that same edge, reset wins: the next state is the initial state and the output must be 0. A post-edge reset change does not affect that transition; it is carried to the next row and sampled at the following posedge. Thus the final Python checker should evaluate each sampled edge using only the pre-edge `reset` and `data`, then compare the post-edge `start_shifting` against the resulting state. This is the principal place where a pattern-only model or a final-value sampler will diverge from the public specification.
