The public interface is narrow and fully specified: one synchronous active-high reset input, one serial data input, one clock, and one registered output. All ports are one bit wide. There are no multi-bit buses, no enable, no valid qualifier, and no separate done pulse. The only numeric boundary values that matter are 0 and 1 on each port. The output is not a pulse; it is a sticky flag that becomes 1 when the pattern 1101 has been observed and remains 1 until a synchronous reset is sampled high.

Because reset is synchronous and active high, it is sampled on the same posedge as data. Reset has priority over data and over the current state. When reset is sampled as 1, the next settled state must be the initial state and start_shifting must be 0, regardless of data or of any prior accept condition. When reset is sampled as 0, the sequence logic advances according to the current state and the sampled data bit. The checker should treat reset and data as pre-edge values, apply reset first, and only then consider the data-driven transition.

The output must be evaluated from the settled post-edge state. In particular, the accept condition is absorbing until reset. Once the machine has reached accept, every subsequent non-reset sample keeps start_shifting at 1, even if the incoming data would otherwise look like a fallback or a new partial match. A checker that recomputes the output from the current input alone, or that lets the state leave accept on later bits, will fail. The correct behavior is a latched or absorbing accept flag, cleared only by synchronous reset.

The fallback transitions are also important. From the initial state, 0 stays initial and 1 moves to the one-bit prefix state. From the one-bit prefix, 0 returns to initial and 1 moves to the two-bit prefix. From the two-bit prefix, 0 moves to the three-bit prefix and 1 stays in the two-bit prefix, because the trailing two bits remain a valid prefix. From the three-bit prefix, 1 reaches accept and 0 returns to initial, since the four-bit history has no useful suffix. From accept, all non-reset data stays in accept with output 1.

A short worked example clarifies the sampling boundary. Suppose the pre-edge state is the two-bit prefix, reset is 0, and data is 0. The sampled edge moves to the three-bit prefix and start_shifting remains 0. If data changes to 1 after sampling, that change belongs to the next row and cannot complete the pattern on the same edge. Only the following posedge, with the new sampled data, can move to accept and set start_shifting to 1.

For the final Python checker, the useful focus is therefore: latch pre-edge reset and data per sampled edge, apply reset priority first, update the state with the specified fallback transitions, preserve the absorbing accept condition, and compare the settled post-edge start_shifting value. Do not infer the output from the raw input stream or from a transient match.
