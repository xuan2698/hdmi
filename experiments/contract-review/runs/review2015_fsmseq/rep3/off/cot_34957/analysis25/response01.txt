The public spec fixes a synchronous, active-high reset and a Moore-style output that becomes 1 on detecting `1101` and then remains 1 until reset. The timing description matters because the checker must distinguish values driven before the sampled edge from optional mid-input changes that occur after sampling and before the opposite edge. In practice, the checker should treat `reset` and `data` as sampled at the posedge, with reset taking priority over any data transition, and should read `start_shifting` only after the posedge has settled. Mid-input changes are not sampled at that edge; they are carried into the next row and affect only the next sampled posedge. This prevents a checker from accidentally accepting a transition caused by a value that was never present at a sampling edge.

The useful design point is the fallback from the `110` prefix state. A correct machine must send `110` followed by `0` back to the state representing a trailing `0`, not to the state representing a trailing `1`. If the fallback is wrong, the machine can still appear correct on some inputs because the erroneous state may later be overwritten by a genuine match. The checker therefore needs a case where the bad fallback is observable. A compact example is input `01101`. The correct machine processes `0` to the start state, `1` to the one-bit prefix, `1` to the `11` prefix, `0` to the `110` prefix, and the final `1` to accept, so `start_shifting` becomes 1 at the last sample. A machine that sends `110` on `0` to the one-bit prefix state instead ends the same input in the `11` prefix state and never asserts the output. That single sequence exposes the fallback error without relying on a longer history.

The checker should also verify that acceptance is absorbing. Once `start_shifting` is 1, no later data value may clear it; only a sampled synchronous reset may do so. A short sequence such as `11010` is useful: the correct outputs after each sampled bit are 0, 0, 0, 1, 1, because the final `0` cannot undo acceptance. A machine that allows the accepting state to fall back on `0` would produce 0, 0, 0, 1, 0. This directly tests the “forever, until reset” requirement.

Finally, the checker should apply reset before data on every sampled edge. If reset is high at a posedge, the next state and output must be the reset state and 0, regardless of the simultaneous data value. The checker should not infer behavior from values that change between edges; it should compare only the settled post-edge output against the expected state after the sampled inputs. Keeping the fallback case and the absorbing-accept case separate makes failures easier to diagnose: one catches an incorrect prefix restart, and the other catches an accepting state that is not truly permanent.
