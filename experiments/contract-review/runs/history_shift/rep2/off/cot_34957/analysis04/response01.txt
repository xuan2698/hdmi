The interface is a single 32-bit state element with a 1-bit asynchronous reset and four 1-bit control/data inputs plus a 32-bit training-history bus. All control signals (`areset`, `predict_valid`, `predict_taken`, `train_mispredicted`, `train_taken`) are exactly 1 bit wide; `train_history` and `predict_history` are exactly 32 bits wide. There are no multi-bit control fields, so no partial-width decoding is needed. The only boundary values that matter are 0 and 1 on the 1-bit signals, and the full 32-bit range on the two history buses. Because the state is exactly 32 bits, the shift and concatenation operations are total: `{predict_history[30:0], predict_taken}` and `{train_history[30:0], train_taken}` both produce exactly 32 bits with no truncation or extension ambiguity. The checker should treat `train_history[31]` as the oldest bit and `train_history[0]` as the youngest, consistent with the stated LSB-first convention for the newest branch direction.

The transition logic has a strict four-level priority. First, `areset` overrides everything: on a sampled edge where reset is asserted, the next state is 32'h0000_0000 regardless of any other input. Second, if reset is not asserted but `train_mispredicted` is, the next state is `{train_history[30:0], train_taken}`; this load ignores `predict_valid` and `predict_taken` completely, because the flush that accompanies a misprediction also discards the in-flight prediction. Third, if neither reset nor misprediction is active but `predict_valid` is, the next state is `{predict_history[30:0], predict_taken}`, shifting the prediction in at bit 0. Fourth, if none of those three is asserted, the state holds. Inputs not selected by the active priority level are don't-cares: `train_taken` and `train_history` matter only under misprediction, and `predict_taken` matters only under a prediction that is not overridden by misprediction.

A useful worked example for the checker: from history 32'h0000_0003 with `predict_valid=1`, `predict_taken=1`, and no misprediction, the next state is 32'h0000_0007. If instead `train_mispredicted=1`, `train_history=32'h0000_0005`, and `train_taken=0`, the next state is 32'h0000_000A even if `predict_valid=1` and `predict_taken=1`, because misprediction outranks prediction.

For the final Python checker, the most valuable point is to encode this as one explicit next-state function with the priority order reset > misprediction > prediction > hold, and to apply it only to inputs sampled at the active clock edge. Mid-row input changes after sampling belong to the following row, not the row just sampled. The checker should also avoid assuming any power-up value before the first reset; either require a reset row or initialize the model to the testbench's assumed prior state. Finally, verify bit ordering: the newest direction must land at bit 0 in both the prediction shift and the misprediction load.
