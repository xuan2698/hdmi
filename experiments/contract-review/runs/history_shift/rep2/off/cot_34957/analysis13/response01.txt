The public spec defines a 32-bit global branch history shift register with three behaviors that interact through a strict priority chain. The checker must model the register as a single state element updated once per rising clock edge, with the next-state function evaluated on the inputs captured at that edge. The prose below focuses on the timing and priority details most likely to trip up a Python checker.

**Edge sampling and mid-input timing.** The protocol says each row's values are driven before the sampled edge, and optional mid-input changes occur after sampling but before the other edge, carried to the start of the next row. This means the checker should snapshot all inputs (`areset`, `predict_valid`, `predict_taken`, `train_mispredicted`, `train_taken`, `train_history`) at the rising edge, compute the next state from that snapshot, and compare `predict_history` at the same edge. Any mid-row change to `areset` or `train_mispredicted` belongs to the following row and must not retroactively alter the transition just committed. A checker that reads inputs lazily (e.g., re-reads `train_history` after the edge) can silently apply a mid-row change to the wrong cycle.

**Priority chain.** Reset has top priority: when `areset=1`, the next state is zero regardless of every other input. Next, `train_mispredicted=1` overrides prediction, because the pipeline flush also flushes the branch currently predicting. The loaded value is `train_history` concatenated with `train_taken`, i.e. `{train_history[30:0], train_taken}` — the actual result is appended at the LSB, not left in place. A checker that loads `train_history` unchanged matches only when `train_taken` happens to equal `train_history[31]`; it fails when the shift matters. Finally, `predict_valid=1` alone shifts in `predict_taken` at bit 0, so `predict_history[0]` is the youngest branch. Inserting at the MSB produces bit-reversed histories that agree only on palindromic patterns.

**Power-up.** The register has no defined initial value. The checker should either require an `areset` before the first comparison or treat pre-reset samples as don't-care. Assuming zero at time zero can cause a spurious first-edge mismatch and can mask a real reset bug.

**Worked example.** Suppose the register holds `32'h0000_0005` and one edge captures `areset=1`, `train_mispredicted=1`, `train_taken=0`, `train_history=32'hFFFF_FFFF`, `predict_valid=1`, `predict_taken=1`. Reset wins, so the next state is `32'h0000_0000`. Applying misprediction first gives `32'hFFFF_FFFE`; applying prediction first gives `32'h0000_000B`. Both are wrong, isolating the priority rule.

**Checker guidance.** Snapshot inputs at the edge, compute one next state via a priority-ordered selection with `areset` at the top, then `train_mispredicted`, then `predict_valid`, and never assume a defined power-up value.
