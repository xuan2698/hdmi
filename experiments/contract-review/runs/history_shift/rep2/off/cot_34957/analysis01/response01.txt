The timing contract here is a single-clock, edge-sampled design with asynchronous reset and a priority rule that must be reflected exactly in the checker. All state changes are observed at the rising edge of `clk`; the checker should sample after the posedge has settled, so it compares the post-edge `predict_history` against the value implied by the inputs that were stable before that edge. Inputs are driven before the sampled edge. Optional mid-cycle changes occur after sampling and before the next edge, and are carried forward to the start of the next row. That means the checker must not treat a mid-input change as affecting the just-sampled edge; it only affects the next sampled edge.

The state is a 32-bit global history shift register. On a normal prediction, when `predict_valid = 1` and no misprediction is being trained, the register shifts left by one bit position toward higher indices and inserts `predict_taken` at the LSB. Equivalently, the new history is `{predict_history[30:0], predict_taken}` if we describe the old value as `predict_history[31:0]`. The spec explicitly says `predict_history[0]` is the direction of the youngest branch, so the LSB is the newest bit. This orientation matters for the checker: a common bug is to shift the wrong direction or to insert at the MSB.

On a misprediction, when `train_mispredicted = 1`, the register is loaded with the history after completion of the mispredicted branch. That value is `train_history` concatenated with `train_taken`, with `train_taken` as the newest bit. In bit-vector terms, the loaded value should be `{train_history[30:0], train_taken}` if `train_history` is interpreted as the 32-bit history before the mispredicted branch and the result is a 32-bit register. The spec says “train_history concatenated with the actual result,” and because the youngest branch is at bit 0, the actual result belongs at bit 0. The checker should therefore verify that the post-edge value equals that concatenation, not `{train_taken, train_history[31:1]}` or any other ordering.

Priority is the key edge case. If both `predict_valid` and `train_mispredicted` are asserted for the same sampled edge, the misprediction wins. The prediction is effectively discarded because the pipeline flush also flushes the branch currently making the prediction. Thus the checker’s next-state function should be: if `areset` is asserted, history becomes zero; else if `train_mispredicted` is asserted, history becomes `{train_history[30:0], train_taken}`; else if `predict_valid` is asserted, history becomes `{predict_history[30:0], predict_taken}`; else history holds. The asynchronous reset is positive-edge triggered and resets the history counter to zero. Because it is asynchronous, the checker should allow the reset to take effect without waiting for `clk`; however, the public timing note says sampling occurs after the posedge has settled, so in the row-based checker the reset should be applied according to the row’s driven value before the sampled edge, and the post-edge output should be zero whenever reset is active at that sample.

A short worked example: suppose the current `predict_history` is 32’h0000_0003, `predict_valid = 1`, `predict_taken = 1`, and `train_mispredicted = 0`. The post-edge history should be `{30’h0000_0000, 1’b1}` shifted from the old value, i.e. `32’h0000_0007`. If instead `train_mispredicted = 1`, `train_history = 32’h0000_0005`, and `train_taken = 0`, the post-edge history should be `{train_history[30:0], 1’b0} = 32’h0000_000A`, regardless of `predict_valid` and `predict_taken`.

The most useful point for the final Python checker is to encode the priority and bit ordering explicitly in one next-state function, and to sample only after the posedge using the inputs that were stable before that edge. Mid-input changes should be stored for the next row and must not retroactively alter the current sample.
