The state is a single 32-bit register, `predict_history`, representing the global branch history. Its value is observable directly as the output, so there is no separate output logic to reason about: the output equals the register contents at all times. The only state transition occurs on the rising edge of `clk`, and the next-state value is a pure function of the current register value and the sampled inputs. Because `areset` is asynchronous and positive-edge triggered, it can also force the register to zero outside the clock edge; the spec says reset dominates, so any assertion of `areset` must produce zero regardless of the other control signals.

The transition function has a clear priority ladder implied by the spec. First, `areset` forces the register to zero. Second, if `train_mispredicted` is asserted, the register loads the concatenation of `train_history` with `train_taken`: the new history is `{train_history[31:1], train_taken}` under the convention that `predict_history[0]` is the youngest branch. This represents the history before the mispredicted branch followed by the actual outcome, discarding the speculative prediction. Third, if `predict_valid` is asserted (and no misprediction), the register shifts in `predict_taken` from the LSB side: `{predict_history[31:1], predict_taken}`. Fourth, if none of these controls is asserted, the register holds its value.

The critical subtlety is the simultaneous case: when both `predict_valid` and `train_mispredicted` are asserted at the same sampled edge, the misprediction must win. The pipeline flush discards the in-flight prediction, so the speculative shift must not be applied. An implementation that checks prediction first will pass isolated tests but fail this boundary vector. Similarly, reset must dominate a simultaneous misprediction, since the spec states reset zeroes the counter without exception.

For the checker, the key point is to compare the observed `predict_history` after each sampled edge against the register value that was current before that edge, applying the priority ladder explicitly. Recomputing the expected value from the same edge's inputs using a different priority order can mask a priority-inversion bug. Directed vectors should assert reset, misprediction, and prediction together, and misprediction plus prediction without reset, rather than relying on random coverage to hit these rare combinations.

A short worked example: suppose the pre-edge register is `0x0000_0005`, and at one sampled edge `areset=0`, `train_mispredicted=1`, `train_taken=0`, `train_history=0xFFFF_FFFF`, `predict_valid=1`, `predict_taken=1`. The correct next state is `{0xFFFF_FFFF[31:1], 0} = 0xFFFF_FFFE`. A prediction-wins implementation would instead produce `{0x0000_0005[31:1], 1} = 0x0000_0003`, which the checker must reject.

Finally, the checker should keep `areset` stable across the mid-input window, since the spec does not define intra-cycle ordering beyond reset dominance, and should begin full state comparison only after the first observed reset has established a known zero state. Before that, check only width and within-cycle stability.
