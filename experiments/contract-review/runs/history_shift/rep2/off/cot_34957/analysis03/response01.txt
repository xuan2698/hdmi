The register is a 32-bit global branch history shift register. Its state is the full 32-bit `predict_history` value, and the output is simply that state. The youngest branch direction occupies bit 0; older directions occupy progressively higher bits. All updates occur on the rising edge of `clk`, and the checker should sample after the edge has settled.

The next-state function has three priority levels. Highest priority is `areset`: when asserted, the history becomes `32'h0000_0000` asynchronously, independent of every other input. This means a reset row must produce zero even if `predict_valid`, `train_mispredicted`, `train_taken`, or `train_history` are also asserted. The checker should model reset as overriding all other transition logic.

Second priority is `train_mispredicted`. When asserted (and reset is not), the register loads the concatenation `{train_history[30:0], train_taken}`. This represents the history before the mispredicted branch followed by the actual direction of that branch, with the actual direction at bit 0. This load ignores `predict_valid` and `predict_taken` entirely. The reason is that a pipeline flush caused by the misprediction also flushes the branch currently making a prediction, so the prediction must not be allowed to update history.

Third priority is `predict_valid`. When asserted and neither reset nor misprediction is active, the register shifts left by one bit and inserts `predict_taken` at bit 0: `{predict_history[30:0], predict_taken}`. This updates history for the predicted branch, with the newest prediction at the LSB.

If none of `areset`, `train_mispredicted`, or `predict_valid` is asserted, the register holds its current value. `train_taken` and `train_history` are irrelevant unless `train_mispredicted` is asserted; `predict_taken` is irrelevant unless `predict_valid` is asserted and misprediction is not.

A short worked example: suppose current history is `32'h0000_0003`, `predict_valid = 1`, `predict_taken = 1`, and `train_mispredicted = 0`. The next history is `32'h0000_0007`. If instead `train_mispredicted = 1`, `train_history = 32'h0000_0005`, and `train_taken = 0`, the next history is `32'h0000_000A`, regardless of `predict_valid` and `predict_taken`.

For the final Python checker, the key is to implement one next-state function with explicit priority: reset first, then misprediction load, then prediction shift, then hold. Bit ordering must be LSB-first for the newest direction. Inputs that change mid-row, after sampling and before the next edge, belong only to the following row's transition, not to the row just sampled. The checker should also avoid assuming a power-up value before the first reset; either require a reset row or initialize its model to the testbench's assumed prior state.
