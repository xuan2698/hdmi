**Reset and power-up behavior**

The public specification defines `areset` as a positive-edge-triggered asynchronous reset that clears the 32-bit global history shift register to zero. Two properties matter for the checker. First, the reset is *asynchronous*: it does not wait for a `clk` edge to take effect. Second, the sampling convention in this problem is that each row's inputs are driven before the sampled `posedge`, and the output is examined after that edge has settled. Consequently, whenever `areset` is asserted in the row being sampled, the post-edge value of `predict_history` must be `32'h0000_0000`, independent of any simultaneous `predict_valid`, `predict_taken`, `train_mispredicted`, `train_taken`, or `train_history` values. Reset has the highest priority in the next-state function.

Power-up is not separately specified beyond the reset behavior. The checker should not assume any particular initial register contents before the first sampled edge; it should treat the first row as establishing state only through the specified reset or update rules. If the first sampled row has `areset = 1`, the expected history is zero. If it does not, the checker should either seed from a known prior value supplied by the testbench or treat the first non-reset row as unconstrained for the output comparison, depending on how the harness is structured. The safest approach is to require a reset row before checking non-reset transitions, or to initialize the checker's model to the same value the testbench assumes.

The update rules after reset are: if `train_mispredicted` is asserted, load `{train_history[30:0], train_taken}`; else if `predict_valid` is asserted, shift in `predict_taken` at the LSB, giving `{predict_history[30:0], predict_taken}`; else hold. Misprediction takes precedence over prediction when both are asserted on the same sampled edge, because the pipeline flush also flushes the branch currently making the prediction. The youngest branch direction is at bit 0, so the newly resolved or predicted direction belongs at bit 0, and older history shifts toward the MSB.

A short worked example: with current history `32'h0000_0003`, `predict_valid = 1`, `predict_taken = 1`, and `train_mispredicted = 0`, the post-edge history is `32'h0000_0007`. If instead `train_mispredicted = 1`, `train_history = 32'h0000_0005`, and `train_taken = 0`, the post-edge history is `32'h0000_000A`, regardless of `predict_valid` and `predict_taken`.

The most useful point for the final Python checker is to encode reset priority, misprediction-over-prediction priority, and LSB-first bit ordering in a single next-state function, and to apply mid-row input changes only to the following row.
