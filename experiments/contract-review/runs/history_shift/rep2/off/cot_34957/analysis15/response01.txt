The state is a single 32-bit global branch history register. Its next value is determined entirely by the sampled inputs at a rising edge, with a strict priority ordering. The output `predict_history` is simply the current register contents; it is not a separately computed function of the inputs. Consequently, the checker should model one register and compare the sampled output against the register's pre-edge value, then update the register according to the priority chain.

The priority chain is: asynchronous reset dominates everything; otherwise a misprediction load dominates a prediction shift; otherwise a prediction shift occurs; otherwise the register holds. This ordering matters because the public spec explicitly states that when prediction and misprediction coincide, the misprediction wins, since the pipeline flush also discards the branch currently predicting. Reset is asynchronous and positive-edge triggered, so an asserted `areset` forces the register to zero regardless of any other input. The checker should treat reset as the highest-priority event in the next-state function, not as a separate side condition that can be overridden.

For the prediction case (`predict_valid=1`, no reset, no misprediction), the register shifts left by one bit position and the new LSB receives `predict_taken`. Equivalently, the next value is `{old_history[30:0], predict_taken}`. The spec notes that `predict_history[0]` is the direction of the youngest branch, so the newest prediction enters at bit 0 and older history moves toward the MSB. The checker should verify this bit ordering explicitly, because reversing the shift direction is a common implementation error that still produces plausible-looking history values.

For the misprediction case (`train_mispredicted=1`, no reset), the register is loaded with the history after completion of the mispredicted branch. The spec defines this as `train_history` concatenated with `train_taken`, with `train_taken` as the newest bit. Thus the next value is `{train_history[30:0], train_taken}`. The checker should not shift the old register in this case; the old register contents are irrelevant to the load. It should also confirm that `train_history` supplies bits 31 down to 1 of the new value, not bits 30 down to 0 of some shifted combination.

When neither prediction nor misprediction is active and reset is not asserted, the register holds its value. The checker should still sample and compare the output each edge, since a spurious update during an idle cycle is a real defect even though the expected next state equals the current state.

The output timing is straightforward: `predict_history` reflects the register value after the sampled edge has settled. The checker should compare the output observed at a given sampled edge against the register value that was current before that edge, then apply the next-state rule to obtain the value expected at the following sampled edge. This avoids off-by-one confusion between "history used for prediction" and "history after prediction."

A useful worked example: suppose the register holds `32'h0000_0005`, and at one sampled edge `areset=1`, `train_mispredicted=1`, `train_taken=0`, `train_history=32'hFFFF_FFFF`, `predict_valid=1`, `predict_taken=1`. Reset dominates, so the next sampled value is `32'h0000_0000`. A checker applying misprediction first would expect `32'hFFFF_FFFE`; one applying prediction first would expect `32'h0000_000B`. Both are wrong, isolating the reset-priority rule.

The most useful point for the final checker is to implement exactly one next-state function with the priority order reset, then misprediction, then prediction, then hold, and to compare the output against the pre-edge register value rather than recomputing it from the same inputs. The checker should also avoid asserting and releasing `areset` entirely between sampled edges, since the public spec does not define intra-cycle ordering beyond reset dominance. Until a reset has been observed, the checker should not require any particular output value; it should only verify width and within-cycle stability, then begin state comparison after the first sampled reset.
