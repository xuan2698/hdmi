The interface is a single 32-bit state register with a one-bit asynchronous reset and four one-bit control/data inputs plus a 32-bit training-history bus. All control signals (`areset`, `predict_valid`, `predict_taken`, `train_mispredicted`, `train_taken`) are width 1, so their only legal values are 0 and 1; the checker should treat them as booleans, not as multi-bit fields. `train_history` and `predict_history` are both width 32, so every legal value lies in `0x0000_0000` through `0xFFFF_FFFF`. There is no partial-width output: the checker compares all 32 bits of `predict_history` after the edge settles.

The reset is positive-edge-triggered asynchronous and clears the history register to zero. Because it is asynchronous, the checker should be able to assert `areset` between clock edges and observe `predict_history == 0` without waiting for a posedge; after reset is released, normal shifting resumes from the zero state. The reset has no stated priority interaction with the other inputs beyond clearing the register, so the safest reference model treats an asserted `areset` as forcing the next/output state to zero regardless of the other control signals.

The functional core is a two-event priority chain. Highest priority is `train_mispredicted`: when asserted, the next state is `{train_history[30:0], train_taken}`, i.e. the low 31 bits of the independent `train_history` input with `train_taken` appended as the new LSB. This is a load, not a shift of the current register. The checker must therefore drive `train_history` independently of the pre-edge `predict_history`; a buggy design that shifts the current register instead of loading `train_history` will then be exposed. Second priority is `predict_valid` when `train_mispredicted` is low: the next state is `{old_history[30:0], predict_taken}`, shifting the predicted direction in at the LSB. If neither event fires, the register holds. The output is the post-edge register value, so the checker computes the expected next state from the pre-edge reference and compares after the edge settles.

The critical boundary case is simultaneous `train_mispredicted` and `predict_valid`. Misprediction wins because the pipeline flush also flushes the branch currently predicting. The checker should assert both with `predict_taken != train_taken` and confirm the next state depends only on `train_history` and `train_taken`. This one edge catches implementations that shift in `predict_taken` and then partially overwrite, or that merge the two paths.

Worked example: pre-edge reference `0x1234_5678`, `areset=0`, `predict_valid=1`, `predict_taken=1`, `train_mispredicted=0` gives `0x2468_ACF1`. If `train_mispredicted=1` and `predict_valid=1` occur together, `predict_taken` is ignored and the next state is `{train_history[30:0], train_taken}`. That distinction is the reference model's core.
