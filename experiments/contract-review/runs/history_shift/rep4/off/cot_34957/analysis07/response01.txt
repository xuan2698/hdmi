The public specification defines a 32-bit global branch-history shift register with two update paths and an asynchronous reset. The checker’s central task is to maintain a reference model of the 32-bit history and compare it against `predict_history` at the correct observation points. The timing analysis matters because the DUT has both sampled-edge behavior and an asynchronous reset that can change state between edges.

On each rising clock edge, the checker should first inspect `areset`. If `areset` is asserted at the edge, the reference history becomes zero. Otherwise, the checker applies the normal update rules. If `train_mispredicted=1`, the misprediction path takes priority over prediction. The new history is `{train_history[30:0], train_taken}`: the older 31 bits of `train_history` followed by the actual branch outcome as the new youngest bit. If `train_mispredicted=0` and `predict_valid=1`, the checker shifts in `predict_taken` from the LSB side, producing `{history[30:0], predict_taken}`. If neither update condition is true, the history holds its previous value. The output `predict_history` is simply the current 32-bit history value.

The priority rule is important. When `predict_valid=1` and `train_mispredicted=1` occur together, the prediction is ignored. The pipeline flush associated with the misprediction also flushes the branch currently making the prediction, so only the misprediction update is architecturally visible. The checker should encode this priority explicitly rather than applying prediction first and then overwriting with the misprediction result. Although many input combinations may produce the same final value either way, the checker should not depend on incidental equivalence.

The asynchronous reset requires separate treatment. `areset` is positive-edge triggered and asynchronous, so a rising edge of `areset` must immediately force the reference history to zero, regardless of whether a clock edge has occurred. The checker must not wait for the next posedge to apply reset. If it does, it may accept a nonzero `predict_history` during the interval after reset rises and before the next clock edge, and it may also mishandle a prediction that occurs before that edge. After the posedge has settled, the checker samples `predict_history` and compares it to the reference. If `areset` is high at that sampled edge, the expected value is zero.

Mid-input changes occur after sampling and before the other edge, and are carried to the start of the next row. These changes can include a rising `areset`, which must be applied immediately to the reference. Other mid-input changes should not alter the reference until the next sampled edge, except insofar as they define the inputs for that next edge.

A short worked example clarifies the interaction. Suppose the reference history is `0x1234_5678`. Before a rising clock edge, `predict_valid=1`, `predict_taken=1`, `train_mispredicted=0`, and `areset=0`. The checker updates the reference to `0x2468_ACF1` and compares the sampled `predict_history` to that value. If, after sampling but before the next edge, `areset` rises, the checker must immediately set both the reference and expected output to zero, even though no clock edge has occurred. If instead `train_mispredicted=1` and `predict_valid=1` occur together at an edge, the checker computes `{train_history[30:0], train_taken}` and ignores `predict_taken`.

Boundary values are legal and must not be special-cased. The checker should use a plain 32-bit reference and allow natural truncation. Shifting `0xFFFF_FFFF` with `predict_taken=0` yields `0xFFFF_FFFE`; with `predict_taken=1` it yields `0xFFFF_FFFF`. Shifting `0x0000_0000` with `predict_taken=1` yields `0x0000_0001`. The checker must not treat all-ones as a sentinel or reset value.
