The interface is a single 32-bit state register with one-bit control and data inputs. `predict_history` is the only output and is exactly 32 bits wide, so its boundary values are `0x0000_0000` and `0xFFFF_FFFF`. `train_history` is also 32 bits, with the same boundary values; its LSB is discarded during a misprediction load, and its upper 31 bits become the new upper bits of `predict_history`. All other inputs (`areset`, `predict_valid`, `predict_taken`, `train_mispredicted`, `train_taken`) are one bit, so each is either 0 or 1.

The update rule has three cases. If `train_mispredicted` is high, the next state is `{train_history[30:0], train_taken}`. Otherwise, if `predict_valid` is high, the next state is `{predict_history[30:0], predict_taken}`. Otherwise the state holds. When both update signals are high, misprediction wins and the prediction is ignored.

The checker should pin down reset first. After `areset` is released, the next posedge must operate from zero. A prediction then gives 0 or 1; a misprediction gives `{train_history[30:0], train_taken}`. Testing only after history has built up can hide incomplete reset behavior, so exercise prediction and misprediction immediately after reset release.

Mid-cycle changes are the second subtlety. Inputs may change after a sampling edge and before the next edge; those changes are setup for the next posedge, not immediate effects. Changing `train_history` mid-cycle must not alter `predict_history` until a posedge that actually performs a misprediction load. The checker should hold pending inputs for the next edge and apply them only when modeling that edge. The exception is `areset`: if it rises mid-cycle, the expected output becomes zero immediately, and pending prediction/misprediction inputs are irrelevant until reset is released.

Worked example: suppose after a posedge `predict_history = 0x1234_5678`. Mid-cycle the checker sets `train_history = 0xDEAD_BEEF`, `train_taken = 0`, `predict_taken = 1`, and asserts both `predict_valid` and `train_mispredicted`. Misprediction takes precedence, so the next posedge yields `{0xDEAD_BEEF[30:0], 0} = 0xBD5B_7DDE`. If `areset` is asserted mid-cycle in that same window instead, the expected output becomes `0x0000_0000` immediately.

For the final checker, construct expected values with explicit bit slicing, `{train_history[30:0], train_taken}`, rather than a shift operator, and sample the asynchronous reset before any posedge so that mid-cycle reset assertion is caught immediately.
