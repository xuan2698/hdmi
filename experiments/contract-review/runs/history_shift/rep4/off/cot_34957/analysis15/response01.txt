The design is a single 32-bit state register, `predict_history`, updated on the rising edge of `clk`. The only asynchronous control is `areset`, which is positive-edge triggered and clears the register to zero. The checker should treat reset as dominant over every other input: if `areset` is sampled high at an edge, the post-edge reference must be zero regardless of `predict_valid`, `predict_taken`, `train_mispredicted`, `train_taken`, or `train_history`. This dominance is the first thing to encode, because a common bug is to let a prediction or misprediction update survive a reset cycle. The checker should also handle the startup case: if the first sampled edge has `areset` deasserted, initialize the reference to zero and let the first observed reset establish the authoritative cleared state.

Outside reset, the update is a strict priority chain over two events. The highest-priority event is `train_mispredicted`. When it is asserted, the next state is the 32-bit value formed by taking the low 31 bits of `train_history` and appending `train_taken` as the new LSB: `{train_history[30:0], train_taken}`. This is a load from the independent `train_history` input, not a shift of the current register. The checker must not assume `train_history` equals the pre-edge `predict_history`; the public interface exposes them as separate signals, and a correct reference model uses `train_history` directly. The second-priority event is `predict_valid` when `train_mispredicted` is low. In that case the next state is `{old_history[30:0], predict_taken}`, shifting the predicted direction in at the LSB. If neither event is asserted, the register holds its value. The output `predict_history` is the post-edge register value, so the checker computes the next state from the pre-edge reference and compares all 32 bits after the edge settles.

The most important edge case is simultaneous assertion of `train_mispredicted` and `predict_valid`. The specification says misprediction takes precedence because the pipeline flush also flushes the branch currently making a prediction. The checker should drive both signals together with `predict_taken` differing from `train_taken`, and confirm the next state depends only on `train_history` and `train_taken`. A buggy implementation might shift in `predict_taken` and then partially overwrite, or combine the two paths; this single-edge test catches both. The checker should also vary `train_history` independently of the current register so that a mistaken shift-based implementation is exposed.

Worked example: suppose the pre-edge reference is `0x1234_5678`. With `areset=0`, `predict_valid=1`, `predict_taken=1`, and `train_mispredicted=0`, the next state is `0x2468_ACF1`. If instead `train_mispredicted=1` and `predict_valid=1` occur together, the checker must ignore `predict_taken` and use `{train_history[30:0], train_taken}`. That distinction is the core of the reference model.
