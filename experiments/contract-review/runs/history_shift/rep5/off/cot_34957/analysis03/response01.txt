The register is a 32-bit global branch history shift register. Its state is the 32-bit value `predict_history`, which is also the only output. The state updates only on the rising edge of `clk`, as observed at the sampling point after the edge has settled. The checker should compute a single next-state value from the sampled inputs at each posedge, using a strict priority ordering, and should not attempt to model any sub-cycle asynchronous behavior.

The priority order is: `areset` first, then `train_mispredicted`, then `predict_valid`, then hold. When `areset` is sampled asserted, the next state is zero, regardless of all other inputs. When `areset` is not asserted but `train_mispredicted` is asserted, the next state is formed from `train_history` and `train_taken`: the history before the mispredicted branch is shifted left by one bit and the actual branch outcome is inserted at the LSB. In bit terms, the next state is `{train_history[30:0], train_taken}`. This rollback discards any prediction that may have been made for the mispredicted branch and restores the correct post-branch history. When neither reset nor misprediction is asserted but `predict_valid` is asserted, the next state shifts in `predict_taken` at the LSB: `{predict_history[30:0], predict_taken}`. When none of these conditions hold, the register holds its current value.

The precedence of misprediction over prediction is important. If both `predict_valid` and `train_mispredicted` are asserted at the same sampled edge, the prediction is ignored and the rollback value is loaded. This reflects the pipeline flush: the branch currently making a prediction is flushed, so its speculative history update must not survive. The checker should therefore evaluate the conditions in the stated order and stop at the first true condition.

Reset is asynchronous in the specification, but the sampling protocol only exposes values at sampled edges. Mid-cycle input changes occur after sampling and are carried to the start of the next row. For deterministic checking, reset should be applied at the sampled edge where `areset` is observed asserted: the output at that sample is zero, and it remains zero at subsequent samples while reset stays asserted. The checker should not model a sub-cycle clear between edges. Before the first observed reset assertion, the register value is not defined by the public specification, so the checker should treat pre-reset history samples as don't-care or begin checking from the first reset assertion.

A short worked example: suppose the current history is `0x0000_0005`, and at a sampled posedge `areset=0`, `predict_valid=1`, `predict_taken=1`, `train_mispredicted=1`, `train_taken=0`, `train_history=0x0000_0005`. Misprediction wins, so the next history is `{0x0000_0005[30:0], 0} = 0x0000_000A`, and the prediction is ignored. If `areset=1` at that same edge, the next history is `0x0000_0000`.

The key point for the final Python checker is to implement exactly one next-state function per sampled posedge with priority `areset` > `train_mispredicted` > `predict_valid` > hold, to defer mid-cycle changes to the next row, and to avoid modeling asynchronous sub-cycle clearing. This keeps the checker aligned with the public protocol and deterministic.
