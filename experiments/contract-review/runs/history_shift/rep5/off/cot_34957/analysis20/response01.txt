# Reset and Power-Up Analysis

The specification defines `areset` as a positive-edge-triggered asynchronous reset that clears the 32-bit global history shift register to zero. Two properties matter for the checker: the reset is *asynchronous* (it takes effect without waiting for a clock edge) and it is *positive-edge triggered* (the assertion is recognized on the rising edge of `areset`, not on a level-sensitive basis). In practice, the checker should model reset as an immediate override: whenever `areset` is sampled high, the expected history becomes `0x0000_0000` and any simultaneous `predict_valid` or `train_mispredicted` update is suppressed. The spec does not define the interaction between reset and prediction/training in the same cycle, so the only defensible expectation is zero; stimulus that combines reset with an update should be avoided in directed tests, or at minimum the checker should not attempt to model a "reset plus shift" result.

Power-up state is explicitly undefined. The spec says nothing about the register's value before the first reset, so the checker must not assume it starts at zero. Any comparison that depends on a known history must be preceded by at least one sampled row with `areset=1`. Without that, the first expected value is underdetermined and a mismatch would be a false failure. This is the single most important point for the final Python checker: initialize the model variable to a sentinel (e.g., `None`) and refuse to compare until a reset has been observed, or simply drive a reset in the first stimulus row.

The update priority is: reset (highest) > misprediction training > prediction. When `train_mispredicted=1`, the next state is `(train_history << 1) | train_taken`, and this must override any simultaneous `predict_valid`. When only `predict_valid=1`, the next state is `(history << 1) | predict_taken`. The shifted-in bit appears in the *same* sampled row's `predict_history` output — the checker must compare against the post-edge next state, not the pre-edge value, and must not add an extra output register. LSB insertion is required because `predict_history[0]` is the youngest branch; inserting at the MSB would invert age ordering.

Worked example: after a reset sample, history is zero. Apply `predict_valid=1, predict_taken=1`; expected `predict_history = 0x0000_0001` on that same row. Then apply `train_mispredicted=1, train_history=0x0000_0001, train_taken=0`; expected `0x0000_0002`, confirming LSB insertion and training precedence over any concurrent prediction.
