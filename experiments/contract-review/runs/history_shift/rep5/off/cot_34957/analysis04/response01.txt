The public interface is a single 32-bit global branch-history shift register with one clock and six one-bit control/data inputs plus one 32-bit training-history input. The only output is `predict_history`, 32 bits wide. All control signals (`areset`, `predict_valid`, `predict_taken`, `train_mispredicted`, `train_taken`) are one bit; `train_history` is 32 bits and supplies the pre-mispredicted-branch history used during rollback. Because the register is exactly 32 bits, every shift or concatenation must preserve width 32: a prediction shift discards the oldest bit (`predict_history[31]`) and inserts `predict_taken` at bit 0; a misprediction load forms `{train_history[30:0], train_taken}`, again 32 bits, discarding `train_history[31]`.

Boundary values matter for the checker. The history register can legally hold any 32-bit value, including all zeros and all ones. `train_history` likewise spans the full unsigned 32-bit range, so the checker must not assume small or sign-extended values. The inserted bits `predict_taken` and `train_taken` are single bits and must land in bit position 0 only. The output `predict_history` is the registered state after the sampled posedge has settled; it is not a combinational function of the current inputs. Consequently, the checker should compare the output observed at a sample against the state computed from the previous sampled state and the inputs driven before that edge.

The next-state priority is the central semantic point. At each sampled posedge, evaluate in this order: if `areset` is asserted, the next history is zero; else if `train_mispredicted` is asserted, the next history is `{train_history[30:0], train_taken}`; else if `predict_valid` is asserted, the next history is `{predict_history[30:0], predict_taken}`; else hold. The misprediction branch overrides prediction when both are asserted at the same edge, modeling the pipeline flush that removes the speculative update. The checker should implement this as a single ordered conditional and stop at the first true condition, rather than combining updates.

Reset handling deserves care. Although `areset` is described as asynchronous and positive-edge triggered, the sampling protocol exposes only sampled edges. Mid-cycle input changes occur after sampling and are carried to the start of the next row. Therefore the checker should treat an observed asserted `areset` at a sampled edge as forcing the output to zero at that sample and at subsequent samples while reset remains asserted, without modeling any sub-cycle clear between edges. Before the first observed reset assertion, the register contents are not defined by the public specification; the checker should treat those pre-reset samples as don't-care or begin checking only from the first reset assertion.

A compact worked example illustrates precedence and width. Let the current history be `0x0000_0005`, with `areset=0`, `predict_valid=1`, `predict_taken=1`, `train_mispredicted=1`, `train_taken=0`, and `train_history=0x0000_0005`. Misprediction wins, so the next history is `{0x0000_0005[30:0], 0} = 0x0000_000A`; the prediction is ignored. If `areset=1` at that same edge instead, the next history is `0x0000_0000`.

For the final Python checker, the useful focus is exact one-step next-state evaluation per sampled posedge with priority `areset` > `train_mispredicted` > `predict_valid` > hold, correct 32-bit masking of shifted and concatenated values, and deferral of mid-cycle changes to the next row.
