The checker must treat the branch history register as a single 32-bit state element whose next value is selected by a strict priority among three possible actions: asynchronous reset, misprediction training, and prediction. Because the output `predict_history` is the register itself (not a separately registered copy), the value sampled on a given row is the post-edge state for that row. The checker should therefore compute the next state from the inputs sampled on that row and compare it directly to the sampled output on the same row, with no extra pipeline delay.

Reset is the highest-priority action. Whenever `areset` is sampled high, the expected history becomes `0x0000_0000`, and any simultaneous `predict_valid` or `train_mispredicted` update is suppressed. The public specification does not define the interaction between reset and prediction/training in the same cycle, so the only defensible expectation is zero. Directed tests should avoid combining reset with an update; at minimum, the checker should not attempt to model a "reset plus shift" result.

Power-up state is explicitly undefined. The specification says nothing about the register's value before the first reset, so the checker must not assume it starts at zero. Any comparison that depends on a known history must be preceded by at least one sampled row with `areset=1`. Without that, the first expected value is underdetermined and a mismatch would be a false failure. The model variable should be initialized to a sentinel (for example, `None`) and comparisons should be refused until a reset has been observed, or the first stimulus row should simply drive a reset.

The update priority below reset is: misprediction training over prediction. When `train_mispredicted=1`, the next state is `(train_history << 1) | train_taken`, and this must override any simultaneous `predict_valid`. When only `predict_valid=1`, the next state is `(history << 1) | predict_taken`. The shifted-in bit appears in the same sampled row's `predict_history` output, so the checker must compare against the post-edge next state, not the pre-edge value, and must not add an extra output register. LSB insertion is required because `predict_history[0]` is the youngest branch; inserting at the MSB would invert age ordering.

Worked example: after a reset sample, history is zero. Apply `predict_valid=1, predict_taken=1`; expected `predict_history = 0x0000_0001` on that same row. Then apply `train_mispredicted=1, train_history=0x0000_0001, train_taken=0`; expected `0x0000_0002`, confirming LSB insertion and training precedence over any concurrent prediction.
