The key distinguishing behavior is the priority ordering at a sampled posedge, especially the collision of `predict_valid` and `train_mispredicted`. A naive checker might apply both updates, or apply prediction first and then misprediction, producing a history that reflects two speculative shifts. The public spec instead says the misprediction flush removes the branch currently predicting, so only the misprediction update should occur. The final checker should encode this as a single ordered conditional: reset first, then misprediction, then prediction, then hold.

A useful short example: suppose the current `predict_history` is `0x0000_0005`, and at one sampled edge `areset=0`, `predict_valid=1`, `predict_taken=1`, `train_mispredicted=1`, `train_taken=0`, and `train_history=0x0000_0005`. Because misprediction has priority, the next history is `{train_history[30:0], train_taken}` = `{0x0000_0005[30:0], 0}` = `0x0000_000A`. The prediction shift is ignored. If `areset` were asserted at that same edge, the next history would instead be `0x0000_0000`, overriding both training and prediction.

The checker should also be careful about width and masking. The history is exactly 32 bits, so every shift-and-insert operation must discard the oldest bit and keep only 32 bits. In Python, this means masking with `0xFFFF_FFFF` after forming `(history << 1) | bit`, or equivalently using `((history << 1) | bit) & 0xFFFF_FFFF`. For the misprediction path, the source is `train_history`, not the current `predict_history`; using the wrong source is a likely bug. The inserted bit is `train_taken`, not `predict_taken`.

Reset semantics are another likely source of checker error. The public description calls reset asynchronous, but the sampling protocol only exposes sampled edges. Mid-cycle changes occur after sampling and are carried to the start of the next row. Therefore the checker should not try to model a sub-cycle clear between edges. It should treat an asserted `areset` observed at a sampled edge as forcing the output to zero at that sample and at subsequent samples while reset remains asserted. Before the first observed reset assertion, the register contents are not defined by the public specification, so those samples should be treated as don't-care or checking should begin only from the first reset assertion.

Finally, the checker should defer mid-cycle input changes to the next row. If an input changes after the sampled edge but before the next edge, that change affects only the next sampled evaluation. The checker should not retroactively alter the previous sample. This matters for distinguishing a correct one-step next-state model from a combinational or same-cycle model.
