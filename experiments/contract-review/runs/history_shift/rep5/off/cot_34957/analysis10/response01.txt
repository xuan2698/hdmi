The interface is a single 32-bit state register with five 1-bit controls and one 32-bit training-history input. All control signals are single-bit and are interpreted as booleans at the sampling edge. `predict_history` is the only output and is 32 bits wide, so every legal value lies in `0x0000_0000` through `0xFFFF_FFFF`. The input `train_history` is likewise 32 bits, so it spans the same range; its high bit (`bit 31`) is the boundary case that most often exposes width bugs. `areset` is asynchronous and positive-edge triggered, but the checker samples after each `posedge clk` has settled, so the effective rule at a sampled edge is: if `areset` is high at that sample, the state is zero regardless of the other controls. The prose note that reset should not be assumed to act only at edges is a caution about modeling; for the sampled checker, treat `areset = 1` as forcing `predict_history = 0` at that edge.

When reset is not active, the next-state function has a strict priority. First, if `train_mispredicted = 1`, the register loads the post-completion history formed from `train_history` and `train_taken`: `{train_history[30:0], train_taken}`, equivalently `((train_history << 1) | train_taken) & 0xFFFF_FFFF`. This path overrides any simultaneous prediction. Second, if `train_mispredicted = 0` and `predict_valid = 1`, the register shifts in the predicted direction: `{predict_history[30:0], predict_taken}`, equivalently `((predict_history << 1) | predict_taken) & 0xFFFF_FFFF`. Third, if neither update control is asserted, the register holds its current value. The spec does not define reset combined with the other controls beyond reset taking effect, so the checker should simply force zero when `areset` is sampled high.

The most important checker point is source selection under precedence. A row with `predict_valid = 1`, `train_mispredicted = 1`, `predict_taken` different from `train_taken`, and `train_history` different from the current `predict_history` must produce exactly the training concatenation. `predict_taken` must have no effect, and the shift source must be `train_history`, not the current register. An implementation that computes the prediction first and then overwrites with training is fine; one that lets prediction win, ORs the two paths, or shifts the wrong history is wrong.

Width handling is the second checker point. Both update expressions must be masked to 32 bits. The prediction next value is `((predict_history << 1) | predict_taken) & 0xFFFF_FFFF`; the training next value is `((train_history << 1) | train_taken) & 0xFFFF_FFFF`. Without masking, a set high bit yields a 33-bit intermediate.

Worked example: with `predict_history = 0x8000_0000`, `predict_valid = 1`, `predict_taken = 1`, and no misprediction, the next value is `0x0000_0001`, not `0x1_0000_0001`. The checker should include high-bit cases on both paths and verify that training uses `train_history` rather than the current `predict_history`.
