The register is a single 32-bit state element, `predict_history`, updated only on the rising edge of `clk`. Its value is the branch direction history, with bit 0 being the youngest branch. The public spec defines three behaviors: asynchronous reset, prediction update, and misprediction recovery, with a strict precedence ordering.

Reset is positive-edge-triggered and asynchronous. When `areset` is asserted, `predict_history` becomes zero independently of the clock. The checker should not constrain samples before the first observed `areset` assertion, because power-up state is unspecified. Strict checking begins at the first sampled edge where `areset` is high, where zero is expected, and continues on every subsequent sample. Because reset is asynchronous, a mid-cycle assertion can change the output before the next sampling edge; the checker should treat the sampled value at each edge according to the inputs present at that edge, not assume reset only acts at edges.

When no reset is active, the next-state function is selected by `train_mispredicted` first, then `predict_valid`. If `train_mispredicted = 1`, the register loads the post-completion history: the previous history `train_history` shifted left by one with `train_taken` inserted at the LSB, i.e. `{train_history[30:0], train_taken}`. This path overrides prediction entirely. If `predict_valid = 1` and `train_mispredicted = 0`, the register shifts in the predicted direction: `{predict_history[30:0], predict_taken}`. If neither is asserted, the register holds its value. The spec does not define simultaneous reset with the other controls beyond reset taking effect; the safe checker treats `areset = 1` as forcing zero at that sample.

The critical checker point is precedence and source selection. A row with `predict_valid = 1`, `train_mispredicted = 1`, differing `predict_taken` and `train_taken`, and `train_history` different from the current `predict_history` must yield exactly the training concatenation. `predict_taken` must have no influence, and the shift source must be `train_history`, not the current register. Implementations that compute prediction then overwrite with training are acceptable; implementations that let prediction win, OR the paths, or shift the wrong history are not.

Width handling matters in Python. Both update expressions must be masked to 32 bits. The prediction next value is `((predict_history << 1) | predict_taken) & 0xFFFF_FFFF`; the training next value is `((train_history << 1) | train_taken) & 0xFFFF_FFFF`, equivalent to `{train_history[30:0], train_taken}`. Without masking, a set high bit produces a 33-bit intermediate.

Worked example: with `predict_history = 0x8000_0000`, `predict_valid = 1`, `predict_taken = 1`, and no misprediction, the next value is `0x0000_0001`, not `0x1_0000_0001`. The checker should include high-bit cases on both paths and verify that training uses `train_history` rather than the current `predict_history`.
