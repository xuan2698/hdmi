The public interface is a single 32-bit state element with six one-bit control/data inputs and one 32-bit output. All scalar inputs (`areset`, `predict_valid`, `predict_taken`, `train_mispredicted`, `train_taken`) are one bit wide; `train_history` and `predict_history` are 32 bits wide. There are no multi-bit arithmetic ports beyond the history words, so boundary analysis centers on the 32-bit shift/concatenate behavior and on the priority and reset semantics rather than on numeric ranges.

The state is a 32-bit global branch history register. On each sampled rising edge, the next state is selected by priority. If `train_mispredicted` is asserted, the register loads `(train_history << 1) | train_taken`, truncated to 32 bits. This is the pre-mispredicted-branch history with the actual branch outcome inserted at the LSB, so bit 0 is the youngest branch. If `train_mispredicted` is not asserted but `predict_valid` is, the register shifts left by one and inserts `predict_taken` at the LSB: `(state << 1) | predict_taken`, again truncated to 32 bits. If neither is asserted, the state holds. When both `predict_valid` and `train_mispredicted` are asserted, training wins and the prediction is discarded, matching the pipeline-flush rationale.

The output `predict_history` is the current register value. Because sampling occurs after the posedge has settled, the observed output on a row is the post-edge state, i.e., the next-state function applied to the previous state using that row's inputs. The checker should therefore maintain one 32-bit variable, update it once per sampled edge using the priority above, and compare it directly to `predict_history` after each edge. No separate output register or delayed comparison is needed.

Reset is the main boundary concern. `areset` is positive-edge-triggered asynchronous: asserting it forces the register to zero independent of the clock, and the output should read zero while asserted. The specification does not define power-up state, so the checker must not assume zero before any reset. The robust stimulus approach is to assert `areset` for at least one sample at the start, then deassert and begin directed rows; this establishes a known zero history and makes the first post-reset prediction fully determined. Rows combining reset with prediction or training should be avoided, since the only defensible expectation is zero output, and no update should be modeled as surviving reset.

A short worked example: after one reset sample the history is zero. Deassert reset and apply `predict_valid = 1, predict_taken = 1` with no training; the next state is `(0 << 1) | 1 = 0x0000_0001`, so `predict_history` reads `0x0000_0001` after that edge. A later row with `train_mispredicted = 1, train_history = 0x0000_0001, train_taken = 0` yields `(0x0000_0001 << 1) | 0 = 0x0000_0002`, confirming both the LSB insertion order and training precedence over any simultaneous prediction.

For the final Python checker, the key point is to implement exactly one 32-bit next-state function with the stated priority, apply it only on sampled edges, treat asynchronous reset as an immediate zero that suppresses updates, and never assume an initial value without an explicit reset.
