The state is a single 32-bit register, `predict_history`. Its next value is determined by exactly one of three rules, applied in priority order.

**Rule 1 — asynchronous reset dominates.** If `areset` is high at the sampled edge, the next `predict_history` is `0`, regardless of every other input. This is the highest-priority rule and must be checked in combination with the other control signals, not just in isolation. A common bug is to let `train_mispredicted` or `predict_valid` override reset, or to clear only the low bit rather than the whole register.

**Rule 2 — misprediction load dominates prediction.** Absent reset, if `train_mispredicted` is high, the next state is `(train_history << 1) | train_taken`. This is a *load* of a supplied value, not a shift of the current register. The distinction matters: a buggy implementation that shifts `predict_history` instead of loading `train_history` will only be caught if the checker drives `train_history` to a value that differs from `predict_history` in many bits. If the checker happens to set `train_history == predict_history`, the bug is invisible. So the checker should choose `train_history` patterns deliberately unlike the current register.

**Rule 3 — prediction shift.** If neither reset nor misprediction is asserted but `predict_valid` is high, the next state is `(predict_history << 1) | predict_taken`. New bits enter at bit 0 (the youngest branch), and older bits move toward higher indices. A checker that reverses this ordering will fail shift probes even when priority logic is correct.

**Rule 4 — hold.** If none of the above, the register retains its value.

The combined-edge case is the highest-value probe because it exercises priority and load semantics simultaneously. Worked example: let `predict_history = 0x0000_0001`, `predict_valid = 1`, `predict_taken = 1`, `train_mispredicted = 1`, `train_history = 0x0000_0003`, `train_taken = 0`, `areset = 0`. The correct next state is `(0x3 << 1) | 0 = 0x0000_0006`. A prediction-first-then-load implementation that shifts the current history would land on `0x0000_0003`; an implementation that ignores `train_history` and shifts `predict_history` would land elsewhere again. These candidate values are distinct, so one edge discriminates among the plausible bugs. The checker should also include a variant with `areset = 1` on the same combined edge and expect zero, catching implementations that let training override reset or that only clear the LSB.

For the final Python checker, the most useful focus is: (a) always drive `train_history` to a pattern unlike the current register on misprediction edges, (b) include at least one edge where reset, prediction, and misprediction are all asserted and expect zero, and (c) verify bit ordering by checking that `predict_taken` appears at bit 0 after a prediction-only edge. These three checks together pin down the priority order, the load-vs-shift semantics, and the shift direction.
