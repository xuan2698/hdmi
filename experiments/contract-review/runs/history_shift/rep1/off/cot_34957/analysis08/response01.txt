The reset and power-up model for this 32-bit global history shift register is straightforward but has one detail that matters a lot for the checker: the output `predict_history` is a registered value that only changes on a clock edge or on an asynchronous reset assertion. There is no combinational path from the inputs to the output. So the checker must treat `predict_history` as state, sample it after the posedge has settled, and compare it against the value the model predicts for that edge. Any test that reads the output mid-cycle and expects it to reflect the current inputs is wrong.

Power-up is not specified by the public spec beyond the asynchronous reset. The spec says `areset` is a positive-edge-triggered asynchronous reset that resets the history counter to zero. In practice, the checker should not assume any particular initial value before the first reset; the safe protocol is to assert `areset` at the start of the sequence, sample the edge, and confirm `predict_history == 0`. That establishes a known state. After that, every sampled edge must be explained by exactly one of three rules, applied in priority order.

The priority order is the crux. Asynchronous reset dominates everything: if `areset` is asserted at the sampled edge, the next `predict_history` is zero regardless of `predict_valid`, `predict_taken`, `train_mispredicted`, `train_taken`, or `train_history`. Absent reset, `train_mispredicted` dominates `predict_valid`. When `train_mispredicted` is high, the next state is `(train_history << 1) | train_taken` — a load of a supplied value, not a shift of the current register. This distinction is the single most useful thing for the checker to probe. If the checker drives `train_history` equal to `predict_history`, a buggy "shift the current history" implementation would coincidentally match, so the checker must choose `train_history` patterns that differ from the current register in many bits. When only `predict_valid` is high, the next state is `(predict_history << 1) | predict_taken`. When neither is high, the register holds.

The combined-edge case is the highest-value probe because it exercises the priority rule and the load semantics at once. Worked example: let `predict_history = 0x0000_0001`, `predict_valid = 1`, `predict_taken = 1`, `train_mispredicted = 1`, `train_history = 0x0000_0003`, `train_taken = 0`, `areset = 0`. The correct next state is `(0x3 << 1) | 0 = 0x0000_0006`. A prediction-first-then-load implementation that shifts the current history would land on `0x0000_0003`; an implementation that ignores `train_history` and shifts `predict_history` would land elsewhere again. These candidate values are distinct, so one edge discriminates among the plausible bugs. The checker should also include a variant with `areset = 1` on the same combined edge and expect zero, catching implementations that let training override reset or that only clear the LSB.

Finally, note the bit ordering: `predict_history[0]` is the youngest branch direction, so new bits enter at bit 0 and the shift is toward higher indices. A checker that reverses this will fail the shift probes even when priority is correct.
