## Reset and power-up behavior

The specification defines `areset` as a positive-edge-triggered asynchronous reset that clears the 32-bit global history register to zero. Two properties matter for the checker: the reset is *asynchronous*, so it takes effect without waiting for a clock edge, and it is *dominant*, so it overrides any simultaneous prediction or misprediction activity on the same edge.

At power-up, before any clock edge and before `areset` has been asserted, the register contents are not specified by the public contract. The checker should therefore not assume a particular initial value; it should either drive `areset` first to establish a known zero state, or treat the first sampled value as an opaque starting point and only compare subsequent transitions. Relying on an implicit zero at time zero is a common source of false failures, because a real implementation may power up to an arbitrary value and the spec only guarantees zero *after* reset.

The asynchronous nature means the checker must be careful about when it samples. The protocol states that inputs are driven before the sampled edge and that the sample occurs after the posedge has settled. If `areset` is asserted between edges, the register should already read zero at the next sample even if no clock edge intervened. A checker that only verifies reset on a clocked edge will miss a purely asynchronous reset path, but a checker that asserts `areset` mid-cycle and samples before the next edge will catch it. The safest stimulus is to assert `areset` while the clock is idle, allow the asynchronous clear to propagate, and then sample.

Reset dominance is the second key point. When `areset = 1` coincides with `predict_valid = 1` and/or `train_mispredicted = 1`, the next sampled `predict_history` must be zero regardless of `predict_taken`, `train_taken`, or `train_history`. This is a distinct behavior from the predict/mispredict precedence rule: misprediction beats prediction, but reset beats both. A checker should include an edge where all three control signals are high and confirm the output is exactly zero, not a shifted or loaded value.

A useful worked example: suppose the register holds some nonzero `H`, and on one sampled edge the testbench drives `areset = 1`, `predict_valid = 1`, `predict_taken = 1`, `train_mispredicted = 1`, `train_history = X`, `train_taken = 0`. The correct next `predict_history` is `32'b0`. An implementation that lets misprediction load `{X, 1'b0}` would fail this check, as would one that shifts in `predict_taken`. This single edge isolates reset dominance from the other precedence rules.

For the final checker, the highest-value reset stimuli are: (1) an asynchronous assertion between edges with no clock activity, verifying the register clears without a posedge; (2) a reset edge coincident with prediction and misprediction, verifying dominance; and (3) a post-reset prediction edge, verifying that the first shift after reset inserts `predict_taken` at bit 0 and that the upper bits are zero. Vary the timing of `areset` relative to the clock so that a purely synchronous reset implementation is exposed. Finally, avoid assuming any particular power-up value; always establish state via reset or via a known transition before comparing.
