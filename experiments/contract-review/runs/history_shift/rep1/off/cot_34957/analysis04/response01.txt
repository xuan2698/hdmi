The public interface is a single 32-bit state register with a small set of one-bit controls and a 32-bit training-history input. The output `predict_history` is exactly 32 bits wide, so every update must be interpreted modulo 2^32: left shifts discard the old bit 31, and the inserted bit becomes bit 0. The one-bit inputs (`areset`, `predict_valid`, `predict_taken`, `train_mispredicted`, `train_taken`) are Boolean controls; their boundary values are simply 0 and 1. `train_history` is a full 32-bit vector, so its boundary values include all-zero, all-one, and values with only bit 31 or only bit 0 set. Those extremes are useful for catching accidental sign extension, width truncation, or a mistaken shift direction.

The important checker point is that the state is not specified before reset or before the first sampled edge establishes it. The reference model should not invent a power-up value such as zero unless a reset has actually been observed. Instead, it should initialize from the first post-reset sampled result, or otherwise treat the first sampled edge as establishing state. This matters because the public specification only defines behavior through `areset` and through sampled updates; it does not promise any particular initial contents.

For each sampled non-reset edge, priority is strict: misprediction first, then prediction, then hold. If `train_mispredicted` is 1, the next state is `(train_history << 1) | train_taken`, truncated to 32 bits. This is a load, not a shift of the current `predict_history`; the current register value is irrelevant on that edge. The concatenation means `train_taken` becomes new bit 0 and the 32-bit `train_history` is shifted upward, with its old bit 31 discarded. If `train_mispredicted` is 0 and `predict_valid` is 1, the next state is `(predict_history << 1) | predict_taken`, again truncated to 32 bits. If neither control is asserted, the register holds. When both `train_mispredicted` and `predict_valid` are 1, the misprediction path wins and the prediction is ignored.

Reset is asynchronous and positive-edge triggered. The checker should give reset precedence over all other inputs at a sampled edge, and should not let a mid-cycle change to `areset` retroactively alter the just-sampled result. More generally, only the input values present at the sampled edge govern that edge; optional mid-cycle changes apply to the next row. This deferral rule is especially important for reset and for simultaneous prediction/misprediction cases.

A short worked example: with current history `0x0000_0001`, a sampled edge with `predict_valid=1`, `predict_taken=1`, and no misprediction yields `0x0000_0003`. If instead that edge has `train_mispredicted=1`, `train_taken=0`, and `train_history=0x0000_0003`, the misprediction wins and the next value is `0x0000_0006`. The checker should encode reset first, then misprediction, then prediction, then hold, while deferring mid-cycle input changes to the next row.
