The register is a single 32-bit state element, `predict_history`, updated only on the rising edge of `clk` (with the asynchronous-reset exception). Its next-state function has three mutually exclusive cases, evaluated in strict priority order: asynchronous reset dominates everything; misprediction training dominates prediction; prediction-only shifts; otherwise hold.

**Priority 1 — asynchronous reset.** `areset` is positive-edge triggered and asynchronous, so it is not gated by `clk`. Whenever `areset` is high, the register is forced to `32'h0000_0000`. This must hold even if `areset` is asserted mid-cycle (after a sampling edge, before the next posedge): the very next sample must show zero. Crucially, reset also dominates the two update controls. If `areset` coincides with `predict_valid`, with `train_mispredicted`, or with both, the result is still zero — not a shifted value, not a `train_history` load. Random stimulus rarely aligns reset with an update control on the same edge, so the checker must deliberately construct these coincident vectors; they are the highest-value reset tests.

**Priority 2 — misprediction training.** When `areset` is low and `train_mispredicted` is high, the register loads the post-branch history: `{train_history[30:0], train_taken}`. That is, the 32-bit `train_history` (history before the mispredicted branch) is shifted left by one, its old MSB dropped, and `train_taken` inserted at bit 0. This is a *load*, not a shift of the current register contents — a common bug is to shift `predict_history` instead of using `train_history`. Because misprediction has priority over prediction, if `predict_valid` is also high on the same edge, the prediction is ignored entirely (the pipeline flush discards the in-flight prediction). The checker should include a coincident predict-plus-misprediction vector to confirm this dominance.

**Priority 3 — prediction shift.** When `areset` and `train_mispredicted` are both low and `predict_valid` is high, the register shifts left by one and inserts `predict_taken` at bit 0: `{predict_history[30:0], predict_taken}`. Bit 0 is the youngest branch direction. A prediction-only vector issued right after reset cleanly exposes MSB-insertion bugs, since the expected value is `predict_taken` in bit 0 with zeros above.

**Priority 4 — hold.** With all controls low, the register retains its value; no spurious update may occur.

**Mid-cycle changes.** `predict_*` and `train_*` may change between edges; those changes must not affect the register until the next posedge. The checker should model the value sampled just after each posedge as authoritative and must not let mid-cycle glitches on update controls leak into its expected state. The sole exception is `areset`, which acts immediately wherever asserted.

**Worked example.** Register `32'hFFFF_FFFF`, `train_history = 32'h0000_0000`, `train_taken = 1`, only `train_mispredicted` high: correct next value is `32'h0000_0001`. A shift-of-current bug yields `32'hFFFF_FFFF` or `32'hFFFF_FFFE`, cleanly separating load-from-history from shift-current.

**Checker guidance.** Never assume a power-up value; establish state via reset or a known transition first. Then exercise: mid-cycle reset sampling, reset coincident with each/both update controls (expect zero), prediction-only after reset, misprediction-only with `train_history` bit 31 differing from expected bit 0, an all-low hold edge, and a coincident predict-plus-misprediction edge.
