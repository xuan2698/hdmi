The public spec defines a 32-bit global branch history register with three mutually prioritized update modes, sampled after each posedge of `clk`. The final Python checker should concentrate on priority resolution and on the exact bit-level construction of the next state, because those are where a plausible-looking implementation most easily diverges from the specification.

The priority order is unambiguous. Asynchronous reset (`areset`) dominates everything: it is positive-edge triggered and asynchronous, so it must clear the register to zero without waiting for a clock edge. Next, `train_mispredicted` dominates `predict_valid`; when both are asserted on the same edge, the misprediction path wins because the pipeline flush also removes the branch currently making the prediction. Only when `train_mispredicted` is low does `predict_valid` matter, and only when both are low does the register hold.

The two active update formulas are distinct and must not be conflated. A prediction edge computes `{predict_history[30:0], predict_taken}`: the predicted direction enters at bit 0 (the youngest branch), and the old bit 31 is discarded. A misprediction edge computes `{train_history[30:0], train_taken}`: the register is overwritten from the supplied pre-branch history plus the actual branch result, and the current `predict_history` is entirely irrelevant. In particular, `train_history[31]` is dropped, `train_history[30:0]` shifts up one position, and `train_taken` becomes bit 0. An implementation that instead shifts the current register, or that concatenates `train_history` with `predict_taken`, would pass many random tests but fail a targeted misprediction check.

A short worked example illustrates the rollback formula. Suppose the current register is `32'hA5A5_5A5A`, and on an edge `areset=0`, `train_mispredicted=1`, `predict_valid=1`, `predict_taken=1`, `train_history=32'h0000_0003`, `train_taken=0`. The misprediction wins, so the next value is `{32'h0000_0003[30:0], 1'b0} = 32'h0000_0006`. The prediction inputs are ignored. If `areset=1` on that same edge, the next value is `32'h0000_0000` regardless of the other inputs.

For the checker, the highest-value distinguishing sequences are: (1) assert `areset` between clock edges with no clock activity and confirm the register is already zero before the next posedge, which exposes synchronous-only reset logic; (2) drive a coincident reset-plus-predict-plus-mispredict edge and require zero; (3) after reset, drive a prediction edge and require `predict_taken` in bit 0 with the upper 31 bits zero; (4) drive a misprediction-only edge with a `train_history` whose bit 31 differs from bit 0 of the expected result, confirming the exact concatenation order and the dropped top bit; and (5) drive a hold edge with all controls low and confirm no spurious update. Vary reset timing relative to the clock, and never assume a power-up value—establish state through reset or a known transition before comparing.
