The timing analysis centers on three distinct sampling concerns: the clock edge, the asynchronous reset, and the mid-cycle input changes that the protocol allows.

**Edge behavior.** All state updates are synchronous to the rising edge of `clk`. The checker samples `predict_history` after the posedge has settled, so the value it observes reflects the register state *after* any update triggered by that edge. Inputs (`predict_valid`, `predict_taken`, `train_mispredicted`, `train_taken`, `train_history`) are driven before the sampled edge and are stable across it. The update rule is a priority mux: if `train_mispredicted` is high, load `{train_history[30:0], train_taken}` (i.e., the pre-branch history with the actual outcome appended at the LSB, top bit dropped); else if `predict_valid` is high, shift left and insert `predict_taken` at bit 0; else hold. Misprediction priority matters because a flush discards the in-flight prediction, so the loaded history must reflect the *actual* branch, not the speculative one.

**Asynchronous reset.** `areset` is positive-edge triggered and asynchronous, so it must clear the register immediately, independent of `clk`. The checker should assert `areset` at a time clearly away from any posedge and sample `predict_history` *before* the next posedge to confirm the clear happened asynchronously. A synchronous-reset design would still show the old value in that window and fail. Reset must also dominate the update paths: a coincident reset-plus-predict-plus-mispredict edge must produce zero, not the concatenation or shift result. This is a priority question the checker must drive deliberately, since random stimulus rarely aligns all controls on one edge.

**Mid-input changes.** The protocol permits inputs to change after sampling and before the other edge, carrying into the next row. These mid-cycle transitions must not affect the register until the next posedge (except for `areset`, which acts immediately). The checker should therefore treat the value sampled after each posedge as authoritative and not let mid-cycle glitches on `predict_*`/`train_*` leak into the expected model.

**Worked example (load-vs-shift).** Current register `32'hFFFF_FFFF`, `train_history = 32'h0000_0000`, `train_taken = 1`, only `train_mispredicted` asserted. Correct next value is `{31'b0, 1'b1} = 32'h0000_0001`. A buggy "shift the current register" implementation yields `32'hFFFF_FFFF` or `32'hFFFF_FFFE`, so this single vector cleanly separates the two designs.

**Highest-value checker sequences.** (1) Asynchronous reset asserted between edges, sampled before the next posedge. (2) Coincident reset with both update controls, requiring zero. (3) Prediction-only after reset, requiring `predict_taken` at bit 0 and zeros above — this catches MSB-insertion bugs. (4) Misprediction-only with `train_history` chosen so its bit 31 differs from the expected bit 0, confirming exact concatenation and the dropped top bit. (5) A hold edge with all controls low, confirming no spurious update. (6) A coincident predict-plus-mispredict edge, confirming misprediction priority. Never assume a power-up value; establish state via reset or a known transition before comparing.
