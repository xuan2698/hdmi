The key discriminator for the final checker is the **load-versus-shift** distinction on a misprediction edge. The spec says the register is loaded with `(train_history << 1) | train_taken`, where `train_history` is the history *before* the mispredicted branch — not the current register contents. A plausible buggy implementation shifts the live `predict_history` instead of loading `train_history`. To catch that, the checker must drive `train_history` to a value deliberately different from the current `predict_history`; otherwise both implementations coincide and the bug hides.

Worked example: let `predict_history = 0x0000_0001`, `predict_valid = 1`, `predict_taken = 1`, `train_mispredicted = 1`, `train_history = 0x0000_0003`, `train_taken = 0`, `areset = 0`. Correct next state is `(0x3 << 1) | 0 = 0x0000_0006`. A prediction-first-then-load implementation that shifts the current history lands on `0x0000_0003`; an implementation ignoring `train_history` lands elsewhere again. One edge discriminates among plausible bugs.

Also worth probing: the combined reset+prediction+misprediction edge should yield zero, catching implementations that let training override reset or that only clear the LSB. And a prediction-only edge confirms `predict_taken` lands at bit 0 (shift direction).
