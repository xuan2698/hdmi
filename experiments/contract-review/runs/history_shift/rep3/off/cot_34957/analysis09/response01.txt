The design is a single 32-bit global branch-history register with one asynchronous override and two edge-sampled update modes. The register value is exposed directly as `predict_history`; there is no separate output register or combinational transformation. All behavior is therefore determined by how the 32-bit state is updated at a sampled clock edge or by an asynchronous reset assertion.

The asynchronous reset has highest priority and is not merely a synchronous input. When `areset` is asserted, the history register is forced to zero immediately, independent of `clk`. If `areset` is asserted between sampled edges, the state becomes zero at that moment, and the next sampled edge starts from zero. A checker must model this as an override rather than as a value sampled only at the edge; otherwise a stale nonzero history could survive into the next sample. When `areset` is not asserted, the state evolves only at the sampled positive clock edge.

At a sampled edge with `areset` deasserted, the update priority is: misprediction training first, prediction second, hold otherwise. If `train_mispredicted` is asserted, the register is loaded with the post-completion history of the mispredicted branch. That value is formed by taking `train_history`, dropping its oldest bit, shifting left by one, and inserting `train_taken` at the least-significant bit. In bit terms this is `{train_history[30:0], train_taken}`. This restores the history to what it should be after the actual branch outcome, discarding any younger speculative history that may have been shifted in.

If `train_mispredicted` is not asserted but `predict_valid` is asserted, the register shifts in the predicted direction. The new value is `{predict_history[30:0], predict_taken}`. Here `predict_history[0]` is the youngest branch direction, so shifting left moves older bits toward higher indices and inserts the new prediction at bit 0. If neither `train_mispredicted` nor `predict_valid` is asserted, the register holds its current value.

The critical priority case is when both `train_mispredicted` and `predict_valid` are asserted at the same sampled edge. The misprediction must win, because the pipeline flush also removes the branch currently making the prediction. Thus the edge update is equivalent to: if `train_mispredicted`, load `{train_history[30:0], train_taken}`; else if `predict_valid`, shift in `predict_taken`; else hold. A checker that applies the prediction shift first and then overwrites with training, or that uses an `if predict_valid ... elif train_mispredicted ...` chain, will compute the wrong value in this coincident case. The checker should sample after the positive edge has settled, carry any mid-row input changes to the start of the next row, and ensure that a prediction coincident with a misprediction never corrupts the restored history.

A short worked example: start with history zero. At one sampled edge, `predict_valid=1` and `predict_taken=1`, so history becomes `32'h0000_0001`. At the next row, suppose `train_mispredicted=1`, `train_taken=0`, `train_history=32'h0000_0001`, and also `predict_valid=1`, `predict_taken=1`. Misprediction wins, so the next history is `{32'h0000_0001[30:0], 1'b0} = 32'h0000_0002`, not the prediction-shifted value. If `areset` is asserted mid-row instead, the register becomes zero immediately, and the next sampled edge begins from zero. No extra state beyond the 32-bit register is required.
