The public spec defines a 32-bit global branch history shift register with three edge-sampled behaviors and one asynchronous override. The key timing distinction is between inputs sampled at the posedge and mid-row input changes that occur after sampling but before the next edge. The checker must model the register as a single 32-bit state updated at each sampled posedge, with `areset` acting immediately and asynchronously.

At a sampled posedge, the next-state priority is fixed by the spec. If `train_mispredicted=1`, the register is loaded with the history after the mispredicted branch: `{train_history[30:0], train_taken}`. This is the concatenation of the pre-branch history with the actual branch outcome, and it takes precedence over any simultaneous prediction. If `train_mispredicted=0` and `predict_valid=1`, the register shifts left by one and inserts `predict_taken` at the LSB, so `predict_history[0]` is the youngest branch direction. If neither is asserted, the register holds its value. The asynchronous reset `areset` overrides all of these: when high, the history becomes zero immediately, independent of the clock edge.

The most important subtlety for the final Python checker is the priority of misprediction over prediction. The spec explains that a pipeline flush caused by a misprediction also flushes the branch currently making a prediction, so the prediction must not affect the restored history. A checker that applies the prediction shift first and then conditionally overwrites with training, or that uses an `if predict_valid ... elif train_mispredicted ...` chain, will produce a wrong value when both are asserted. The correct order is: asynchronous reset first, then `train_mispredicted`, then `predict_valid`, then hold.

A second subtlety is reset timing. Because `areset` is positive-edge-triggered asynchronous, it is not merely another synchronous input sampled at the clock edge. If `areset` is asserted mid-row, after the sampled edge and before the next edge, the register should become zero immediately, and the next sampled edge should begin from zero. Treating reset only as a synchronous input can leave a stale nonzero history at the next sample.

A short worked example: start with history zero. At one sampled edge, `predict_valid=1`, `predict_taken=1`, so history becomes `32'h0000_0001`. At the next row, suppose `train_mispredicted=1`, `train_taken=0`, `train_history=32'h0000_0001`, and also `predict_valid=1`, `predict_taken=1`. Misprediction wins, so the next history is `{32'h0000_0001[30:0], 1'b0} = 32'h0000_0002`, not the prediction-shifted value. If `areset` is asserted mid-row instead, the register should immediately become zero, and the next sampled edge should begin from zero.

For the final Python checker, the useful focus is therefore to separate the asynchronous reset override from the edge-sampled priority function, and to verify the exact priority order `train_mispredicted` over `predict_valid` over hold. The checker should sample after the posedge has settled, carry any mid-row input changes to the start of the next row, and ensure that a prediction coincident with a misprediction never corrupts the restored history. No extra state beyond the 32-bit register is required.
