**Reset and power-up behavior**

The only reset in this design is `areset`, a positive-edge-triggered asynchronous reset. Its effect is unconditional and immediate: whenever `areset` is asserted, the 32-bit global history register is forced to zero, independent of `clk`, `predict_valid`, `predict_taken`, `train_mispredicted`, `train_taken`, or `train_history`. Because the reset is asynchronous, it does not wait for a clock edge; the clearing takes effect as soon as the reset is active. This matters for the checker because a reset asserted between sampled edges must still be reflected in the state seen at the next sample. In particular, if `areset` is asserted after one sampled edge and before the next, the register is zero at the start of the next row, and any prediction or training inputs in that row operate from zero rather than from the previously held history.

Power-up is not separately specified beyond this reset. The public specification gives no defined initial value for the history register in the absence of `areset`; the only guaranteed initialization path is assertion of `areset`. A checker should therefore not assume a particular power-up value unless the testbench drives `areset` first. The safe interpretation is that all meaningful checks begin after a reset has established the zero state, and that any pre-reset value is unspecified. This is a useful point for the final Python checker: model the register as a single 32-bit state variable whose value is only guaranteed after `areset`, and drive `areset` at the start of sequences that depend on a known history.

When `areset` is not asserted, the register updates only at a sampled positive clock edge, following a strict priority order. `train_mispredicted` has highest priority: when asserted, the register loads `{train_history[30:0], train_taken}`, which is the pre-misbranch history shifted left by one with the actual branch outcome inserted at the LSB. Next, if `train_mispredicted` is not asserted and `predict_valid` is asserted, the register shifts left and inserts `predict_taken` at the LSB, giving `{predict_history[30:0], predict_taken}`. If neither is asserted, the register holds its value. The coincident case `train_mispredicted = 1` and `predict_valid = 1` must resolve to the misprediction update, because the pipeline flush also flushes the branch currently making a prediction. A checker that applies the prediction shift first, or that orders `predict_valid` above `train_mispredicted`, will diverge exactly in this case.

**Short worked example.** Start from history zero after reset. At one sampled edge with `predict_valid = 1`, `predict_taken = 1`, history becomes `32'h0000_0001`. At the next row, let `train_mispredicted = 1`, `train_taken = 0`, `train_history = 32'h0000_0001`, and also `predict_valid = 1`, `predict_taken = 1`. Misprediction wins, so the next history is `{32'h0000_0001[30:0], 1'b0} = 32'h0000_0002`, not the prediction-shifted value. If `areset` is asserted mid-row instead, the register becomes zero immediately and the next sampled edge begins from zero.

For the final checker, the useful point is to model the register as a single 32-bit state updated by the strict priority chain reset, then `train_mispredicted`, then `predict_valid`, then hold, and to verify the coincident prediction-plus-misprediction case explicitly. No state beyond the 32-bit register is required.
