The public interface is a single 32-bit global branch-history register with one clock, one asynchronous active-high reset, and five one-bit control/data inputs plus a 32-bit training-history bus. All control signals (`areset`, `predict_valid`, `predict_taken`, `train_mispredicted`, `train_taken`) are one bit wide, so their only legal values are 0 and 1; there is no multi-bit encoding to decode. `train_history` and `predict_history` are both exactly 32 bits wide, so every legal value lies in `0` through `2^32 - 1`. The output `predict_history` is the current contents of the register, and `predict_history[0]` is defined as the direction of the youngest branch, with older entries occupying higher indices.

The boundary behavior that matters most for a checker is the simultaneous-assertion case. The specification states that when `train_mispredicted = 1`, the register is loaded with the history after the mispredicted branch, namely `train_history` shifted left by one with `train_taken` inserted at the least significant bit: `{train_history[30:0], train_taken}`. When only `predict_valid = 1`, the register shifts in `predict_taken` at the LSB: `{predict_history[30:0], predict_taken}`. When neither is asserted, the register holds. When both are asserted at the same sampled edge, the misprediction takes precedence, because the pipeline flush also removes the branch currently making the prediction. Therefore the correct priority is: `train_mispredicted` first, then `predict_valid`, then hold. A checker that orders `predict_valid` before `train_mispredicted`, or that applies the prediction shift and then overwrites with training, will disagree with the specification in exactly this coincident case.

The reset is asynchronous and positive-edge triggered, resetting the history counter to zero. Because it is asynchronous, an asserted `areset` forces the register to zero without waiting for a clock edge; the checker should treat reset as dominating all other inputs. Sampling is specified after the positive edge has settled, and optional mid-row input changes occur after sampling and before the other edge, carried to the start of the next row. This means the checker must not let a mid-row change retroactively alter the value sampled at the preceding edge.

A short worked example illustrates the priority. Start from history zero. At one sampled edge with `predict_valid = 1` and `predict_taken = 1`, the history becomes `32'h0000_0001`. At the next row, let `train_mispredicted = 1`, `train_taken = 0`, `train_history = 32'h0000_0001`, and also `predict_valid = 1`, `predict_taken = 1`. Misprediction wins, so the next history is `{32'h0000_0001[30:0], 1'b0} = 32'h0000_0002`, not the prediction-shifted value. If `areset` is asserted mid-row instead, the register becomes zero immediately and the next sampled edge begins from zero.

For the final Python checker, the useful point is to encode the update as a strict priority chain — reset, then `train_mispredicted`, then `predict_valid`, then hold — and to verify the coincident case explicitly, since that is the only place where a plausible but incorrect ordering produces a different 32-bit result. No state beyond the 32-bit register is required.
