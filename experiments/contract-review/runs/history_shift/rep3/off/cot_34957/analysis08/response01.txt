The public specification defines a 32-bit global branch history shift register with two distinct update mechanisms and an asynchronous reset. The register holds the direction history of recent branches, with `predict_history[0]` representing the youngest branch. On a normal prediction (`predict_valid = 1`), the register shifts left by one bit and inserts `predict_taken` at the LSB, so the new value is `{predict_history[30:0], predict_taken}`. On a misprediction recovery (`train_mispredicted = 1`), the register is loaded with the post-completion history: the pre-branch history `train_history` shifted left by one with the actual outcome `train_taken` inserted at the LSB, i.e. `{train_history[30:0], train_taken}`. The specification explicitly states that when both a prediction and a misprediction occur simultaneously, the misprediction takes precedence, because the pipeline flush also flushes the branch currently making the prediction. Thus the prediction must not perturb the restored history in that cycle.

Reset behavior is the other critical axis. `areset` is described as a positive-edge-triggered asynchronous reset that clears the history counter to zero. This means reset is not simply another synchronous input sampled at the clock edge; it is an override that takes effect when asserted, independent of the clock. If `areset` is asserted mid-row—after one sampled edge and before the next—the register should become zero immediately, and the next sampled edge should begin from that zero state. A checker that treats `areset` only as a synchronous input sampled at the edge can leave a stale nonzero history at the next sample, which would be incorrect.

For the final Python checker, the useful focus is to separate the asynchronous reset override from the edge-sampled priority function. The correct evaluation order is: first, if `areset` is asserted, force the history to zero; otherwise, at the sampled edge, apply `train_mispredicted` before `predict_valid`, and hold if neither is asserted. Equivalently, the edge update is `train_mispredicted ? {train_history[30:0], train_taken} : predict_valid ? {predict_history[30:0], predict_taken} : predict_history`. A checker that applies the prediction shift first and then conditionally overwrites with training, or that uses an `if predict_valid ... elif train_mispredicted ...` chain, will produce a wrong value when both are asserted. The checker should sample after the posedge has settled, carry any mid-row input changes to the start of the next row, and ensure that a prediction coincident with a misprediction never corrupts the restored history.

A short worked example illustrates both subtleties. Start with history zero. At one sampled edge, `predict_valid=1`, `predict_taken=1`, so history becomes `32'h0000_0001`. At the next row, suppose `train_mispredicted=1`, `train_taken=0`, `train_history=32'h0000_0001`, and also `predict_valid=1`, `predict_taken=1`. Misprediction wins, so the next history is `{32'h0000_0001[30:0], 1'b0} = 32'h0000_0002`, not the prediction-shifted value. If instead `areset` is asserted mid-row, the register should immediately become zero, and the next sampled edge should begin from zero. No extra state beyond the 32-bit register is required.
