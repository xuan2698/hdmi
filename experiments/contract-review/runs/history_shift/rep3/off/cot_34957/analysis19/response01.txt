The public spec defines a single 32-bit architectural state, `predict_history`, updated only on the rising edge of `clk` (with asynchronous reset). The checker should therefore treat the sampled value after each posedge as the sole source of truth and avoid any temptation to model prediction and training as separate registers or as two sequential nonblocking assignments whose ordering happens to work. The priority is explicit: `areset` dominates; otherwise `train_mispredicted` dominates over `predict_valid`; otherwise `predict_valid` shifts; otherwise hold. The phrase "if both a prediction and misprediction occur at the same time, the misprediction takes precedence" is not merely a tie-break hint—it means the prediction's shift is semantically discarded, because the pipeline flush removes the branch that was predicting. A checker that computes the prediction shift and then overwrites with the misprediction load can accidentally match in many rows, but it is still the wrong model and will fail on vectors where the two operations would interact through intermediate state. The clean encoding is a single `if/elif/elif/else` chain over the sampled inputs.

Timing matters for the final checker because the spec says "sample after the posedge edge has settled" and that each row's values are driven before the sampled edge, with optional mid-input changes occurring after sampling and before the other edge, carried to the start of the next row. In practice this means the checker should evaluate the next-state function using the input values associated with the row whose posedge is being sampled, not values that change mid-cycle. Mid-cycle changes are not edges for this register; they only become relevant if they persist to the next sampled posedge. A common checker bug is to let a mid-input change leak into the current row's update, which can make a coincident prediction/misprediction row appear to behave differently depending on stimulus ordering rather than on the specified priority.

The misprediction load source is another high-value point. The spec says load with `train_history` concatenated with `train_taken`, i.e. `{train_history[30:0], train_taken}`. It does not say to use the current `predict_history`. When only `train_mispredicted` is asserted, these often coincide in simple tests, so a checker using `predict_history` can pass many rows. The divergence appears when a prediction is also valid, or when `train_history` intentionally differs from the current register to represent the pre-branch history. The final checker should therefore include at least one vector where `train_history` is not equal to the current `predict_history` and `train_mispredicted` is asserted, plus one coincident row.

Worked example: start at zero. A prediction with `predict_taken=1` yields `32'h0000_0001`. Later, assert `train_mispredicted=1`, `train_taken=0`, `train_history=32'h0000_0001`, and simultaneously `predict_valid=1`, `predict_taken=1`. Correct next state is `{32'h0000_0001[30:0], 1'b0} = 32'h0000_0002`; the prediction is suppressed. A checker that shifts first then loads, or that uses the current register instead of `train_history`, can produce a different word.

For the final Python checker, anchor the state machine on the four boundary words—zero, one, all-ones, and `32'h8000_0000`—to exercise insertion at bit 0, discard at bit 31, and wrap behavior, and include the coincident prediction-plus-misprediction vector as the decisive priority test.
