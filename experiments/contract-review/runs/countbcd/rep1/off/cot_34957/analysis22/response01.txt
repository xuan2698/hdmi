The public interface is a single clocked block with a 1-bit synchronous active-high `reset` input and two registered outputs: a 16-bit `q` and a 3-bit `ena`. The 16-bit `q` is partitioned into four 4-bit BCD digits, little-endian by significance: `q[3:0]` is the ones digit, `q[7:4]` the tens, `q[11:8]` the hundreds, and `q[15:12]` the thousands. Each nibble is a legal BCD digit only when its value is in 0–9; values 10–15 are illegal in normal (non-reset) rows. The 3-bit `ena` is indexed by digit position: `ena[0]` corresponds to the tens digit, `ena[1]` to the hundreds digit, and `ena[2]` to the thousands digit. There is no enable for the ones digit, since the ones digit increments on every normal clock.

Boundary behavior follows from BCD carry semantics. The ones digit always advances 0→1→…→9→0. A higher digit increments only when all lower digits are simultaneously 9. Thus `ena[0]` (tens enable) is high exactly when the ones digit is 9. `ena[1]` (hundreds enable) is high exactly when ones and tens are both 9. `ena[2]` (thousands enable) is high exactly when ones, tens, and hundreds are all 9. At `0x9999`, all three enables are high and the next normal value wraps to `0x0000`. Enables describe the current sampled row’s digits, not the carry that produced that row; they are the conditions under which the next increment will propagate into each upper digit.

Reset is synchronous and active-high: on a sampled rising edge with `reset` high, `q` becomes `0x0000` and `ena` becomes `000`. Reset rows are terminal for progression checking. The specification does not require the first normal row after reset to be zero, nor the first normal row of a trace to be zero; a trace may legally begin at any valid BCD value such as `0x0042`. Consequently the checker must not infer state from reset beyond the reset row’s own outputs.

The key checker point is to validate three independent properties per sampled row and one relational property between adjacent normal rows. First, reset rows must have `q == 0` and `ena == 0`. Second, every normal row must have all four nibbles ≤ 9, and its `ena` bits must equal the carry conditions derived from its own `q`: `ena[0] = (q[3:0]==9)`, `ena[1] = (q[3:0]==9 && q[7:4]==9)`, `ena[2] = (q[3:0]==9 && q[7:4]==9 && q[11:8]==9)`. Third, for consecutive normal rows A then B with no reset row between them, B must equal the BCD increment of A, with `0x9999` wrapping to `0x0000`. Reset rows break this chain in both directions: do not compare a normal row to a preceding reset row, and do not compare a reset row to its successor as if counting continued.

Worked example: a normal row at `0x0009` has ones=9, so `ena[0]=1`; tens=0 so `ena[1]=0`; hundreds=0 so `ena[2]=0`. The next normal row must be `0x0010`. At `0x0010`, no lower digit is 9, so all enables are 0. The carry is already reflected in `q`; enables on the second row describe that row’s digits.

The final Python checker should sample `q`, `ena`, and `reset` together at each rising edge, then apply reset validation, normal-row enable decoding, and normal-to-normal progression only across adjacent normal rows. It must not re-read `reset` after sampling, must not assume an initial zero state, and must not require a post-reset normal row to be zero. This avoids false failures around mid-cycle reset changes and carry-derived enables.
