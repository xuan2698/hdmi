The public interface is a 32-bit synchronous detector with a single-bit active-high synchronous reset. The input vector `in` is 32 bits wide, the output vector `out` is 32 bits wide, and `reset` is 1 bit. All state updates are sampled on the rising edge of `clk`, after the edge has settled. The output is per-bit sticky: once a falling transition (1 in the previous sampled cycle, 0 in the current sampled cycle) is captured for a bit, that bit of `out` remains 1 until a reset clears it. Reset has priority over capture and over baseline update.

The key boundary condition for the final Python checker is the distinction between sampled values and mid-row changes. Each row's driven values are established before the sampled edge. Optional mid-row input changes occur after sampling and before the next edge; those changes belong to the next row's pre-edge history, not to the current row's capture computation. A checker that compares a mid-row value against the current row's baseline will over-capture. The falling mask for a given edge must be computed only from the sampled `in` at that edge and the baseline established at the previous sampled edge.

A short worked example illustrates reset priority and persistence. Suppose at row N the sampled `in[0]` is 1 and reset is low. The baseline becomes 1 and no capture occurs. A mid-row change then drives `in[0]` to 0, but row N ignores it. At row N+1, reset is high and the sampled `in[0]` is 0. Reset wins: `out[0]` becomes 0, and the baseline becomes 0. The mid-row change creates no capture, and reset both clears and re-baselines the detector. If instead row N+1 had reset low, the sampled 0 would compare against baseline 1 and set `out[0]` to 1. On the following row, even if `in[0]` stayed 0, `out[0]` must remain 1 because the capture is sticky and no reset has occurred.

Power-up behavior is the remaining subtlety. The specification does not define the initial value of `prev_in` or the initial value of `out` before the first sampled edge. The checker should not assume that the first sampled edge can produce a definite falling-edge capture from an unknown prior baseline. If the first sampled edge has reset high, the expected output is zero and the baseline is established from the sampled input. If the first sampled edge has reset low, the checker should establish the baseline without demanding a definite capture from an unknown power-up state. Treating the initial output as known-zero, or inferring a capture from an unknown prior baseline, would produce false failures. The safe checker model is therefore: on the first sampled edge, initialize the baseline from the sampled `in`; if reset is high, expect `out` to be zero; if reset is low, do not require a specific capture from the unknown prior state. After that first edge, the baseline is known and the normal reset-priority and sticky-capture rules apply.
