The public specification defines a 32-bit falling-edge capture register with active-high synchronous reset. For each bit, the detector must remember the input value sampled on the previous clock edge and, on the current edge, capture a 1-to-0 transition by setting the corresponding output bit. Once set, an output bit remains 1 until a reset edge clears it. The output is therefore a sticky record of falling edges, not a pulse or a one-cycle event.

Reset behavior is the first thing the final checker should pin down. Because reset is synchronous and active high, it is evaluated only at a sampled clock edge, and it has priority over capture. On any sampled edge where reset is high, every output bit must be zero after the edge, regardless of what the input did on that edge. The same edge must also re-baseline the detector: the previous-sampled input for the next edge becomes the input sampled on the reset edge. This re-baselining matters because it prevents a transition that straddles the reset edge from being captured later as a phantom falling edge. If reset merely cleared the outputs but left the old baseline in place, a 1 sampled before reset followed by a 0 sampled after reset could produce a spurious capture on the next non-reset edge.

Power-up behavior is deliberately underspecified. The public spec does not state a value for the output before the first sampled edge, and it does not define a previous-input baseline before that edge. The checker should therefore avoid asserting any particular output value at time zero or before the first sampled edge. Comparison should begin at the first sampled edge, and even there the checker must respect reset priority: if reset is high at that first edge, expect zeros and establish the baseline from the sampled input; if reset is low, record the sampled input as the baseline and do not demand a definite captured output unless the testbench has explicitly established one. Treating the initial output as known-zero, or inferring a capture from an unknown power-up baseline, would create false failures.

The per-edge ordering is the most useful point for the final checker. On each sampled edge the correct sequence is: first apply reset priority, forcing outputs to zero and re-baselining to the current sampled input when reset is high; second, only when reset is low, compute the falling-edge mask from the previous sampled input and the current sampled input and OR it into the output; third, in all cases, advance the previous-sampled baseline to the current sampled input. Computing the mask before reset can leave a stale capture bit set on a reset edge or fail to advance the baseline, causing a spurious capture on the following edge. Advancing the baseline before computing the mask makes the mask zero and loses legitimate captures. The checker should encode this ordering explicitly rather than relying on incidental evaluation order.

A short worked example illustrates the interaction. At row N, reset is low, bit 0 is sampled as 1, and the output is unknown; the checker records the baseline as 1 and demands no capture. A mid-row change drives bit 0 to 0 after sampling, which is ignored for row N. At row N+1, reset is high and bit 0 is sampled as 0. Reset wins: the output bit becomes 0 and the baseline becomes 0. The mid-row change creates no capture, and reset both clears and re-baselines the detector.

For the final checker, the key invariant is to separate driven input from sampled input, apply reset first, compute the falling-edge mask only when reset is low, and advance the baseline in all cases.
