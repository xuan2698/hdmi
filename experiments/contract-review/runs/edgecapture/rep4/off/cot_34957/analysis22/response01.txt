The interface is a single-clock synchronous design with one-bit `reset`, 32-bit `in`, and 32-bit `out`; `clk` is the only clock. All state is sampled on the rising edge, and the specification says to sample after the posedge has settled. Each row’s driven values are present before the sampled edge; optional mid-cycle input changes occur after sampling and before the opposite edge, so they belong to the next row rather than the current one. The checker should therefore treat each row as one atomic sampled transition: read `reset` and `in`, compute the next state from the previous state, and commit `out` and the history register together.

The boundary values are straightforward but important. `reset` is active high and synchronous, so a high `reset` at a sampled edge clears `out` regardless of any simultaneous 1→0 transition on `in`. The 32-bit vectors are independent per bit; there is no cross-bit carry, masking, or priority among bits. The only per-bit history is the previous sampled `in` value, often called `prev_in`. The next `out` bit is zero when `reset` is high; otherwise it is the old `out` bit ORed with the fall term “old `prev_in` is 1 and new `in` is 0.” The next `prev_in` is exactly the newly sampled `in`, including when `reset` is high. That last point is the usual source of checker mistakes: reset clears `out` but does not freeze or clear history to an assumed value other than the sampled `in`.

A useful focus for the final Python checker is reset-adjacent edges treated as ordinary sampled transitions with reset priority. Consider a bit with `prev_in=1`, `out=0`. At edge 1, `reset=1`, `in=0`: next `out=0`, `prev_in=0`. At edge 2, `reset=0`, `in=0`: next `out=0`, `prev_in=0`; there is no fabricated fall. At edge 3, `reset=0`, `in=1`: next `out=0`, `prev_in=1`. At edge 4, `reset=0`, `in=0`: next `out=1`, `prev_in=0`; the genuine fall is captured. This short trace distinguishes correct reset priority and correct history loading from two common bugs: keeping stale `prev_in=1` after reset, which can falsely assert a fall on a later zero, and failing to load a rise after reset, which can suppress a later genuine fall.

Power-up values are outside the public behavior to validate. The checker should not assume any particular initial `out` or `prev_in` beyond what the testbench establishes before the first sampled edge. It should also ignore asynchronous reset behavior and mid-cycle changes, since those changes occur after sampling and are carried to the start of the next row. The invariant to enforce is: at every sampled edge, `prev_in` becomes exactly the sampled `in`; `out` is cleared if `reset` is high; otherwise `out` is the old `out` ORed with the old-`prev_in`/new-`in` fall term.
