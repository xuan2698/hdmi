The interface is a single-clock synchronous block with one-bit `reset`, 32-bit `in`, and 32-bit `out`. All 32 bits are independent and share the same clock and reset. The only state beyond `out` is a 32-bit history register, `prev_in`, which is not a port but is essential to the behavior. Because `reset` is active-high synchronous, it is evaluated at the same edge as the input sample, not as an asynchronous override between edges.

The natural per-bit next-state equations are: `next_out = reset ? 0 : (out | (prev_in & ~in))`, and `next_prev_in = in`. Both assignments must be understood as simultaneous at the sampled edge. The checker should sample `reset` and `in` once per row, compute the next state from the old `out` and old `prev_in`, and only then commit both updates. It should not allow the capture term to be applied after a reset clear, nor allow `prev_in` to remain stale across a reset edge.

The reset-dominance issue is the most likely source of divergence. If `prev_in=1`, `out=0`, and a sampled edge has `in=0` with `reset=1`, the correct next state is `out=0`, `prev_in=0`. The falling transition is not captured because reset takes priority. A checker that computes `out | (prev_in & ~in)` first and then clears on reset is correct only if the clear is applied last; if it clears first and then applies capture, it yields `out=1`, which is wrong. Similarly, a checker that clears `out` on reset but fails to load `prev_in` with the current `in` leaves stale history. If `in` remains 0 on the next non-reset edge, that stale `prev_in=1` fabricates a fall that actually occurred during the reset edge. Conversely, if `in` rises immediately after reset, stale history can suppress a genuine later fall.

The final checker should therefore treat reset-adjacent edges as ordinary sampled transitions with reset priority, and should include traces where a 1-to-0 input change coincides with reset, where reset is followed immediately by another 0, and where reset is followed by a rise then fall. It should ignore power-on values, asynchronous reset behavior, and mid-cycle changes, since the spec says mid-cycle input changes occur after sampling and are carried to the start of the next row. The useful invariant is: at every sampled edge, `prev_in` becomes exactly the sampled `in`, and `out` is cleared if `reset` is high, otherwise it is the old `out` ORed with the old-`prev_in`/new-`in` fall term.
