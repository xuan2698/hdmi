The key distinguishing scenario for the checker is a reset cycle that coincides with a falling edge on some input bit. Because reset has priority over capture, `out` must be cleared to zero even though `prev_in & ~curr_in` would otherwise be 1 for that bit. A checker that computes capture first and then applies reset, or that skips the history update on reset, will diverge from the spec on exactly this case.

Consider one bit: at posedge N, `in[0]=1`, `out[0]=0`, `reset=0`. History becomes 1. At posedge N+1, `in[0]=0` and `reset=1`. The correct result is `out[0]=0` (reset wins), and history becomes 0. A naive checker that ORs in the capture before resetting would produce `out[0]=1` at that edge, which is wrong. Equally, a checker that leaves history at 1 on the reset cycle would then fail to capture a later genuine fall from 1 to 0, since it would think the bit was already 0.

The second useful point is that mid-cycle activity must be ignored entirely. The checker should sample `in` and `reset` only at the post-posedge instant and never derive transitions from changes between edges. A 1→0→1 glitch between posedges must not set `out`, and a bit that is 1 at one sampled edge and 0 at the next must capture regardless of what happened in between. This means the checker's state should be updated once per sampled edge, using only the sampled values, with no event-driven intermediate updates.

The third point is that `prev_in` must be updated on every sampled edge, including reset edges, after the output update. The order is strictly: apply reset to `out`, then apply capture to `out` for non-reset bits, then replace `prev_in` with the current sampled `in`. Since reset forces `out` to zero for all bits, the capture term is irrelevant on reset cycles, but the history replacement still matters for the next cycle's fall detection.

Finally, the checker must compare the full 32-bit `out` vector at each sampled edge, not just individual bits, because the public interface exposes a 32-bit output. Per-bit reasoning is valid for deriving expected values, but the comparison should be vector-wide to catch any bit-position or masking error. There is no asynchronous or power-on reset in the public spec, so the checker should not model one; the only clearing mechanism is a sampled `reset=1`.
