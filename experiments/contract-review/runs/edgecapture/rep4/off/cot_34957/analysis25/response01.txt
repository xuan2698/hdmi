The public specification defines a 32-bit synchronous fall detector with an active-high synchronous reset. At each rising clock edge, the checker samples `reset` and `in`, then computes the next state. For each bit, a fall is detected when the previous sampled input bit was 1 and the current sampled input bit is 0. When a fall is detected, the corresponding output bit is set to 1 and remains 1 until reset clears it. Reset has priority over fall detection, so if `reset` is high at a sampled edge, all output bits become 0 regardless of any 1→0 transitions on `in`.

The critical timing point for the final Python checker is that `prev_in` must always be updated with the sampled `in` value at every edge, including edges where `reset` is high. The specification does not say that reset clears or preserves the previous-input history in any special way. It only says that reset clears the output. Therefore, the history register must follow the input unconditionally. A checker that clears `out` on reset but leaves `prev_in` unchanged, or that forces `prev_in` to zero on reset, will diverge from the specification on the next edge.

A short worked example for one bit illustrates this. Suppose before edge 1, `prev_in=1` and `out=0`. At edge 1, `reset=1` and `in=0`. Because reset has priority, the next `out` is 0, not 1, even though there is a 1→0 transition on `in`. The next `prev_in` is 0, the sampled `in`. At edge 2, `reset=0` and `in=0`: `out` remains 0 and `prev_in` remains 0. At edge 3, `reset=0` and `in=1`: `out` remains 0 and `prev_in` becomes 1. At edge 4, `reset=0` and `in=0`: now the genuine fall is captured, so `out` becomes 1 and `prev_in` becomes 0.

This trace distinguishes correct behavior from two common checker bugs. First, if the checker keeps stale `prev_in=1` through the reset edge, then at edge 2 it would see old `prev_in=1` and new `in=0` and falsely set `out=1`. Second, if the checker fails to load the rise at edge 3, then at edge 4 it would see old `prev_in=0` and miss the genuine fall, leaving `out=0`. Both errors are reset-adjacent and are easy to expose with a short directed sequence rather than random vectors.

The checker should treat every sampled edge uniformly: read `reset` and `in`, compute the next `out` as zero if `reset` is high, otherwise old `out` ORed with the per-bit fall term, and always set `prev_in` to the sampled `in`. It should not assume power-up values for `out` or `prev_in`; those must be established by the testbench before the first sampled edge. It should also ignore asynchronous reset behavior and mid-cycle input changes, since those occur after sampling and are carried to the start of the next row. The public invariant is per-bit and independent across the 32 lanes: no cross-bit masking, priority, or carry.
