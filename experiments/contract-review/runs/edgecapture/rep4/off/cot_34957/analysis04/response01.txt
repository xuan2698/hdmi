The interface is a single-clock synchronous design with one 1-bit control input and two 32-bit data vectors. `reset` is 1 bit wide and is an active-high synchronous reset sampled at the clock edge. `in` is 32 bits wide, one independent bit per detector channel. `out` is also 32 bits wide, with bit *i* corresponding to `in[i]`. There is one clock, `clk`, and all sampling is specified at the post-posedge point after the edge has settled. No other ports, enables, or asynchronous controls are part of the public interface.

Boundary values follow directly from those widths. `reset` can only be 0 or 1; there is no multi-bit reset encoding and no active-low interpretation. `in` and `out` range over all 32-bit patterns from `0x00000000` to `0xFFFFFFFF`. Each bit of `out` is a sticky flag: once set by a detected 1→0 transition, it stays 1 until a sampled reset clears it. All-zero `out` is the cleared state; all-ones `out` is the fully saturated state in which every channel has captured at least one falling edge since the last reset. Because the operation is per-bit and there is no cross-bit interaction, the 32 channels can be reasoned about independently, but the checker must still compare the full 32-bit vector at each sampled edge.

The update order is reset first, then capture, then history. If the sampled `reset` is 1, `out` is forced to all zeros for every bit, and any simultaneous 1→0 transition on `in` is discarded; reset has priority over capture. If the sampled `reset` is 0, each bit updates as `out_next = out | (prev_in & ~curr_in)`, where `prev_in` is that bit's value at the previous posedge and `curr_in` is its value at the current posedge. After the output update, `prev_in` is replaced by `curr_in` for all bits, including when reset was asserted, so the next cycle's fall detection uses the current sample as its reference. Mid-cycle changes are irrelevant: only the post-posedge samples matter, so a 1→0→1 glitch between edges does not capture, while a bit that is 1 at one sampled edge and 0 at the next is captured regardless of intermediate activity.

A short worked example for one bit: at posedge N, `in[0]=1`, `out[0]=0`, `reset=0`, so `prev_in[0]` becomes 1 and `out[0]` stays 0. If `in[0]` is 0 at posedge N+1, then `prev_in=1` and `curr_in=0`, so `out[0]` becomes 1 and remains sticky. If instead `in[0]` is 1 again at posedge N+1, no capture occurs and `out[0]` stays 0.

The useful point for the final Python checker is to maintain exactly two per-bit state elements—previous sampled input and sticky output—and to apply the order reset, capture, history at every sampled posedge, comparing `out` only at the post-edge sampling instant. The checker should not model any asynchronous or power-on reset, because the public specification provides none; the only clearing mechanism is a sampled `reset=1`. It should also avoid inferring transitions from intermediate waveform activity and should treat `prev_in` as updated even on reset cycles, since the history replacement occurs after the output update regardless of reset priority.
