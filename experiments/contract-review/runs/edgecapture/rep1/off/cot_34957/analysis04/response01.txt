The interface is a single-clock synchronous design with one-bit `reset`, a 32-bit input vector `in`, and a 32-bit output vector `out`. All three data/control ports are sampled with respect to `clk`; the prose says to sample after the posedge has settled, and each row's values are driven before the sampled edge. Thus the checker should treat each row as a pre-edge snapshot: `reset`, `in[31:0]`, and the current registered `out[31:0]`. The output is a 32-bit vector, so every bit position is independent for capture purposes, but all bits share the same clock and the same synchronous reset. There are no per-bit enables, masks, or priority signals in the public interface.

Boundary values matter in three places. First, `reset` is one bit and is active high; a row with `reset = 1` is a reset row, and a row with `reset = 0` is a normal capture row. Second, `in` is exactly 32 bits, so the legal sampled values are 0 through 2^32 - 1; the checker should not assume narrower vectors or sign extension. Third, `out` is also exactly 32 bits and is sticky: once a bit is set by a captured 1-to-0 transition, it remains 1 on subsequent non-reset rows until a synchronous reset row clears it to zero. The public specification does not define power-up state, so the checker should not require any particular initial `out` unless a reset row has occurred. A reset row is dominant: on a row where `reset` is high, `out` is synchronously cleared to zero. The specification does not state that a reset row may also capture a falling edge, so the checker should not credit a capture on that same row. The safe interpretation is that reset clears the output and suppresses capture for that row. However, the previous-input history should still be updated from that row's sampled `in`, because history concerns the sampled signal, not whether a capture was credited.

Mid-row input changes are explicitly outside the current row's capture logic. Optional mid input changes occur after sampling, before the other edge, and are carried to the start of the next row. Therefore, a 1-to-0 transition that happens only in the middle of a row must not set `out` in that row; it can only influence the next row's sampled input value. The checker should compare consecutive sampled pre-edge input vectors, not scan intra-row waveform events.

A short worked example: suppose bit 0 of `in` is 1 in row N and 0 in row N+1, with reset low in both rows. At row N+1's sampling edge, the checker sees previous sampled bit 1 and current sampled bit 0, so `out[0]` becomes 1. If instead `in[0]` changes from 1 to 0 only in the middle of row N+1, after that row's sampling edge, then row N+1 still samples 1 and row N+2 samples 0; the capture belongs to row N+2, not row N+1. The sticky behavior then holds `out[0]` at 1 through later rows until a synchronous reset row clears it.

For the final Python checker, the useful point is to model reset as a synchronous row-level clear that also updates the previous-input history, and to derive captures only from sampled pre-edge values. Power-up should be treated as unspecified unless reset is driven, and mid-row changes should never create a capture in the current row.
