The public specification defines a synchronous 12-hour clock counter with BCD outputs and an AM/PM flag. The critical checker-relevant point is the ordering of reset versus enable at each sampled rising edge. Because reset is synchronous, active high, and has higher priority than enable—and because it must take effect even when `ena` is low—the checker must decide the expected next state from the sampled `reset` input before considering any increment logic. If the sampled `reset` is high, the expected next state is exactly `12:00:00 AM`: `hh=0x12`, `mm=0x00`, `ss=0x00`, and `pm=0`. This expectation is unconditional with respect to the prior counter values and with respect to `ena`. Only when the sampled `reset` is low should the checker evaluate the enabled transition, then apply BCD/range and `pm` flip/hold checks.

This ordering matters because range and BCD checks alone are insufficient to detect reset-priority bugs. A design that gates reset behind `ena` can remain at a perfectly legal-looking state such as `11:59:59 PM` across a reset edge. Every digit is in range and BCD-valid, so a checker that only validates output encoding would pass it. The reset-priority expectation is what catches the error. Similarly, a design that increments before applying reset on an enabled reset edge can produce a transient legal-looking state such as `12:00:00 PM` or `12:00:01 AM`. Again, BCD and range checks may not flag it; only the exact reset expectation does. The checker should therefore snapshot the driven inputs at the posedge, branch on reset first, and compare outputs to the reset expectation without consulting prior counters or `ena`. If reset is low, it computes the enabled transition and then applies independent BCD/range and `pm` assertions.

Mid-input changes occur after sampling and before the other edge, and are carried to the start of the next row. They must be merged only after the current row is evaluated, so a reset asserted after sampling cannot retroactively rewrite the already-checked row. Rows before the first sampled `reset=1` edge should be skipped because power-up state is unspecified. The useful checker order is: reset branch first, then transition, then BCD/range and `pm` checks.
