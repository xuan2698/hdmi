The clock is a synchronous state machine sampled on the rising edge of `clk`. The stored state consists of the four output fields `hh`, `mm`, `ss`, and `pm`; all four must be treated as state, not as derived combinational signals, because `pm` cannot be recovered from `hh` alone (12:00 AM and 12:00 PM share `hh=0x12`). At each sampled edge the checker should read the sampled `reset` and `ena` inputs and compute the expected next state from the previous expected state.

Reset has priority over enable. If `reset` is sampled high at an edge, the next state is unconditionally `hh=0x12`, `mm=0x00`, `ss=0x00`, `pm=0`, regardless of `ena`. This is a transition override, not a continuous override: a reset asserted between edges has no effect until the next sampled edge, and a reset that is high at an edge but drops before the next edge still forces the reset state at that edge. The checker must not assume any power-on value for the outputs. Before the first sampled reset edge, `hh`, `mm`, `ss`, and `pm` are unspecified; the checker should either start from a known reset-sampled state or ignore pre-reset output rows. In particular, it must not require the first observed row to be 12:00 AM unless a reset was actually sampled.

If `reset` is low and `ena` is high, the state advances by exactly one second in BCD with the 12-hour wrap and AM/PM toggle rule. Seconds increment: if `ss` is not `0x59`, add one to the BCD value; if it is `0x59`, set `ss=0x00` and carry into minutes. Minutes behave the same way: if `mm` is not `0x59`, increment; if `0x59`, set `mm=0x00` and carry into hours. Hours use the 12-hour encoding 01–12. If `hh` is not `0x12`, increment the BCD hour; if `hh` is `0x12`, wrap to `hh=0x01` and toggle `pm`. Note that the hour wrap toggles `pm` exactly when going from 12 to 1, which is the AM/PM boundary. If `reset` and `ena` are both low, the state holds.

A short worked example: suppose the previous expected state is 11:59:59 AM, i.e. `hh=0x11`, `mm=0x59`, `ss=0x59`, `pm=0`. At the sampled edge with `reset=0`, `ena=1`, seconds wrap to `0x00`, minutes wrap to `0x00`, hours go from `0x11` to `0x12`, and since the hour did not wrap from 12 to 1, `pm` stays 0 — wait, that yields 12:00:00 PM only if the hour increment from 11 to 12 also toggles `pm`. The correct 12-hour rule is that 11:59:59 AM advances to 12:00:00 PM, so the transition from 11 to 12 must set `pm=1`. Thus the hour logic must treat the 11→12 step as the AM-to-PM transition, and the 12→1 step as the PM-to-AM transition. The checker should encode this explicitly: when `hh=0x11` and a carry occurs, next `hh=0x12` and `pm` toggles; when `hh=0x12` and a carry occurs, next `hh=0x01` and `pm` toggles. If `reset=1` at that same edge, expected is 12:00:00 AM (`pm=0`) even though `ena=1`.

Finally, the checker should validate BCD ranges after reset and after every enabled transition: `ss` and `mm` low digits 0–9 and high digits 0–5; `hh` must encode 01–12, so it is never `0x00`, the tens digit is 0 or 1, and the ones digit is valid for the chosen tens digit. Because `ena` is a pulse, consecutive enabled rows need not be evenly spaced in real time; the checker verifies only one increment per enabled sampled edge.
