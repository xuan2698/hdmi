The timing model has two distinct input windows per cycle, and the checker must treat them differently. The `clk` edge is the sampling point: all registered outputs (`pm`, `hh`, `mm`, `ss`) are captured just after the posedge has settled, so the checker compares the settled post-edge values against the state implied by the previous settled state plus the inputs that were valid at that edge. The "row" inputs (`reset`, `ena`) are driven before the sampled edge, so they are the ones that govern that edge's transition. Any optional mid-cycle input change occurs after sampling and before the opposite edge; it does not affect the just-sampled transition, but it is carried forward and becomes the input seen at the next sampled edge. In practice this means the checker should latch the row's `reset`/`ena` at the sampling edge, compute the expected next state from the prior settled state and those latched inputs, and then compare against the settled outputs. Mid-input changes should never be used to justify a change in the current row's outputs; they only set up the following row.

This matters most for reset priority and for enable gating. Reset is synchronous, active high, and has higher priority than `ena`, and it must work even when `ena=0`. So a row with `reset=1, ena=0` from a non-trivial state must produce the exact reset state `pm=0, hh=0x12, mm=0x00, ss=0x00` on the next settled sample. A checker that only tests reset with `ena=1` cannot distinguish correct priority from an implementation that gates reset behind enable. Likewise, a row with `reset=0, ena=0` must hold all outputs unchanged; this catches free-running counters and any logic that increments on every `clk` rather than on the enable pulse. The row immediately after a reset should also hold the reset state until another reset or an enabled increment arrives.

For enabled increments, the checker should follow the BCD carry chain and the 12-hour wrap, paying special attention to `pm`. The `pm` bit toggles only on the `11→12` hour transition, not on `12→01`. Thus from `11:59:59 AM` with `ena=1`, the next state is `12:00:00 PM`; from `12:59:59 PM` with `ena=1`, the next state is `01:00:00 PM` with `pm` still 1. A checker that flips `pm` on every hour wrap, or on the 12-to-1 transition, will fail these rows.

The checker should also reject illegal BCD outputs outright: hours must be `01`–`12` (`00` and `13`–`19` invalid), and minutes/seconds must be `00`–`59`, so any nibble above 9 is invalid. Because power-up state is unspecified, the first sampled edge should not be judged unless it is a reset edge. A clean sequence starts with `reset=1`, verifies the following settled state, then compares each subsequent row's settled outputs against the state implied by the previous row plus that row's latched `reset`/`ena`.

Worked example: settled state `pm=1, hh=0x11, mm=0x59, ss=0x59`; row inputs `reset=1, ena=0`. Expected next settled outputs: `pm=0, hh=0x12, mm=0x00, ss=0x00`. This one row simultaneously checks reset priority over enable, correct reset value (not `00:00`), and suppression of any pending increment.
