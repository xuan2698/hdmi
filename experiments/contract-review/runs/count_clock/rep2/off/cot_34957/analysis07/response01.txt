The key timing distinction for the final checker is between the sampled edge and the settled outputs. At each sampled posedge, the checker reads `reset` and `ena` as they are at that edge, computes the next state, and then compares the settled outputs after the edge has propagated. A mid-row change to `ena` or `reset` occurs after sampling and before the next edge, so it belongs to the next row's input set, not the row already sampled. This means the checker should not let a late `ena` pulse retroactively enable the current row, nor let a late `reset` clear the current row's expected result.

Reset priority is the first branch in the reference model. If the sampled edge has `reset=1`, the expected settled outputs are `pm=0`, `hh=0x12`, `mm=0x00`, `ss=0x00`, independent of `ena` and independent of the prior state. The checker should include at least one row with `reset=1` and `ena=0` from a non-reset prior state, because the public spec explicitly allows reset when not enabled. A model that gates reset on `ena` would fail that row.

If `reset=0` and `ena=0`, the settled outputs should equal the prior settled outputs. The checker should not advance seconds, minutes, hours, or `pm` on a disabled edge. This is the simplest row type but still useful for catching a model that increments on every clock edge rather than on `ena`.

If `reset=0` and `ena=1`, the counter advances by one second in BCD. The checker should compute seconds first: `00–58` increment normally, `59` rolls to `00` and carries to minutes. Minutes behave the same way, with `59` rolling to `00` and carrying to hours. Hours are the special case: the sequence is `12, 01, 02, ..., 11, 12`, not a simple BCD increment through `00`. The `pm` flag flips only on the `11→12` hour transition, not on `12→01`. So from `11:59:59 AM`, the next state is `12:00:00 PM` with `pm=1`; from `11:59:59 PM`, the next state is `12:00:00 AM` with `pm=0`; from `12:59:59 AM`, the next state is `01:00:00 AM` with `pm=0`; from `12:59:59 PM`, the next state is `01:00:00 PM` with `pm=1`.

A short worked example: prior settled state `11:59:59 AM` (`pm=0`, `hh=0x11`, `mm=0x59`, `ss=0x59`), sampled edge with `reset=0`, `ena=1`. Seconds roll `59→00`, minutes roll `59→00`, hours go `11→12`, and `pm` flips to 1. Expected settled outputs: `pm=1`, `hh=0x12`, `mm=0x00`, `ss=0x00`. If a mid-row `ena` change occurs after this edge, it must not alter this row's expected result; it only affects the next sampled edge.

The checker should also enforce BCD legality: `hh` in `0x01–0x12`, `mm` and `ss` in `0x00–0x59`. Illegal observed values are failures, not states to normalize. Because power-up state is unspecified, the checker should establish a known state with a reset edge and begin comparing from the following settled state, avoiding false failures on the first row.
