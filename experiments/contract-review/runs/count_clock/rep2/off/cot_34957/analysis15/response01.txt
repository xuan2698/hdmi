The public spec defines a synchronous 12-hour clock counter with BCD outputs and an AM/PM flag. The key state is the tuple `(pm, hh, mm, ss)`, where `hh` encodes 01–12, `mm` and `ss` encode 00–59, and `pm` is 0 for AM and 1 for PM. The counter advances only when `ena` is high at a settled rising edge; `reset` is synchronous, active high, has priority over `ena`, and forces the state to `12:00:00 AM` (`pm=0, hh=0x12, mm=0x00, ss=0x00`). Because reset is synchronous, the reset value appears only after the edge on which `reset=1` is sampled, not combinationally before it.

The checker should treat each sampled row as: latch the row’s `reset` and `ena`, then compare the settled outputs after that edge against the transition implied by the previous settled state. The first row should be a reset row, since power-up state is unspecified. After a reset row, the next row must either hold the reset state (if `reset=0, ena=0`) or advance from it (if `ena=1`). A hold row with `reset=0, ena=0` is essential: it catches free-running counters and designs that increment on every `clk` rather than only on `ena`. A reset row with `ena=0` from a non-trivial state is also essential: it catches implementations that accidentally gate reset behind enable, or that reset to `00:00:00` instead of `12:00:00 AM`.

For enabled increments, the checker must implement BCD carry and the 12-hour wrap. Seconds increment 00→01→…→59→00, carrying into minutes; minutes likewise carry into hours. Hours increment 01→02→…→11→12, then wrap 12→01. The `pm` bit toggles only on the 11→12 transition, not on 12→01. Thus from `11:59:59 AM` with `ena=1`, the next state is `12:00:00 PM`; from `12:59:59 PM` with `ena=1`, the next state is `01:00:00 PM` with `pm` still 1. A checker that flips `pm` on every hour wrap, or on the 12→1 transition, will fail these rows. The checker should also reject illegal BCD outputs outright: hours must be 01–12 (00 and 13–19 invalid), and minutes/seconds must be 00–59, so any nibble above 9 is invalid.

Mid-row input changes occur after sampling and before the other edge, so they set up the following row and must not be used to explain the current row’s outputs. The checker should therefore compare each row’s settled outputs only against the previous settled state plus that row’s latched inputs.

Worked example: settled state `pm=1, hh=0x11, mm=0x59, ss=0x59`; row inputs `reset=1, ena=0`. Expected next settled outputs: `pm=0, hh=0x12, mm=0x00, ss=0x00`. This single row checks reset priority over enable, the correct reset value rather than `00:00`, and suppression of any pending increment.
