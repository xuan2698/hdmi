One implementation mistake worth targeting is treating `pm` as a function of `hh` rather than as stored state that changes only on the 11→12 boundary. A designer might write combinational logic such as "PM when `hh` is 12, or when `hh` is between 01 and 11 and some separate flag is set," or more simply flip `pm` whenever the hour rolls over. Both are wrong under the public spec. The spec says `pm` is asserted if the clock is PM, and the 12-hour sequence is 01→…→11→12→01. The only transition that changes AM/PM is 11→12: `11:59:59 AM` plus one enabled tick becomes `12:00:00 PM`. The 12→01 transition keeps PM: `12:59:59 PM` plus one enabled tick becomes `01:00:00 PM` with `pm` still 1. Likewise 12→01 in the AM half stays AM.

This matters to the final checker because `pm` must be compared as part of the latched state transition, not recomputed from the new `hh`. If the checker derives expected `pm` from `hh` alone, it will either accept a buggy design that toggles `pm` on every hour wrap or reject a correct design at the 12→01 boundary. The checker should carry `pm` forward from the previous settled state and apply exactly one rule: on an enabled tick where the previous time is `11:59:59`, set `pm` to its complement; otherwise leave `pm` unchanged. Reset forces `pm=0` along with `hh=12, mm=00, ss=00`.

A short worked example: suppose the previous settled state is `hh=12, mm=59, ss=59, pm=1` and the latched inputs are `reset=0, ena=1`. The correct next state is `hh=01, mm=00, ss=00, pm=1`. A checker that infers PM from `hh` would expect `pm=0` here and flag a correct design; a checker that toggles `pm` on hour wrap would also expect `pm=0`. Only state-carrying comparison gets this row right. The complementary row from `11:59:59 AM` must yield `12:00:00 PM`, so the checker needs both boundaries to pin the rule down.

The same principle applies to reset gating. The checker should latch `reset` and `ena` at the sampled edge and compare settled outputs against the transition implied by the previous settled state plus those latched inputs. A `reset=1, ena=0` row from a non-trivial state is essential: it must produce `12:00:00 AM`, not hold the old state and not advance by incrementing. Mid-row input changes belong to the next row and must not justify the current row's outputs. The first row should be a reset row because power-up state is unspecified. Illegal BCD outputs should be rejected outright rather than normalized.
