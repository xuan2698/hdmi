The timing model here separates two kinds of input events: values present at a sampled posedge, and optional mid-row changes that occur after sampling but before the next edge. For the final Python checker, the important consequence is that the checker must not treat every input transition as immediately effective. Only the values that have been carried to a sampled posedge determine the next output row. Mid-row changes are pending inputs for the following sampled edge.

At each sampled posedge, the checker should first settle the row’s inputs, then compute the next state from the previous state using the public priority rules. Reset is synchronous and active high, so it affects state only at a sampled edge. Reset also has higher priority than enable, so if both are asserted at the same sampled edge, the result is the reset state “12:00 AM” with `pm = 0`, not an increment. If reset is not asserted and `ena` is asserted, the clock advances by one second with the specified BCD rollovers. If neither is asserted, the state holds. The checker should compare `pm`, `hh`, `mm`, and `ss` only after the sampled edge has settled, not in response to a mid-row input change.

The rollover rules are a common source of checker mistakes. Seconds roll from 59 to 00 and carry into minutes; minutes roll from 59 to 00 and carry into hours. Hours are 12-hour BCD with legal values 01 through 12. The transition from 11 to 12 toggles `pm`; the transition from 12 to 01 does not toggle `pm`. Thus `pm` changes only on the 11→12 boundary, not on every hour rollover. A checker that increments hours modulo 12 without toggling `pm` at 11→12, or that toggles `pm` whenever hours roll over, will produce mismatches.

A short worked example: suppose the sampled state is 11:59:59 AM, with `ena = 1` and `reset = 0`. At the next sampled posedge, seconds become 00, minutes become 00, hours become 12, and `pm` becomes 1, giving 12:00:00 PM. If instead `reset = 1` and `ena = 1` at that same sampled edge, the result is 12:00:00 AM with `pm = 0`, because reset dominates enable. If `reset` is asserted only after the 11:59:59 AM row has already been sampled, that mid-row assertion does not change the already-sampled outputs; it is carried to the next sampled edge and applied there.

The final checker should therefore maintain pending `reset` and `ena` values, apply them only at the next sampled posedge, evaluate reset before enable, and compare outputs only at posedge boundaries after settling. It should not infer an undefined power-up state, and it should not silently normalize malformed BCD or out-of-range values. The public specification defines legal ranges and rollover behavior; deviations should be reported as mismatches rather than corrected.
