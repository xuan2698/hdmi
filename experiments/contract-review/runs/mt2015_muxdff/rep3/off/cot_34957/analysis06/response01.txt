The most useful mistake to guard against in the final Python checker is **conflating the pre-edge control inputs with mid-cycle input changes**. The public spec says each row's values are driven before the sampled posedge, and optional mid input changes occur *after* sampling, before the other edge, and are carried to the start of the next row. A naive checker often folds those mid-inputs into the current row's evaluation, which is wrong.

Consider the pre-edge state `q=001`, `L=0`, `r=000`. The correct post-posedge value is the LFSR step: `{q[1]^q[2], q[0], q[2]} = {0^1, 0, 1} = 101`. If a mid-input change sets `L=1` after sampling, that change belongs to the *next* row's pre-edge window. A checker that applies it to the current row would instead predict `q <= r = 000` and fail. The correct sample is `101`; the mid-input `L=1` only affects the next row.

A second, subtler mistake is **trusting functional output comparison alone to validate the three-instance hierarchy**. The submodule contains a flipflop and a 2-1 mux, and the top module must instantiate it exactly three times, one per bit. Because the three instances are identical, a design that wires the XOR feedback `q[1]^q[2]` into the wrong instance can still produce correct-looking output for some seeds and states. The LFSR step is a rotation with feedback, so certain miswirings coincide with the reference on specific pre-edge states. The checker should therefore verify structurally that the XOR net reaches the correct instance (the one driving `q[2]`'s next value), not merely that sampled `Q` matches the reference function. The public spec explicitly requires exactly three submodule instances and that the XOR feedback net reaches the correct instance.

Third, **do not over-model widths**. `L`, `r_in`, and `q_in` are all 1-bit, so there is no truncation, sign extension, or width coercion to get wrong. The only width-sensitive operation is the 3-bit concatenation `{q[1]^q[2], q[0], q[2]}`. A checker that introduces masking or slicing here can accidentally hide a miswired bit, so keep the reference next-state computation as a plain 3-bit concatenation and compare directly to the sampled `Q`.

The single most useful check for the final Python checker: for each row, compute the reference next-state from the *pre-edge* `q` and *pre-edge* `L`/`r`, compare to the sampled post-edge `Q`, then update the carried mid-inputs for the next row. Keep the structural instance/XOR-destination check separate from the functional comparison, because functional comparison alone is not sufficient to distinguish all miswirings under seed 20261122.
