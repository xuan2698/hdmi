The structural pass should be run first and independently of the functional pass, because a mis-wired instance can produce a sampled output that happens to match the expected functional value on some rows. The three instances are bit-slices of the same recurrence, so the most exposed rows are those where the three slices' expected values differ from one another and from the loaded value. Under `L=1`, all three slices load distinct bits of `r_in`; a swapped `r_in`/`q_in` connection, a crossed clock, or a mis-ordered slice will show up on the very first row where `r_in` has mixed bits, before any feedback can mask it. Under `L=0`, the recurrence `{q[1]^q[2], q[0], q[2]}` makes bit 1 a pure copy of the previous bit 0 and bit 0 a pure copy of the previous bit 2, so a slice swap between bits 0 and 1 or between bits 1 and 2 is exposed as soon as the prior word has differing bits in the relevant positions. The XOR in bit 2 is the only place where a wiring error can be partially hidden, because a swapped pair feeding the XOR can coincide; the checker should therefore prioritize rows where `q[1] != q[2]` for exposing bit-2 wiring, and rows where `q[0] != q[2]` for exposing the copy paths.

The functional pass must be dependency-aware from the first sampled edge. There is no reset, so the pre-edge word for row 0 is unknown. Under `L=1`, the load path overwrites all three bits from `r_in`, so all three slices become checkable at the first rising edge regardless of the unknown prior state. Under `L=0`, the next-state function reads the prior word, so an unknown prior bit poisons only the slices whose expected value depends on it: bit 2 depends on `q[1]` and `q[2]`, bit 1 on `q[0]`, bit 0 on `q[2]`. The checker should compare a slice only when every pre-edge bit feeding that slice's expected value is known, and skip otherwise — never fail on `x`.

The mid-input change window is transport only. It occurs after sampling and before the next edge, so it belongs to the start of the following row. It must not be attributed to the edge just sampled, and it must not be treated as a reset or as a way to clean unknown state. Unknowns propagate through the feedback path exactly as the RTL dictates; the checker models that propagation rather than assuming the mid-window resolves it.

Worked example: suppose after some edge the reconstructed pre-edge word for the next row is `q = 3'b1x0` and `L=0`. Expected next word is `{q[1]^q[2], q[0], q[2]} = {x, 1, 0}`. Bit 2 is skipped (depends on unknown `q[1]`); bits 1 and 0 are compared. If instead `L=1` with `r_in = 3'b011`, all three slices are compared against `011` even though the prior word was unknown.

The useful point for the final checker: treat power-up as all state unknown with no reset, run the structural pass unconditionally on every row including unknown rows, and run the functional pass with per-slice dependency gating — full comparison under `L=1`, dependency-limited comparison under `L=0`. This ordering prevents structural violations from being masked by coincidentally correct sampled data and prevents unknown-state rows from producing false functional failures.
