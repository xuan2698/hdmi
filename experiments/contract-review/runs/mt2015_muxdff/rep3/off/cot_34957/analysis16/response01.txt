The public module `full_module` is a 3-bit register with a load enable. When `L=1`, the register loads `r` on the rising clock edge. When `L=0`, it advances through a fixed linear feedback law: the new bit 2 is `q[1] ^ q[2]`, the new bit 1 is `q[0]`, and the new bit 0 is `q[2]`. The hierarchical target `top_module` must reproduce this behavior using three instances of a submodule that contains one flip-flop and one 2-to-1 multiplexer per bit.

Port widths are narrow and uniform. The parent has a 3-bit input `r`, a 1-bit input `L`, a clock `clk`, and a 3-bit output `q`. Each submodule instance has a 1-bit data input `r_in`, a 1-bit load input `L`, a 1-bit clock, a 1-bit feedback input, and a 1-bit output `Q`. The parent's `r` and `q` are therefore vectors of three 1-bit slice signals, and the parent must fan out `clk` and `L` identically to all three instances. Boundary values are the usual 1-bit set: `0`, `1`, `x`, and `z`. The parent-level word can therefore be any of the 4^3 = 64 three-valued combinations, and the checker must not assume only binary values.

The structural requirements are independent of sampled data. The parent must contain exactly three submodule instances. Each instance must receive the same `clk` and the same `L`. Each instance's internal mux must choose between that instance's own `r_in` bit and that instance's own feedback input. The parent must form the feedback word at the parent level: feedback bit 2 is `q[1] ^ q[2]`, feedback bit 1 is `q[0]`, and feedback bit 0 is `q[2]`. A design that moves the XOR inside one instance, or that wires one instance's `Q` directly into another instance's mux, may be functionally equivalent for some traces but is structurally wrong. The checker should verify these connections on every row, including rows with unknown state.

Functional checking is per slice and depends on `L`. After a sampled rising edge, reconstruct the pre-edge word from the three instance `Q` outputs. If `L=1`, every slice is checkable: expected bit `i` is the corresponding `r_in` bit, and the prior `Q` value is irrelevant, even if it is `x` or `z`. If `L=0`, expected bit 2 depends on pre-edge bits 1 and 2 through XOR; expected bit 1 depends on pre-edge bit 0; expected bit 0 depends on pre-edge bit 2. A slice is checkable only when every pre-edge bit feeding its expected value is known. Thus an unknown pre-edge `q[2]` suppresses comparison of output bits 2 and 0, while an unknown pre-edge `q[1]` suppresses only output bit 2.

Worked example: with pre-edge `q = 3'b1x0` and `L=0`, the expected word is `{x, 1, 0}`. Bit 2 is skipped because it depends on unknown `q[1]`; bits 1 and 0 are compared. With `L=1`, all three slices are compared against `r_in` regardless of prior unknowns.

The final Python checker should therefore separate structural checks from functional checks, reconstruct the word from the three `Q` outputs, compute the parent-level next word, and compare each bit only when its dependencies are known or when `L=1`.
