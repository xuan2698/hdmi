The public spec fixes a three-bit state `q` with a synchronous load/shift behavior. When `L` is high at a rising edge, `q` loads `r`; otherwise `q` shifts as `{q[1]^q[2], q[0], q[2]}`. The hierarchical implementation must therefore place the one-bit flipflop and 2-1 mux in a submodule, instantiate that submodule three times, and compute the XOR feedback in `top_module` because it spans two state bits. Port widths are all one bit in the submodule: `L`, `r_in`, `q_in`, and output `Q`, with shared `clk`. The top-level ports remain `r[2:0]`, `L`, `clk`, and `q[2:0]`.

Boundary values are straightforward but important for the checker. `L` is a single control bit: `L=1` selects `r_in`, `L=0` selects `q_in`. Each `r_in` and `q_in` is one bit, so no truncation or sign extension should occur. The three instances map to the three output bits: the instance producing `q[0]` receives `q_in=q[2]`; the instance producing `q[1]` receives `q_in=q[0]`; and the instance producing `q[2]` receives `q_in=q[1]^q[2]`. Each `r_in` receives the corresponding `r` bit. All three share `L` and `clk`. The checker should confirm exactly three submodule instances and that the XOR feedback net reaches the correct instance, not merely that some feedback exists.

Timing is the main risk. The design is purely edge-triggered, so row *i*'s sampled `Q` depends only on the pre-edge state and pre-edge inputs at row *i*'s posedge. Mid-input changes occur after sampling and before the next edge; they are carried into row *i+1*'s pre-edge window unless row *i+1* explicitly drives a new value. A checker that applies mid-inputs to the current row will mispredict whenever a mid-input differs from that row's pre-edge value. The correct order per row is: drive pre-edge inputs, sample after the posedge settles, then apply optional mid-inputs, carrying them forward.

Worked example: row 1 has `L=0`, `r=000`, and pre-edge `q=001`. After the posedge, the checker samples `Q`. A mid-input then sets `L=1`. Row 2 begins with `L=1` carried forward unless row 2 drives a new `L`. If row 2 does not override, its posedge performs a parallel load rather than an LFSR step; if it overrides, the override wins and the carried value is discarded. The same carry rule applies to `r_in` and `q_in` mid-changes.

For functional comparison, the checker should compute the three-bit next-state function from the pre-edge state and inputs, compare it against the sampled post-edge `Q`, and use carried mid-inputs only for the following row. Separating sampled-edge semantics from mid-input carry is the single most important modeling decision for matching the seed-20261122 protocol.
