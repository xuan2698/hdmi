The public spec fixes a 3-bit LFSR with a load path: on each posedge, if `L` is high the register takes `r`; otherwise it rotates as `{q[1]^q[2], q[0], q[2]}`. The hierarchical requirement is that a submodule containing one flipflop and one 2-1 mux be instantiated exactly three times, once per bit, with the XOR feedback `q[1]^q[2]` routed to the instance that drives the next value of `q[2]`.

The timing protocol is the main source of checker bugs. Each row's inputs are driven before the sampled posedge, and the sample is taken after that edge has settled. Optional mid-input changes occur *after* sampling and before the next edge, so they are carried forward and become part of the next row's pre-edge window. The checker must therefore maintain a carried state for `L`, `r_in`, and `q_in` across rows: the values used to predict row *n*'s next state are the values that were in force at row *n*'s posedge, which may include a mid-input change applied at the end of row *n-1*. Applying a mid-input change to the row in which it appears is the classic off-by-one error.

Worked example: suppose pre-edge `q = 001`, `L = 0`, and a mid-input change after sampling sets `L = 1` with `r = 000`. The correct prediction for this row is the LFSR step `{q[1]^q[2], q[0], q[2]} = {0^1, 0, 1} = 101`. The mid-input `L=1` belongs to the next row; a checker that folds it into the current row would predict `q <= r = 000` and fail. The sampled `Q` should be `101`, and the carried `L` for the next row is `1`.

A second pitfall is relying on functional output comparison alone to validate the three-instance hierarchy. Because the three instances are identical, a design that routes the XOR feedback into the wrong instance can still match the reference on some pre-edge states, since the LFSR step is a rotation with feedback and certain miswirings coincide with the reference for particular states. The checker should structurally confirm that exactly three submodule instances exist and that the XOR net reaches the instance driving `q[2]`'s next value, independently of the sampled-output comparison.

Third, do not over-model widths. `L`, `r_in`, and `q_in` are 1-bit, so there is no truncation or sign extension to get wrong. The only width-sensitive construct is the 3-bit concatenation; keep the reference next-state as a plain concatenation and compare directly to sampled `Q`, avoiding masks or slices that could mask a miswired bit.

The single most useful rule for the final Python checker: for each row, compute the reference next-state from the pre-edge `q` and pre-edge `L`/`r`, compare to the sampled post-edge `Q`, then update the carried mid-inputs for the next row. Keep the structural instance/XOR-destination check separate from the functional comparison, because functional comparison alone cannot distinguish all miswirings under seed 20261122.
