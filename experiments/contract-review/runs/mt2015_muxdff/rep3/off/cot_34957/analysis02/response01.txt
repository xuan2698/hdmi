The key modeling point for the Python checker is the distinction between the sampled edge value and the carried mid-input value. Because the design is edge-triggered with no asynchronous paths, the only thing that determines row *i*'s output is the state and inputs present at row *i*'s posedge. Mid-input changes after that edge cannot affect row *i*'s sampled `Q`; they only affect row *i+1*. A checker that naively applies all inputs for a row before sampling, including mid-inputs, will mispredict whenever a mid-input differs from the row's pre-edge value. The correct model is: pre-edge inputs → sample → optional mid-inputs → next row's pre-edge inputs (with mid-inputs carried in unless overridden).

A short worked example clarifies the carry rule. Suppose row 1 drives `L=0`, `r=000`, `q=001` before the posedge; after settling the checker samples `Q`. Then a mid-input sets `L=1` after sampling. Row 2's pre-edge window begins with `L=1` carried from the mid-input, unless row 2 explicitly drives a new `L`. If row 2 does not override `L`, the checker must use `L=1` for row 2's posedge, producing a parallel load rather than an LFSR step. If row 2 does override `L`, the override wins and the carried value is discarded. The same carry logic applies to `r_in` and `q_in` mid-changes.

For the hierarchical structure, the checker should also verify that `top_module` instantiates the one-bit submodule exactly three times and that the LFSR feedback `q[1]^q[2]` is routed to the correct instance's `q_in` (the bit that becomes `q[2]` next cycle), with `q[0]` and `q[2]` shifted appropriately. Since the submodule is one bit wide, any cross-bit XOR must be computed at the `top_module` level and fed into the submodule's `q_in`, while `r_in` receives the corresponding bit of `r`. The checker's functional comparison should therefore evaluate the three-bit next-state function against the sampled post-edge `Q`, using the carried mid-inputs only for the following row. This separation of sampled-edge semantics from mid-input carry is the single most important modeling decision for matching the seed-20261122 protocol.
