The public spec fixes three one-bit lanes feeding a three-bit register, with a single-bit load select `L`, a one-bit clock, and per-lane inputs `r_in` and `q_in` (the latter being the feedback view of the register). Output `Q` is one bit per lane. Because every lane is one bit wide, boundary values are trivial per lane (0 or 1), but the interesting boundaries are at the word level: the all-zero and all-one states, and states where the three lane results are pairwise distinct versus states where two or three lanes coincide. The checker must reason about lane-indexed expectations, not just the packed word.

The next-state function is lane-specific. Lane 0 computes `q[1] ^ q[2]`; lane 1 passes `q[0]`; lane 2 passes `q[2]`. The load override is whole-word: when `L = 1`, all three lanes take `r_in` simultaneously, so the load path is the only reliable way to establish a known state, since power-up `q` is unspecified. Any first-edge comparison that assumes a particular initial register value is testing an artifact, not the spec. The checker should drive `L = 1` with known patterns first, then drop to `L = 0` for feedback rows.

The deferred-promotion rule governs timing. Inputs present before a sampled posedge define that row. Mid-cycle changes occur after sampling and before the next edge, so they become the pre-edge inputs of the following row, never the current one. The checker must snapshot inputs at the sample point, compute expected `Q` from that snapshot, compare, and only then promote mid-cycle changes into the next row's pre-edge values. Applying a mid change early, or letting a lane read an updated `q` bit, yields false mismatches.

Worked example: old `q_in = 3'b101`, `L = 0`. Lane 0 = `1^1 = 0`, lane 1 = `1`, lane 2 = `1`, so expected `Q = 3'b011`. A mid-cycle change to `L = 1, r_in = 3'b110` must not affect this row; it becomes the next row's pre-edge input, which then expects `3'b110` via the load path. Note lanes 1 and 2 coincide here, so this row cannot detect a swap between them.

For the final Python checker, the useful focus is to keep snapshot, per-lane expected computation, comparison, and deferred promotion as distinct steps; establish known state through the load path before any feedback comparison; and select or annotate stimulus so lane-index faults are observable rather than masked by coincident lane values.
