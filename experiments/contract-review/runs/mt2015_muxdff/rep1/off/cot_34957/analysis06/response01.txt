One useful implementation mistake to flag for the final Python checker is **treating the three submodule instances as interchangeable or updating the reference state bit-by-bit instead of atomically**. The public spec describes a single 3-bit register whose feedback path is asymmetric: in the `L == 0` case, the new bit 2 is `q[1] ^ q[2]`, the new bit 1 is `q[0]`, and the new bit 0 is `q[2]`. Those three assignments all read the *old* `q`. If the checker models the design by mutating a list or packed integer in place, it can easily read a bit that has already been overwritten. For example, if it writes `q[2]` first and then computes `q[0] = q[2]`, it will use the new bit 2 rather than the old one, producing a wrong expected value. The same hazard appears if the checker collapses the three instances into a set or a dictionary keyed by value rather than by position: the feedback mapping is not symmetric, so bit 0, bit 1, and bit 2 must each be tracked separately.

The safe pattern is to snapshot the old `q` and the pre-edge `L`/`r_in`, compute all three next bits from that snapshot, and only then assign the result. This also protects the load path: when `L == 1`, each instance loads its own `r_in` bit, so position must be preserved there too.

A second, related mistake is mishandling the mid-row input changes. The spec says values are driven before the sampled edge, and optional mid changes occur after sampling but before the other edge, carried to the start of the next row. A checker that applies a mid change to the current row's expectation will fail rows where `L` or `r_in` changes after the edge. The checker should latch pre-edge inputs for the current row, compare against settled `Q`, then promote mid values into the next row's pre-edge inputs.

Short worked example: suppose pre-edge `q = 3'b101`, `L = 0`, `r_in = 3'b000`. Atomic feedback gives `next = {q[1]^q[2], q[0], q[2]} = {1^1, 1, 1} = 3'b011`. If a mid change then sets `L = 1`, `r_in = 3'b110`, the current row still expects `3'b011`; the next row starts with `L = 1`, `r_in = 3'b110` and expects `3'b110`. A checker that updates in place or applies the mid change early would report a false mismatch.

So the final checker's core invariant should be: snapshot old state and pre-edge inputs, compute all three next bits from the snapshot, compare only settled `Q`, and defer mid-row changes to the next row.
