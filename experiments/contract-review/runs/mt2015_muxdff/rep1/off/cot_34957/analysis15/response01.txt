The public contract is a three-lane feedback register with a synchronous load override. Each sampled rising edge observes the pre-edge values of `L`, `r_in`, and `q_in` (the current register state), then computes the next state. When `L = 1`, the next state is simply `r_in`; when `L = 0`, the next state is the concatenation of three lane functions of the old state: lane 0 = `q_in[1] ^ q_in[2]`, lane 1 = `q_in[0]`, lane 2 = `q_in[2]`. The output `Q` is the register content after the edge settles. The hierarchical decomposition into a flipflop plus a 2-1 multiplexer, instantiated three times, is an implementation structure; the observable behavior is the per-lane next-state function and the load override.

Two properties dominate checker design. First, power-up state is unspecified. Any comparison on the first sampled edge that assumes a particular initial `q` is testing an implementation artifact. The checker must first drive `L = 1` with known patterns to establish state, then switch to `L = 0` for feedback rows. Second, the lanes are not symmetric. Lane 0 mixes bits 1 and 2, lane 1 passes bit 0, lane 2 passes bit 2. On many states two lanes coincide, so a whole-word comparison can mask a swapped or mis-indexed lane. The checker should track expected values per lane index and prefer stimulus where the three candidate bits are pairwise distinct, or at least where the lane under test differs from its neighbors.

The deferred-promotion rule is the other key point. Inputs driven before a sampled edge define that row. Any mid-cycle change occurs after sampling and before the next edge, so it becomes the pre-edge input for the following row, not the current one. The checker must snapshot inputs at the sample point, compute expected outputs from the snapshot, compare, and only then promote mid-cycle changes to the next row's pre-edge values. Applying a mid change early, or letting a lane read an updated `q` bit, produces false mismatches.

Worked example: old `q_in = 3'b101`, `L = 0`. Lane 0 = `1^1 = 0`, lane 1 = `1`, lane 2 = `1`, so expected `Q = 3'b011`. A mid-cycle change to `L = 1, r_in = 3'b110` must not alter this row; it becomes the next row's pre-edge input, which then expects `3'b110` via the load path. Note that lanes 1 and 2 coincide here, so this row alone cannot detect a swap between them — the checker should add rows where the three lane results are pairwise distinct.

For the final Python checker, the useful focus is: separate snapshot, per-lane expected computation, comparison, and deferred promotion into distinct steps; establish known state via the load path before any feedback comparison; and select or annotate stimulus so lane-index faults are observable rather than masked by coincident lane values.
