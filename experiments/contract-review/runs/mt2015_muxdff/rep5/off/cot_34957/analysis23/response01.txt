The key point for the final checker is that the three submodule instances are not interchangeable: each one receives a different `q_in` bit and produces a different `Q` bit, and the top-level feedback wiring determines which old bit feeds which submodule. A checker that only verifies the width of `q`, or that compares bit-by-bit without regard to position, can miss a permutation error in the feedback path. The full three-bit vector must be compared as a unit.

A useful distinguishing example is the initial state `q = 110` with `L = 0`. The correct next state is `{q[1]^q[2], q[0], q[2]} = {1^1, 0, 1} = 001`. If the feedback wiring swaps the `q[0]` and `q[2]` inputs to the submodules, the computed next state becomes `{1^1, 1, 0} = 010`, which differs from `001` in two positions. A per-bit checker that only confirms each output is a legal one-bit value would accept this; a full-vector equality check rejects it. Similarly, if the XOR submodule receives `q[0]` instead of `q[1]`, the result is `{0^1, 0, 1} = 101`, again caught only by full-vector comparison.

The checker should also avoid the absorbing states `000` and `111` as the sole test vectors. Under `L = 0`, `000` maps to `000` and `111` maps to `111`, so many wiring errors are invisible from those states. A mixed vector such as `110` or `101` exposes the feedback network. The load path with `L = 1` must be tested separately, because it bypasses the next-state function entirely and would otherwise mask a broken feedback network.

Finally, the checker must sample `q` only after the posedge has settled, compute the expected next state from the latched old bits, and compare against the settled `Q`. Mid-cycle input changes belong to the next row, not the current one. The initial `q` is a harness-supplied starting condition, not a design property, so the first comparison must use that declared value rather than assuming a reset state.
