The key distinguishing point is that the submodule boundary must preserve the original module's *parallel* feedback semantics, not a sequential bit-by-bit update. In the public spec, when `L=0`, the next state is `{q[1]^q[2], q[0], q[2]}`. All three right-hand sides refer to the same pre-edge `q`. A hierarchical implementation that instantiates three one-bit submodules must therefore feed each submodule's `q_in` from the *old* three-bit register value, and must not let one submodule's newly computed `Q` feed another submodule's `q_in` within the same edge. The final Python checker should verify this by comparing the sampled `Q` against a single simultaneous computation from the sampled `q_in` snapshot.

A second useful point is the mux select. `L` is shared across all three instantiations. When `L=1`, every bit's next value is its corresponding `r_in` bit; when `L=0`, every bit uses its feedback expression. The checker should not allow mixed behavior, such as one bit taking `r_in` while another takes feedback, unless the harness explicitly drives separate selects (which the public spec does not). The submodule's `L` input is one bit, and the top-level `L` is one bit, so all three slices see the same select value at the sampled edge.

Initialization is the third point. The checker must begin in an uninitialized state and wait for the harness to declare the initial three-bit `q`. It must not assume `q=0`, must not infer a reset, and must not derive the first row's `q_in` from a computed `Q`. The first sampled row uses the harness-declared initial `q` as `q_in`. After that, each row's `q_in` is the previous row's computed `Q`, unless a mid-cycle change is carried in. Mid-cycle changes occur after sampling and before the next edge; they affect the next row's inputs, not the current row's computation.

A short worked example: suppose the harness declares initial `q = 3'b101`, and before the first sampled edge drives `L=0`, `r_in=3'b000`. The checker samples `q_in=101`, `L=0`. It computes `Q[2]=q[1]^q[2]=0^1=1`, `Q[1]=q[0]=1`, `Q[0]=q[2]=1`, giving `Q=3'b111`. If a mid-cycle change then sets `L=1` and `r_in=3'b010`, that carry applies to row two, so the next sampled `Q` is `3'b010`. The checker must not retroactively alter row one's result.

For the final Python checker, the most useful discipline is: sample all inputs and the old `q` together, compute all three next bits from that single snapshot, then advance the carried state. Reject or skip rows sampled before the harness declares the initial `q`. Do not model the submodule as three independent flip-flops with cross-coupled next-state wires that update in sequence; model it as one parallel next-state function split across three instances. This preserves the public spec's clocked behavior from an arbitrary starting state and avoids false mismatches caused by initialization assumptions or ordering.
