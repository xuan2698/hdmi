The public spec describes a three-bit shift/feedback register with a synchronous load. The top-level `full_module` has a single 3-bit state `q`, a single 1-bit load select `L`, a 3-bit load data input `r`, and a clock `clk`. On each posedge, if `L` is high the register loads `r`; otherwise it applies the feedback transform `{q[1]^q[2], q[0], q[2]}`. The hierarchical requirement is that a submodule containing one flip-flop and one 2-to-1 multiplexer be instantiated three times, once per bit, with the submodule named `top_module`. The public input widths are `L:1`, `q_in:1`, `r_in:1`, and the output width is `Q:1`; the clock is `clk`, and sampling occurs after the posedge has settled.

The critical timing point for the final checker is that the three per-bit instances must be evaluated from a single pre-edge snapshot of the whole 3-bit `q`, together with the pre-edge `L` and `r`. The update is conceptually parallel: every next-state bit is a function of the old state and old inputs only. If the checker instead updates `q[0]`, then uses the new `q[0]` when computing `q[1]`, and then uses both new bits when computing `q[2]`, it will produce results matching a ripple or sequential evaluation rather than the specified flip-flop behavior. This is especially dangerous because the feedback expression `{q[1] ^ q[2], q[0], q[2]}` mixes bits across positions, so ordering errors can easily change the observed `Q`.

A second, closely related mistake is to let the three instances disagree about `L`. The public spec has a single one-bit `L` at the top level and a single one-bit `L` input on the submodule. All three instances should therefore see the same select value at a sampled edge. A checker that accidentally drives one instance with `L=1` and another with `L=0`, or that models per-bit load enables, would accept behavior that the public module cannot produce. When `L=1`, every next bit must come from the corresponding `r_in` bit; when `L=0`, every next bit must come from the feedback expression. Mixed behavior is not part of the public specification.

A third mistake is initialization handling. The checker must not assume `q` starts at zero, must not invent a reset, and must not compute the first row’s `q_in` from a previous `Q`. The first sampled row uses the harness-declared initial three-bit `q`. Rows sampled before that declaration should be rejected or skipped. Mid-cycle input changes occur after sampling and before the next edge, so they belong to the next row, not the current one.

Worked example: with initial `q=3'b101`, `L=0`, and `r_in=3'b000`, the correct next state is computed from the snapshot `q[2]=1`, `q[1]=0`, `q[0]=1`: `Q[2]=q[1]^q[2]=1`, `Q[1]=q[0]=1`, `Q[0]=q[2]=1`, so `Q=3'b111`. A checker that updates in place might compute `Q[0]=1`, then use that new bit in another position and get a different result. The final checker should therefore snapshot all inputs and old `q`, compute all three next bits from that snapshot, and only then advance the carried state.
