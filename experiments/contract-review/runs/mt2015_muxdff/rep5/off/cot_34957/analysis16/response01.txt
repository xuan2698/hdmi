The public module `full_module` has three one-bit control/data inputs (`r[2:0]`, `L`) plus `clk`, and a three-bit registered output `q`. The hierarchical target `top_module` must expose the same observable interface: a 3-bit `r`, a 1-bit `L`, `clk`, and a 3-bit `Q` (or `q`) output assembled from three one-bit submodule outputs. Each submodule is one bit wide in every port: one data input from `r`, one feedback input from the corresponding old `q` bit, one load-enable `L`, `clk`, and one registered output bit. Because all submodule ports are width 1, the Verilog compiler cannot flag a miswired instance: feeding `q[1]` where `q[2]` belongs, or routing the XOR result into the wrong output position, remains width-legal. The final checker must therefore validate behavior over time, not hierarchy or net names.

Boundary values matter. With `L = 1`, the next state is exactly `r`; all eight `r` values are legal and each must appear on `Q` after the sampled edge. With `L = 0`, the next state is `{q[1]^q[2], q[0], q[2]}`. The all-zero state `000` maps to `000`, and `111` maps to `{1^1,1,1} = 111`; both are fixed points under `L = 0`, so they cannot reveal a swapped feedback or XOR term. The load path with `r = 000` or `r = 111` likewise cannot distinguish bit positions. The checker must include mixed states such as `q = 110` with `L = 0`, and a mixed load such as `r = 101` with `L = 1`, to confirm each bit lands in its correct position and that all three flipflops load on the same edge.

Timing is the second trap. Inputs are driven before the sampled posedge; the sample is taken after the edge has settled; optional mid-cycle changes occur after sampling and before the next edge, and are carried into the next row. The checker must latch the three old `q` bits at the sampled edge, compute the expected next state from those latched bits and the current `L`/`r`, and compare against the settled `Q` for that row. It must not re-read `q` after the edge, since `q` has already advanced, and it must not apply a mid-cycle change to the current row; that change belongs to the following row. No reset is assumed, so the harness-declared initial `q` is the starting state.

Worked example: drive `q = 3'b110`, `L = 0`. Correct next state is `{1^1, 0, 1} = 3'b001`. If the instance producing bit 0 is fed `q[1]` instead of `q[2]`, the low bit becomes `1`, giving settled `Q = 3'b011`. That is a one-bit, width-legal error visible only on a mixed state, which is exactly why the checker needs mixed-state vectors and a full-vector comparison rather than per-bit or structural inspection.
