The key point for the final checker is that the public spec fixes behavior at the *full 3-bit vector* level, but the hierarchical decomposition into three 1-bit submodules makes every wiring mistake width-legal. So the checker's discriminating power comes entirely from choosing vectors where the three bit positions carry different information, and from sampling at the right moment.

Consider the load path first. When `L = 1`, the settled `Q` must equal `r` exactly. Because each submodule port is one bit wide, an instance that receives `r[1]` where `r[2]` belongs, or that drives the wrong output bit, still compiles cleanly. Only a mixed load such as `r = 3'b101` (or `011`, `110`) exposes a permutation: `000` and `111` are invariant under any bit permutation, so they are useless as load discriminators. The checker should include at least one load vector with distinct bits, and ideally all eight `r` values across a run, so that every output position is exercised with both a 0 and a 1.

The feedback path is the richer source of discrimination. With `L = 0`, the next state is `{q[1]^q[2], q[0], q[2]}`. The fixed points `000` and `111` again reveal nothing: `000` maps to `000`, and `111` maps to `{1^1,1,1} = 111`. A swapped XOR input, a dropped `q[0]`, or a misrouted `q[2]` all leave these two states unchanged. Mixed states are required. The worked example in the spec is the canonical one: from `q = 110` with `L = 0`, the correct next state is `{1^1, 0, 1} = 001`; a single miswire on the low bit yields `011`, a one-bit error that only a full-vector comparison catches. The checker should therefore drive a sequence of mixed states under `L = 0`, including states where `q[1]^q[2]` differs from each of `q[0]` and `q[2]`, so that the XOR result, the shifted `q[0]`, and the copied `q[2]` each land in a distinguishable position.

Timing is the second trap, and it interacts with the state choice. Inputs are driven before the sampled posedge; the sample is taken after the edge settles. The checker must latch the three old `q` bits at that sample, compute the expected next state from the latched bits plus the current `L`/`r`, and compare against the settled `Q` for the same row. It must not re-read `q` after the edge, because `q` has already advanced, and it must not fold a mid-cycle change into the current row — that change belongs to the next row. Since no reset is assumed, the harness-declared initial `q` is the starting state, so the first row's expected value depends on that initial vector; choosing a mixed initial state (e.g. `110`) makes the very first comparison discriminating.

A useful final-checker heuristic: prefer vectors where the three bits of `q` are not all equal, and where `q[1]^q[2]` differs from `q[0]` and from `q[2]`. Under those conditions, any single-bit miswire in the three instances produces a settled `Q` that differs from the expected full vector, and a full-vector equality check flags it. Per-bit checks or structural inspection would miss exactly these width-legal errors.
