The public spec defines a three-bit register with a synchronous load path and a linear-feedback path. The parent module `full_module` has inputs `r[2:0]`, `L`, `clk`, and output `q[2:0]`. On each posedge, if `L` is high the register loads `r`; otherwise it shifts/rotates according to `q <= {q[1]^q[2], q[0], q[2]}`. The hierarchical requirement is that a one-bit flip-flop plus a 2-to-1 multiplexer live in a submodule (`top_module`), instantiated three times, with the XOR computed in the parent and routed to the bit-2 instance.

Edge and mid-input timing matter because the spec says to sample after the posedge has settled, with each row's values driven before the sampled edge. Optional mid-input changes occur after sampling and before the other edge, and are carried to the start of the next row. In practice this means the checker must treat the sampled edge as the decision point: the pre-edge `q` and the pre-edge `L`/`r` determine the next state. Any `r` or `L` change that happens mid-cycle must not retroactively alter the just-sampled transition; it belongs to the following row. This is the classic synchronous-register discipline, and it is the main place a naive checker goes wrong, because it may apply a late `L` change to the edge that already occurred.

The subtle structural hazard is the wiring of the bit-2 submodule. The correct mapping is: `q_in` receives `q[2]`, `r_in` receives the XOR `q[1]^q[2]`, and `L` selects between them so that `L=1` loads `r[2]` and `L=0` feeds back the XOR. A common mistake is to swap these: put the XOR on `r_in` and `q[2]` on `q_in`. That design is correct only when the XOR happens to equal `q[2]`, i.e. when `q[1]=0`, and it is silently wrong otherwise. Because the public seed vector has `q[1]=0`, it cannot distinguish the two wirings, so the checker needs an explicit state with `q[1] != q[2]` under `L=0`.

Worked example: let `q=3'b110`, `L=0`. Correct next state is `{1^0, 0, 0} = 3'b100`. If bit 2 is miswired with `q_in=q[2]=0` and `r_in=XOR=1`, then `L=0` selects `q_in=0`, giving bit 2 = 0 and next state `3'b000` — wrong, but indistinguishable whenever `q[1]=q[2]`.

For the final Python checker, the useful focus is: verify one-bit submodule ports, verify `L=1` selects `r_in` and `L=0` selects `q_in`, sample only after the posedge settles using pre-edge `q`, carry mid-cycle input changes to the next row, and include a discriminating vector with `q[1] != q[2]` and `L=0`. Also do not assume `q` starts at zero; with `L=0` an unknown `q` propagates unknown, so either force an initial `L=1` load with known `r` or track per-bit unknown propagation.
