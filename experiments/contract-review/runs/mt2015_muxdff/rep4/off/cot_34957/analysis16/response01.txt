The public spec defines a three-bit shift/feedback register with a load enable, but the hierarchical decomposition into three one-bit submodules changes how the checker must reason about state, widths, and unknowns. Port widths are narrow: `r` is 3 bits at the top level but each submodule sees a 1-bit `r_in`; `L` is 1 bit and fans out to all three instances; `q` is 3 bits at the top level but each submodule contributes a 1-bit `Q`. The clock is shared. The boundary values that matter are therefore per-bit: `L ∈ {0,1}`, `r_in ∈ {0,1}`, `q_in ∈ {0,1}`, and `Q ∈ {0,1}`. At the top level the corresponding boundaries are `r ∈ {0..7}`, `q ∈ {0..7}`, with `L` still binary.

The critical width issue is that the feedback equation `{q[1] ^ q[2], q[0], q[2]}` is a three-bit expression, but in the hierarchical design each submodule only owns one bit. The submodule must therefore receive the two bits it needs to compute its own next state, or the top module must wire the XOR and shifts explicitly. A checker that flattens the design and a checker that models the hierarchy must agree bit-for-bit on which submodule owns which output bit. The public spec's bit ordering is `Q[2] = q[1] ^ q[2]`, `Q[1] = q[0]`, `Q[0] = q[2]`. Any swap in the submodule wiring — especially the bit-2 XOR inputs — is invisible to vectors where `q[1] == q[2]`, so the checker needs at least one vector with `q[1] != q[2]` and `L = 0` to discriminate.

The unknown-state issue is the most important point for the final checker. There is no reset and no initialization in the public spec. If the first sampled edge has `L = 0`, the feedback equation is applied to an unknown `q`, and the result stays unknown in the affected bits. In Verilog, `q[1] ^ q[2]` with either operand unknown yields `x`, and the concatenation propagates that `x`. A checker that seeds `q` to zero silently diverges from the spec on any vector whose first edge has `L = 0`. The checker should either require an initial `L = 1` load with known `r` before comparing states, or model per-bit unknown propagation. The former is acceptable only if the public vectors guarantee an initial load; the latter is more faithful.

A related hierarchy subtlety: if the checker models the three submodule state bits, it must initialize all three as unknown consistently. Mixing a zero-initialized flattened `q` with `x`-initialized submodule bits produces spurious mismatches. Sampling must occur after the posedge settles, using pre-edge values, and mid-cycle input changes must be carried to the next row rather than applied to the current sample.

Worked example: suppose the first sampled edge has `L = 0` and `q` is unknown. The next state's bit 2 is `x ^ x = x`, bit 1 is `x`, bit 0 is `x`. A zero-seeded checker would predict `000` and flag a mismatch; the correct expectation is `xxx`. That single vector is enough to expose the initialization assumption.

The stopping point for this pass: the final checker should treat power-up as unknown, require an explicit `L = 1` load to reach a known state, propagate unknowns through the `L = 0` path, sample post-edge with pre-edge values, carry mid-cycle changes forward, and include a discriminating vector with `q[1] != q[2]` and `L = 0` to catch the bit-2 wiring swap.
