The key point for the final checker is that the hierarchical decomposition must preserve the *bit permutation and cross-bit XOR* of the public recurrence, not merely reproduce a one-bit flipflop-plus-mux structure. The public update when `L=0` is

`q_next = { q[1]^q[2], q[0], q[2] }`.

That means the three submodule instances are not symmetric: the MSB instance's combinational input must be the XOR of the *current* `q[1]` and `q[2]`; the middle instance's input must be the current `q[0]`; and the LSB instance's input must be the current `q[2]`. A common but incorrect hierarchical wiring connects instance `i`'s data input to `q[i]`, which would produce `{q[1]^q[1], q[0], q[2]}` — a different function. The checker should therefore validate against the public recurrence, not against any particular internal netlist.

A short worked example makes the distinction concrete. Suppose a prior `L=1` row establishes `q = 3'b110`. Then drive `L=0`. Correct next state: MSB `= q[1]^q[2] = 1^0 = 1`, middle `= q[0] = 0`, LSB `= q[2] = 0`, so `Q = 3'b100`. The same-index miswiring would give MSB `= q[1]^q[1] = 0`, middle `= q[0] = 0`, LSB `= q[2] = 0`, i.e. `000`. Thus a single post-establishment `L=0` row after `110` separates the two designs. The checker should include at least one such row, and ideally several states where `q[1] != q[2]` so the XOR is exercised in both polarities.

On timing: the design is edge-triggered on `posedge clk`, with no reset. The checker must drive each row's `L` and `r` before the sampled edge, wait for the posedge to settle, then sample `Q`. Any optional mid-cycle changes to `L` or `r` occur after sampling and before the next edge; they must be carried forward as the inputs for the next row and must not retroactively affect the just-sampled `Q`. Because `q` is unknown at time zero, the checker should either begin with an `L=1` row to load a known state, or mark outputs before the first load as don't-care. After establishment, each expected `Q` is a pure function of the previous sampled `q` and the current row's `L`/`r`: if `L=1`, `Q = r`; if `L=0`, `Q = {q[1]^q[2], q[0], q[2]}`. The checker's reference model should implement exactly this recurrence and compare bit-for-bit, rather than inferring behavior from the submodule structure.
