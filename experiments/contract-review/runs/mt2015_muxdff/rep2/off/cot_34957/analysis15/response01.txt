The public spec defines a single 3-bit state register `q` updated on each rising edge of `clk`. When `L=1`, the next state is the 3-bit input `r`; when `L=0`, the next state is the fixed linear recurrence `{q[1]^q[2], q[0], q[2]}`. The hierarchical requirement is structural: a submodule containing one flip-flop and one 2-to-1 multiplexer must be instantiated three times, once per state bit. The checker, however, should validate only the observable top-level behavior — the three-bit `q` after each sampled edge — not the internal hierarchy, port names, or instantiation count. The public spec constrains the implementation shape, but the checker's oracle is the recurrence and the load semantics.

The key timing fact is that `L` and `r` are driven before the rising edge and `q` is sampled after the edge settles. Therefore the checker's reference model should compute the next `q` from the inputs present at that edge and the previous sampled `q`. No combinational path from `L` or `r` to `q` should be visible in the sample; only the registered result matters. Mid-cycle input changes occur after sampling and before the next edge, and are carried to the next row's drive. They must not retroactively alter the just-sampled `q`. A correct edge-triggered design naturally satisfies this; a design that lets `L` or `r` leak combinationally into `q` would fail.

Power-up is unspecified. The first sampled `q` before any `L=1` load may be `x`, `z`, or any value; the checker must not require a particular reset value. The first row with `L=1` is the synchronization point: after that edge, `q` must equal `r` exactly. From then on, every `L=0` row must match the recurrence applied to the previously sampled `q`. This means the checker should seed its model as unknown, then overwrite with `r` at the first `L=1` sample, then apply the recurrence thereafter. It should not compare pre-synchronization samples against a guessed seed.

A subtle failure mode is an extra register stage in the parent. If `L` or `r` is latched through an additional flop before reaching the submodule's `D` input, the load is delayed by one cycle: the first `L=1` row appears to have no effect, and the unknown seed persists one row longer. Likewise, if the parent computes the XOR from registered copies of `q[1]` and `q[2]` instead of the current outputs, the recurrence is delayed by one cycle. The checker should therefore compare the top-level `q` against a direct software model evaluated at the same edge, with no extra latency.

Worked example: load `r=101` with `L=1`, so sampled `q=101`. Then drive `L=0`. The correct next state is `{q[1]^q[2], q[0], q[2]} = {0^1, 1, 1} = 110`. A design that mistakenly treats the recurrence as an identity permutation would produce `101`, which differs. However, loads of `000` or `111` make correct and buggy designs agree, so the checker must include at least one `L=0` step after a load where `q[1] != q[2]` to exercise the XOR polarity. The checker should also avoid assuming any internal port order; expected `q` must be derived solely from the public recurrence and the sampled edge timing.
