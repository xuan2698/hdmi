The key distinguishing point is that the parent must not introduce an extra register stage between the three submodule outputs and the top-level `q`. The public module updates `q` on the same `posedge clk` that samples `L` and `r`. In the hierarchical version, each submodule contains a flipflop and a 2-to-1 mux; the mux selects `r_in` when `L=1` and the feedback `q_in` when `L=0`. The submodule's `Q` is the registered output. The parent wires the three `Q` bits directly to the 3-bit `q` output and routes the recurrence feedback combinationally from those same `Q` bits back into the `q_in` ports. If the parent instead registered the concatenated `q` again, or if it fed the recurrence from `r` or from a pre-edge copy, the checker would see a one-cycle offset or a wrong next state.

A short worked example: suppose the first sampled edge has `L=1` and `r=101`. All three submodules load, so `q` becomes `101`. On the next sampled edge with `L=0`, the correct recurrence gives `q[2] <= q[1]^q[2] = 0^1 = 1`, `q[1] <= q[0] = 1`, and `q[0] <= q[2] = 1`, so `q=110`. The checker should expect exactly `110` at that second sampled edge. A hierarchical design that accidentally delays the feedback by one cycle would instead present the old `q=101` to the muxes at that edge and produce `101`, which the checker must reject. Likewise, a design that computes the XOR from `r[1]^r[2]` rather than from the current `q[1]^q[2]` would fail whenever `r` differs from the loaded `q` after a load.

Because the submodule is only one bit wide, the checker should also verify that the parent's bit ordering is consistent: the instance producing the MSB of `q` must receive the XOR of the two high bits of the current `q`, the middle instance must receive the old LSB, and the LSB instance must receive the old MSB. Any permutation of these three feedback connections is a functional bug even though each individual submodule behaves correctly. The checker should therefore drive at least one `L=0` edge after a load where the three bits are not all equal, and preferably where `q[1]^q[2]` differs from both `q[1]` and `q[2]`, so that a swapped feedback path is visible. The example `q=101` then `L=0` giving `110` satisfies this: the XOR term is `1`, the middle bit is `1`, and the LSB is `1`, so a design that fed `q[2]` into the MSB instance or `q[1]` into the LSB instance would produce a different three-bit result.

Finally, the checker must treat the initial state as unknown and only begin comparing after the first sampled edge with `L=1`. Before that, the submodule flipflops may hold any value, and the parent's `q` is not constrained by the public specification. Mid-cycle changes to `L` or `r` after a sampled edge must not alter the just-sampled `q`; they are visible only at the next `posedge clk`. The checker should therefore sample `q` after the edge has settled, then apply any optional mid-cycle stimulus, and compare only at the following sampled edge.
