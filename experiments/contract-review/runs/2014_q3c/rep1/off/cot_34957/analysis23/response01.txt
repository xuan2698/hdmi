A useful distinguishing example is the row `y=011`. With sampled `x=0`, the table selects next state `001`, so expected `Y0=1` and `z=1`. If `x` changes to `1` after the sampling edge, the same present state would select `010` with `Y0=0`, but that later value belongs to the next row. The checker must latch the sampled `y` and `x` at the active edge and compute expected `Y0` and `z` from that latched pair only. Recomputing from live `x` after the edge can falsely flag a correct design. Also, only listed states have required outputs; unlisted states and reset behavior are unspecified and should not be treated as violations. Compare only `Y[0]` and `z`, not `Y[2:1]`.
