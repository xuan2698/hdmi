The key point for the final checker is that the expected values are a pure function of the sampled `(y, x)` pair, not of any later input value. At each positive edge, capture `y` and `x` as they are at that instant, then look up the row. For `Y[0]`, select the next-state entry for the captured `x` and take bit 0. For `z`, use the row’s output bit, which is independent of `x`.

A short worked example: if the sampled pair is `y=011, x=1`, the row selects next state `010`, so `Y[0]=0`, and the row output is `z=1`. If `x` later changes to `0` before the next edge, that change belongs to the next row; using it for the current row would wrongly predict next state `001` and `Y[0]=1`. The checker should therefore latch the sampled pair and compare only against that lookup, skipping undefined `y` encodings and making no assumptions about reset or initial state.
