The most useful implementation mistake to flag is **input attribution**: the checker must snapshot `(y, x)` at the intended sampling point and perform the table lookup using only that snapshot. It should compare `Y[0]` against the least-significant bit of the next state selected by the snapshot’s `x`, and compare `z` against the row’s output column. Any post-sampling change on `x` belongs to the next row and must not be applied retroactively to the current row. A checker that reads `x` after the edge, or that lets the mid-cycle change overwrite the sampled `x`, will produce false failures.

Worked example: sampled edge sees `y=011`, `x=0`. Row `011` gives next state `001` when `x=0`, so `Y[0]=1`; `z=1`. If `x` changes to `1` after sampling, that belongs to the next row. Reading `x` late would wrongly expect `Y[0]=0` for the `y=011` row.
