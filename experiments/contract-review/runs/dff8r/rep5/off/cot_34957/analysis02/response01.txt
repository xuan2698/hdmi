The public specification describes a single 8-bit register built from eight D flip-flops that share one clock and one active-high synchronous reset. Because every flip-flop sees the same `clk` and the same `reset`, the output `q` is always an all-or-nothing 8-bit value: on a sampled rising edge it is either the full current `d` byte or `0x00`. There is no legitimate state in which some bits update and others do not. That invariant is the most useful anchor for the final Python checker, because it lets the checker reject any observed `q` that is neither the expected data byte nor zero without needing to reason bit by bit.

Reset behavior is synchronous and edge-sampled. A high `reset` has no effect between edges; it only matters at the positive edge of `clk`. At that edge, if `reset` is high, all eight flip-flops load zero, so `q` becomes `0x00` regardless of `d`. If `reset` is low at the edge, the register loads the current 8-bit `d`. The checker should therefore evaluate reset only at the sampled edge, using the reset value in force at that edge, and should not treat a reset pulse that begins and ends between edges as having cleared `q`.

Power-up behavior is not specified as a defined value. The prose gives no initial `q`, no reset-at-time-zero guarantee, and no statement that the register starts at zero. The checker should therefore avoid asserting a particular `q` before the first sampled rising edge, or should treat the pre-first-edge output as don't-care unless the testbench explicitly drives a reset edge first. After the first sampled edge with `reset=1`, `q` is known to be `0x00`; after the first sampled edge with `reset=0`, `q` is known to be the `d` present at that edge. Any assumption of zero-initialized state would be an extra contract not present in the public spec.

The timing model has three distinct moments the checker must keep separate: the input state at the sampled rising edge, the post-edge output `q`, and any carried mid-row input change for the next row. A mid change occurs after sampling and before the other edge, and it is carried to the start of the next row. It must not retroactively alter the current row's sampled `q`, but it must be used when computing the next row's expected output. The checker should sample `q` immediately after each rising edge against the inputs stable at that edge, then apply mid changes to the input state for the following row.

A short worked example: at row 1, `reset=0` and `d=0x3C` at the rising edge, so `q` becomes `0x3C`. A mid change later in row 1 sets `d=0xA5`; row 1's `q` remains `0x3C`, but the carried state for row 2 is `d=0xA5`. At row 2's rising edge, if `reset=0`, expected `q` is `0xA5`; if `reset=1`, expected `q` is `0x00`.

The useful point for the final Python checker: compute expected `q` only from the input state at the sampled edge, including any carried mid change, and enforce the full-width invariant that `q` is either the expected `d` byte or `0x00`. Do not let mid changes affect the current row, do not ignore them for the next row, and do not assume a defined power-up value.
