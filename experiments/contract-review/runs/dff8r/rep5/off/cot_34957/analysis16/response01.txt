The public interface is an 8-bit D flip-flop bank with a single active-high synchronous reset and a positive-edge clock. Inputs are `d` (8 bits) and `reset` (1 bit); output is `q` (8 bits). Because `d` and `q` are both 8 bits wide, the natural temptation is to model them as bytes. The specification’s boundary behavior argues against that shortcut: the eight flip-flops are independent storage elements sharing only `clk` and `reset`, and the checker should preserve that independence.

The reset is synchronous and active high. It is not an asynchronous clear. A high `reset` sampled at a rising edge forces all eight outputs to zero at that edge. A high `reset` that appears and disappears between rising edges has no effect on `q` until the next sampled edge. Likewise, a high `reset` held across an edge clears `q` at that edge, and `q` stays cleared only as long as subsequent sampled edges also see `reset` high (or see `d=0` with reset low).

The key bookkeeping point for the final Python checker is that the eight data bits and eight output bits must be tracked per bit, not as a single byte. The public spec permits mid-cycle input changes that may affect only some of the eight D inputs. If the checker stores `d` as one byte and applies an override as one byte, it can mask or misplace bits. Each D input is captured independently at the rising edge, and each Q output is updated independently, all gated by the same sampled reset. A mid-cycle change to `d` after sampling must be carried to the next edge bit-for-bit, not collapsed into a byte-level last value.

A short worked example shows the divergence. Suppose at edge 1 the captured inputs are `d=0xF0`, `reset=0`, so expected `q=0xF0`. After sampling, a mid-cycle override changes only the low nibble of `d` to `0x0F`, giving `d=0xFF` for the next edge, with `reset` still 0. At edge 2 the expected `q` is `0xFF`. A checker that stored the override as a byte and then applied it with a mask error, or that validated edge 1 against the post-override byte, would report a false mismatch at edge 1 or a false pass at edge 2. The per-bit view makes the carry unambiguous: bits 7..4 keep `0xF`, bits 3..0 become `0xF`.

The final checker should keep the expected next-state vector as eight independent bits, update it only at the sampled edge using the captured `reset` and `d`, and apply any mid-cycle override to that vector before the next sample. The reset must be evaluated at the edge, not as an asynchronous clear. Since the spec defines no power-up value, the checker must not assume `q=0x00` before the first sampled edge, and it must not treat a `0x00` result with `reset=0`, `d=0x00` as evidence of a reset. Classify each edge by the captured `reset` and `d`, then compare the settled `q`.
