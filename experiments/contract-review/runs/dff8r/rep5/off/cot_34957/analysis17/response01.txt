The public spec defines eight independent positive-edge-triggered D flip-flops sharing one clock, one active-high synchronous reset, and an 8-bit data input. The essential behavior is: at each rising edge of `clk`, if the sampled `reset` is high, every `q` bit becomes 0; otherwise each `q` bit takes the value of its corresponding `d` bit. Because the reset is synchronous, it has no effect except at a sampled rising edge. Because there are eight separate flip-flops, the checker must reason per bit rather than treating `d` and `q` as atomic bytes.

A useful distinguishing example for the final Python checker is a mid-cycle change that touches only part of the data bus. Suppose before edge 1 the driven inputs are `d = 0xF0` and `reset = 0`. At edge 1 the expected output is therefore `q = 0xF0`. After that edge has been sampled, the protocol allows an optional mid-cycle input change before the next edge. Let that change alter only the low nibble of `d`, so the value carried to edge 2 is `d = 0xFF`, while `reset` remains 0. At edge 2 the expected output becomes `q = 0xFF`. The high nibble keeps the value captured at edge 1, and the low nibble takes the newly driven value at edge 2.

This example exposes two common checker mistakes. First, a checker that validates edge 1 against the post-override byte `0xFF` would falsely flag a mismatch, because the override occurred after sampling and must not retroactively affect the edge-1 comparison. Second, a checker that stores the override as a single byte and then applies it incorrectly, for example by replacing the whole `d` byte or by using a wrong mask, could lose the distinction between the high and low nibbles. The correct bookkeeping is bitwise: bits 7 through 4 retain `0xF`, and bits 3 through 0 become `0xF`, yielding `0xFF` for the next sampled edge.

The final checker should therefore maintain the expected next-state vector as eight independent bits. At each sampled rising edge, it should read the captured `reset` and `d`, compute the next `q` bit by bit, and compare against the settled output. Any mid-cycle input change should update the pending `d` vector for the next edge only, without altering the already-sampled edge’s expected result. The reset must be evaluated at the edge, not as an asynchronous clear. Also, since the public spec gives no power-up value, the checker must not assume `q = 0x00` before the first sampled edge, and it must not confuse a legitimate `q = 0x00` produced by `reset = 0` and `d = 0x00` with a reset event. Each edge should be classified by its captured `reset` and `d`, then compared to the settled `q`.
