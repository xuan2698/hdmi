The public specification defines an 8-bit register bank: eight D flip-flops sharing a common clock `clk`, a common active-high synchronous reset `reset`, an 8-bit data input `d[7:0]`, and an 8-bit output `q[7:0]`. All eight flip-flops update on the positive edge of `clk`. The reset is synchronous and active high, so when `reset` is high at a rising edge, every flip-flop loads zero; when `reset` is low at that edge, each flip-flop loads its corresponding bit of `d`. There is no asynchronous clear and no specified power-up value for `q`.

Port widths are straightforward but worth stating explicitly for the checker. The input `d` is 8 bits wide, so valid driven values range from `0x00` through `0xFF`. The input `reset` is 1 bit wide, so its meaningful values are 0 and 1; any multi-bit representation should be treated as a single-bit control, and the checker should not infer behavior from wider encodings. The output `q` is 8 bits wide, with the same `0x00`–`0xFF` range. The clock `clk` is a single sampling signal, not a data port. Because the design contains eight independent D flip-flops sharing reset and clock, all eight output bits update together at the sampled edge; there is no per-bit enable or independent reset.

The boundary behavior follows from the synchronous nature of reset. A high `reset` does not clear `q` as soon as it is asserted; it only forces zero if it is high at the positive clock edge. Similarly, changes on `d` between edges do not affect the current `q`; they only become candidates for the next sampled edge. The protocol note that optional mid input changes occur after sampling and before the other edge, then carry to the start of the next row, reinforces that the checker must separate edge-time values from later row values.

A short worked example: suppose before a rising edge `d = 0xA5` and `reset = 0`, with previous `q = 0x3C`. After the edge settles, expected `q` is `0xA5`. If after sampling `d` changes to `0x0F` and `reset` changes to 1, the current `q` remains `0xA5`; those mid values are carried to the next row. At the next rising edge, if no new pre-edge drive overrides them, `reset = 1` forces `q` to `0x00`.

For the final Python checker, the key point is to snapshot the inputs present at the sampled positive edge and compute the expected post-edge `q` solely from that snapshot: `q_next = 0x00` if `reset` is high, otherwise `q_next = d`. Compare `q` only after the positive edge has settled, and do not let mid-row changes retroactively alter the current comparison. Also avoid assuming a defined pre-first-edge `q`, since the specification gives no asynchronous power-up value; begin strict checking from the first post-edge sample using the reset value carried into that edge. This prevents the checker from confusing edge-time inputs with later row inputs, which is the most consequential distinction in this specification.
