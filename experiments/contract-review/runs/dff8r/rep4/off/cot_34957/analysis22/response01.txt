The public spec defines an 8-bit register bank: eight D flip-flops sharing a single clock `clk`, a single active-high synchronous reset `reset` (1 bit), and an 8-bit data input `d`. The output is `q`, 8 bits wide. All eight flops are triggered on the positive edge of `clk`. Reset is synchronous and active high, meaning when `reset` is sampled high at a rising edge, every flop loads zero; when `reset` is sampled low at a rising edge, each flop loads its corresponding bit of `d`. There is no asynchronous clear, no enable, and no per-bit reset.

Port widths are therefore: `clk` scalar, `reset` 1 bit, `d` 8 bits, `q` 8 bits. Boundary values worth noting for the checker: `d` ranges over 0x00–0xFF inclusive, and both extremes are legal data values, so a checker must not treat 0x00 as a sentinel for "no data" or as evidence of reset. `reset` takes only 0 or 1; any other value is out of scope. Because reset is synchronous, a high `reset` has no effect between edges — it only matters at the sampled rising edge. This is the single most important semantic point: the checker must not model reset as level-sensitive or immediate.

The protocol note sharpens the edge-sampling model. Inputs present at the positive edge determine the expected `q` for that edge. Changes to `reset` or `d` that occur after sampling and before the opposite edge are carried forward to the start of the next row and must not retroactively change the expected output for the edge just sampled. In checker terms, each stimulus row is the set of values driven before the sampled edge; optional mid-row changes update inputs for the following row only.

Worked example: at a rising edge, sampled `reset=0`, `d=0xA5`, so expected `q=0xA5`. If `reset` then rises mid-cycle, `q` stays `0xA5` until the next rising edge; at that edge, with `reset=1` sampled, expected `q=0x00`. If instead mid-cycle `d` becomes `0x3C` with `reset` low, the next edge loads `0x3C`, and `0xA5` remains valid until then.

A critical limitation: the spec does not state power-up clears the flops and provides no time-zero reset. The checker must not assume `q=0` before the first sampled positive edge. Only edge-produced values are constrained: a reset edge loads zero, a normal edge loads `d`. Before any such edge, `q` is unspecified. The checker should either wait for an explicit initialization event or begin comparing only after the first sampled edge whose behavior the stimulus defines. Inventing an initial zero is unsupported.

For the final Python checker, the key modeling rule is: keep one 8-bit state, sample inputs only at positive edges after settling, and apply mid-cycle updates only to the next row. That ordering prevents asynchronous reset handling, prevents late `d` changes from affecting the previous edge, and avoids unsupported power-up assumptions.
