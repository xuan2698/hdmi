The public specification describes eight independent D flip-flops sharing a common clock, a common active-high synchronous reset, and a common 8-bit data input. The output is the 8-bit state of those flip-flops. The only edge that matters is the positive edge of `clk`. Because reset is synchronous and active high, it is not an asynchronous clear: a high reset value affects the outputs only when it is present at the sampled positive edge. A reset pulse that occurs entirely between edges, or that is removed before the next sampled edge, does not clear the outputs.

The checker is instructed to sample after the positive edge has settled. Therefore the observed `q` for a row is the settled post-edge value. The row’s inputs are driven before that sampled edge, so the expected post-edge `q` is determined by the pre-edge values of `d` and `reset`. If the pre-edge `reset` is high, all eight flip-flops are synchronously cleared and expected `q` is `0x00`. If the pre-edge `reset` is low, each flip-flop loads its corresponding `d` bit, so expected `q` is the 8-bit value of `d`. There is no other state transition in this specification: no enable, no load control, and no asynchronous behavior.

Optional mid-row input changes occur after sampling and before the other clock edge. They are carried to the start of the next row. This timing detail is important because it means a mid-row change to `d` or `reset` must not retroactively alter the current row’s expected output. The current row’s expected value is fixed by the pre-edge snapshot that was sampled. The carried inputs then become the starting inputs for the next row, subject to whatever further driving occurs before that next sampled edge.

A useful discipline for the final Python checker is to separate the pre-edge snapshot from the carried state. For row N, read the pre-edge `d` and `reset`, compute expected `q` as `0x00` when `reset` is high and otherwise as `d`, compare that against the settled post-edge `q`, and only afterward apply any mid-row changes to the carried inputs for row N+1. A mid-row change to `d` or `reset` must never alter row N’s expected value. Likewise, a reset pulse that appears and disappears entirely between sampled edges has no effect, because reset is synchronous: only its value at the sampled positive edge matters. The checker should avoid race-resolution logic and instead rely on the settled post-edge observation plus the pre-edge snapshot.

A short worked example: row N drives `d = 0x3C` and `reset = 0` before the edge, so expected `q = 0x3C`. After sampling, `d` changes to `0xA5`. Row N’s expected `q` stays `0x3C`; the change is carried to row N+1. If row N+1 samples with `reset = 0`, expected `q = 0xA5`; if it samples with `reset = 1`, expected `q = 0x00`.

The key point to stop on: compute the current row’s expected `q` from the pre-edge sampled `d` and `reset`, compare it, and only afterward advance the carried inputs. Mid-row updates must not leak backward into the current row’s expected output.
