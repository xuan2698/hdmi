The public interface is an 8-bit register bank with a single clock, `clk`, an 8-bit data input `d`, a 1-bit synchronous reset `reset`, and an 8-bit output `q`. All eight D flip-flops share the same clock and reset, so the register behaves as one 8-bit word rather than eight independently controlled elements. There is no enable, no load-select, and no asynchronous reset path. The only sampled control is `reset`, and it is active high.

The boundary values follow directly from those widths. `d` ranges over `0x00` through `0xFF`, and `q` ranges over the same 8-bit space. `reset` is a single bit, so its meaningful values are 0 and 1. At each sampled positive edge, if the pre-edge `reset` is high, every flip-flop is synchronously cleared and the expected `q` is `0x00`. If the pre-edge `reset` is low, each flip-flop loads its corresponding `d` bit, so the expected `q` is exactly the 8-bit value of `d`. There is no other state transition in this specification.

The timing boundary is the positive edge of `clk`. The checker should sample after that edge has settled, using the pre-edge values of `d` and `reset` as the inputs that determine the row’s expected output. Optional mid-row input changes occur after sampling and before the other clock edge, and they are carried to the start of the next row. That means a mid-row change to `d` or `reset` must not retroactively alter the current row’s expected `q`. The current row’s expected value is fixed by the pre-edge snapshot. The carried inputs then become the starting inputs for the next row, subject to any further driving before that next sampled edge.

A useful discipline for the final Python checker is to separate the pre-edge snapshot from the carried state. For row N, read the pre-edge `d` and `reset`, compute expected `q` as `0x00` when `reset` is high and otherwise as `d`, compare that against the settled post-edge `q`, and only afterward apply any mid-row changes to the carried inputs for row N+1. A mid-row change to `d` or `reset` must never alter row N’s expected value. Likewise, a reset pulse that appears and disappears entirely between sampled edges has no effect, because reset is synchronous: only its value at the sampled positive edge matters. The checker should avoid race-resolution logic and instead rely on the settled post-edge observation plus the pre-edge snapshot.

A short worked example: row N drives `d = 0x3C` and `reset = 0` before the edge, so expected `q = 0x3C`. After sampling, `d` changes to `0xA5`. Row N’s expected `q` stays `0x3C`; the change is carried to row N+1. If row N+1 samples with `reset = 0`, expected `q = 0xA5`; if it samples with `reset = 1`, expected `q = 0x00`.

The key point to stop on: compute the current row’s expected `q` from the pre-edge sampled `d` and `reset`, compare it, and only afterward advance the carried inputs. Mid-row updates must not leak backward into the current row’s expected output.
