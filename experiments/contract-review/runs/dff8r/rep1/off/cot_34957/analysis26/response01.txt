The public specification defines eight D flip-flops sharing `clk`, with active-high synchronous `reset` forcing `q` to zero. Because reset is synchronous, it is sampled at the positive edge like `d`; it does not asynchronously clear outputs between edges. Power-up behavior is not specified, so the checker should not assume any particular initial `q` before the first sampled edge—only post-edge values are meaningful. The timing protocol is the main source of checker errors: each row's inputs are driven before the sampled positive edge, so the expected `q` for that row depends only on the `d` and `reset` values present at that edge. Mid-row changes occur after sampling and carry to the next row. For example, if at row N's edge `d = 0x3C` and `reset = 0`, expected `q` is `0x3C`; a later mid-row change to `d = 0xA5` affects only row N+1. The checker should sample, compute, compare, then advance carried inputs.
