The public specification describes a synchronous decade counter with a single active-high reset and a 4-bit output. The counter advances on the rising edge of `clk`, producing the sequence 0,1,2,…,9,0,… with period 10. Reset is synchronous and active high: when `reset` is 1 at the sampled rising edge, the next state is 0 regardless of the previous count. When `reset` is 0 at that edge, the next state is the previous count plus one, except that 9 wraps to 0. The output `q` is 4 bits wide, but only values 0 through 9 are legal after any sampled edge. The input `reset` is 1 bit wide and should be treated as a Boolean at the edge.

The key point for the final Python checker is the timing separation encoded by each row. Each row has three regions: the pre-edge driven values, which determine what the sampled edge sees; the post-edge settled output, which is the row’s expected `q`; and an optional mid-cycle input change that occurs after sampling and before the next edge. The checker must compute the expected next state from the previous sampled state and the `reset` value that was active at the sampled edge. It must not compare the current row’s `q` against a reset value that appears only after sampling. Mid-cycle changes are carried forward to the next row’s pre-edge values and must never retroactively affect the current row’s expected output.

A short worked example illustrates the hazard. Suppose the previous sampled state is `q=9`, and the next row drives `reset=0` before the rising edge. After the edge settles, the expected `q` is 0 because 9 wraps to 0. If that same row then has a mid-cycle change setting `reset=1` after sampling, that change belongs to the start of the following row. It does not make the current row’s `q` become 0 again at the same edge. The following row would then sample `reset=1` and also produce `q=0`. This distinction prevents an off-by-one-row error in the checker.

Because reset is synchronous, an asynchronous reset assertion between edges should not be modeled as immediately clearing `q`. Only the sampled edge matters. The checker should therefore ignore mid-cycle reset changes for the current row’s expected output and apply them only when they become pre-edge values for the next row. It should also enforce that `q` is always in 0–9 after each sampled edge, including after reset. The modulo behavior must be implemented as wrap from 9 to 0, not as binary modulo 16, since the output is 4 bits but the legal range is decimal 0–9. The checker should validate bit widths: `reset` as a single-bit Boolean at the sampled edge and `q` as a 4-bit value whose numeric value is constrained to 0–9. The protocol seed affects only stimulus order, not the functional contract, so the checker should rely on row semantics rather than seed-specific assumptions. The main risk is conflating mid-input changes with edge-sampled inputs; the final checker should explicitly carry mid changes to the next row and never apply them to the current row’s expected output.
