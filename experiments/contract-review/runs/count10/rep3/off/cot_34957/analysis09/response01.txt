The public specification defines a synchronous decade counter with a single active-high reset input and a 4-bit output q. The counter advances on the rising edge of clk, counting 0,1,2,...,9 and then wrapping back to 0, giving a period of 10. Reset is synchronous and active high: when reset is asserted at the sampled clock edge, the counter is forced to 0 regardless of its previous value. When reset is inactive, the counter increments by one modulo 10.

The key state variable for checking is the previous sampled output value, which represents the counter state before the current edge. For each sampled row, the checker should determine the reset value that is actually present at the clock edge, not any later value that may appear mid-cycle. The expected next output is then computed as follows: if reset is active at the sampled edge, expected q is 0; otherwise expected q is (previous state + 1) mod 10. This formulation correctly handles the wrap from 9 to 0 and also correctly gives priority to reset at the wrap boundary.

A subtle but important point is that the reset priority at state 9 produces the same output, 0, whether reset is active or inactive. A checker that only compares the output q to 0 cannot distinguish a correct wrap from a reset-induced clear. That is acceptable for output-only checking, but the checker should still compute the expectation using the reset-at-edge value and the previous state, rather than first incrementing 9 to 10 and then clearing. Modeling the increment as producing 10 and then applying reset can hide a design that fails to wrap when reset is inactive, because the erroneous intermediate value is never observed.

Another important point concerns mid-cycle input changes. The protocol states that each row’s values are driven before the sampled edge, and optional mid input changes occur after sampling, before the other edge, and are carried to the start of the next row. Therefore, a reset change that occurs after the sampled edge must not affect the current row’s expected output. It becomes the reset value for the next row. A checker that reads the final reset value of the row, rather than the reset value active at the sampled edge, can either falsely flag a correct design or accept an incorrect one.

Worked example: suppose the previous sampled state is q=9 and the current row drives reset=0 before the edge. The expected q after the edge is 0 because of the decade wrap. If reset then changes to 1 after sampling, the next row samples reset=1 and also expects q=0, but the current row’s expected q remains based on reset=0 and previous state 9.

For the final Python checker, the useful focus is to track the previous sampled state, use the edge-sampled reset value, compute expected next state as 0 if reset_at_edge else (prev+1)%10, and carry mid-cycle reset changes only to the next row. The checker should not model reset as an immediate asynchronous clear, should not use modulo 16, and should not let seed-specific stimulus order affect the functional expectation.
