The decade counter is a synchronous finite-state machine with ten legal states, 0 through 9. Its output `q` is the state itself, so state and output transitions coincide. The only control input is `reset`, which is active high and synchronous: it is sampled at the rising edge of `clk`, and when sampled high it forces the next state to 0. When sampled low, the next state advances by one modulo 10. There are no other inputs, no enable, and no direction control. The period is therefore exactly ten clock edges in the absence of reset.

The transition relation is total on the legal state set. From any state `s` in 0–8 with `reset=0`, the next state is `s+1`. From state 9 with `reset=0`, the next state is 0. From any state with `reset=1`, the next state is 0. This means reset and the natural 9-to-0 wrap both produce output 0, but for different reasons. That coincidence is the central hazard for the checker: a row where the previous state is 9, reset is low, and the observed next state is 0 is a legitimate wrap, not evidence of reset. Conversely, a row where reset is high and the observed next state is 0 is a reset, even if the previous state was 8 and a normal increment would also have produced 9. The checker must classify the row by the reset value sampled at the edge, not by the observed output alone.

Because reset is synchronous, it does not affect the current sampled output; it affects the next sampled output. A reset asserted before edge N is visible in the state sampled at edge N, and it determines the state sampled at edge N+1. The checker should therefore hold the previous sampled state and the reset value driven before the current sampled edge, then compute the expected current state as 0 if that reset value is 1, otherwise `(prev+1) mod 10`. Post-sampling changes to reset belong to the next row and must not retroactively change the current row's expectation.

Illegal outputs must be rejected independently of reset. If the sampled `q` is 10 through 15, the design has left the decade state set, and no reset value makes that observation acceptable. This is the point that distinguishes a decade counter from a modulo-16 counter that happens to return to 0 after sixteen states. Eventual return to 0 is not sufficient evidence of correctness; each transition must satisfy the decade rule.

Initialization is underspecified. The public specification defines synchronous reset but not a power-up value. The checker should not assume the first sampled output is 0. It can either use the first sample only as a reference and begin judging from the second row, or require an initial sampled reset assertion to establish state 0. If the first judged edge has reset high, the expected output is 0; otherwise the first row should not be used to infer a power-up state.

Worked example: previous sampled state 9, reset driven low before the edge, observed `q=0`. Expected next state is `(9+1) mod 10 = 0`, so the row passes as a wrap. If reset changes to 1 after sampling, that change applies to the following row only. A checker that used the later reset value would still predict 0, but for the wrong reason, and could mask a modulo-16 defect on the same row.

For the final Python checker, the useful focus is to latch the edge-sampled reset, keep the previous sampled state, compute `next = 0` if reset is 1 else `(prev+1) mod 10`, reject any `q` outside 0–9, and ignore post-sampling stimulus changes for the current row. Do not assume asynchronous reset or a modulo-16 wrap.
