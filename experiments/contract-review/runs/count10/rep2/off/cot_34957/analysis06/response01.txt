One likely implementation mistake is to treat the reset as asynchronous, or to let a mid-cycle reset change affect the transition that was already sampled. The public specification says the reset is active high and synchronous. That means the reset value is observed at the sampled rising edge and determines the next state from that edge. A reset that changes after sampling but before the next edge belongs to the next row, not the current one. A checker that simply looks at the final reset value for a row, or that lets a post-sample change rewrite the expected transition, can accept or reject the wrong behavior.

A second common mistake is to assume a particular power-up state. The specification defines the decade sequence and synchronous reset-to-zero, but it does not promise that `q` starts at 0 before any reset. If the checker begins from an unknown or uninitialized `q`, it must not assume a pre-reset count. It should apply the sampled reset priority first: if reset is high, expected next `q` is 0 regardless of current `q`. Otherwise, if current `q` is 9, expected next `q` is 0; otherwise expected next `q` is current `q + 1`. Values 10 through 15 are not normal successor states and should not appear outside reset.

A short worked example: before a sampled rising edge, suppose `reset = 0` and current `q = 9`. The expected next `q` is 0. If `reset` then changes to 1 after sampling and before the next edge, that change belongs to the next row. At the next sampled edge, with `reset = 1`, the expected `q` is again 0. The mid-cycle change must not retroactively alter the already-sampled 9→0 transition.

For the final Python checker, the useful focus is to model the sampled edge explicitly. Read the row’s driven `reset` and current `q`, compute the expected next `q` using synchronous reset priority, then compare after the posedge has settled. Keep “input value at the sampled edge” separate from “input value carried into the next row.” Verify that reset forces 0 regardless of current count, that counting increments otherwise, and that the only normal wrap is 9→0. Do not assume asynchronous reset or a defined power-up state. This discipline captures the public timing contract and the decade behavior.
