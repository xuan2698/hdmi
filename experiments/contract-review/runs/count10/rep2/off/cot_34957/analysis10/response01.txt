The public interface is a single clocked block with one 1-bit input, `reset`, and one 4-bit output, `q`. The clock is `clk`; sampling is specified after the positive edge has settled. Because `q` is 4 bits, its representable values are 0 through 15, but the public behavior is confined to the decade cycle 0 through 9. Values 10 through 15 are outside the normal cycle and should not be produced by normal operation. The checker should therefore treat any observed normal-state value above 9 as a failure, while still allowing an arbitrary first observable value before the first sampled reset if the specification leaves power-up undefined.

The reset input is active high and synchronous. Its priority is important: when a sampled edge has `reset` high, the expected next `q` is 0, independent of the current `q`. When `reset` is low, the expected next `q` follows the decade rule: 0→1, 1→2, …, 8→9, and 9→0. The wrap from 9 to 0 is the only normal wrap. The checker should not model values 10 through 15 as part of the cycle, and it should not infer an asynchronous reset from the word “reset.” Only the sampled value at the positive edge matters for the transition being checked.

A subtle boundary is the initial state. The public specification does not define a power-up value for `q`. The checker must not assume that the counter starts at 0 before any reset. On the first sampled edge, it should use the observed current `q` together with the sampled `reset`. If that first sampled `reset` is high, the expected next `q` is 0 regardless of the observed initial value. If that first sampled `reset` is low, the checker should apply the normal decade rule to the observed current `q`, not to an assumed initial state. This avoids a false failure when a correct implementation has an undefined or arbitrary first observable state before reset.

Mid-cycle input changes are carried to the next row and must not retroactively change the transition already sampled. For example, suppose the current `q` is 9 and `reset` is low at a sampled rising edge. The expected next `q` is 0. If `reset` then changes to high after sampling and before the next edge, that high value belongs to the next row. At the next sampled edge, with `reset` high, the expected next `q` is again 0. The earlier 9-to-0 transition remains valid. Similarly, if `reset` is high at a sampled edge and then goes low mid-cycle, the reset transition to 0 still stands; the low value only prepares the next row.

The final checker should separate the input value at the sampled edge from the input value carried into the next row. It should compute the expected next `q` from the sampled `reset` and the current `q`, then compare after the positive edge has settled. It should verify reset priority, normal incrementing, the single wrap 9-to-0, and the absence of normal states 10 through 15. It should not assume asynchronous reset or a defined power-up state.
