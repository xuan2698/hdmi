The key distinguishing point for the checker is the interaction between the synchronous reset and the unspecified out-of-range states. A short example: suppose the sampled row has `q = 9`, `reset = 0`. The expected next `q` is 0. After sampling, `reset` is driven high before the next rising edge. At the next sampled edge, the observed `q` is 0 and sampled `reset` is 1, so the expected next `q` is again 0. The earlier 9→0 transition must remain valid; the later reset applies only to the following transition. This shows why the checker must evaluate reset at the sampled edge, not let a mid-cycle reset change the prior expectation.

A second useful point is that the checker should not require the first sampled `q` to be 0. The public spec gives no power-up value, so the first row is an observed state. If the first sampled `q` is, say, 4, the checker should accept that and begin checking transitions from 4. Requiring an initial 0 would reject a legal trace.

For out-of-range states, the checker should be permissive only in the normal-transition branch. If the observed `q` is 10–15 and sampled `reset` is 0, the public spec does not define the next state, so the checker should not impose 0, saturation, or any wrap rule. If sampled `reset` is 1, however, the next state must be 0 even from an out-of-range value, because the reset rule is unconditional on the current `q`.

The decision order should therefore be: read observed `q` and sampled `reset`; if `reset` is high, expect next `q = 0`; otherwise, if observed `q` is in 0–9, expect the decade successor with 9→0; otherwise, impose no normal transition. Post-sampling input changes should be carried only to the next row. This avoids three common errors: letting reset priority leak backward across the sampled edge, requiring an unspecified initial 0, and inventing behavior for out-of-range states.
