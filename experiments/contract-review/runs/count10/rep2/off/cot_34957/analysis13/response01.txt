The key distinction for the checker is between the `reset` value that is sampled at a rising edge and the `reset` value that is carried forward to the next row. The public spec says reset is active high synchronous, so reset affects the transition that is checked at the edge where it is sampled. A mid-cycle change in `reset` occurs after sampling and before the next edge; it must not retroactively change the already-sampled transition. It only becomes the sampled reset value for the next row.

For each sampled edge, the checker should compute the expected next `q` from two inputs: the current observed `q` and the `reset` value sampled at that same edge. If the sampled `reset` is high, the expected next `q` is 0. If the sampled `reset` is low, the expected next `q` follows the decade rule: 0→1, 1→2, …, 8→9, 9→0. The checker should not treat reset as asynchronous. It should not require `q` to become 0 immediately when `reset` changes between edges. It should only require the reset-to-0 behavior at the next sampled rising edge where `reset` is high.

The initial state is deliberately unspecified. A correct implementation may have an arbitrary first observable `q` before reset. Therefore, on the first sampled edge, the checker must use the observed current `q` together with the sampled `reset`. If that first sampled `reset` is high, the expected next `q` is 0 regardless of the observed initial value. If that first sampled `reset` is low, the checker must apply the decade rule to the observed current `q`, not to an assumed 0. Assuming a power-up value of 0 would create false failures.

A short worked example makes the timing clear. Suppose at a sampled rising edge the observed `q` is 9 and sampled `reset` is low. The expected next `q` is 0, the normal wrap. After sampling, `reset` goes high before the next rising edge. That high value is carried into the next row. At the next sampled edge, current `q` is 0 and sampled `reset` is high, so expected next `q` is 0. The earlier 9→0 transition remains valid; the mid-cycle reset change does not alter it. Conversely, if `reset` is high at a sampled edge and then drops low mid-cycle, the reset-to-0 transition still stands, and the low value only prepares the following row.

The checker should compare only after the positive edge has settled. It should verify reset priority, normal incrementing, the single 9→0 wrap, and the absence of normal states 10–15. It should carry post-sample input changes to the next row and avoid assuming either asynchronous reset or a defined power-up state.
