The public spec fixes `reset` at 1 bit and `q` at 4 bits, so the checker should compare only the low four bits of any expected count and treat `reset` as a single-bit sampled control. Boundary values are `q = 0` and `q = 9`: from 9 with `reset = 0`, the next settled `q` is 0; from any `q` with sampled `reset = 1`, the next settled `q` is 0. The key checker point is that the `reset` governing a rising-edge expectation is the value sampled for that row, not a later mid-cycle change. Example: settled `q = 4`, sampled `reset = 0` gives expected `q = 5`; a later `reset = 1` in that row applies to the next row, not retroactively.
