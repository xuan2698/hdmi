One likely implementation mistake is to treat the row’s final input values as the values seen by the sampled clock edge. The public protocol says each row’s values are driven before the sampled edge, and optional mid input changes occur after sampling and before the other edge. Those mid-row changes are carried to the start of the next row; they are not retroactively visible to the current row’s settled output. A checker that instead uses the final values of the row, or that applies reset/data changes before the sampled edge, will disagree with the specification on exactly the cases that distinguish a correct synchronous D flip-flop from a combinational or late-sampling model.

The reset is active high and synchronous. That means `r = 1` matters only if it is present in the pre-edge sampled snapshot at a positive clock edge. Merely holding `r` high between edges, or observing it after the edge, does not force `q` to 0. Likewise, power-up does not specify an asynchronous reset value. Any initial `q` used by the checker is a checker convention, not part of the reset behavior. The first row should therefore be evaluated from that convention plus the pre-edge sampled inputs, not from an assumption that reset has already cleared the state.

A useful implementation point for the final Python checker is to keep two separate carried values per row: the pre-edge input snapshot used to compute the current expected output, and the post-sampling input values that will seed the next row. The expected next state should be computed only from the sampled snapshot and the previous expected state. After comparing the settled observed `q` against that expectation, the checker updates its expected state and carries the post-sampling inputs forward. It must not recompute the current row from the row’s final input values, and it must not apply reset or data changes before the sampled edge.

Short worked example: suppose the state entering a row is `q_prev = 1`. Before the sampled rising edge, the driven inputs are `d = 0`, `r = 0`. After sampling, before the next edge, the inputs change to `d = 1`, `r = 0`. The correct settled output for this row is `q = 0`, because the sampled edge saw `d = 0`. The later `d = 1` is carried to the start of the next row and may affect the next sampled edge, but it must not change this row’s expected `q`. A checker using the row’s final input values would incorrectly expect `q = 1`.
