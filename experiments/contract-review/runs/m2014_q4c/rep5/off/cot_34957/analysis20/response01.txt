**Reset and power-up behavior**

The public specification defines a one-bit D flip flop with a single clock `clk`, data input `d`, active-high synchronous reset `r`, and output `q`. The critical timing statement is that the checker samples after the positive edge has settled. Inputs for a row are driven before that sampled edge. Optional mid-row input changes occur only after sampling and before the opposite edge, and those changes are carried to the start of the next row. This means the row’s expected output is determined by the input values present at the sampled positive edge, not by any later values that appear in the same row.

Because reset is synchronous, `r` does not act as an asynchronous clear. A high `r` only forces `q` to 0 when it is sampled at the active clock edge. If `r` rises after the sampled edge, it has no effect on the current row’s `q`; it is merely carried forward as part of the next row’s starting inputs. Likewise, if `r` is high before the sampled edge, reset has priority over `d`, so the next state is 0 regardless of the sampled data value. When sampled `r` is 0, the next state is simply the sampled `d`.

Power-up behavior is not specified as an asynchronous initialization value in the public description. The checker should therefore treat the initial expected state as part of the checker’s own setup rather than inferring an automatic hardware reset from power-on. In particular, the presence of a synchronous reset input does not imply that `q` is forced to 0 merely because power is applied or because `r` is high outside a sampled edge. The observable rule is edge-based: reset affects `q` only through the sampled positive edge. Any initial-state convention used by the checker must be kept separate from the synchronous reset semantics, and the first row should be evaluated using the previous expected state established by that convention together with the pre-edge sampled inputs.

A useful point for the final Python checker is to maintain two distinct notions per row: the pre-edge sampled inputs used to compute the current expected output, and the post-sampling carried inputs used as the next row’s starting inputs. The expected next state should be computed only from the sampled snapshot and the previous expected state. After comparing the settled observed `q` with that expected value, the checker updates its state and carries the post-sampling inputs forward. It must not recompute the current row from the row’s final input values, and it must not apply reset or data changes before the sampled edge.

Short worked example: suppose the state entering a row is `q_prev = 1`. Before the sampled rising edge, the driven inputs are `d = 0`, `r = 0`. After sampling, before the next edge, the inputs change to `d = 1`, `r = 0`. The correct settled output for this row is `q = 0`, because the sampled edge saw `d = 0`. The later `d = 1` is carried to the start of the next row and may affect the next sampled edge, but it must not change this row’s expected `q`. A checker using the row’s final input values would incorrectly expect `q = 1`.
