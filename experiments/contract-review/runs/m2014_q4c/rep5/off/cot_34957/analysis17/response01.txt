The key distinction for the checker is between the **sampled snapshot** and the **carried-forward inputs**. The public spec says each row's values are driven before the sampled edge, the checker samples after the positive edge has settled, and optional mid-row changes occur after sampling and before the other edge. Those mid-row changes are carried to the start of the next row. So the expected output for the current row must be derived from the pre-edge snapshot plus the previous expected state, never from the row's final input values.

For this D flip flop with active-high synchronous reset, the next-state rule is simple and has reset priority: if the sampled `r` is 1, the next `q` is 0 regardless of `d`; if the sampled `r` is 0, the next `q` equals the sampled `d`. Because reset is synchronous, a high `r` that appears only after the sampled edge does not affect the current row's output. It can only be carried forward and observed at the next sampled edge. Likewise, a `d` change after sampling must not retroactively alter the current row's expected `q`.

A useful point for the final Python checker is to maintain two separate pieces of information per row: the pre-edge sampled inputs used to compute the current expected output, and the post-sampling carried inputs used as the next row's starting inputs. Compute the expected next state only from the sampled snapshot and the previous expected state. Compare that expected value to the settled observed `q`. Then update the checker state and carry the post-sampling inputs forward. Do not recompute the current row from final row values, and do not apply reset or data changes before the sampled edge.

Short worked example: suppose the state entering a row is `q_prev = 1`. Before the sampled rising edge, the driven inputs are `d = 0`, `r = 0`. After sampling, before the next edge, the inputs change to `d = 1`, `r = 0`. The correct settled output for this row is `q = 0`, because the sampled edge saw `d = 0`. The later `d = 1` is carried to the start of the next row and may affect the next sampled edge, but it must not change this row's expected `q`. A checker using the row's final input values would incorrectly expect `q = 1`.
