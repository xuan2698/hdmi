The public interface is a single-bit D flip flop: inputs `d` and `r` are each one bit wide, output `q` is one bit wide, and there is one clock `clk`. The only legal values on each of `d`, `r`, and `q` are 0 and 1. There are no multi-bit buses, no enable, no separate set, and no asynchronous clear. The boundary values are therefore trivial in width but important in timing: every sampled input is either 0 or 1, and every expected output is either 0 or 1. The interesting boundary is not numeric range but the sampling boundary around the positive clock edge.

The specification says the flip flop has active-high synchronous reset. That means reset is not a level that immediately clears the output whenever `r` is high. Instead, `r` is observed at the sampled positive edge. If the sampled `r` is 1, the next output is forced to 0 regardless of `d`. If the sampled `r` is 0, the next output follows the sampled `d`. Because reset is synchronous, a change on `r` after the sampled edge must not retroactively affect the output for that row; it can only be carried forward to the next sampled edge.

The timing description also matters. Each row’s values are driven before the sampled edge. The checker should sample after the positive edge has settled. Optional mid-row input changes occur after sampling and before the other edge, and those changed values become the starting inputs for the next row. Thus each row has two relevant input pictures: the pre-edge snapshot used to compute the current expected output, and the post-sampling carried values used as the next row’s starting inputs. The expected output for the current row must be computed from the pre-edge snapshot and the previous expected state, not from the row’s final input values.

A useful point for the final Python checker is to keep those two notions separate. Compute the expected next state only from the sampled snapshot and the previous expected state, with reset priority: if sampled `r` is 1 then expected `q` is 0, else expected `q` is sampled `d`. Compare that to the settled observed `q`, then update the checker state and carry the post-sampling inputs forward. Do not recompute the current row from final row values, and do not apply reset or data changes before the sampled edge.

Short worked example: suppose the state entering a row is `q_prev = 1`. Before the sampled rising edge, the driven inputs are `d = 0`, `r = 0`. After sampling, before the next edge, the inputs change to `d = 1`, `r = 0`. The correct settled output for this row is `q = 0`, because the sampled edge saw `d = 0`. The later `d = 1` is carried to the start of the next row and may affect the next sampled edge, but it must not change this row’s expected `q`. A checker using the row’s final input values would incorrectly expect `q = 1`.
