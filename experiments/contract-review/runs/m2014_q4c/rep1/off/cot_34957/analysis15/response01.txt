The specification describes a one-bit D flip flop with active-high synchronous reset. The inputs are `d` and `r`, each one bit wide; the output is `q`, also one bit. The clock is `clk`, and sampling occurs after the positive edge has settled. Values for each row are driven before the sampled edge. Optional mid-row input changes occur after sampling and before the other edge, and those changes are carried to the start of the next row.

The key behavioral rule is reset priority at the sampled rising edge. At that edge, the checker should resolve the pre-edge values of `d` and `r`, then decide `q`. If the resolved `r` is 1, `q` becomes 0 regardless of `d`. If the resolved `r` is 0, `q` takes the resolved `d`. This decision uses only the inputs present at the settled edge. Mid-row changes must not retroactively affect the edge decision or the output already computed for that row.

It is useful to keep three pieces of state distinct: the current output `q`, the carried `d`, and the carried `r`. The carried values are those that survive from the previous row’s post-sampling mid-row changes. For each row, the pre-edge inputs are formed from the carried values plus any values driven in the current row before the sampled edge. At the settled rising edge, the checker resolves those pre-edge inputs and applies reset priority. Only after that edge decision should mid-row changes be processed. Those changes update the carried `d` and `r` for the next row; they do not alter `q` or the inputs already used at the edge.

A short worked example makes the separation concrete. Suppose a row begins with carried `d=1`, `r=0`, and current `q=0`. Before the rising edge the row drives `d=0`, `r=1`. The resolved pre-edge inputs are therefore `d=0`, `r=1`. At the settled edge, reset wins and `q` becomes 0. After sampling, a mid-row change sets `r=0` and leaves `d=0`. That change does not alter the just-computed `q`; it only means the next row begins with `d=0`, `r=0`. If the next row drives nothing before its edge, the next sampled inputs are `d=0`, `r=0`, so `q` remains 0. If the mid change had instead set `d=1`, the next row would begin with `d=1`, and a later rising edge with `r=0` would capture 1.

For the final checker, the practical rule is: resolve pre-edge inputs, apply reset priority at the settled edge, update `q` only from those resolved inputs, then process mid-row changes as carry for the next row. Make the initial `q` convention explicit and consistent, because the public specification does not define power-up behavior.
