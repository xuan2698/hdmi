The public interface is deliberately narrow: one data input `d`, one reset input `r`, one clock `clk`, and one output `q`. All three data-bearing ports are one bit wide. There is no enable, no load, no separate set, and no multi-bit bus. Consequently every legal value on `d`, `r`, or `q` is exactly `0` or `1`; there are no intermediate widths, no signedness questions, and no out-of-range encodings to reject. The only boundary values that matter are the two Boolean states, and the only interesting boundary behavior is the ordering between the sampled rising edge and optional mid-row input changes.

The transition rule is synchronous and active-high: at the settled rising edge, if the resolved `r` is `1`, the next `q` is `0`; otherwise the next `q` equals the resolved `d`. Reset therefore has priority over data. “Resolved” means the value formed from the carried input state plus any drives applied before that edge. Mid-row changes occur after sampling and before the other edge; they update the carried `d` and `r` for the following row but must not retroactively alter the `q` just sampled.

A short worked example: a row begins with carried `d=0`, `r=0`, current `q=0`. Before the edge the row drives `d=1`, `r=0`, so the sampled `q` becomes `1`. After sampling, a mid-row change sets `r=1`. That does not change the just-sampled `q=1`; it only makes the next row begin with carried `r=1`. If the next row drives nothing before its edge, the resolved inputs are carried `d=1`, `r=1`, so reset priority forces `q=0`.

For the final Python checker, the most useful point is strict state separation and event ordering. Keep `q`, carried `d`, and carried `r` as distinct state. Construct pre-edge inputs from the carry plus pre-edge drives. At the settled rising edge, resolve those inputs and apply reset priority. Only afterward may mid-row changes update the carried `d` and `r`. Do not let a mid-row change affect the sampled result, and do not ignore mid-row changes when forming the next row’s carry. Also make the initial `q` convention explicit: the public spec does not define power-up behavior, so initializing `q` to `0` is reasonable only if stated and applied consistently. Finally, do not treat “no drive before the edge” as an implicit zero unless the carry already supplies that value; the carry is the baseline for the next row’s pre-edge inputs. The same caution applies to the first row’s carried inputs: unless the protocol seed or harness establishes them, the checker should not silently assume undocumented history.
