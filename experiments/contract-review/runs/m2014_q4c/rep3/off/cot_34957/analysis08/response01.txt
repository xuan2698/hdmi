**Reset and power-up behavior**

The specification defines a single-bit D flip flop with an active-high synchronous reset. The only state is `q`. The inputs are `d` and `r`, both one bit wide, and the clock is `clk`. Sampling occurs after the positive edge has settled. The transition rule is: at a sampled positive edge, if the sampled `r` is 1, the next `q` is 0; otherwise the next `q` is the sampled `d`. Reset therefore has priority over data, but only at the edge.

The important distinction is between synchronous reset and asynchronous reset. A synchronous reset is not an immediate output override. If `r` is asserted between edges, `q` does not change until the next sampled positive edge. A checker that reacts to `r = 1` as soon as it appears in the row data, rather than only at the sampled edge, will incorrectly expect `q` to go low early. Likewise, a mid-row change in `r` must not retroactively alter the expected result for the edge that has already been sampled. The reset input is sampled like `d`: its value at the row start determines the edge behavior, and later changes are carried forward to the next row.

Power-up behavior is not fully determined by the public specification. The spec gives the transition rule but does not state an initial value for `q`. A correct checker should therefore avoid assuming `q = 0` or `q = 1` at time zero unless the harness explicitly supplies an initial state. Before the first sampled edge with a known prior state, the expected output may be unknown. The safest approach is to compare only after the first edge whose result is determined by the specified transition rule and a known previous `q`. If the harness does provide an initial `q`, then the checker can begin comparing immediately after the first sampled edge.

A useful worked example: suppose the previous `q` is 1, and at the start of a row `d = 0` and `r = 0`. At the sampled positive edge, reset is inactive, so the flip flop loads `d`, and the expected `q` becomes 0. If `d` later changes to 1 in the middle of the row, that change is carried to the next row; it must not change the current expected `q` to 1. Similarly, if `r` changes to 1 mid-row, it waits for the next sampled edge and does not immediately force the current output low.

For the final Python checker, the key discipline is to separate edge-sampled inputs from carried-forward mutations. Compute the expected post-edge `q` only from the previous `q` and the row-start `d` and `r`, with reset priority over data. Do not merge mid-row changes into the current row’s sampled inputs. Do not treat reset as an asynchronous output override. Do not assume an initial `q` unless the harness supplies one. Compare only after the first sampled edge whose state is determined by the specified transition rule.
