The public specification defines a one-bit D flip flop with a single clock, one data input `d`, one synchronous active-high reset input `r`, and one output `q`. The only state is the stored output value. The transition rule is evaluated at the positive clock edge: if `r` is high at that sampled edge, `q` becomes 0 regardless of `d`; otherwise `q` takes the sampled value of `d`. Reset is synchronous, so it affects the output only through the clock edge, not immediately when `r` changes.

The input widths are one bit each for `d` and `r`, and the output width is one bit for `q`. The clock is named `clk`. Sampling occurs after the positive edge has settled. Each row’s values are driven before the sampled edge. Optional mid-row input changes occur after sampling and before the other edge, and those changes are carried to the start of the next row. This timing distinction is central: the checker must use the row-start values of `d` and `r` for the edge being sampled, not later mutations within the same row.

State behavior is therefore simple but timing-sensitive. Let `q_prev` be the output value immediately before the sampled positive edge. At that edge, the next state is:

- if sampled `r = 1`, then `q_next = 0`;
- else if sampled `r = 0`, then `q_next = sampled d`.

Reset has priority over data. There is no separate enable, no asynchronous clear, and no other state. The output `q` is just the stored state after the edge settles. Between edges, `q` should remain stable according to the flip-flop model; mid-row changes on `d` or `r` do not alter the already-sampled result.

A checker must not react to `r = 1` as soon as it appears in the row data. If `r` changes after the sampled edge, that change is for the next row. Likewise, a mid-row change in `d` must not retroactively alter the expected output for the edge already sampled. The row-start values determine the edge result; later changes are carried forward.

Power-up behavior is not fully specified. The public specification gives the transition rule but does not state an initial value for `q`. A checker should not assume `q = 0` or `q = 1` at time zero unless the harness explicitly supplies an initial state. Before the first sampled edge with a known prior state, the expected output may be unknown. The safest approach is to compare only after the first edge whose result is determined by the specified transition rule and a known previous `q`. If the harness provides an initial `q`, comparison can begin immediately after the first sampled edge.

Worked example: suppose the previous `q` is 1, and at the start of a row `d = 0` and `r = 0`. At the sampled positive edge, reset is inactive, so the flip flop loads `d`, and expected `q` becomes 0. If `d` later changes to 1 mid-row, that change is carried to the next row and must not change the current expected `q` to 1. If `r` changes to 1 mid-row, it waits for the next sampled edge and does not immediately force the current output low.

For the final Python checker, the key discipline is to separate edge-sampled inputs from carried-forward mutations. Compute expected post-edge `q` only from the previous `q` and the row-start `d` and `r`, with reset priority over data. Do not merge mid-row changes into the current row’s sampled inputs. Do not treat reset as an asynchronous output override. Do not assume an initial `q` unless the harness supplies one. Compare only after the first sampled edge whose state is determined by the specified transition rule.
