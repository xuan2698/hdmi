The public specification describes a single-bit D flip-flop with an active-high synchronous reset. The key phrase is “synchronous”: reset is not an asynchronous clear. A high `r` only affects `q` at a sampled positive clock edge. Between edges, `q` must remain stable regardless of changes on `d` or `r`. This matters for the final checker because a mid-row `r` pulse must not be interpreted as an immediate output override. The expected output for the current row is fixed by the values present at the sampled edge, not by later activity in the same row.

The protocol note adds a second important constraint: optional mid-row input changes occur after sampling and are carried to the start of the next row. Therefore the checker must preserve the row-start values of `d` and `r` for the sampled edge. The expected next `q` is computed from the previous `q` and those preserved row-start inputs. Mid-row changes must not retroactively alter the current row’s expected output. In particular, if `d` changes after the sampled edge, that new `d` belongs to the next row, not the current one. Likewise, a mid-row rise of `r` does not asynchronously clear `q`; it only matters at the next sampled positive edge.

A second boundary is initialization. The public specification gives the transition rule but does not state a power-up value for `q`. A checker should not assume `q` starts at 0 or 1 unless the harness explicitly supplies an initial state. Before the first sampled edge with a known previous `q`, the expected output may be unknown. Comparison should begin only after the first sampled edge whose result is determined by the specified rule and a known prior `q`. If the harness supplies an initial `q`, comparison can begin immediately after the first sampled edge.

Worked example: suppose the previous `q` is 1, and at the start of a row `d = 0`, `r = 0`. At the sampled positive edge, reset is inactive, so the flip-flop loads `d`, and expected `q` becomes 0. If `d` later changes to 1 mid-row, that change is carried to the next row and must not change the current expected `q` to 1. If `r` changes to 1 mid-row, it waits for the next sampled edge and does not immediately force the current output low.

For the final Python checker, the useful discipline is therefore: separate edge-sampled inputs from carried-forward mutations; compute expected post-edge `q` only from the previous `q` and the row-start `d` and `r`, with reset priority over data; do not merge mid-row changes into the current row’s sampled inputs; do not treat reset as an asynchronous output override; and do not assume an initial `q` unless the harness supplies one. Compare only after the first sampled edge whose state is determined by the specified transition rule.
