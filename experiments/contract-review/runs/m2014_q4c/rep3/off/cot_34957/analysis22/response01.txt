The public interface is deliberately narrow: one data input `d` of width 1, one reset input `r` of width 1, one clock `clk`, and one output `q` of width 1. Because every listed signal has width 1, each sampled value is a single bit and the only legal boundary values are 0 and 1. There is no multi-bit packing, no byte-enable, and no separate enable input. The checker should therefore treat `d`, `r`, and `q` as scalar bits, not as vectors whose width might vary with the harness.

The timing boundary is the positive edge of `clk`. The specification says to sample after the posedge has settled. That means the checker should not compare against values captured at the exact instant of the edge transition; it should use the settled post-edge value. Each row’s `d` and `r` values are driven before the sampled edge. Optional mid-row input changes occur after sampling and before the other edge, and those changes are carried to the start of the next row. This is the central boundary for the final checker: the current row’s expected `q` must be computed from the preserved row-start `d` and `r`, together with the previous `q`. Mid-row mutations must not be folded back into the current row’s sampled inputs.

Reset priority is explicit. If the preserved row-start `r` is 1, the expected post-edge `q` is 0 regardless of `d`. If `r` is 0, the expected post-edge `q` equals the preserved row-start `d`. Reset is synchronous and active high, so a mid-row rise of `r` does not asynchronously force the current `q` low. It only affects the next sampled edge. Likewise, a mid-row change of `d` does not alter the current expected output; it becomes the next row’s data input.

Initialization is a boundary the public specification leaves open. The transition rule is given, but no power-up value for `q` is stated. The checker should not assume `q` begins at 0 or 1 unless the harness explicitly supplies an initial state. Before the first sampled edge with a known previous `q`, the expected output may be unknown. Comparison should begin only after the first sampled edge whose result is determined by the specified rule and a known prior `q`. If the harness supplies an initial `q`, comparison can begin immediately after the first sampled edge.

A short worked example: suppose previous `q` is 1, and at row start `d = 0`, `r = 0`. At the sampled positive edge, reset is inactive, so the flip-flop loads `d`, and expected `q` becomes 0. If `d` later changes to 1 mid-row, that change is carried to the next row and must not change the current expected `q` to 1. If `r` changes to 1 mid-row, it waits for the next sampled edge and does not immediately force the current output low.

For the final Python checker, the useful discipline is therefore: separate edge-sampled inputs from carried-forward mutations; compute expected post-edge `q` only from the previous `q` and the row-start `d` and `r`, with reset priority over data; do not merge mid-row changes into the current row’s sampled inputs; do not treat reset as an asynchronous output override; and do not assume an initial `q` unless the harness supplies one. Compare only after the first sampled edge whose state is determined by the specified transition rule.
