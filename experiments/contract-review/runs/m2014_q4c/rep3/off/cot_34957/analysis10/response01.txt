The public interface is a single-bit D flip-flop with a single-bit active-high synchronous reset. The input map is `{'d': 1, 'r': 1}` and the output map is `{'q': 1}`. Thus every port is exactly one bit wide: `d`, `r`, and `q` each carry only 0 or 1. There are no multi-bit vectors, no byte lanes, and no partial-width concerns. The clock is `clk`, and sampling occurs after the positive edge has settled. The specification’s boundary values are therefore the two binary values for each signal: `d ∈ {0,1}`, `r ∈ {0,1}`, and `q ∈ {0,1}`. The meaningful input combinations at a sampled edge are four: `(r,d) = (0,0)`, `(0,1)`, `(1,0)`, and `(1,1)`. Because reset is active high and synchronous, `r = 1` forces the next `q` to 0 regardless of `d`; when `r = 0`, the next `q` equals `d`. There is no enable, no asynchronous clear, and no other control input.

The timing boundary is the important part. Each row’s values are driven before the sampled edge. Optional mid-row input changes occur after sampling and before the other edge, and those changes are carried to the start of the next row. Therefore the checker must distinguish row-start sampled values from later mutations. The expected post-edge `q` is computed only from the previous `q` and the row-start `d` and `r`, with reset priority over data. A mid-row change on `d` or `r` must not retroactively change the result of the edge already sampled. In particular, `r = 1` appearing after the sampled edge is not an immediate output override; it is an input for the next sampled edge. Similarly, a mid-row `d` change is carried forward and does not alter the current expected `q`.

Power-up is not fully specified. The public specification gives the transition rule but does not state an initial value for `q`. A checker should not assume `q = 0` or `q = 1` at time zero unless the harness explicitly supplies an initial state. Before the first sampled edge with a known prior state, the expected output may be unknown. The safest approach is to compare only after the first edge whose result is determined by the specified transition rule and a known previous `q`. If the harness provides an initial `q`, comparison can begin immediately after the first sampled edge.

Worked example: suppose the previous `q` is 1, and at the start of a row `d = 0` and `r = 0`. At the sampled positive edge, reset is inactive, so the flip-flop loads `d`, and expected `q` becomes 0. If `d` later changes to 1 mid-row, that change is carried to the next row and must not change the current expected `q` to 1. If `r` changes to 1 mid-row, it waits for the next sampled edge and does not immediately force the current output low.

For the final Python checker, the key discipline is to separate edge-sampled inputs from carried-forward mutations. Compute expected post-edge `q` only from the previous `q` and the row-start `d` and `r`, with reset priority over data. Do not merge mid-row changes into the current row’s sampled inputs. Do not treat reset as an asynchronous output override. Do not assume an initial `q` unless the harness supplies one. Compare only after the first sampled edge whose state is determined by the specified transition rule.
