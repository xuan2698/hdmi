The public specification describes a single-bit D flip flop with active-high synchronous reset. The input set is `d` and `r`, each one bit wide, and the output is `q`, also one bit. The clock is `clk`, and sampling occurs after the positive edge has settled. Each row’s input values are driven before the sampled edge. Optional mid-row input changes occur after sampling and before the other edge; those changes are carried to the start of the next row. The protocol seed is 20261122.

The key timing distinction is between row-start inputs and mid-row mutations. The expected post-edge `q` for a row must be computed from the previous `q` and the row-start values of `d` and `r`. A mid-row change to `d` or `r` does not retroactively affect the current row’s expected output. It becomes part of the next row’s starting inputs. This means a checker must latch or otherwise preserve the sampled input values at the edge, rather than reading the latest visible values later in the row. If `d` changes from 0 to 1 after the sampled edge, the current expected `q` remains whatever the row-start rule produced; the new `d = 1` is relevant only to the next sampled edge. Similarly, if `r` changes to 1 mid-row, reset does not immediately force the current output low. The reset takes effect only at the next sampled positive edge, when `r = 1` is present at row start.

Reset priority is the second critical point. If row-start `r = 1`, the expected post-edge `q` is 0 regardless of `d`. The checker should branch on `r` first: when `r` is high, expected `q` is 0; otherwise expected `q` is the row-start `d`. A naive implementation that computes `q_next = d` and then applies reset as a separate override can produce the same result in many rows, but it is the wrong model and can misjudge cases where reset and data interact. The public spec makes reset synchronous and dominant, so the transition rule is effectively: if `r` then 0 else `d`.

Initialization is deliberately unspecified. The public spec gives no power-up value for `q`. A checker must not assume `q` starts at 0 or 1. Before the first sampled edge with a known prior `q`, the expected output may be unknown. Comparison should begin only after the first sampled edge whose result is determined by the specified rule and a known prior `q`. If the harness explicitly supplies an initial `q`, comparison can begin immediately after the first sampled edge. Otherwise, the first row’s expected `q` is not determined unless the harness provides that prior state.

A short worked example: suppose the previous `q` is known to be 1. At row start, `d = 0` and `r = 0`. After the sampled edge, expected `q` is 0. Later in the same row, `d` changes to 1. That mid-row change must not alter the current expected `q`; it is carried to the next row. If instead row-start `r = 1` and `d = 1`, expected post-edge `q` is 0 because reset has priority.

For the final Python checker, the useful discipline is to separate edge-sampled inputs from carried-forward mutations, compute expected post-edge `q` only from the previous `q` and row-start `d` and `r` with reset priority, avoid merging mid-row changes into the current row, avoid treating reset as an asynchronous override, and avoid assuming an initial `q` unless the harness supplies one. Compare only after the first sampled edge whose state is determined by the specified transition rule.
