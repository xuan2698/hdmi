The public specification describes a single-bit D flip flop with a synchronous active-high reset. The key behavioral rule is: at each sampled positive clock edge, the next value of `q` is `0` if the row-start reset input `r` is high; otherwise the next value of `q` is the row-start data input `d`. Reset is synchronous, so asserting `r` does not immediately force `q` low between edges. It only affects the next sampled positive edge. Reset also has priority over data, so when both `r` and `d` are high at the sampled edge, the result is `q = 0`.

The timing protocol is the main source of checker mistakes. Each row’s values are driven before the sampled positive edge, and those row-start values are the ones the flip flop observes at that edge. After the edge has settled, `q` reflects the transition computed from the previous `q` and the row-start `d` and `r`. Optional mid-row input changes occur after sampling and before the other edge; they are not inputs to the edge that has just been sampled. They are carried to the start of the next row. Therefore the checker must not merge a row’s row-start values with its mid-row changes into a single input tuple. If it does, a post-sample change can be incorrectly applied to the current edge.

A short worked example clarifies the boundary. Suppose the current `q` is 1, and at row start `d = 0`, `r = 0`. At the sampled positive edge the flip flop sees `r = 0`, so it loads `d = 0` and `q` becomes 0. If a mid-row change then sets `d = 1`, that change is the starting condition for the next row; it does not retroactively make the current sampled `q` equal 1. Likewise, a mid-row change to `r = 1` waits for the next sampled edge rather than resetting immediately.

For the final Python checker, the useful point is to keep edge-local inputs separate from carried-forward mutations. Compute the expected post-edge `q` solely from the previous `q` and the row-start `d` and `r`, with reset priority over data load. Do not model reset as an immediate output override, do not assume an initial `q`, and do not let mid-row changes affect the current row’s expected output. The checker should also avoid treating the absence of a specified initial state as an error; it should either accept a harness-provided initial value or compare only after the first sampled edge whose state is determined by the specified transition rule.
