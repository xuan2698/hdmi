The public specification defines a single-bit D flip-flop with a single-bit active-high synchronous reset. The transition rule is: at a sampled rising clock edge, if `r` is high, `q` becomes 0; otherwise `q` becomes the value of `d`. Because reset is synchronous, it affects the output only at the sampled edge, not immediately when `r` changes. Because the reset is active high, `r = 1` has priority over `d` at that edge.

The timing protocol is the main source of subtlety. Each row’s values are driven before the sampled edge. Optional mid-row changes occur after sampling and before the other edge, and are carried to the start of the next row. Therefore, for the current sampled edge, the checker must use the row-start values of `d` and `r`, together with the previous `q`. A mid-row change to `d` or `r` must not retroactively alter the expected `q` for the row in which the change occurs. It becomes an input for the following sampled edge. This is the central point for the final Python checker: preserve the row-start inputs for the current edge, compute the expected next `q` from the previous `q` and those preserved inputs, and only then allow mid-row mutations to update the carried state for the next row.

A second boundary is initialization. The public specification gives the transition rule but does not state a power-up value for `q`. The checker should not assume that `q` starts at 0 or 1 unless the harness explicitly supplies an initial state. Before the first sampled edge with a known previous `q`, the expected output may be unknown. Comparison should begin only after the first sampled edge whose result is determined by the specified rule and a known prior `q`. If the harness supplies an initial `q`, comparison can begin immediately after the first sampled edge.

A short worked example makes the separation concrete. Suppose the previous `q` is 1, and at the start of a row `d = 0`, `r = 0`. At the sampled positive edge, reset is inactive, so the flip-flop loads `d`, and expected `q` becomes 0. If `d` later changes to 1 mid-row, that change is carried to the next row and must not change the current expected `q` to 1. If `r` changes to 1 mid-row, it waits for the next sampled edge and does not immediately force the current output low.

For the final Python checker, the useful discipline is therefore: separate edge-sampled inputs from carried-forward mutations; compute expected post-edge `q` only from the previous `q` and the row-start `d` and `r`, with reset priority over data; do not merge mid-row changes into the current row’s sampled inputs; do not treat reset as an asynchronous output override; and do not assume an initial `q` unless the harness supplies one. Compare only after the first sampled edge whose state is determined by the specified transition rule.
