The public specification describes a single-bit D flip flop with active-high synchronous reset. The sampled event is the positive clock edge, and the checker should evaluate the output after that edge has settled. Inputs `d` and `r` are one bit each; output `q` is one bit. The protocol seed is 20261122, but the key modeling issue is not the seed—it is how row-start inputs and optional mid-row changes are separated.

Each row’s values are driven before the sampled edge. That means the row-start tuple `(d, r)` is the input state that the flip flop sees at the positive edge. The optional mid input changes occur after sampling and before the other edge; those changes are carried to the start of the next row. Therefore the checker must not collapse a row into a single “latest seen” tuple. If it stores only one tuple per row and overwrites the row-start values with mid-row values, it will apply the later values to an edge that has already occurred. That is not just a row-alignment error: it changes the transition rule for the current sample.

The correct edge-local model is: snapshot `d` and `r` at the row start; compute the next `q` from the previous `q` and that snapshot; then carry any mid-row changes forward as the next row’s starting inputs. The transition rule is simple. If the sampled `r` is 1, the next `q` is 0 regardless of sampled `d`. If the sampled `r` is 0, the next `q` is the sampled `d`. Reset priority applies only at the sampled edge.

A second common mistake is treating synchronous reset as an immediate override. Asserting `r` between edges must not force `q` low before the next positive edge. A checker that applies reset as soon as it sees `r = 1` in the row data, or that lets a mid-row reset change affect the current row’s expected output, will reject a correct flip flop. Reset priority matters only at the sampled edge: row-start `r` high means expected post-edge `q = 0`; row-start `r` low means expected post-edge `q = row-start d`.

Worked example: previous `q = 1`, row-start `d = 0`, `r = 0`. At the sampled edge, the DUT loads 0, so expected `q = 0`. If `d` then changes to 1 mid-row, that change is carried to the next row; it must not make the current expected `q` equal 1. Similarly, if `r` changes to 1 mid-row, it waits for the next sampled edge and does not immediately reset the current output.

For the final Python checker, the useful discipline is to separate sampled-edge inputs from carried-forward mutations. Compute expected post-edge `q` only from the previous `q` and the row-start `d` and `r`, with reset priority over data. Do not merge mid-row changes into the current row’s sampled inputs, do not treat reset as an asynchronous output override, and do not assume an initial `q` unless the harness supplies one. Compare only after the first sampled edge whose state is determined by the specified transition rule.
