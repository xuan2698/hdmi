The public specification defines a one-bit D flip flop with a one-bit synchronous active-high reset. The sampled inputs are `d` and `r`; the sampled output is `q`. The clock is `clk`, and checking is performed after the positive edge has settled. Inputs are driven before the sampled edge. Optional mid-row input changes occur after sampling and before the other edge, and those changes are carried to the start of the next row. The protocol seed is 20261122.

The central behavioral rule is that the next sampled `q` is determined by the row-start values of `d` and `r`, together with the prior sampled `q`. Reset is synchronous, so it affects the output only at a sampled positive edge. Reset is also active high and dominant: if `r = 1` at the row start, then the post-edge `q` is 0 regardless of `d`. If `r = 0`, then the post-edge `q` takes the row-start value of `d`. In effect, the transition rule is: expected next `q` is 0 when `r` is high, otherwise it is `d`.

This priority matters for the final Python checker. The checker should branch on `r` first. When `r` is high, expected `q` is 0. Only when `r` is low should the checker use `d` as the expected next `q`. A model that computes `q_next = d` and then applies reset as a separate override may appear correct in many rows, but it is not the right model of the public specification. The specification makes reset synchronous and dominant, so the clean transition rule is “if `r` then 0 else `d`.”

Power-up behavior is deliberately unspecified. The public specification gives no initial value for `q`. Therefore the checker must not assume that `q` starts at 0 or at 1. Before the first sampled edge with a known prior `q`, the expected output may be unknown. Comparison should begin only after the first sampled edge whose result is determined by the specified transition rule and a known prior `q`. If the harness explicitly supplies an initial `q`, then comparison can begin immediately after the first sampled edge. Otherwise, the first row’s expected `q` is not determined unless the harness provides that prior state.

A short worked example: suppose the previous `q` is known to be 1. At row start, `d = 0` and `r = 0`. After the sampled edge, expected `q` is 0. Later in the same row, `d` changes to 1. That mid-row change must not alter the current expected `q`; it is carried to the next row. If instead row-start `r = 1` and `d = 1`, expected post-edge `q` is 0 because reset has priority.

For the final Python checker, the useful discipline is to separate edge-sampled inputs from carried-forward mutations, compute expected post-edge `q` only from the previous `q` and row-start `d` and `r` with reset priority, avoid merging mid-row changes into the current row, avoid treating reset as an asynchronous override, and avoid assuming an initial `q` unless the harness supplies one. Compare only after the first sampled edge whose state is determined by the specified transition rule.
