The public interface is a single-bit D flip flop: inputs `d` and `r` are each 1 bit wide, output `q` is 1 bit wide, and there is one clock `clk`. Because every data-bearing port is one bit, the only legal values are 0 and 1; there are no multi-bit boundary cases, no signedness questions, and no truncation or extension behavior to analyze. The meaningful boundary conditions are therefore logical rather than numeric: `r = 1` versus `r = 0`, `d = 0` versus `d = 1`, and the previous state `q` being 0 versus 1. Reset is active high and synchronous, so `r = 1` does not force `q` to 0 asynchronously; it only causes the next sampled positive edge to load 0. When `r = 0`, the next sampled edge loads `d`. Reset has priority over the data input, so the transition rule is: next `q` is 0 if row-start `r` is 1, otherwise next `q` is row-start `d`.

The timing boundary is the central issue for the checker. Each row’s values are driven before the sampled positive edge, and those row-start values are what the flip flop sees at that edge. After the edge has settled, `q` reflects the transition computed from the previous `q` and the row-start `d` and `r`. Optional mid-row input changes occur after sampling and before the other edge; they are not inputs to the edge that has just been sampled. They are carried to the start of the next row. Thus the checker must not collapse a row’s row-start values and its mid-row changes into one input tuple. Doing so can wrongly apply a post-sample change to the current edge.

A short worked example: suppose the current `q` is 1, and at row start `d = 0`, `r = 0`. At the sampled positive edge the flip flop sees `r = 0`, so it loads `d = 0` and `q` becomes 0. If a mid-row change then sets `d = 1`, that change is the starting condition for the next row; it does not retroactively make the current sampled `q` equal 1. Similarly, a mid-row change to `r = 1` waits for the next sampled edge rather than resetting immediately.

For the final Python checker, the useful point is to keep edge-local inputs separate from carried-forward mutations. Compute the expected post-edge `q` solely from the previous `q` and the row-start `d` and `r`, with reset priority over data load. Do not model reset as an immediate output override, do not assume an initial `q`, and do not let mid-row changes affect the current row’s expected output. The checker should also avoid treating the absence of a specified initial state as an error; it should either accept a harness-provided initial value or compare only after the first sampled edge whose state is determined by the specified transition rule.
