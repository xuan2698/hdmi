The public interface is a single-bit D flip flop with a single-bit active-high synchronous reset. The input map is `{'d': 1, 'r': 1}` and the output map is `{'q': 1}`. All three signals are one bit wide, so every sampled value is either 0 or 1. There are no multi-bit packing, endianness, or truncation concerns: `d`, `r`, and `q` each occupy exactly one bit. The clock is `clk`, and the output is sampled after the positive edge has settled. The specification does not define power-up state, so the checker must not derive an initial `q` from the reset rule. Reset is synchronous and active high: when the sampled edge sees `r=1`, the next `q` is 0 regardless of `d`. When `r=0`, the next `q` is the sampled `d`. Because reset is synchronous, asserting `r` between edges does not immediately clear `q`; only the next sampled positive edge applies it.

The row protocol is the main boundary condition. Each row’s values are driven before the sampled edge. Optional mid-input changes occur after sampling and before the other edge, and those changes are carried to the start of the next row. Therefore, for a given row, the expected output must be computed from that row’s pre-edge `d` and `r`, not from any mid-row changes after the sampled edge. A mid-row change to `r` or `d` belongs to the next row’s pre-edge inputs. The checker should process rows in order: read the row’s pre-edge `d` and `r`, compute the expected next `q` from the current model state, compare the observed `q` after the sampled edge has settled, update the model state to the expected next `q`, and only afterward apply any mid-input changes for the next row.

Power-up behavior is unspecified. The synchronous reset rule cannot establish `q` before the first sampled edge. The checker should not infer an initial `q` from reset behavior alone. It should either use a known initial state supplied by the harness or begin checking only after the harness has established one. Any assumed initial value comes from the test setup, not from the flip flop specification.

A short worked example: suppose the model state before a row is `q=1`. Before the sampled edge, the row drives `d=0` and `r=0`. Since reset is low, the sampled edge gives next state `q=0`. If a mid-input change after sampling then sets `r=1`, that change must not retroactively affect the current row. The current edge already used `r=0`. The carried `r=1` becomes the pre-edge reset value for the next row, where the next sampled edge would force `q=0` regardless of `d`.

The useful point for the final checker is to keep `q` as the sole state variable and to enforce the fixed order: read pre-edge inputs, compute expected next state, compare after the sampled edge, commit the model state, then apply mid-input changes for the next row. This preserves synchronous-reset semantics and prevents post-sample changes from contaminating the current row’s expected result.
