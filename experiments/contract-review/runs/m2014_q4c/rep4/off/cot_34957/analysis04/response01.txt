The public interface is deliberately narrow: one data input `d` of width 1, one reset input `r` of width 1, one clock `clk`, and one output `q` of width 1. All values are single-bit, so the boundary values for every port are simply 0 and 1. There are no multi-bit encodings, no enable, no set, and no asynchronous reset. The reset is active high and synchronous, meaning it is consulted only at the sampled positive edge of `clk`. When `r` is 1 at that edge, the next state of `q` is 0 regardless of `d`. When `r` is 0 at that edge, the next state of `q` is `d`. Because the output width is also 1, the observed `q` must always be either 0 or 1; any other observed value is a protocol or harness error rather than a legal D flip flop output.

The timing convention matters more than the Boolean equation. Each row supplies inputs before the sampled positive edge. The checker should treat those pre-edge values as the inputs for the current sample. After the edge has settled, the harness observes `q`. Only after that observation may optional mid-row input changes occur; those changes are not inputs to the current sample. They are carried forward and become the starting input values for the next row. Thus a row can contain a pre-edge pair `(d, r)` used for the current expected output, and possibly a post-sample pair that seeds the next row. The checker must not let a post-sample reset change retroactively alter the current row’s expected result.

The only persistent state in the model is `q`. For each row, let `q_prev` be the modeled value before the sampled edge. The expected sampled value is `q_next = 0` if the pre-edge `r` is 1, otherwise `q_next = d`. The checker compares the observed output for that row against `q_next`, then updates its model state to `q_next`. Only after that update should it apply any mid-input changes, because those changes affect the next row’s pre-edge inputs, not the current row’s expected output.

A short worked example: suppose the modeled `q_prev` is 1. Before a sampled edge the row drives `d=0`, `r=0`, so the expected sampled output is `q_next=0`. After sampling, a mid-input change sets `r=1`. That change must not make the current row’s expected output depend on reset; the current edge already used `r=0`. Instead, the carried `r=1` becomes the starting reset value for the next row, where the next sampled edge would force `q=0` regardless of `d`.

The most useful point for the final Python checker is that the specification does not define a power-up value for `q`. A synchronous reset can only force `q` to 0 at a clock edge; it cannot define the value before the first sampled edge. Therefore the checker should either treat the pre-first-row state as an input to the checking problem or begin checking only after the harness has established a known state. If the harness implies a particular initial value, that value comes from the harness, not from the flip flop specification. The checker should maintain `q` as its sole state variable, compute each row’s expected value from the row’s pre-edge inputs, compare after the sampled edge, update `q`, and only afterward apply mid-input changes for the next row.
