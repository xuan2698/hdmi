The public interface is a single-bit D flip flop: one data input `d` (width 1), one synchronous reset input `r` (width 1), one clock `clk`, and one output `q` (width 1). Because every port is one bit wide, the only legal values on `d`, `r`, and `q` are 0 and 1. There are no multi-bit boundary cases, no signedness questions, and no truncation or extension behavior to analyze. The meaningful boundary values are therefore the four input combinations `(d,r) = (0,0), (0,1), (1,0), (1,1)` together with the two possible prior states of `q`.

The reset is active high and synchronous. That means `r=1` does not asynchronously force `q` to 0 at the moment `r` changes; it only causes the next sampled clock edge to load 0 into `q`. When `r=0`, the next sampled edge loads `d`. Thus the expected next state at a sampled positive edge is: if `r=1` then `q_next=0`; otherwise `q_next=d`. This rule uses the values of `d` and `r` as they stand just before the sampled edge. The checker must compare the observed `q` after the edge has settled against this expected value, and only then update its internal model state to `q_next`.

A critical boundary condition is the timing of optional mid-input changes. These changes occur after sampling and before the other edge, and they are carried to the start of the next row. They must not alter the expected result for the row whose edge has already been sampled. A useful failure mode is treating a post-sample reset change as though it applied to the just-sampled edge. For example, suppose the model state before a row is `q=1`, and before the sampled edge the row drives `d=0`, `r=0`. The expected sampled output is `q_next=0`. If after sampling a mid-input change sets `r=1`, that change must not retroactively make the current row’s expected output reset to 0. The current edge already used `r=0`. The carried `r=1` instead becomes the starting reset value for the next row, where the next sampled edge would force `q=0` regardless of `d`.

Another important point is that the public specification does not define a power-up value for `q`. A synchronous reset can force `q` to 0 only at a clock edge; it cannot establish the value before the first sampled edge. Therefore the final Python checker should either treat the pre-first-row state as an input to the checking problem or begin checking only after the harness has established a known state. If the harness implies a particular initial value, that value comes from the harness, not from the flip flop specification.

In prose, the checker’s model should maintain `q` as its sole state variable. For each row it should compute the expected value from the row’s pre-edge inputs, compare after the sampled edge, update `q` to the expected next value, and only afterward apply any mid-input changes for the next row. This preserves the synchronous-reset semantics and prevents post-sample changes from contaminating the current row’s expected result.
