The predictor's state consists of two things: a 7-bit global history register (`history`) and a 128-entry PHT of 2-bit saturating counters. Reset is asynchronous and active-high, and it dominates everything: on reset, `history` becomes 0 and every PHT counter returns to its reset value (the spec's saturating-counter reset state, conventionally `2'b01` unless the checker's reference model fixes otherwise — the key point is that reset defines a single deterministic initial PHT). Because reset is asynchronous, the checker must apply it with priority over any same-cycle predict or train activity, and it must take effect as soon as it is observed, not deferred to the posedge.

Prediction path: when `predict_valid = 1`, the index is `predict_pc[6:0] XOR history` (both 7 bits). The selected PHT counter's MSB gives `predict_taken`. The output `predict_history` is the current `history` value used for that lookup — i.e., the pre-edge history, not the updated one. The prediction is purely combinational with respect to current state; it does not see any PHT write or history update that will occur at the upcoming posedge. This is the timing-diagram point: a training request in the same cycle as a prediction of the same PHT entry does not affect that cycle's `predict_taken`, because the PHT write lands only at the next posedge.

History update on prediction: at the posedge, if `predict_valid` and no training override, `history` shifts left by one and the predicted direction is inserted (typically `history <= {history[5:0], predict_taken}`). The checker should use the predicted direction, not the true outcome, for this speculative update.

Training path: when `train_valid = 1`, the PHT entry indexed by `train_pc[6:0] XOR train_history` is updated at the posedge according to `train_taken` using the 2-bit saturating counter rule (increment on taken unless at max, decrement on not-taken unless at min). The training lookup uses `train_history`, the supplied history value for that branch, not the current `history` register. If `train_mispredicted = 1`, the history register is also recovered at the posedge to the state immediately after the mispredicting branch, which the spec expresses via the supplied `train_history` and the actual outcome — the checker should follow the reference convention (commonly `history <= {train_history[5:0], train_taken}`), matching the recovery semantics rather than the speculative prediction update.

Conflict resolution: if training (especially mispredicted training) and a prediction occur in the same cycle, training wins for the history register, since the predicted instruction is younger and will be flushed. The prediction still outputs its combinational result based on pre-edge state. If training and prediction touch the same PHT entry, the prediction sees the old counter; the write applies at the edge.

Worked example: after reset, `history = 0`. A prediction with `predict_pc = 7'b0000000` indexes entry 0 and outputs `predict_history = 0`; this is the clean first-prediction check. If in that same cycle `train_valid = 1, train_mispredicted = 1, train_history = 7'b0000000, train_taken = 1`, the PHT entry 0 write and history recovery to `{6'b0,1}` both occur at the posedge, while the prediction output still reflects the pre-edge counter and `predict_history = 0`.
