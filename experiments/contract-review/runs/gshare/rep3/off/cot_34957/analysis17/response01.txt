**Distinguishing input example (prose).**

The most useful single probe for the final checker is a same-cycle collision between a prediction and a mispredicted training, because it exercises three independent semantics at once: (a) the PHT read is pre-edge (prediction sees the old counter even though training writes the same index), (b) the GHR update is training-dominant (the prediction's shift is discarded), and (c) the recovered GHR must equal the value derived from `train_history`, not the prediction-shifted value. A secondary probe worth keeping is the aliasing pair `(predict_pc=0, train_history=0)` vs `(predict_pc=127, train_history=127)`, both mapping to index 0, plus `(127,0)` mapping to index 127 — these confirm the XOR hash and that the checker is not accidentally indexing on `predict_pc` alone.

**Worked example.** First, prime PHT index 0 to a known state. Drive `train_valid=1, train_pc=0, train_history=0, train_taken=1, train_mispredicted=0` for two consecutive cycles so the counter at index 0 saturates at 3 (prediction would be taken). Then, in one cycle, assert `predict_valid=1, predict_pc=0` (index 0, GHR=0) together with `train_valid=1, train_pc=0, train_history=0b1010101, train_taken=0, train_mispredicted=1`. Expected at that sampled edge: `predict_taken=1` (pre-edge counter is 3, MSB=1) and `predict_history=0` (current GHR, before any update). At the next edge, the PHT entry at index 0 decrements to 2, and the GHR is recovered to the value implied by `train_history` for the mispredicting branch — not `(0<<1)|1` from the prediction shift. The checker should then issue a fresh `predict_valid` with `predict_pc=0` and confirm `predict_taken=1` still (counter 2, MSB=1) and that `predict_history` reflects the recovered GHR, not the discarded prediction shift. This single sequence distinguishes a correct implementation from one that (i) lets prediction win the GHR, (ii) applies the training write before the read, or (iii) ignores `train_mispredicted` recovery.

**Reset-dominance probe.** Assert `areset=1` in the same cycle as a mispredicted training with a distinctive `train_history` (e.g., `0b1110001`), then release reset and issue a prediction; the returned `predict_history` must equal the reset GHR value, proving reset dominates both the training recovery and any pending shift. Keep this separate from the collision probe so a failure localizes cleanly.

**Checker guidance.** Drive counters to known states via training rather than assuming a reset encoding; only the reset GHR value and "some defined PHT state" are guaranteed. Use the aliasing pairs to validate the hash, the collision cycle to validate pre-edge read plus training-dominant GHR, and the reset-concurrent-training cycle to validate asynchronous reset dominance.
