**Distinguishing input example (prose).** The sharpest test for this gshare predictor is a same-cycle collision between prediction and training on the same PHT index, combined with a mispredicted training that must override the prediction's GHR shift. A useful seed is to first establish a nonzero GHR and a known counter state, then issue one row where `predict_valid=1` and `train_valid=1` address the same index, with `train_mispredicted=1`.

Concretely, suppose after reset the shadow GHR is `0000000` and PHT[0] holds `01` (weakly not-taken). Drive a first row with `predict_valid=1, predict_pc=7'b0000000` and no training. The index is `0 XOR 0 = 0`, so `predict_taken=0` and `predict_history=0000000`. At the edge the GHR shifts in the predicted bit `0`, so it stays `0000000`. This row alone is not distinguishing, but it pins the counter at `01` and confirms the prediction path reads the pre-edge PHT.

Now drive a second row that is the discriminator: `predict_valid=1, predict_pc=7'b0000000`, and simultaneously `train_valid=1, train_pc=7'b0000000, train_history=7'b0000000, train_taken=1, train_mispredicted=1`. Both operations hash to index 0. The prediction must output the **old** counter value `01`, hence `predict_taken=0`, and `predict_history=0000000` (the GHR used for the prediction, before any edge update). At the positive edge, two things happen: PHT[0] increments from `01` to `10`, and because `train_mispredicted=1` has priority over `predict_valid`, the GHR is recovered to `{train_history[5:0], train_taken} = {000000, 1} = 0000001`, **not** shifted from the prediction. A checker that lets the prediction shift win, or that lets the prediction observe the incremented counter, will disagree here.

A third row then exposes the committed state: `predict_valid=1, predict_pc=7'b0000001` with no training. The index is `0000001 XOR 0000001 = 0`, so the prediction reads PHT[0], which is now `10`, giving `predict_taken=1`, and `predict_history=0000001`. This confirms both the edge-committed PHT write and the misprediction GHR recovery. If the implementation had instead shifted the GHR on the prediction in row two, the GHR would be `0000000` and the third row's index would be `0000001`, reading a different counter and likely producing `predict_taken=0` — a clean divergence.

The key checker point: on a same-index predict/train row, sample `predict_taken` and `predict_history` from the pre-edge shadow state, then apply reset > mispredicted-train GHR recovery > prediction GHR shift > hold, and apply the saturating PHT update only after sampling. Ordinary (non-mispredicted) training must not touch the GHR unless a prediction also occurs that cycle.
