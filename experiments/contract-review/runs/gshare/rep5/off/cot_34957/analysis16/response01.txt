The public interface is small but has several boundary-sensitive details that the final checker should encode explicitly.

**Port widths and value ranges.** All control signals are one bit: `areset`, `predict_valid`, `train_valid`, `train_taken`, and `train_mispredicted`. The address/history fields are all 7 bits: `predict_pc`, `train_pc`, `train_history`, and the output `predict_history`. The only other output is `predict_taken`, one bit. Because the PHT has 128 entries and the index is 7 bits, every possible 7-bit XOR result maps to exactly one counter; there is no out-of-range index and no aliasing beyond the intended hash. The saturating counters are 2 bits, so their legal states are `00`, `01`, `10`, `11`; increment saturates at `11` and decrement saturates at `00`.

**Prediction path.** When `predict_valid=1`, the prediction index is `predict_pc[6:0] XOR GHR[6:0]`, where GHR is the current 7-bit global history register before the edge. The addressed 2-bit counter determines `predict_taken`: the usual convention is that the MSB of the counter is the direction, so `10` and `11` predict taken, while `00` and `01` predict not taken. The output `predict_history` is the current GHR used for that prediction, not the next GHR. The GHR is updated at the positive edge only if no higher-priority event overrides it.

**Training path.** When `train_valid=1`, the training index is `train_pc[6:0] XOR train_history[6:0]`. The addressed counter is updated at the edge: increment if `train_taken=1`, decrement if `train_taken=0`, with saturation. This write is edge-committed, so a same-cycle prediction to the same PHT entry must observe the old counter value. If `train_valid=0`, no PHT write occurs.

**GHR update priority.** At the edge: first, asynchronous active-high reset forces GHR to zero. Otherwise, if `train_valid && train_mispredicted`, recover GHR to `{train_history[5:0], train_taken}`. Otherwise, if `predict_valid`, shift in the predicted direction: `{GHR[5:0], predict_taken}`. Otherwise hold. A non-mispredicted training request does not modify GHR. A mispredicted training request takes precedence over a simultaneous prediction for GHR update, because the predicted instruction is younger and will be flushed.

**Checker focus.** The final Python checker should maintain a shadow GHR and a 128-entry shadow PHT. Apply reset first, then the priority rules above. Compare `predict_taken` and `predict_history` only on rows where `predict_valid=1`, or where `areset=1` expecting zero outputs. The most error-prone point is same-cycle predict/train to the same index: prediction must use the pre-edge counter, while the PHT write and GHR update take effect only after the sampled edge. Also verify that only mispredicted training recovers GHR; ordinary training must leave GHR unchanged unless a prediction also occurs.

**Short worked example.** Suppose GHR=`0000000`, PHT[0]=`01`, and a row has `predict_valid=1, predict_pc=0`, plus `train_valid=1, train_pc=0, train_history=0, train_taken=1, train_mispredicted=0`. The prediction index is 0, so `predict_taken=0` and `predict_history=0`. At the edge, PHT[0] becomes `10`; GHR shifts in the predicted bit and remains `0000000`. A later prediction to index 0 then sees `10` and predicts taken.
