The public interface is narrow and fully specified by widths, so the checker should treat every port as an exact-width unsigned vector and never infer extra bits. Inputs: `areset` (1), `predict_valid` (1), `predict_pc` (7), `train_valid` (1), `train_taken` (1), `train_mispredicted` (1), `train_history` (7), `train_pc` (7). Outputs: `predict_taken` (1), `predict_history` (7). Clock is `clk`; sampling is after the posedge has settled, with each row's values driven before the sampled edge. Optional mid-cycle input changes occur after sampling and before the other edge, carried into the next row.

Boundary values matter because the index is formed by XOR of two 7-bit quantities: `predict_pc ^ ghr` for prediction and `train_pc ^ train_history` for training. Both operands range 0..127, so the XOR index also ranges 0..127, exactly covering the 128-entry PHT. No masking beyond 7 bits is needed, but the checker must ensure it does not accidentally use a wider intermediate. The PHT counters are 2-bit saturating: legal states are 0,1,2,3. Training toward taken increments unless already 3; training toward not-taken decrements unless already 0. The predicted direction is the counter's MSB, so states 0 and 1 predict not-taken, states 2 and 3 predict taken. `predict_history` is the 7-bit GHR value used for the prediction, i.e. the pre-edge GHR, not the shifted value.

The GHR is 7 bits. Prediction shift is `{ghr[5:0], predict_taken}`. Misprediction recovery is `{train_history[5:0], train_taken}`. These are distinct: recovery uses the supplied `train_history`, not the current GHR, and appends the actual outcome. A non-mispredicted training updates only the PHT and leaves GHR alone. A prediction with no training recovery shifts GHR by the predicted direction. If both prediction and misprediction-training occur, recovery wins for GHR; the prediction's shift is discarded. If training and prediction hit the same PHT entry in one cycle, prediction reads the pre-edge counter; the write appears only after the edge.

Reset is asynchronous, active-high, and level-sensitive. It has highest priority over all next-state actions. While `areset` is high, next GHR is zero and PHT returns to reset contents, regardless of `predict_valid`, `train_valid`, `train_mispredicted`, or training-over-prediction precedence. A mid-cycle assertion must clear state without waiting for a posedge; a mid-cycle deassertion must not itself create a spurious update. Power-up without reset is unspecified, so the checker must assert `areset` before trusting state. Sampled outputs during a reset cycle may still reflect pre-reset registered state; the checker should judge next-edge state, not necessarily the same-cycle output, when reset is asserted.

Priority for next state is therefore: reset, then training recovery, then prediction shift, then hold. A useful checker point is to separate the PHT write decision from the GHR next-state decision: PHT training occurs whenever `train_valid` and not reset, using `train_pc ^ train_history`; GHR recovery occurs only when `train_valid && train_mispredicted` and not reset; otherwise GHR shifts only when `predict_valid` and not reset. Prediction output uses the pre-edge PHT entry at `predict_pc ^ ghr` and reports pre-edge `ghr`.

Worked example: `ghr=7'h2A`, prediction index `predict_pc ^ ghr` holds `2'b11`, and in one cycle `predict_valid=1`, `train_valid=1`, `train_taken=0`, `train_mispredicted=1`, `areset=1`. Sampled outputs may show pre-reset registered state, but next-edge state is reset: `ghr=7'h00` and reset PHT contents. Reset overrides training recovery and prediction shift.
