The public interface is small but the boundary behavior matters. Inputs: `areset` (1), `predict_valid` (1), `predict_pc` (7), `train_valid` (1), `train_taken` (1), `train_mispredicted` (1), `train_history` (7), `train_pc` (7). Outputs: `predict_taken` (1), `predict_history` (7). Clock `clk`; sample after posedge settles. All 7-bit fields span 0..127 inclusive, so the PHT has exactly 128 entries and the GHR is exactly 7 bits wide. The index is `predict_pc ^ predict_history` (or `train_pc ^ train_history` for training), also 7 bits, so every index is valid and no masking is needed. The GHR shift is 7 bits: on a taken prediction it becomes `{history[5:0], 1'b1}`, on not-taken `{history[5:0], 1'b0}`; the shifted-out bit is discarded, so 127 shifted with a 1 stays 127 and 0 shifted with a 0 stays 0.

Boundary values to exercise: pc=0 and pc=127; history=0 and history=127; index=0 and index=127; counter values 0,1,2,3 with the saturating transitions 0→1, 1→2, 2→3, 3→3 on taken and 3→2, 2→1, 1→0, 0→0 on not-taken. `predict_taken` is the MSB of the selected counter, so counters 0 and 1 predict not-taken, 2 and 3 predict taken. `predict_history` is the GHR value used for the prediction, i.e. the pre-edge GHR, not the shifted value.

Combinational outputs: when `areset` is high, `predict_history=0` and `predict_taken=0` regardless of any inputs. Otherwise, if `predict_valid`, `predict_history` is the current GHR and `predict_taken` is the MSB of `PHT[pc ^ GHR]`; if `predict_valid=0`, the outputs are still defined by the current state (the spec ties `predict_history` to the GHR used, so the checker should treat the GHR as the output when no prediction is requested, or at minimum not depend on `predict_pc`). The prediction read is combinational and sees the pre-edge PHT, so a same-cycle training write to the same index does not affect `predict_taken`.

Sequential behavior at posedge: reset dominates — GHR←0 and all counters←0 even if train/predict are asserted. Otherwise, if `train_valid`, the PHT entry at `train_pc ^ train_history` is updated by `train_taken` (saturating), and if `train_mispredicted`, GHR←shift(`train_history`, `train_taken`). Training takes precedence over prediction for the GHR: if both occur, the GHR is the training recovery value, not the prediction shift. If only `predict_valid`, GHR←shift(GHR, predicted direction). If neither, GHR holds.

Worked example: GHR=127, PHT[127]=3, `areset=1`, `predict_valid=1`, `predict_pc=0`, `train_valid=1`, `train_mispredicted=1`. Outputs must be `predict_history=0`, `predict_taken=0`; next state GHR=0 and all counters 0. This checks reset dominance over both the prediction read and the training write, and that the checker does not let a same-cycle train override reset.
