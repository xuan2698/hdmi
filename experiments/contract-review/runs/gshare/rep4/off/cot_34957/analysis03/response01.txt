**State and output transitions.** The design has two state elements: a 7-bit global history register (GHR) and a 128-entry PHT of 2-bit saturating counters. Reset is asynchronous active-high and has absolute priority: when `areset` is high, the GHR is cleared to 0 and every PHT entry is cleared to 0, regardless of any simultaneous `predict_valid` or `train_valid` activity. This priority extends to the misprediction-recovery path: a reset asserted while a mispredicted training request is pending discards that recovery, leaving the GHR at 0 rather than at `train_history`.

**Prediction path.** When `predict_valid` is sampled high, the predictor forms the index as `predict_pc ^ ghr` (7-bit XOR), reads the corresponding 2-bit counter, and drives `predict_taken` from the counter's MSB (taken when the counter is 2 or 3). It also drives `predict_history` equal to the current GHR value used for that lookup. These outputs are combinational functions of the pre-edge state: a training request sampled in the same cycle does not affect the prediction, because the PHT write and GHR update only land at the next positive edge. At that edge, the GHR is updated for the predicted branch (shift in the predicted direction) unless training takes precedence.

**Training path.** When `train_valid` is sampled high, the PHT entry indexed by `train_pc ^ train_history` is updated at the next edge according to `train_taken`: saturating increment toward 3 on taken, decrement toward 0 on not-taken. If `train_mispredicted` is also high, the GHR is recovered at the next edge to the state immediately after the mispredicting branch, i.e., `train_history` shifted with `train_taken` inserted. If a prediction for a different, younger instruction occurs in the same cycle as a mispredicted training, training wins the GHR update; the prediction's GHR update is suppressed because that predicted instruction will be flushed. If training and prediction touch the same PHT entry in the same cycle, the prediction still reads the old counter value (pre-edge), while the write takes effect for subsequent cycles.

**Reset timing.** Because reset is asynchronous, a mid-cycle assertion of `areset` (after a sample, before the next edge) clears GHR and PHT immediately, so the next sampled edge already observes the cleared state. The checker should therefore apply reset at the moment it rises, not defer it to the next edge. Before any reset, GHR and PHT contents are undefined; meaningful comparison should begin only after a reset has established the all-zero state.

**Worked example.** At cycle 4, PHT entry 0 holds 2 and GHR holds `7'b1010101`. `areset` rises mid-cycle after the cycle-4 sample. The checker immediately zeroes entry 0 and the GHR. At the cycle-5 sample, a prediction hashing to entry 0 must yield `predict_taken = 0` and `predict_history = 0`; any cycle-4 training request is discarded by the reset.

**Checker takeaway.** Treat `areset` as an asynchronous level with priority over prediction reads, PHT writes, and GHR updates (including misprediction recovery). Begin state comparison only after a reset establishes the all-zero state, and apply mid-cycle reset assertions immediately.
