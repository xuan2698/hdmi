The interface is narrow and fully specified: all data ports are 7 bits except the single-bit control and outcome signals. `predict_pc` and `train_pc` are 7-bit PCs, `train_history` and `predict_history` are 7-bit GHR values, and the PHT index is the 7-bit XOR `pc ^ history`, so the table has 128 entries indexed 0..127. Counters are 2-bit saturating values 0..3. `predict_taken` and `train_taken` are 1-bit directions; `train_mispredicted` is a 1-bit flush indicator. `areset` is asynchronous active-high, so it dominates all state regardless of clock.

Boundary values matter for the checker. A 7-bit history can be 0 or 127; shifting left and OR-ing a direction naturally truncates to 7 bits, so `(127<<1)|1` becomes 127 again, and `(127<<1)|0` becomes 126. The XOR index is always in 0..127 because both operands are 7-bit. Counter saturation means increment only when the current value is below 3 and decrement only when above 0; a taken training on counter 3 leaves it at 3, and a not-taken training on counter 0 leaves it at 0. Prediction direction is the counter's MSB, i.e. taken when the counter is 2 or 3.

The key checker point is the separation of combinational prediction from edge state updates. Prediction outputs must be computed from the pre-edge GHR and pre-edge PHT entry selected by `predict_pc ^ ghr`. Training in the same cycle must not affect that cycle's prediction output, even when the training index equals the prediction index. The PHT write occurs at the edge whenever `train_valid` is high (and reset is low), using `train_pc ^ train_history`, not the live GHR. The GHR update priority at the edge is: reset clears it; else if `train_valid && train_mispredicted`, load `(train_history<<1)|train_taken`; else if `predict_valid`, shift in `predict_taken`; else hold. A correctly predicted training request (`train_mispredicted=0`) updates only the PHT and does not recover the GHR, because the speculative shift already applied is assumed correct. A mispredicted training request overrides any simultaneous prediction shift.

Worked boundary example: let GHR=127 and suppose `predict_valid=1, predict_pc=0`, so index is 127. If that counter is 3, `predict_taken=1` and `predict_history=127`. If in the same cycle `train_valid=1, train_pc=0, train_history=127, train_taken=0, train_mispredicted=1`, the PHT entry 127 decrements to 2 at the edge, and the GHR becomes `(127<<1)|0 = 126`, not the prediction shift result. The prediction output for that cycle still reports taken and history 127.

For the final Python checker, model only the 7-bit GHR and 128 two-bit counters as state. Compute outputs combinationally before applying edge updates, then apply reset first, then the PHT write if `train_valid`, then the GHR priority chain. Do not let a same-cycle training write leak into the prediction output, and do not use the live GHR in place of `train_history` for the training index.
