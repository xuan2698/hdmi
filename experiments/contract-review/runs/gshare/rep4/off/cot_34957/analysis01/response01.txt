The public spec defines a gshare predictor with a 7-bit PC, a 7-bit global history register (GHR), and a 7-bit XOR hash indexing 128 two-bit saturating counters. The prediction interface is combinational in the sense that when `predict_valid` is high, the outputs `predict_taken` and `predict_history` reflect the current PC and current GHR state, and the GHR is updated at the next positive clock edge to incorporate the predicted branch. The training interface, when `train_valid` is high, supplies `train_pc`, `train_taken`, `train_mispredicted`, and `train_history`; the PHT update is applied at the next positive clock edge, and if `train_mispredicted` is asserted the GHR is recovered to the supplied `train_history` state at that same edge.

The timing analysis hinges on the distinction between values sampled at the posedge and values that change mid-cycle. Inputs are driven before the sampled edge; the checker samples after the posedge has settled. Therefore, for any cycle, the prediction outputs and the PHT/GHR state visible to the checker correspond to the register contents and combinational logic as they stand at the sampling instant. A training request asserted in cycle N does not alter the PHT entry or GHR until the posedge ending cycle N, so a prediction request in the same cycle N must observe the pre-training PHT state and the pre-training GHR. This is the explicit rule in the spec: if training and prediction of the same PHT entry coincide, the prediction sees the old PHT state because training only modifies the PHT at the next positive clock edge.

The GHR arbitration rule is equally important for the checker. If a misprediction training request and a prediction request occur in the same cycle, both would want to write the GHR at the next edge. Training takes precedence, because the predicted instruction is younger and will be flushed. Thus at the edge, the GHR becomes `train_history` (the state immediately after the mispredicting branch), not the prediction-derived update. If training is not a misprediction, the GHR update from training is not specified to override the prediction update; only the mispredicted case forces recovery. The checker should therefore model the next-GHR selection as: if `train_valid && train_mispredicted`, next GHR = `train_history`; else if `predict_valid`, next GHR = shift-in of the predicted direction; else hold. The PHT write, when `train_valid`, targets the entry indexed by `train_pc` XOR `train_history` and saturates the two-bit counter according to `train_taken`, independent of any simultaneous prediction read.

Mid-cycle input changes occur after sampling and before the other edge, and are carried to the start of the next row. This means the checker must not let a mid-cycle change retroactively affect the just-sampled outputs or the just-committed state; it only affects the next sampled edge. Asynchronous active-high reset clears the GHR and PHT immediately, so any sampled state after reset assertion must reflect cleared registers regardless of clock phase.

Worked example: in cycle 4, `train_valid=1` targets PHT entry 0 with `train_taken=1`, while `predict_valid=1` also hashes to entry 0. The sampled `predict_taken` in cycle 4 must reflect the old counter value at entry 0, not the incremented value. At the posedge ending cycle 4, entry 0 increments, and if `train_mispredicted` was set the GHR loads `train_history`; otherwise the GHR shifts in the predicted direction. The checker should compare cycle-4 outputs against pre-edge state and cycle-5 state against post-edge updates.
