The distinguishing case is a same-cycle collision between prediction and training, especially when the training request is a misprediction. A naive implementation might compute `predict_taken` after applying the PHT write, or might update the GHR using the prediction shift before honoring the training recovery. Both would be wrong.

Consider the public timing rule: prediction outputs are combinational from the current state, while PHT and GHR changes happen at the positive edge. So if `predict_valid=1` and `train_valid=1` in the same cycle, the prediction must use the old PHT entry and old GHR. The training write may target the same PHT entry, but the prediction still reports the pre-write counter value. At the edge, the PHT entry is updated according to `train_taken`, and the GHR update priority is reset, then mispredicted training recovery, then prediction shift, then hold.

A useful short example: start with GHR = 127. Drive `predict_valid=1`, `predict_pc=0`, so the prediction index is `0 ^ 127 = 127`. Suppose PHT[127] = 3. Then `predict_taken=1` and `predict_history=127`. In the same cycle drive `train_valid=1`, `train_pc=0`, `train_history=127`, `train_taken=0`, `train_mispredicted=1`. The training index is also `0 ^ 127 = 127`. The prediction output for this cycle must still be taken with history 127, because the PHT write has not happened yet. At the edge, PHT[127] decrements from 3 to 2. The GHR becomes `(127 << 1) | 0 = 126`, because mispredicted training takes precedence over the prediction shift. If the checker instead applied the prediction shift first, it would get `(127 << 1) | 1 = 127`, which is wrong. If it let the training write affect the combinational prediction, it might report not-taken, also wrong.

This example stresses three independent requirements at once: combinational prediction before edge updates, training index using `train_history` rather than the live GHR, and GHR priority favoring mispredicted training over prediction. A final Python checker should keep only the 7-bit GHR and 128 two-bit counters as state, compute outputs from the pre-edge state, then apply reset, then the PHT write if `train_valid`, then the GHR priority chain. That ordering catches the common bugs without needing a larger trace.
