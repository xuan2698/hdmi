The key timing point for the checker is that this design has one clocked state element—the 7-bit global history register—and one combinational read path—the PHT lookup—and the two interfaces interact only through the history register and through the PHT read/write ordering. All sampled behavior is defined at the posedge, with asynchronous active-high reset overriding everything.

At each posedge, the checker should first apply reset semantics: if `areset` is high at the sampled edge, the history register becomes 0 and the PHT is cleared (or otherwise reset to its specified initial state), regardless of `predict_valid` or `train_valid`. Because reset is asynchronous, a high `areset` asserted mid-cycle can also force the state before the next edge; the checker should treat any sampled edge with `areset=1` as authoritative reset, and should not let same-edge predict/train updates survive it.

For a normal sampled edge with `areset=0`, the outputs `predict_taken` and `predict_history` are combinational functions of the inputs and current state as seen before the edge. Specifically, when `predict_valid=1`, the index is `predict_pc ^ history_reg` (7-bit xor), `predict_taken` is the current PHT counter’s MSB at that index, and `predict_history` is the current history register value used for that lookup. The PHT read must reflect the pre-edge table contents: if training targets the same PHT entry in the same cycle, the prediction still sees the old counter, because the PHT write is edge-triggered. This is the explicit timing-diagram requirement in the spec.

The history register update at the edge depends on priority. If `train_valid=1` and `train_mispredicted=1`, training recovery wins: the history register is restored to the state immediately after the mispredicting branch, which the spec supplies as `train_history`. This takes precedence over any same-cycle prediction update, since the predicted younger instruction will be flushed. If `train_valid=1` but `train_mispredicted=0`, the history register is not recovered by training; a same-cycle valid prediction may still update it. If `predict_valid=1` and no higher-priority training recovery occurs, the history register shifts in the predicted direction for the predicted branch. The checker should model the update as a single next-state assignment with priority: reset > mispredicted-training recovery > prediction update. Ordinary training without misprediction does not itself change history.

The PHT update is independent of the history-register priority, except that it uses `train_pc ^ train_history` as the training index. When `train_valid=1`, the addressed 2-bit saturating counter is updated at the edge according to `train_taken`: increment toward 3 on taken, decrement toward 0 on not-taken. This write occurs after the combinational read for that cycle, so same-cycle predict/train to the same entry is not a hazard for the prediction output. If `train_valid=0`, no PHT entry changes.

Mid-cycle input changes matter only insofar as they are present at the next sampled posedge. The checker should not evaluate outputs continuously for mid changes unless the harness explicitly samples them; the stated protocol is “sample after the posedge has settled,” with inputs driven before the sampled edge. Thus mid-cycle changes are carried to the start of the next row and should be treated as the inputs for the next edge, not as immediate state mutations (except asynchronous reset).

Short worked example: suppose history=H, `predict_valid=1`, `predict_pc=P`, and `train_valid=1`, `train_mispredicted=1`, `train_history=H*`, with training index equal to `P^H`. At the edge, `predict_taken` and `predict_history=H` reflect the old PHT entry at `P^H`; the PHT entry at `train_pc^H*` updates; and the history register becomes `H*`, not the shifted prediction history. The checker should therefore compute outputs from pre-edge state, then apply next-state with training-recovery priority.
