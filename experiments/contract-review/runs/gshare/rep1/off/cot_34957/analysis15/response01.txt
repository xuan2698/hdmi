The predictor is a small synchronous machine with one architectural register (the 7-bit GHR) and a 128-entry PHT of 2-bit saturating counters. All state updates occur at the rising clock edge; outputs are combinational functions of current state and current inputs. The checker must therefore sample outputs *after* the edge settles, but must reason about which inputs were present *before* that edge.

**Prediction path (combinational).** When `predict_valid=1`, the index is `predict_pc[6:0] XOR ghr` (the current GHR, before any edge update). `predict_taken` is the MSB of `PHT[index]` (1 = taken). `predict_history` is the current GHR value itself — the history *used* to make this prediction, not the post-shift value. This is the key subtlety: the output reflects pre-edge state, so a same-cycle train that will modify the PHT or GHR must not be visible in these outputs. The GHR shift (append predicted direction) happens at the edge, only if `predict_valid` and no higher-priority event overrides.

**Training path (edge update).** When `train_valid=1`, the PHT entry at `train_pc[6:0] XOR train_history` is updated at the edge: taken → saturating increment (max `2'b11`), not-taken → saturating decrement (min `2'b00`). The training index uses `train_history`, the supplied history for that branch, *not* the live GHR. If `train_mispredicted=1`, the GHR is also recovered at the edge to `{train_history[5:0], train_taken}` — the history immediately after the mispredicting branch. If `train_mispredicted=0`, the GHR is not touched by training.

**Priority at the edge.** Three writers can target the GHR: prediction shift, misprediction recovery, and reset. Order: reset > misprediction recovery > prediction shift. So if `train_valid & train_mispredicted` coincides with `predict_valid`, recovery wins and the predicted branch's shift is discarded (that younger instruction is flushed anyway). If only `train_valid` (no mispredict) coincides with `predict_valid`, the prediction shift still applies — training without recovery does not write the GHR. The PHT write from training and the PHT read for prediction are independent: the read is combinational on pre-edge state, the write lands at the edge, so a same-cycle predict sees the old counter.

**Reset.** Asynchronous active-high: asserting `areset` forces GHR to 0 and all PHT entries to `2'b00` immediately, and outputs must reflect the cleared state (predict_history = 0, predict_taken = 0 for any index since all counters are 0). A train coincident with reset must not leak into post-reset state.

**Worked example.** GHR = `1010101`, PHT[0] = `11`. Cycle N: `predict_valid=1`, `predict_pc` hashing (with current GHR) to entry 0. Outputs: `predict_taken=1`, `predict_history=1010101`. Same cycle `train_valid=1`, `train_mispredicted=1`, `train_taken=0`, `train_history=0000000`, `train_pc` hashing to entry 0. At the edge: PHT[0] decrements to `10`; GHR recovers to `{0000000[5:0],0}=0000000` (recovery beats the prediction shift). Next cycle, a fresh predict with `predict_pc` hashing to entry 0 reads `10` → not-taken, and `predict_history=0000000`.

**Checker focus.** The most discriminating checks: (1) `predict_history`/`predict_taken` are pre-edge values, unaffected by same-cycle training; (2) recovery-over-shift priority when both fire; (3) reset dominance over any concurrent train, with post-reset GHR=0 and PHT all-zero.
