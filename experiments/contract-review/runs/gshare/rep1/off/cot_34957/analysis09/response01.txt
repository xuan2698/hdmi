The design has two pieces of architectural state: a 7-bit global history register (`ghr`) and a 128-entry PHT of 2-bit saturating counters. Both are cleared to zero by asynchronous active-high reset. The PHT index is formed by XORing the 7-bit `predict_pc` (or `train_pc`) with the 7-bit history value used for that access; the resulting 7-bit index selects one counter. Prediction reads the counter and outputs `predict_taken` (counter's MSB, i.e. taken when counter ≥ 2) together with `predict_history`, which is the `ghr` value used to form the index. Training updates the selected counter according to `train_taken` (increment toward 3 on taken, decrement toward 0 on not-taken), and if `train_mispredicted` is asserted, the `ghr` is recovered to `train_history` shifted appropriately for the trained branch.

The critical checker-relevant behavior is the ordering and dominance of events within a cycle. Reset is asynchronous and dominant: when `areset` is high, `ghr` and all PHT entries are forced to zero immediately, and any prediction or training request in that same cycle must be evaluated against the reset state, not the pre-reset state. Moreover, reset cancels pending next-state updates — a training or prediction that would have modified `ghr` or the PHT at the upcoming edge must not do so if reset is asserted before that edge. The checker should treat reset as an immediate state-clearing event that also discards the current row's next-state computation.

For non-reset cycles, the checker must respect the read-before-write semantics of the PHT and the priority of training over prediction on the `ghr`. A prediction in a cycle observes the PHT state as it exists at the start of that cycle (before any same-cycle training write takes effect at the edge) and observes the current `ghr`. The prediction's `predict_history` output is the `ghr` value used for indexing, sampled combinationally from current state. At the next positive edge, if `predict_valid` is asserted and no training overrides it, `ghr` is updated by shifting in the predicted direction (the predicted taken bit). If `train_valid` is asserted, the PHT entry selected by `train_pc` XOR `train_history` is updated at the edge; if `train_mispredicted` is also asserted, `ghr` is set at the edge to the recovered value derived from `train_history` (the history immediately after the mispredicting branch), overriding any prediction-driven `ghr` update in that cycle. When both training (mispredicted) and prediction occur in the same cycle, training wins on the `ghr`; the prediction still outputs its result based on pre-edge state, but its history update is discarded.

A useful worked example for the checker: start from reset with `ghr=0`, all counters 0. Apply `predict_valid=1, predict_pc=0`. Outputs: `predict_taken=0`, `predict_history=0` (index 0, counter 0). At the edge, since predicted not-taken, `ghr` shifts in 0 and remains 0. Next cycle, assert `train_valid=1, train_taken=1, train_mispredicted=0, train_history=0, train_pc=0`. The PHT[0] counter increments to 1 at the edge; `ghr` is unchanged (no mispredict recovery). A subsequent prediction for `predict_pc=0` with `ghr=0` still reads counter 1, so `predict_taken=0` (MSB still 0), confirming the read-before-write and threshold behavior. If instead `train_mispredicted=1` with `train_history=0`, the edge sets `ghr` to the recovered value (0 shifted for the branch), and any same-cycle prediction's history update is ignored.

The final checker should therefore: (1) apply reset immediately and dominantly, clearing state and suppressing same-row updates; (2) compute prediction outputs from current state before any edge effects; (3) at each edge, apply training PHT writes and, if mispredicted, the `ghr` recovery with priority over prediction-driven `ghr` shifts; (4) otherwise apply the prediction-driven `ghr` shift when `predict_valid` is set. This ordering — reset > training-recovery > prediction-shift, with PHT reads preceding same-cycle writes — captures the spec's timing semantics.
