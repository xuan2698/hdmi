The public interface is small but the widths and edge semantics matter. Inputs: `areset` (1), `predict_valid` (1), `predict_pc` (7), `train_valid` (1), `train_taken` (1), `train_mispredicted` (1), `train_history` (7), `train_pc` (7). Outputs: `predict_taken` (1), `predict_history` (7). Clock is `clk`; sampling is after the posedge settles, with each row's inputs driven before the sampled edge and optional mid-cycle changes carried to the next row.

Boundary values: `predict_pc` and `train_pc` span 0..127; `train_history` spans 0..127; `predict_history` spans 0..127. The PHT index is `pc ^ history`, also 7 bits, so it spans 0..127 and addresses exactly 128 two-bit counters. Counter states are 0..3; the predicted direction is the counter's MSB, so states 0 and 1 predict not-taken, states 2 and 3 predict taken. Saturating means increment stops at 3 and decrement stops at 0. The GHR is 7 bits, so after any shift the new value is `((ghr << 1) | taken) & 0x7F`; the recovered value from `train_history` must likewise be masked to 7 bits. Reset is asynchronous active-high and must clear the GHR and all 128 counters, and must suppress same-row updates.

The key checker point is ordering. Prediction outputs are combinational from pre-edge state: index = `predict_pc ^ ghr`, `predict_taken` = PHT[index][1], `predict_history` = current `ghr`. A same-cycle training write to that index is not visible to the prediction; the read precedes the write. At the edge, priority is reset > training-recovery > prediction-shift. If `train_valid`, the selected counter updates (increment if `train_taken`, else decrement, saturating). If `train_valid && train_mispredicted`, `ghr` is set to the recovered value derived from `train_history` (shift in the mispredicting branch outcome, masked), overriding any prediction-driven shift. Otherwise, if `predict_valid`, `ghr` shifts in the predicted taken bit. If neither, `ghr` holds.

Worked example: after reset, `ghr=0`, counters 0. With `predict_valid=1, predict_pc=0`, output `predict_taken=0`, `predict_history=0`; at the edge `ghr` stays 0 (shift in 0). Next cycle train `train_pc=0, train_history=0, train_taken=1, train_mispredicted=0`: PHT[0] becomes 1 at the edge, `ghr` unchanged. A later prediction at `predict_pc=0, ghr=0` reads counter 1 and still outputs `predict_taken=0`, confirming read-before-write and MSB threshold. If `train_mispredicted=1` with `train_history=0`, the edge sets `ghr` to the recovered value and ignores any same-cycle prediction shift.

So the final checker should: apply reset dominantly and immediately; compute prediction outputs from current state before edge effects; at each edge apply training PHT writes and, on mispredict, GHR recovery with priority over prediction shifts; otherwise apply the prediction-driven shift when `predict_valid`. That ordering captures the spec's timing semantics.
