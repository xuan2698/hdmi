The most useful distinguishing example for the checker is the interaction between a same-cycle prediction and a mispredicted training that target the same PHT index, because it exercises three separate rules at once: the read-before-write behavior of the PHT, the training-over-prediction priority on the global history register, and the 7-bit masking of the shifted history.

Consider a concrete case. Suppose the current `ghr = 7'b0000000`, and the PHT entry at index 0 currently holds state 2 (predict taken). Now drive, in the same cycle, `predict_valid=1` with `predict_pc=7'b0000000` (so index = 0 ^ 0 = 0), and `train_valid=1`, `train_mispredicted=1`, `train_taken=0`, `train_history=7'b0000000`, `train_pc=7'b0000000` (also index 0). The prediction must output `predict_taken=1` (MSB of state 2) and `predict_history=0`, because the read path sees the stored PHT value before the training write commits. At the posedge, the mispredicted training wins the history update: `ghr` becomes `{train_history[5:0], train_taken} = {6'b000000, 1'b0} = 7'b0000000`. The PHT entry at index 0 is decremented from 2 to 1, but that new value is only visible to predictions in the next cycle. A checker that instead let the prediction's shift win, or that let the prediction observe the decremented counter, would produce a different `predict_taken`/`predict_history`/`ghr` triple and be caught here.

This example is valuable because it separates the two state elements. The PHT is a registered array: writes take effect after the sampled edge, so a coincident read returns the pre-edge counter. The `ghr` is also registered, but its next-state selection is priority-encoded: reset, then mispredicted training, then prediction, then hold. The same-cycle collision forces the checker to implement both the "read old PHT" rule and the "training beats prediction for ghr" rule independently; a naive implementation that applies the prediction shift first and then overwrites with training, or that applies training to the PHT before servicing the read, will diverge.

A second point worth encoding is the saturation boundary. If the same index held state 3 and `train_taken=1`, the update must leave it at 3, not wrap to 0; if it held state 0 and `train_taken=0`, it must stay 0. These edges are easy to get wrong with a modulo-4 increment/decrement, so the checker should include at least one directed case at each boundary, ideally combined with a coincident prediction to confirm the read still returns the saturated pre-edge value.

Finally, the 7-bit masking of the history shift deserves an explicit check. With `ghr=7'b1111111` and a taken prediction, the next `ghr` is `(127<<1 | 1) & 127 = 127`, not 255. Any checker that stores an 8-bit intermediate or forgets the mask will fail on this wrap, and the failure will be visible in `predict_history` on the following cycle. Combining the wrap case with the collision case above gives a compact but high-coverage directed test.
