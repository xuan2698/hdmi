The interface is small but the boundary conditions matter. All control signals are one bit: `areset`, `predict_valid`, `train_valid`, `train_taken`, `train_mispredicted`. The address-like fields are 7 bits: `predict_pc`, `train_pc`, `train_history`, and the output `predict_history`. The only other output is `predict_taken`, one bit. Because the PHT has 128 entries and the index is 7 bits, every possible 7-bit index is legal and maps to exactly one entry; there is no out-of-range index to guard against. The hash is `pc ^ history`, so both operands must be treated as unsigned 7-bit vectors and XORed bitwise. No sign extension or truncation is needed, but the checker should mask to 7 bits if it computes the index in a wider integer.

The GHR is 7 bits and is part of the architectural state alongside the 128 two-bit counters. Its update is not a simple shift on every request. Three cases compete. First, asynchronous active-high reset dominates: if `areset` is sampled high, the post-edge state is PHT all zeros and GHR zero, regardless of any simultaneous predict or train request. Second, a mispredicted training request recovers the GHR to the state immediately after the mispredicting branch, namely `{train_history[5:0], train_taken}`. This takes precedence over a same-cycle prediction, because the predicted instruction is younger and will be flushed. Third, if there is no mispredicted training but `predict_valid=1`, the GHR shifts in the predicted direction: `{GHR[5:0], predict_taken}`. If none of these applies, the GHR holds. A non-mispredicted training request does not shift the GHR by itself.

The PHT write is edge-triggered and occurs only when `train_valid=1` and reset is not asserted. The entry is selected by `train_pc ^ train_history`. A taken outcome increments the two-bit saturating counter up to 3; a not-taken outcome decrements it down to 0. The write affects only post-edge state and future predictions. In particular, if a prediction and a training request target the same PHT entry in the same cycle, the prediction output must reflect the pre-edge counter value, not the value that will be written at the edge. The checker should therefore evaluate prediction outputs from the stored state before applying the edge update.

Prediction outputs are combinational from pre-edge state. `predict_taken` is the MSB of the selected counter, i.e., taken when the counter is 2 or 3 and not-taken when it is 0 or 1. `predict_history` is the current GHR value used to form the index, not the next GHR. The prediction request does not itself change the PHT; it only supplies the predicted direction for the GHR shift if no higher-priority update occurs.

Boundary values worth testing include counter states 0 and 3 under repeated training, index 0 and index 127, GHR all zeros and all ones, and simultaneous predict/train with and without misprediction. Reset must be applied before any edge-dependent behavior, and power-up values should not be assumed.

Worked example: with `areset=1`, `train_valid=1`, `train_pc=0`, `train_history=0`, `train_taken=1`, `train_mispredicted=1`, the post-edge state is PHT[0]=0 and GHR=0 because reset wins. After reset is released, the same training request would increment PHT[0] to 1 and, since mispredicted, set GHR to `{000000,1}`.
