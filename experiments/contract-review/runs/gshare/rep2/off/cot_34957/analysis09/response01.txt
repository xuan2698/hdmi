The predictor's state consists of the 7-bit GHR and the 128 two-bit saturating counters. Reset is asynchronous and active-high: asserting `areset` immediately clears the GHR to zero and all PHT counters to zero, and this clearing dominates every other input. In particular, if `train_valid && train_mispredicted` or `predict_valid` is asserted while `areset` is high, neither the training nor the prediction may affect state; the GHR stays zero and the PHT stays zeroed. Because a zeroed two-bit counter has MSB 0, `predict_taken` reads 0 during reset, and `predict_history` reads 0. The checker should verify these output values while reset is asserted rather than assuming any "weakly" initialized counter encoding.

Once reset is deasserted, the first sampled cycle starts from GHR = 0 and an all-zero PHT. A prediction request (`predict_valid = 1`) computes the index `predict_pc ^ GHR`, reads that PHT entry, and drives `predict_taken` from the counter's MSB and `predict_history` from the current GHR. The read is combinational with respect to the current PHT contents: if training targets the same entry in the same cycle, the prediction still observes the pre-training counter value, because training only writes the PHT at the next positive edge. The GHR next-state priority is: (1) if `train_valid && train_mispredicted`, load `train_history`; (2) else if `predict_valid`, shift the GHR left by one, inserting the predicted direction (the MSB of the counter just read) at the LSB; (3) else hold. Ordinary training (`train_valid` without `train_mispredicted`) updates only the counter at `train_pc ^ train_history` and never shifts the GHR. When a misprediction training and a prediction occur in the same cycle, training wins for the GHR, since the predicted instruction will be flushed; the prediction's PHT read still reflects the old counter, and its `predict_history` output still shows the pre-edge GHR.

Counter updates are saturating two-bit: a taken outcome increments toward 3, a not-taken outcome decrements toward 0, with no wrap. The write occurs at the positive edge, so same-cycle predictions see the old value.

Worked example: after reset, GHR = 0, all counters 0. Cycle A: `predict_valid=1`, `predict_pc=7'h05`. Index = 5, counter = 0, so `predict_taken=0`, `predict_history=0`; at the edge GHR becomes 0 (shift in 0). Cycle B: `train_valid=1`, `train_taken=1`, `train_mispredicted=0`, `train_pc=7'h05`, `train_history=0`. Index = 5; at the edge counter[5] becomes 1, GHR unchanged. Cycle C: `predict_valid=1`, `predict_pc=7'h05`, GHR still 0. Index = 5, counter now 1, so `predict_taken=1`, `predict_history=0`; at the edge GHR becomes 1. This confirms the one-cycle write visibility and the shift-in of the predicted bit.

The checker should always begin each test by asserting `areset`, sampling outputs to confirm the asynchronous clear, then deasserting reset before applying normal stimulus; tests that skip reset compare against an unspecified initial state and are non-conforming.
