The public interface is narrow but the boundary behavior is where a checker earns its keep. Inputs: `areset` (1), `predict_valid` (1), `predict_pc` (7), `train_valid` (1), `train_taken` (1), `train_mispredicted` (1), `train_history` (7), `train_pc` (7). Outputs: `predict_taken` (1), `predict_history` (7). All 7-bit fields span 0..127; the single-bit controls are 0/1. The 128-entry PHT is indexed by `pc ^ history`, so index range is exactly 0..127 with no masking surprises — but note the checker must hash `train_pc ^ train_history` for training and `predict_pc ^ GHR` for prediction, and these are *different* histories in general.

Boundary values worth pinning: `predict_pc=0`, `train_pc=0`, `train_history=0`, and `train_history=127` (all ones) exercise the XOR extremes; `train_history=127` with `train_taken=1` yields recovery value `{127[5:0],1} = 0b1111111 = 127`, i.e. the all-ones GHR is a fixed point under a taken recovery — a cheap invariant. Counter saturation: entry at 3 stays 3 on taken, entry at 0 stays 0 on not-taken; the checker should drive repeated same-index trainings to confirm clamping rather than wraparound (a 2-bit add without clamp would wrap 3→0, which is the classic bug).

The highest-value transition is the same-cycle conflict: `train_valid=1 && train_mispredicted=1 && predict_valid=1`. Training wins the GHR write, so next-cycle `GHR == {train_history[5:0], train_taken}`, and the prediction's speculative shift is discarded. The prediction *outputs* in that cycle must still reflect the pre-edge GHR and pre-edge counter (read-before-write). A model that applies the speculative shift first, or that lets prediction override recovery, fails here.

Reset is asynchronous active-high: assert `areset` off-edge and sample immediately — `predict_history` must be 0 and `predict_taken` must be 0 in that same cycle, before any posedge. A posedge-only clear model will still show the old GHR and old counter, which is the cheapest reset bug to catch. Deassert between edges, wait one clean cycle, then confirm a fresh prediction on a zeroed table yields not-taken.

Worked example: GHR=0b1010101, entry 0 counter=3. Off-edge assert `areset=1` with `predict_valid=1`, `predict_pc` hashing to entry 0. Immediately expect `predict_history=0`, `predict_taken=0`. A posedge-only model shows history 0b1010101 and taken=1 that cycle — flag it.

Checker focus: model GHR and PHT as the only state; index = `pc ^ history`; enforce read-before-write for same-cycle train/predict; enforce training priority over prediction for the GHR; test asynchronous reset by sampling off-edge.
