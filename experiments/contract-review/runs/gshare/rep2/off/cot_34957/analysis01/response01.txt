The key timing point for the checker is that this design has **two distinct state elements with different update rules**: the PHT (128 two-bit counters) and the 7-bit global history register (GHR). Both are clocked by `clk`, and both are asynchronously reset by active-high `areset`. The checker must sample outputs *after* the posedge has settled, and must treat all inputs as driven *before* that sampled edge. Mid-cycle input changes (after sampling, before the next edge) must be carried forward to the next row's pre-edge values — they do not retroactively affect the just-sampled outputs.

**Prediction path (combinational read, clocked GHR update).** When `predict_valid=1`, the index is `predict_pc ^ ghr` (7-bit XOR), and `predict_taken` reflects the PHT counter's current MSB *as it stands at the sampled edge*, i.e., before any same-cycle training write takes effect. `predict_history` outputs the GHR value used for that index. The GHR is then updated at the next posedge to shift in the predicted direction. So the checker should expect `predict_taken`/`predict_history` to be pure functions of the *pre-edge* PHT and GHR, while the GHR's new value is visible only in the following row.

**Training path (clocked PHT write, conditional GHR recovery).** When `train_valid=1`, the PHT entry at `train_pc ^ train_history` is updated at the posedge: increment on taken, decrement on not-taken, saturating at 0 and 3. This write is *not* visible to a same-cycle prediction — the spec's timing diagram explicitly shows cycle-4 training changing the entry only in cycle 5, while the cycle-4 prediction reads the old state. The checker must therefore compute `predict_taken` from the pre-edge PHT even when `train_valid` targets the same index. Separately, if `train_mispredicted=1`, the GHR is *recovered* at the posedge to `train_history` shifted with the actual outcome (the state immediately after the mispredicting branch). If not mispredicted, training does not touch the GHR.

**Priority when both fire.** If `train_valid` and `predict_valid` coincide and both would modify the GHR, training wins: the GHR takes the recovery value, and the predicted branch's shift is discarded. The checker should model the GHR next-state as: reset → 0; else if `train_valid && train_mispredicted` → recovered value; else if `predict_valid` → shifted prediction; else hold. Note the subtlety: a *non-mispredicted* training does not override a same-cycle prediction's GHR shift, so the checker must gate the "training wins" rule on `train_mispredicted`, not merely `train_valid`.

**Worked example.** Suppose at a sampled edge GHR=0, PHT[0]=2 (weakly taken), and `predict_valid=1, predict_pc=0`, so index 0 and `predict_taken=1`, `predict_history=0`. Same cycle `train_valid=1, train_pc=0, train_history=0, train_taken=0, train_mispredicted=1`. The checker expects the *current* row's `predict_taken=1` (old PHT), but the *next* row's PHT[0]=1 (decremented) and GHR recovered to the shifted `train_history` value rather than the prediction's shift.

**Reset.** `areset` is asynchronous and active-high: on assertion, PHT counters and GHR go to 0 immediately, independent of `clk`. The checker should apply reset before evaluating any edge-dependent behavior, and should not assume reset is synchronized to the sampled edge.
