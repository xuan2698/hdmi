The interface is small and fully combinational on the read side, with all state changes confined to the positive clock edge. Inputs: `areset` (1), `predict_valid` (1), `predict_pc` (7), `train_valid` (1), `train_taken` (1), `train_mispredicted` (1), `train_history` (7), `train_pc` (7). Outputs: `predict_taken` (1), `predict_history` (7). All 7-bit fields span 0..127 inclusive; the single-bit fields are 0/1. Because the PHT has 128 entries and the index is 7 bits, every index value is legal and maps to exactly one counter — there is no aliasing within a single access, and no out-of-range index to guard against. The GHR is also 7 bits, so it too ranges over 0..127 and wraps naturally under left-shift (the shifted-out MSB is discarded).

Boundary considerations for the checker: counter values are constrained to {0,1,2,3}; a taken outcome at 3 stays 3, a not-taken at 0 stays 0 (saturation, no wrap). The MSB of the counter is bit 1, so `predict_taken` is 1 exactly when the counter is 2 or 3. The index is `pc ^ history` (bitwise XOR of two 7-bit values), always in 0..127. `predict_history` is the pre-edge GHR, i.e., the value used to form the index for this prediction, not the next-state GHR. Reset is asynchronous active-high, so asserting `areset` must clear the GHR and all 128 counters to 0 without waiting for a clock edge; the checker should verify outputs reflect this cleared state.

Priority and timing rules the checker must enforce: (1) GHR next-state priority is mispredicted-training load > prediction shift > hold. A prediction shifts left by one and inserts the predicted direction bit at the LSB. Ordinary training never touches the GHR. (2) When mispredicted training and prediction coincide, training wins the GHR, but the prediction's `predict_taken`/`predict_history` still reflect the pre-edge counter and pre-edge GHR. (3) Same-cycle train and predict on the same PHT entry: the prediction reads the old counter; the write lands at the edge. (4) Counter writes occur only at the positive edge, so any same-cycle read sees the prior value.

Worked example: after reset GHR=0, counters all 0. Cycle A: predict_valid=1, predict_pc=5 → index 5, counter 0 → predict_taken=0, predict_history=0; edge shifts GHR to 0. Cycle B: train_valid=1, train_taken=1, train_mispredicted=0, train_pc=5, train_history=0 → index 5; edge sets counter[5]=1, GHR unchanged. Cycle C: predict_valid=1, predict_pc=5, GHR=0 → index 5, counter now 1 → predict_taken=1, predict_history=0; edge shifts GHR to 1. This demonstrates one-cycle write visibility and predicted-bit insertion.

The single most useful point for the final Python checker: model the PHT and GHR as edge-updated state, compute all outputs combinationally from the *current* (pre-edge) state, and apply the GHR priority (mispredicted-train load, else predict shift, else hold) and saturating counter update only when advancing the clock. Always start with an asserted `areset` and confirm the asynchronous clear before normal stimulus; skipping reset leaves initial state unspecified and is non-conforming.
