**State and output transitions.** The predictor has two pieces of clocked state: a 128-entry PHT of 2-bit saturating counters and a 7-bit GHR. The prediction interface is combinational with respect to the current state: when `predict_valid=1`, the index is `predict_pc ^ GHR` (7-bit XOR), `predict_taken` is the MSB of `PHT[index]`, and `predict_history` is the current GHR. These outputs reflect the pre-edge state, so a same-cycle training write to that same PHT entry is not visible to the prediction; the prediction sees the old counter value. When `predict_valid=0`, the prediction outputs are don't-care for the checker (they may be driven from the same combinational path but are not checked).

**Clocked updates.** At a sampled posedge with `areset=0`, two independent updates may occur. First, if `train_valid=1`, the PHT entry at `train_pc ^ train_history` is updated according to `train_taken`: a 2-bit saturating counter increments on taken (up to 3) and decrements on not-taken (down to 0). This write is edge-triggered, so it affects only post-edge state and future predictions, never the current-cycle prediction output. Second, the GHR update is governed by priority: training with `train_mispredicted=1` takes precedence over a same-cycle prediction. In that case the GHR is recovered to the state immediately after the mispredicting branch, i.e., `{train_history[5:0], train_taken}` (shift in the actual outcome). If no mispredicted training occurs but `predict_valid=1`, the GHR shifts in the predicted direction: `{GHR[5:0], predict_taken}`. If neither applies, the GHR holds. Note that a non-mispredicted training request does not itself shift the GHR; only prediction (for younger instructions) or misprediction recovery does.

**Reset priority.** `areset` is asynchronous active-high and dominates everything. Whenever `areset=1` at the sampled edge, the post-edge state is PHT all zeros and GHR zero, regardless of any simultaneous `predict_valid`, `train_valid`, `train_taken`, or `train_mispredicted`. The checker must apply reset before evaluating any edge-dependent behavior for that row, and must not let a same-cycle training request increment a counter or recover the GHR while reset is asserted.

**Worked example.** With `areset=1` and `train_valid=1, train_pc=0, train_history=0, train_taken=1, train_mispredicted=1`, the expected post-edge state is PHT[0]=0 and GHR=0 — reset wins over both the increment and the recovery. After reset is released, a subsequent training request at a posedge does modify PHT[0] and, if mispredicted, recovers the GHR.

**Checker takeaway.** Compute next state as: if `areset` then {PHT=0, GHR=0}; else apply the saturating PHT write at `train_pc^train_history` when `train_valid`, and set GHR to `{train_history[5:0],train_taken}` if `train_valid && train_mispredicted`, else `{GHR[5:0],predict_taken}` if `predict_valid`, else hold. Prediction outputs are combinational from pre-edge state. Do not assume power-up values; require a reset first.
