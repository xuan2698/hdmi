The design is a single-clock, two-interface gshare predictor. Its architectural state is exactly two things: a 7-bit global history register (GHR) and a 128-entry array of 2-bit saturating counters (the PHT). Everything else is combinational. The checker should model these two state elements explicitly and derive all outputs from them, because the public spec pins down their update rules precisely and leaves little room for alternative implementations.

**Prediction path (combinational).** When `predict_valid=1`, the index is `predict_pc ^ GHR` (both 7 bits, XOR into 7 bits, indexing the 128-entry table). The output `predict_taken` is the MSB of the selected 2-bit counter (1 = taken, 0 = not-taken), and `predict_history` is the current GHR value used for that hash. Crucially, the prediction reads the PHT and GHR *as they stand at the sampling edge* — it does not see the effect of any training in the same cycle, because training only writes at the next posedge. So a same-cycle train+predict on the same entry must show the pre-training counter value in `predict_taken`. The checker should verify this "read-before-write" ordering by driving both interfaces at one entry and confirming the prediction reflects the old counter.

**GHR update on prediction.** At the posedge, if `predict_valid=1` and no training overrides, the GHR shifts in the predicted direction: `GHR <= {GHR[5:0], predict_taken}`. Note the spec says the register is updated "for the predicted branch" — i.e., the predicted outcome, not the true one, feeds the speculative history. The checker should confirm the shift uses `predict_taken`, not `train_taken`.

**Training path.** When `train_valid=1`, the PHT entry at `train_pc ^ train_history` is updated at the posedge according to `train_taken`: increment saturating at 3 if taken, decrement saturating at 0 if not-taken. The `train_history` input is the GHR snapshot that was used when the branch was predicted, so the checker must hash with `train_history`, not the live GHR. Training does *not* itself shift the GHR in the normal (correct-prediction) case.

**Misprediction recovery.** If `train_valid=1 && train_mispredicted=1`, the GHR is *recovered* at the posedge to the state immediately after the mispredicting branch: `GHR <= {train_history[5:0], train_taken}`. This is the one case where training writes the GHR. The checker's highest-value transition test is the priority case: same cycle, `train_valid=1 && train_mispredicted=1` plus `predict_valid=1`. Training wins the GHR write, so the next-cycle GHR must equal the recovery value, and the prediction's speculative shift is discarded. The prediction output in that cycle still reflects the pre-edge GHR and pre-edge counter.

**Reset.** Asynchronous active-high: on `areset=1`, GHR clears to 0 and all counters clear to the not-taken floor (0). The checker should sample outputs in the same cycle as an off-edge assertion, before any posedge, and require `predict_history=0` and `predict_taken=0` immediately — this is the cheapest reset test and catches posedge-only clearing. Deassert between edges, wait one clean cycle, then confirm a fresh prediction still yields not-taken.

**Worked example.** GHR=0b1010101, entry 0 counter=3. Drive `areset=1` off-edge with `predict_valid=1`, `predict_pc` hashing to entry 0. Immediately expect `predict_history=0`, `predict_taken=0`. A posedge-only model would still show history 0b1010101 and taken=1 that cycle — flag it.

**Checker focus.** Model GHR and PHT as the only state; compute index as `pc ^ history`; enforce read-before-write for same-cycle train/predict; enforce training priority over prediction for the GHR; and test asynchronous reset by sampling off-edge.
