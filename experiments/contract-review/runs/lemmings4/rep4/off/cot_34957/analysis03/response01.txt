The machine’s state must encode more than the four visible outputs: walking direction, whether it is currently falling, whether it is currently digging, and the elapsed fall duration up to the splatter threshold. The outputs are Moore outputs, so they are determined by the state alone and remain stable between sampled edges except for the asynchronous reset exception. The checker should therefore compare outputs only after the sampled edge has settled, while still allowing an asynchronous reset to change outputs immediately when it rises.

The precedence rule is the central transition constraint. At each sampled rising edge, if the machine is not splattered and not in reset, first test for loss of ground. If `ground=0` and the machine is not already falling, it enters falling and asserts `aaah`; if it was walking or digging, the remembered walking direction is preserved. While falling, bumps and `dig` are ignored. If `ground=1` while falling, the machine lands: if the fall duration exceeded 20 cycles, it enters the splattered state and all outputs become zero forever; otherwise it resumes walking in the remembered direction. Only if ground is present and the machine is not falling should `dig` be considered. A walking Lemming with `dig=1` enters digging and asserts `digging`; it remains digging until `ground=0`, at which point it falls. Bumps are considered only for a walking Lemming on ground and not digging; if either bump input is asserted, the direction toggles, with simultaneous bumps still causing a toggle.

A useful checker point is that the fall counter must be cleared whenever the machine is not falling, including on reset and on landing, and must not be incremented during digging or walking. The splatter decision is made only on the landing transition, not while airborne. Also, a bump in the same cycle that ground disappears does not affect direction, and a bump in the same cycle that ground reappears while still falling does not affect direction; the remembered direction from before the fall governs resumption.

For reset, the checker should treat `areset` as immediately forcing the walk-left state and clearing all fall/dig/splatter history. No pre-reset fall count, direction, digging status, or splatter flag may survive. After reset deasserts, the next sampled edge is an ordinary edge, with fall having highest precedence, then dig, then bump.

Worked example: if the machine is walking right and has fallen for 25 cycles, then `areset` rises mid-cycle, outputs must immediately become `walk_left=1` and all others 0. At the next edge with `ground=1`, no bump, and no dig, it remains walking left; the long fall must not splatter because reset erased the fall history.
