The key timing point for the checker is that this is a Moore machine sampled on the rising edge, with asynchronous active-high reset. All outputs are functions of the current state only, so the checker should compare outputs to the state that was entered at the sampled edge, not to the inputs that will be applied afterward. Inputs presented before a rising edge determine the next state; inputs changed after sampling (mid-cycle) must not retroactively alter the outputs already sampled for that edge.

Because `areset` is positive-edge-triggered asynchronous, a rising edge on `areset` forces the machine to the walk-left state immediately, independent of `clk`. The checker should therefore treat any sampled row where `areset=1` as forcing `walk_left=1` and all other outputs 0, and should not let prior fall/dig history survive reset. After reset deasserts, normal edge sampling resumes.

For non-reset rows, the precedence rules matter more than the exact input combination. Falling has highest precedence: if the machine is walking on ground and `ground=0`, it enters falling and asserts `aaah`, regardless of `dig` or bumps. Digging has next precedence: a walking Lemming on ground with `dig=1` starts digging and asserts `digging`, ignoring bumps. Direction switching is lowest: only a walking Lemming that is neither falling nor starting to dig responds to `bump_left`/`bump_right`, and simultaneous bumps still cause a direction change. While falling or digging, bumps are ignored for direction. A dig continues until `ground=0`, at which point the Lemming falls; when ground returns it resumes the original walking direction. Splatter occurs only when a fall of more than 20 cycles ends by hitting ground; at that sampled edge all four outputs become 0 permanently until reset. Mid-air long falls do not splatter.

A short worked example: suppose the sampled state is walking right on ground, and before the next rising edge the inputs are `ground=0, dig=1, bump_left=1`. The next sampled outputs must be falling (`aaah=1`, `walk_right=0`, `digging=0`), because ground loss outranks dig and bump. If instead `ground=1, dig=1, bump_left=1`, the next outputs are digging (`digging=1`), because dig outranks the bump. If `ground=1, dig=0, bump_left=1`, the next outputs are walking left. The checker should also verify that a mid-cycle change after sampling does not change the outputs already associated with that edge; it only affects the following edge’s next state.
