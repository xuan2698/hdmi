The key timing point for the checker is that the Moore outputs are sampled after the posedge has settled, while mid-input changes occur after sampling and before the next edge. This means a row's inputs are the values present at the sampled edge; any mid-cycle change is only relevant to the following row. Consequently, the checker should evaluate state transitions and outputs using the sampled input tuple for that row, not a blend of pre- and post-mid values. In particular, a bump that arrives mid-cycle must not retroactively affect the direction decision made at the preceding sampled edge, and a `ground` change that arrives mid-cycle must not be treated as having occurred on the previous edge.

For splatter, the checker must distinguish “fall duration since leaving ground” from “total time spent falling.” A useful test is a long fall that is interrupted by `areset` before landing, followed by a normal short fall and landing. The pre-reset fall must not contribute to splattering. Another useful pair is a fall of exactly 20 cycles followed by landing, which must not splatter, and a fall of 21 cycles followed by landing, which must splatter. The splatter decision is made only on the landing transition, when `ground=1` while the machine is falling; mid-air cycles never splatter. Once splattered, all four outputs must remain zero until reset.

A second related trap is the remembered walking direction. When ground disappears, the machine must latch the current walking direction and resume it on landing, regardless of bumps received during the fall or on the disappearance/reappearance edges. A bump in the same cycle that `ground` goes to 0 must not alter the latched direction; a bump in the same cycle that ground returns while still falling must not alter the resumption direction. Digging similarly preserves the pre-dig direction: the Lemming digs until `ground=0`, falls, then resumes walking the original way.

Precedence on a normal sampled edge is fall over dig over bump. So if `ground=0`, `dig=1`, and a bump arrive together, the machine falls, ignores the dig, and ignores the bump for direction purposes. While falling, both bump and dig are ignored. While digging, bumps are ignored and digging persists until `ground=0`.

Worked example: walking right, `ground=1`, `dig=1`, `bump_left=1` on the same edge. Dig outranks bump, so the machine enters digging and keeps walking-right memory; the bump is discarded. Next edge `ground=0`: digging ends, machine falls, `aaah=1`, direction memory still right. Several falling edges with `bump_right=1` change nothing. Then `ground=1` with fall count ≤20: machine resumes `walk_right=1`. The checker should verify the direction never flipped and that exactly one of the four outputs was asserted throughout, with all zero only after a genuine >20-cycle landing splatter.
