The most useful implementation mistake to target is **conflating the walking-direction memory with the `walk_left`/`walk_right` outputs**. A natural but wrong Moore encoding lets the direction bit *be* the walking output, so that during falling or digging the direction is effectively cleared because both walking outputs must be low. The public spec is explicit that this is wrong: during a fall the Lemming must "resume walking in the same direction as before the fall," and during digging it must "continue walking in its original direction once it hits ground again." That means the direction is a hidden state variable that persists across fall and dig, independent of the visible walking outputs.

The consequence for the checker is that it must not try to read direction from the outputs while `aaah=1` or `digging=1`. Instead it must inject bumps during the fall/dig interval and then verify the *resumed* walking output. The spec names exactly three edges where bumps must be ignored: the edge where ground disappears (still walking, not yet falling), every mid-fall edge, and the edge where ground reappears while still falling. Asserting both `bump_left` and `bump_right` on all three, then checking the resumed direction equals the pre-fall direction, is the sharpest single probe for a leaky direction register. A machine that stores direction only in the walking outputs will flip or lose it here.

A compact worked example: begin walking right on ground. Drive one edge with `ground=1, dig=1, bump_left=1`. Expected sampled outputs: `digging=1`, all others low; direction memory still right; the bump is discarded because dig outranks bump. Next edge drive `ground=0` with dig still 1 and bumps arbitrary: expected `aaah=1`, `digging=0`, direction still right (fall outranks dig). Hold `ground=0` for about five edges with both bumps asserted — direction must not change and no splatter occurs mid-air. Then drive `ground=1` with both bumps asserted: expected `walk_right=1` alone, no splatter (five cycles ≤ 20). This single sequence exercises dig-over-bump, fall-over-dig, bump-ignored-in-fall, bump-ignored-on-landing, and the output invariant at once.

Two supporting checks belong in the same pass. First, the **output invariant**: exactly one of the four outputs is high on every non-splattered sampled edge, and all four are zero on every post-splatter edge until reset. Second, **splatter is terminal and landing-only**: it triggers solely when a fall longer than 20 cycles ends on `ground=1`; mid-air cycles never splatter no matter how many. Because reset is asynchronous and positive-edge-triggered, the checker should apply it between edges and confirm the very next sampled edge shows `walk_left=1` with the other three low, treating reset as immediately effective rather than waiting for a clock edge.
