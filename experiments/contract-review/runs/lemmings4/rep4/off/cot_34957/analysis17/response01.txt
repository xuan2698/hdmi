The most useful thing to pin down for the final checker is the **exact edge on which each state transition is sampled**, because the spec's prose ("when ground=0", "when the ground reappears", "starts digging when dig=1") is easy to misread as level-triggered rather than edge-triggered. The checker should treat every input row as the value *driven before* a rising `clk` edge, and evaluate the Moore outputs *after* that edge settles. That single convention resolves most ambiguity: a Lemming "falls" on the first sampled edge where `ground=0` is observed while it was previously walking/digging on ground; it "lands" on the first sampled edge where `ground=1` is observed while it was previously falling. The entry edge and the landing edge are therefore *not* counted as falling cycles — the fall counter increments only on edges strictly between them. This is the crux of the 20-vs-21 boundary: a fall that spans 20 intermediate sampled edges is survivable; 21 splatters on landing.

A second point worth flagging: **direction memory must be a separate register from the walking-direction output**, because during falling and digging the outputs `walk_left`/`walk_right` are both low, yet the machine must remember which way to resume. The checker should therefore never infer direction memory from the outputs during fall/dig; it must drive a bump pattern during the fall and then confirm the *resumed* walking output matches the pre-fall direction. The three "ignore bump" edges are: the ground-disappearance edge, every mid-fall edge, and the ground-reappearance edge. Asserting both `bump_left` and `bump_right` on all three and checking the resumed direction is unchanged is the sharpest single test for a leaky direction register.

Precedence on a walking edge is the third probe. With `ground=1`, `dig=1` beats bump; with `ground=0`, falling beats both. A compact worked example: start walking right on ground. Drive one edge with `ground=1, dig=1, bump_left=1`. Expected: `digging=1`, other outputs low, direction memory still right, bump discarded. Next edge drive `ground=0` (dig still 1, bumps arbitrary). Expected: `aaah=1`, `digging=0`, direction memory still right. Hold `ground=0` for, say, 5 edges with both bumps asserted — direction must not change, no splatter mid-air. Then drive `ground=1` with both bumps asserted: expected `walk_right=1`, exactly one output high, no splatter (5 ≤ 20). This one sequence exercises dig-over-bump, fall-over-dig, bump-ignored-in-fall, bump-ignored-on-landing, and the output invariant simultaneously.

Finally, the checker should assert the **output invariant** (exactly one of the four outputs high) on every non-splattered sampled edge, and all-zero on every post-splatter edge until `areset`. Splatter is terminal and only triggered by landing after >20 fall cycles; mid-air cycles never splatter regardless of count. Reset is asynchronous and positive-edge-triggered, so the checker should apply it between edges and confirm the very next sampled edge shows `walk_left=1` with the other three low — treating reset as immediately effective rather than waiting for a `clk` edge.
