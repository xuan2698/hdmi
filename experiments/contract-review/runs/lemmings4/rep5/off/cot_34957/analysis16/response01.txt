The interface is narrow and entirely one-bit: inputs `areset`, `bump_left`, `bump_right`, `ground`, and `dig`; outputs `walk_left`, `walk_right`, `aaah`, and `digging`. There are no multi-bit ports, so boundary-value analysis is about timing and state history rather than numeric ranges. The only internal quantity with a meaningful threshold is the fall-duration counter, whose boundary is 20 versus 21 cycles. That threshold is not a port, but it is the central boundary the checker must probe.

The outputs are Moore outputs, so they depend only on the current state and are stable throughout a sampled row. Exactly one of `walk_left` and `walk_right` should be high while the Lemming is walking; `aaah` should be high only while falling; `digging` should be high only while digging. During splatter all four outputs are zero. The checker should treat these as mutually constrained rather than independent bits: for example, `aaah=1` with `walk_left=1` is invalid, and `digging=1` with `aaah=1` is invalid.

The fall counter is the most important hidden state. It must count consecutive cycles with `ground=0` while falling, and it must be cleared on a safe landing. A common bug is to clear the counter only when `aaah` is deasserted, which can leave a stale count hidden while falling. The checker must therefore test a safe landing followed by a second fall: after a 20-cycle fall and landing, the counter should be zero, so a subsequent 20-cycle fall must still land safely, and a subsequent 21-cycle fall must splatter. This distinguishes a correctly cleared counter from one merely masked by the asserted `aaah` output. The same reasoning applies to the splatter latch: after reset, the machine must be able to walk, fall, dig, and splatter again normally, so the checker should verify that reset clears the latch and that a fresh 21-cycle fall after reset still splatters.

Reset timing is the other high-value check. Because `areset` is asynchronous and positive-edge triggered, the checker should assert it between clock edges and verify that the very next sampled row reflects the reset state: walk-left, counter zero, splatter cleared, `aaah` and `digging` low. It should not require a clock edge to propagate reset. If reset is released before the next sampling point, the machine should remain in the reset-defined walk-left state until normal inputs move it.

Precedence must also be verified. A cycle with `ground=0` and `dig=1` must produce falling behavior, not digging. A cycle with `ground=1`, `dig=1`, and a bump must produce digging, not a direction change. A simultaneous `bump_left=1` and `bump_right=1` must still flip direction, so a double bump is not a no-op.

Worked example: hold `ground=0` for 20 sampled cycles, then set `ground=1`. The correct result is a safe landing: `aaah` drops, the prior direction resumes, and the counter clears. Extending the same fall to 21 cycles before `ground=1` must instead splatter: all four outputs become 0 and stay 0 until reset. A reset asserted during either fall must behave as if no fall occurred, so the next sampled row is walk-left with a zero counter.

Finally, sample after the posedge has settled, and carry mid-cycle input changes to the start of the next row. That discipline matters most at the landing edge, where the counter comparison and splatter latch update together.
