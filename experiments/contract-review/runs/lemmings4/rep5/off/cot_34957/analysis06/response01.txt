One likely implementation mistake is treating the fall counter as an ordinary state variable that is only updated on falling cycles, rather than as a counter whose value must be interpreted at the exact landing edge. The public spec says splatter occurs only when a Lemming "falls for more than 20 clock cycles then hits the ground." That means the checker must distinguish three moments: the cycle ground disappears, each subsequent falling cycle, and the cycle ground reappears. A common bug is to increment the counter on the disappearance cycle itself, or to test the counter after clearing it on landing. Either error shifts the threshold by one cycle and can make a 20-cycle fall splatter or a 21-cycle fall survive.

A related mistake is to let the splatter decision be based on the current `ground` input alone. The Lemming splatters only on the transition from falling to grounded, not merely when `ground=1` while already walking. If the checker computes `splatter = (fall_count > 20) && ground`, it may splatter a Lemming that was never falling, or may splatter on the same cycle the ground reappears before the fall state has been recognized. The correct discipline is to detect the landing event: previous state was falling, current `ground=1`, and the accumulated fall duration exceeds 20. After splatter, all four outputs must be zero forever until reset, and the fall counter should not be allowed to influence later behavior.

Another subtle point is reset interaction with the fall counter. `areset` is asynchronous and positive-edge triggered, and it forces the machine to walk left with all other outputs zero and the fall counter cleared. A naive implementation that keeps a separate "doomed" latch set once the counter passes 20, without clearing it on reset, would fail: after reset the Lemming walks left, then later falls briefly and lands, and the stale doomed flag would wrongly zero the outputs. So reset must clear the fall counter and any derived splatter-pending condition together.

A short worked example: suppose the Lemming is walking right, then `ground=0` for 21 sampled cycles, then `ground=1`. On the landing row the checker should output splatter: all outputs zero. If instead the counter was incremented on the disappearance cycle, the count might be 22 and still splatter, but a 20-cycle fall would also splatter incorrectly. The final checker should count only full falling cycles after the disappearance row, test the landing transition, and clear all fall-related state on reset.
