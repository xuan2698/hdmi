**Reset and power-up analysis**

The Lemming FSM has one asynchronous control input, `areset`, and the public spec makes it positive-edge triggered. That means the checker must treat the rising edge of `areset` as an event that can occur between clock edges and must take effect immediately, without waiting for `clk`. A reset asserted while the machine is walking, falling, digging, or already splattered must force the machine into the walk-left state: `walk_left=1`, `walk_right=0`, `aaah=0`, `digging=0`. It must also clear the internal fall-duration counter and clear any splatter latch. Power-up is not separately specified beyond this reset behavior, so the checker should not assume an implicit initial state unless it first applies `areset`; the safe interpretation is that reset defines the known state.

The most important reset point for the final checker is that reset must clear hidden history, not merely mask the current outputs. A Lemming that has been falling for many cycles has an internal counter near or beyond the splatter threshold. If reset occurs during that fall, the next sampled row must show walk-left with a cleared counter. A subsequent fall of 20 cycles must land safely, and a subsequent fall of 21 cycles must splatter. This distinguishes a correctly cleared counter from one that is merely hidden because `aaah` is currently asserted. The same applies to the splatter latch: after reset, the machine must be able to walk, fall, dig, and splatter again normally.

A second reset subtlety is timing. Because `areset` is asynchronous and positive-edge triggered, the checker should assert it between clock edges and verify the very next sampled row reflects the reset state. It should not require a clock edge to propagate reset. Conversely, if reset is released before the next sampling point, the machine should remain in the reset-defined walk-left state until normal inputs move it.

**Precedence and landing checks**

The spec orders fall above dig above direction switching. A cycle with `ground=0` and `dig=1` must produce falling behavior, not digging. A cycle with `ground=1`, `dig=1`, and a bump must produce digging, not a direction change. A simultaneous `bump_left=1` and `bump_right=1` must still flip direction, so a double bump is not a no-op.

The landing edge is the other high-value check. Drive a long-but-safe fall, then a short fall, then a landing, and verify the Lemming is still walking. This catches a counter that is cleared incorrectly or only masked by `aaah`. Worked example: hold `ground=0` for 20 sampled cycles, then set `ground=1`. The correct result is a safe landing: `aaah` drops, the prior direction resumes, and the counter clears. Extending the same fall to 21 cycles before `ground=1` must instead splatter: all four outputs become 0 and stay 0 until reset. A reset asserted during either fall must behave as if no fall occurred, so the next sampled row is walk-left with a zero counter.

Finally, sample after the posedge has settled, and carry mid-cycle input changes to the start of the next row. That discipline matters most at the landing edge, where the counter comparison and splatter latch update together.
