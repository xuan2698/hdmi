The interface is narrow and entirely one-bit except for the internal fall counter, which is not a port but is the only multi-bit state element the checker must reason about. Inputs are `areset`, `bump_left`, `bump_right`, `ground`, and `dig`, each 1 bit. Outputs are `walk_left`, `walk_right`, `aaah`, and `digging`, each 1 bit. Because this is a Moore machine, all four outputs are functions of the current state alone and must be stable across the whole cycle between sampled edges; the checker should compare outputs after the posedge has settled, not at the instant of the edge.

Boundary values matter in three places. First, the fall counter: the splatter threshold is "more than 20 clock cycles," so a fall of exactly 20 cycles must land safely and a fall of 21 must splatter. The counter therefore needs to distinguish 0 through 21 (or saturate above 20), and the landing decision is `count > 20` evaluated at the cycle ground returns. Off-by-one here is the most likely functional bug. Second, the direction bit is a single bit with a defined reset value of left; there is no third "unknown" direction, so every non-splattered, non-falling, non-digging state must assert exactly one of `walk_left`/`walk_right`. Third, the splatter latch is a sticky one-bit state that must dominate all other outputs (all four zero) until reset.

Precedence is the other boundary the checker should probe: fall > dig > direction switch. A cycle with `ground=0` and `dig=1` must fall, not dig. A cycle with `ground=1`, `dig=1`, and a bump must dig, not turn. Simultaneous `bump_left` and `bump_right` still flip direction, so the checker should confirm a double bump is not treated as "no bump."

The reset point deserves emphasis. `areset` is positive-edge-triggered asynchronous, so it acts immediately on its rising edge rather than waiting for `clk`. Reset must restore walk-left, clear the falling, digging, and splattered flags, and zero the fall counter. A surviving counter or splatter latch is the classic bug: reset during a long fall, then a short fall, must land safely rather than splatter from pre-reset history.

Worked example: suppose the Lemming has been falling for 20 cycles with `ground=0`, then `ground` returns to 1. Since 20 is not greater than 20, it lands safely, clears the counter, and resumes its prior direction. If instead it had fallen 21 cycles, landing sets the splatter latch and all outputs go to 0 permanently. A reset asserted mid-fall must behave as if no fall occurred, so the next sampled row shows walk-left with a zero counter.
