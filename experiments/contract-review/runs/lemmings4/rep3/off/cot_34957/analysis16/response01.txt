The interface is a single clocked Moore machine with five one-bit inputs (`areset`, `bump_left`, `bump_right`, `ground`, `dig`) and four one-bit outputs (`walk_left`, `walk_right`, `aaah`, `digging`). All ports are scalar; there are no buses, so no width-truncation or signedness issues arise. The only boundary values are 0 and 1, and the checker should treat them as booleans rather than integers with arithmetic meaning. `areset` is asynchronous and positive-edge triggered: when it is asserted, the machine must immediately enter the walking-left state, clear the fall counter, and clear any splatter condition. Because reset is asynchronous, the checker should not require a clock edge before observing the reset state.

The state variables that matter for checking are the remembered walking direction, whether the machine is currently walking, falling, digging, or splattered, and the fall duration counter. The outputs are pure functions of the current state: `walk_left` and `walk_right` are asserted only in the walking state and only for the remembered direction; `aaah` is asserted only while falling; `digging` is asserted only while digging. In the splattered state all four outputs are zero permanently until reset.

Precedence is central. In the walking state with `ground=1`, a `dig=1` request starts digging rather than switching direction. If `ground=0`, the machine falls regardless of `dig` or bumps. Direction switching happens only in the walking state when neither falling nor digging takes precedence. A bump on the same row as `ground=0` must not change the remembered direction, and a bump on the landing row must not change it either. When both bumps are asserted in a walking row, the direction toggles.

The fall counter must not be cleared by bumps, dig requests, or direction changes. It increments only on cycles that are actually falling, and it must not increment on the landing cycle because that cycle has `ground=1`. Splatter occurs when a landing follows more than 20 falling cycles. The checker should therefore distinguish the state before the edge from the state after the edge: a row with `ground=1` after a long fall is a landing row, not another fall cycle. Falling for exactly 20 cycles and then landing is safe; falling for 21 cycles and then landing splatters.

A short worked example: suppose the machine is walking right, `ground=0`, and `bump_left=1`. The bump is ignored for direction because falling has precedence. The machine outputs `aaah=1`, both walking outputs zero, and increments the fall counter. On the next row, if `ground=1`, the machine lands, resumes walking right, and does not increment the counter on that landing row. If the counter had already exceeded 20, the landing row instead produces all-zero outputs and permanent splatter.
