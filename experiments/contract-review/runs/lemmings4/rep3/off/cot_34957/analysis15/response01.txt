The key implementation point for the checker is that the machine needs a remembered walking direction that is independent of the current output mode. Walking, falling, digging, and splattered are mutually exclusive output modes, but the direction bit persists across fall and dig episodes. Bumps update direction only when the Lemming is in the walking state and is not simultaneously losing ground or landing. Digging and falling suppress bump effects entirely. Splatter is a terminal state until asynchronous reset.

State transitions should be organized by precedence: splatter check on landing, then fall, then dig, then bump/direction switch, then continue walking. On any cycle where `ground=0` and the machine is not already splattered, the machine enters or remains in the falling state and increments a fall counter. The fall counter must count consecutive cycles with `ground=0`; it resets when ground returns or when reset is asserted. If `ground=1` arrives while the machine was falling, the machine checks whether the fall duration exceeded 20 cycles. A duration of exactly 20 is safe; 21 or more causes splatter. On a safe landing, the machine returns to walking in the remembered direction. On a fatal landing, all outputs become zero permanently.

The fall counter should not be cleared by bumps, dig requests, or direction changes. It should also not be incremented on the landing cycle itself, because that cycle has `ground=1`. The checker should distinguish "was falling before this edge" from "is falling after this edge" when evaluating splatter. A row with `ground=1` after a long fall is a landing row, not another fall cycle.

Digging begins only from the walking state with `ground=1` and `dig=1`. While digging, the machine outputs `digging=1` and both walking outputs zero. If `ground=0` occurs during digging, the machine transitions to falling, outputs `aaah=1`, and clears `digging`. The remembered direction is unchanged. Bumps during digging are ignored. When ground returns within the safe window, the machine resumes walking in the remembered direction.

Direction switching occurs only in the walking state. If `bump_left=1`, the remembered direction becomes right. If `bump_right=1`, it becomes left. If both are asserted, the direction still switches, which means the remembered direction toggles. The outputs `walk_left` and `walk_right` reflect the remembered direction only while walking. During falling or digging, both walking outputs are zero even though the remembered direction is retained internally.

The checker should verify outputs after the posedge has settled, using the inputs driven before that edge. Mid-cycle input changes are carried to the next sampled row and should not affect the current outputs. Reset is asynchronous and positive-edge triggered; asserting it should immediately force the walking-left state and clear the fall counter and splatter flag.

A useful final check is to confirm that the machine does not confuse "falling for 20 cycles" with "falling for 20 cycles and then landing." The counter threshold applies at the landing transition. Also verify that a bump on the same row as `ground=0` does not alter direction, and that a bump on the landing row does not alter direction. These two cases catch most incorrect implementations of direction memory and precedence.
