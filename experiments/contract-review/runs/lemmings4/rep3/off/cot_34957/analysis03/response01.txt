The machine’s state must remember more than the four visible outputs. In particular, it needs a mode distinguishing walking, falling, digging, and splattered, plus a remembered walking direction and a fall-duration counter. The visible outputs are decoded from the post-edge state: walking left asserts only `walk_left`, walking right asserts only `walk_right`, falling asserts only `aaah`, digging asserts only `digging`, and splattered asserts none of them. Because this is a Moore machine, the checker should compute outputs from the state after applying the sampled edge, not from the inputs of that row.

Reset has absolute priority. When `areset` is asserted at the sampled edge, the next state is walking left, with fall counter zero, remembered direction left, not digging, not falling, and not splattered. This matters because the spec says a falling Lemming resumes “the same direction as before the fall.” If reset left the remembered direction undefined, the first landing after a reset-induced fall would be ambiguous. Reset must also clear any accumulated fall duration and any splattered condition. A splattered Lemming has all four outputs zero forever “until the FSM gets reset,” so reset is the only escape from splatter.

For non-reset transitions, precedence is fall, then dig, then bump/direction switching. If the machine is walking on ground and `ground=0`, it begins falling immediately; any simultaneous `dig` or bump is ignored for direction memory. While falling, bumps and `dig` are ignored. The fall counter increments each cycle spent falling. If ground reappears, the machine lands: if the accumulated fall duration exceeds 20 cycles, it becomes splattered; otherwise it resumes walking in the remembered direction. A bump in the same cycle that ground disappears, or in the same cycle ground reappears while still falling, does not affect remembered direction.

A walking Lemming on ground may dig when `dig=1`. Digging continues until `ground=0`, at which point the machine falls, then later resumes walking in its original remembered direction. Being bumped while digging has no effect. If `dig=1` occurs while falling or with no ground, it is ignored. If both falling and digging conditions appear possible, falling wins; if digging and bumping appear together on ground, digging wins over direction switching.

A short worked example: suppose the machine is splattered with all outputs zero, and at the next sampled edge `areset=1`. The post-edge state is walking left, so the row’s outputs are `walk_left=1`, `walk_right=0`, `aaah=0`, `digging=0`. Any simultaneous `ground`, `dig`, or bump values are irrelevant because reset has highest priority. If `areset` is instead 0 at that edge, the splattered state persists and all outputs remain zero.

For the final Python checker, the useful rule is: decode outputs from the post-edge state; apply `areset` first with top priority; otherwise apply the normal transition using only pre-edge inputs; ignore mid-inputs entirely for state changes; and enforce fall over dig over bump precedence.
