The key timing point for the final checker is that `areset` must be treated as an unconditional override at the sampled edge, not as another branch inside the normal priority chain. The public spec says the machine is reset to walk left, and splatter is permanent only “until the FSM gets reset.” That means reset must clear not just the visible direction but also auxiliary history: the fall-duration counter and any splatter/sticky terminal flag. If the checker computes the ordinary next state first and then patches only `walk_left`/`walk_right`, stale auxiliary memory can survive and corrupt later rows.

This matters because the Lemming’s behavior depends on history that is not directly visible in the outputs. A fall counter that is not cleared can make a short post-reset fall look too long, causing a false splatter. A splatter flag that is not cleared can keep all outputs at zero after reset even though the machine should be walking left again. Conversely, if reset clears only the counter but not splatter, or only splatter but not the counter, ordinary rows may still pass while reset-boundary rows fail.

The ordinary transition should be evaluated only when `areset` is not asserted. In that case, the precedence is: if `ground=0`, enter or continue falling and increment the fall duration; if the Lemming hits ground after more than 20 fall cycles, splatter permanently. Otherwise, if already digging, continue digging until `ground=0`; if walking on ground and `dig=1`, start digging. Otherwise, apply bump logic: `bump_left` forces walk right, `bump_right` forces walk left, and both together still switch direction. Bumps while falling or digging are ignored, and bumps in the same cycle as ground loss or ground return do not change the remembered walking direction.

Mid-cycle input changes occur after sampling and before the next edge; they are carried to the start of the next row and must not retroactively change the current Moore outputs. The checker should therefore sample inputs at the specified edge, resolve reset first, then resolve the ordinary next state, then decode outputs from that resolved state. A short worked example: if the machine has been falling for 21 cycles and is still airborne, then `areset` is asserted before the next sampled edge, the correct next row is walk-left with cleared fall count and no splatter memory. Any later ground contact must be judged using only post-reset fall history.
