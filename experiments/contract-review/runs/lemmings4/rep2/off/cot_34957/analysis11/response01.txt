The key distinguishing point for the checker is that **reset must be evaluated as a true asynchronous override, not as a transition that competes with ordinary next-state logic**. A common bug is to compute the ordinary next state first (including fall-count increments, splatter detection, direction memory, and dig/fall/bump precedence), then apply reset only if it happens to be asserted. That ordering can produce the right outputs in many rows but fails when reset coincides with a boundary event such as ground contact after a long fall, or with a bump/dig/fall combination.

Consider a Lemming that has been falling for 21 cycles and is still in the air. Suppose `areset` is asserted before the next sampled edge. The correct behavior is that the machine goes directly to the walk-left state, with the fall counter cleared and the splatter memory cleared. The checker must not first decide “ground contact after >20 cycles means splatter,” then apply reset afterward. Reset dominates: the post-reset state is walk-left, and the outputs are `walk_left=1`, all others 0. If the checker instead lets the ordinary transition set a splatter flag and then clears only the direction, a later row can incorrectly remain splattered or retain a stale fall count.

This matters because the public spec makes splatter permanent “until the FSM gets reset,” and also says reset returns the machine to walk left. Those two clauses together imply that reset must clear the splatter memory itself, not merely restart walking. Similarly, the fall counter must be cleared on reset; otherwise a pre-reset long fall could contaminate a post-reset fall and cause a false splatter after only a few cycles.

A useful implementation shape for the final checker is therefore three layers. First, if `areset` is asserted at the sampled edge, force the state to walk-left and clear auxiliary memories. Second, otherwise compute the ordinary next state using the required precedence: falling if `ground=0`; otherwise digging if already digging or if walking on ground with `dig=1`; otherwise bump-based direction switching. Third, decode Moore outputs from the resolved state. Mid-cycle input changes should be carried to the next sampled edge but must not alter the current output row. This separation directly guards against the most likely checker errors: preserving fall count across reset, letting splatter survive reset, and losing the remembered walking direction during fall or dig.
