One likely implementation mistake is to treat the Lemming’s auxiliary history as ordinary state that is updated by the same priority chain as walking, falling, and digging, rather than as memory that reset must unconditionally clear. The public spec says splatter is permanent “until the FSM gets reset,” and that `areset` resets the machine to walk left. A checker that models splatter as a sticky flag but only resets the visible walking direction can pass many ordinary rows and still fail on reset-boundary cases.

The same issue applies to the fall counter. If the counter is not cleared by reset, a pre-reset fall can contaminate a post-reset fall. For example, suppose the machine has been falling for 21 cycles, still airborne, and then `areset` is asserted before the next sampled edge. The correct post-reset behavior is walk-left with a cleared fall count and no splatter memory. If the checker first processes the ordinary transition and then applies reset only to direction, it may retain a splatter flag or a large fall count. A later ground contact could then incorrectly splatter, or a short post-reset fall could be misclassified as too long.

A robust checker should separate reset handling from the ordinary transition. At each sampled edge, if `areset` is asserted, force the state to walk-left and clear auxiliary memories such as fall duration and splatter. Otherwise, compute the next state using the specified precedence: falling when `ground=0`; otherwise digging when already digging or when walking on ground with `dig=1`; otherwise bump-based direction switching. Moore outputs should then be decoded from the resolved state. Mid-cycle input changes should be carried to the next sampled edge and must not alter the current output row. This structure directly guards against stale fall counts, splatter surviving reset, and loss of remembered walking direction during fall or dig.
