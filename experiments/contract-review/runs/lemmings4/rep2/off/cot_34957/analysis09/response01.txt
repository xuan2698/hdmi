The key modeling point is that the Moore outputs are a pure function of the current state, while the next state depends on the current state plus the sampled inputs. The checker should therefore avoid computing outputs directly from raw inputs in the same row; instead it should first resolve the state, then decode `walk_left`, `walk_right`, `aaah`, and `digging` from that state.

The state space needs to distinguish at least: walking-left, walking-right, falling-left, falling-right, digging-left, digging-right, and splattered. The left/right distinction during falling and digging is essential because the Lemming must resume walking in the same direction it had before the fall or dig began. A single “falling” state without direction memory would fail the resume-direction requirement. Similarly, digging must remember the original walking direction so that after the dig causes ground loss and a subsequent fall, the Lemming resumes correctly.

Reset is asynchronous and positive-edge triggered. The checker should treat `areset` as an override that immediately forces the walk-left state and clears both the fall counter and the splatter flag. This matters because the splatter condition is described as permanent “until reset”; reset must therefore clear the splatter memory, not merely restart the walking direction. The fall counter must also be cleared so that a pre-reset long fall cannot contaminate post-reset behavior.

For ordinary clocked transitions, precedence is: fall first, then dig, then bump-based direction switching. If `ground=0` while walking or digging, the Lemming enters the appropriate falling state and asserts `aaah`. While falling, `bump_left`, `bump_right`, and `dig` are ignored. When `ground=1` returns, the Lemming returns to walking in its remembered direction, unless the accumulated fall duration exceeds 20 cycles, in which case it splatters. The splatter check occurs on ground contact, not mid-air. A walking Lemming on ground with `dig=1` starts digging; otherwise a bump on either side switches direction, including simultaneous bumps.

A short worked example: if the Lemming is falling with fall count 21 and `areset` asserts before the next sampled edge, the correct next sampled row is walk-left with all fall/splatter memory cleared. The checker should not first process a ground-contact splatter transition and then reset; reset dominates and directly establishes the walk-left state.

The final Python checker should separate three concerns: asynchronous reset override, ordinary next-state computation with fall/dig/bump precedence, and Moore output decoding from the resolved state. Mid-cycle input changes should be carried to the next sampled edge but must not retroactively alter the current output row. This separation is the most useful guard against incorrect fall-count preservation, splatter persistence across reset, and direction loss during fall or dig.
