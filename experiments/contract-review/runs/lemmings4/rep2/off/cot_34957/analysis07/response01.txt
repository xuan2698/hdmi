The timing protocol separates two kinds of input events. The first is the sampled edge: inputs are driven before the active clock edge, and the checker samples the machine after that edge has settled. Those sampled values determine the next Moore output row. The second is the optional mid-cycle input change: it occurs after sampling and before the opposite edge, and is carried forward to the start of the next row. For the final Python checker, this means the checker should not treat every input change as if it were a clocked transition. Only the values present at the sampled edge advance the ordinary walking/falling/digging/splatter state. Mid-cycle changes matter because they establish what will be sampled at the next edge, but they should not retroactively alter the row already produced.

Reset is the exception. `areset` is positive-edge triggered and asynchronous, so it is not merely another input sampled on `clk`. When `areset` asserts, the Lemming machine must immediately return to walk-left, clear any fall counter, and clear any splatter memory. The Moore outputs after reset are therefore `walk_left=1`, `walk_right=0`, `aaah=0`, `digging=0`. The checker should verify that the row following an asserted reset shows this pattern, regardless of what the Lemming was doing before. This is especially important near the splatter threshold: if the machine had been falling for many cycles and reset arrives, the fall count and splatter condition must be erased. A checker that applied reset only at the next clock edge, or that preserved the fall count, could incorrectly emit `aaah` or splatter later.

For non-reset operation, the checker should keep the state categories distinct: walking, falling, digging, and splattered. Falling has higher precedence than digging, and digging has higher precedence than direction switching. A walking Lemming on ground can begin digging when `dig=1`; otherwise bumps may switch direction. If ground disappears, the Lemming falls and asserts `aaah`. While falling, bumps and dig requests are ignored. When ground reappears, the Lemming resumes walking in the same direction as before the fall. Digging continues until ground disappears, at which point the Lemming falls and later resumes walking in its original direction. If the fall lasts more than 20 clock cycles and then hits ground, the Lemming splatters and all outputs become zero forever until reset.

A short worked example: suppose the Lemming is falling with a large fall count and `areset` asserts asynchronously. The correct next sampled row is the walk-left pattern, with fall count and splatter memory cleared. The checker should not require an ordinary clocked transition first, and it should not carry the old fall count forward.

The useful point for the final Python checker is to separate reset handling from the ordinary precedence rules. Reset should directly set the state to walk-left and clear fall/splatter memory, then Moore outputs should be derived from that state. Ordinary sampled-edge transitions should apply the fall/dig/direction precedence only when reset is not active. Mid-cycle input changes should be carried to the next sampled edge but should not rewrite the current output row. This structure prevents the checker from incorrectly preserving a pre-reset fall count or splatter flag across reset.
