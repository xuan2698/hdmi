**Reset and power-up behavior**

The machine has one asynchronous, positive-edge-triggered reset input, `areset`. Because it is asynchronous, asserting `areset` takes effect immediately rather than waiting for a clock edge; the specification also says the reset is positive-edge triggered, so the checker should treat the assertion event (the 0→1 transition of `areset`) as the moment the machine is forced into its initial state. The initial state is “walking left”: `walk_left=1`, `walk_right=0`, `aaah=0`, `digging=0`. Power-up without an explicit reset is not separately specified, so the checker should not invent a power-up state; it should rely on `areset` to establish the initial condition, and it should not assume any particular history (fall counter, splatter flag, remembered direction) before the first reset.

The important subtlety is that reset must clear *all* internal history, not just the visible outputs. The Lemming’s future behavior depends on at least three pieces of hidden memory: the remembered walking direction, the fall-duration counter, and a sticky splatter/terminal flag. If reset only forces the four Moore outputs to the walk-left pattern while leaving the fall counter or splatter flag intact, later rows can be wrong even though the reset row itself looks correct. For example, a stale fall counter could make a short fall after reset appear to exceed 20 cycles and trigger a false splatter; a stale splatter flag could keep all outputs at zero forever after reset, when the machine should instead be walking left. The checker should therefore model reset as reinitializing the entire state: direction = left, fall count = 0, splatter = false, digging = false, and outputs decoded from that fresh state.

Reset has priority over every ordinary transition. If `areset` is asserted at a sampled edge, the checker must not also apply bump, ground, or dig logic for that row; the reset result is the next state. Ordinary transitions—falling when `ground=0`, splattering after more than 20 fall cycles on ground contact, digging when `dig=1` on ground while walking, and bump-induced direction changes—are evaluated only when reset is not asserted. Mid-cycle input changes occur after sampling and before the next edge, so they are carried into the next row and must not retroactively alter the current Moore outputs.

A short worked example: suppose the machine has been falling for 21 cycles and is still airborne, and then `areset` is asserted before the next sampled edge. The correct next row is walk-left with the fall counter cleared and no splatter memory. Any later ground contact must be judged using only post-reset fall history, not the pre-reset 21 cycles.
