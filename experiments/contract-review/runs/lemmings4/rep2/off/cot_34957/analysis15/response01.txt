The key modeling point for the checker is that this is a Moore machine whose outputs are a pure function of a hidden state, and that state must include more than the four visible bits. The visible outputs are `walk_left`, `walk_right`, `aaah`, and `digging`; the hidden state must at minimum encode the remembered walking direction, whether the Lemming is currently falling, the fall-cycle count, whether it is currently digging, and a sticky splattered/terminal flag. Reset is asynchronous and positive-edge triggered, and it must reinitialize all of that hidden state to the walk-left condition: direction left, not falling, fall count zero, not digging, not splattered. The checker should decode outputs from that fresh state rather than merely forcing the four output bits.

Reset has absolute priority at a sampled edge. If `areset` is asserted, no ordinary transition logic for that row should be applied: bumps, ground loss, dig requests, fall counting, and splatter checks are all suppressed. The next state is the reset state. This matters because a stale fall counter or stale splatter flag can corrupt later rows even when the reset row’s outputs look correct.

When reset is not asserted, evaluate ordinary behavior with the stated precedence: falling has higher priority than digging, and digging has higher priority than bump-induced direction switching. If `ground=0`, the Lemming enters or remains in the falling state, emits `aaah`, and increments the fall-duration counter. While falling, bumps and dig requests are ignored for direction and mode purposes. When ground reappears, the machine checks the accumulated fall duration: if it exceeds 20 cycles, the Lemming splatters and all outputs become zero forever; otherwise it resumes walking in the remembered direction, with the fall counter cleared. A bump in the same cycle that ground disappears, or in the same cycle ground reappears while still falling, does not change the remembered direction.

If the Lemming is walking on ground and `dig=1`, it begins digging and continues digging until `ground=0`; at that point it falls, then resumes walking in its original direction after landing, unless the fall was too long. While digging, bumps are ignored. If no fall or dig condition applies, a bump on either side—or both sides—causes a direction switch; with both bumps asserted, it still switches.

A useful worked example: if the machine has been falling for 21 cycles and is still airborne, then `areset` is sampled as 1, the next state must be walk-left with fall count zero and no splatter memory. Any later ground contact is judged only from post-reset fall history. The checker should therefore compare full hidden-state evolution, not just output bits, and should treat mid-cycle input changes as belonging to the next sampled row.
