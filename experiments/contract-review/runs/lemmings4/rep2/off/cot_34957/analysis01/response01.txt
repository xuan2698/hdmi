The key timing point for the checker is that this is a Moore machine sampled on the rising edge, so every output row must be a pure function of the state *after* the edge has settled, not of the inputs that were present just before that edge. Inputs are driven before the sampled edge; any optional mid-cycle changes occur after sampling and before the next edge, and are carried into the next row. That means the checker should treat each row as: (1) apply the edge using the inputs valid at that edge, (2) settle the next state, (3) emit outputs from that settled state, and only then (4) allow mid-input changes to influence the following row. A common bug is to let a mid-input change retroactively alter the outputs of the row in which it appears; the spec forbids that because outputs are Moore outputs of the post-edge state.

The asynchronous reset is positive-edge triggered and resets to walk-left. For the checker, areset must be handled as an edge event that forces the state to walk-left regardless of the other inputs at that edge, and the outputs for that row should reflect walk_left=1 with the other three outputs 0. Because reset is asynchronous, the prose should be read as: when areset is asserted, the machine is forced to the walk-left state; the sampled row then reports that state. The checker should not require areset to be synchronized to clk, but it should require that the row following a reset edge shows the walk-left outputs.

Precedence is the second critical point. The spec orders fall above dig above direction-switch. So at a given edge, if ground=0 the Lemming enters/continues falling and says aaah; bump inputs are ignored for direction while falling, and dig is ignored. If ground=1 and not falling, dig=1 starts digging (digging=1) and bump inputs do not switch direction during digging. Only when walking on ground and not digging do bump_left/bump_right (including both simultaneously) cause a direction switch. The checker should encode this as a priority decision at the edge, then derive outputs from the resulting state. A subtlety: being bumped in the same cycle that ground disappears, or when ground reappears while still falling, does not affect walking direction. That means the direction memory must be preserved across fall and dig, and bump inputs during those transitions must not overwrite it.

Splatter is a terminal state for the checker. Falling for more than 20 clock cycles and then hitting ground (ground=1) causes all four outputs to become 0 forever until reset. The checker must count fall duration in cycles and only splatter on the ground-hit edge, not mid-air. Once splattered, subsequent rows must remain all-zero regardless of inputs until areset. A useful worked example: suppose the machine is walking left on ground, then ground goes 0 at an edge; the row shows aaah=1, walk_left=0, walk_right=0, digging=0, and the direction memory stays left. If a bump_right=1 arrives mid-cycle after that sample, it is carried to the next edge but must not change the already-emitted aaah row; at the next edge, because still falling, the bump is ignored for direction. When ground returns, the machine resumes walking left, and only then can a bump switch direction. This illustrates why the checker must separate edge-sampled outputs from mid-input carryover and must preserve direction memory across fall/dig.
