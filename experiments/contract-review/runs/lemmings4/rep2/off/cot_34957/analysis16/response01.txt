The port widths are all one bit, so every input and output is a Boolean sampled per clock. `areset`, `bump_left`, `bump_right`, `ground`, and `dig` are inputs; `walk_left`, `walk_right`, `aaah`, and `digging` are Moore outputs determined by the current state. Because the outputs are Moore outputs, they must be stable for the whole cycle associated with a state, and the checker should compare them after the sampled edge has settled. The boundary values that matter are not numeric port ranges but state-history boundaries: the fall counter threshold of 20 versus 21, the transition from walking to digging only when grounded, and the transition from falling to splatter only on ground contact after an overlong fall. A fall of exactly 20 cycles is still survivable; “more than 20” is the splatter condition. The counter must therefore represent at least 0 through 21, and the checker should not collapse “20” and “21” into the same behavior.

The most useful point for the final Python checker is that reset must restore the full hidden state, not merely force the four output bits. If `areset` is sampled high, the next state is the fresh walk-left state: remembered direction is left, fall counter is zero, digging mode is off, and splatter memory is absent. Ordinary transition logic for that row is suppressed, including bumps, ground loss, dig requests, fall counting, and splatter checks. This matters because a stale fall counter or stale splatter flag can corrupt later rows even when the reset row’s visible outputs look correct. The checker should therefore model and compare the complete state evolution, not just the output tuple.

Outside reset, precedence is fall over dig over bump. If `ground=0`, the Lemming falls, emits `aaah`, and increments the fall-duration counter; bumps and dig requests are ignored for direction and mode. When ground reappears, the machine checks the accumulated fall duration: if it exceeds 20 cycles, the Lemming splatters and all outputs become zero forever; otherwise it resumes walking in the remembered direction and clears the fall counter. A bump in the same cycle that ground disappears, or in the same cycle ground reappears while still falling, does not change the remembered direction. If the Lemming is walking on ground and `dig=1`, it begins digging and continues until `ground=0`; then it falls and later resumes walking in its original direction, unless the fall was too long. While digging, bumps are ignored. If no fall or dig condition applies, a bump on either side—or both sides—causes a direction switch; with both bumps asserted, it still switches.

A short worked example: suppose the machine has been falling for 21 cycles and is still airborne, and then `areset` is sampled as 1. The next state must be walk-left with fall count zero and no splatter memory. Any later ground contact is judged only from post-reset fall history. The checker should also treat optional mid-cycle input changes as belonging to the next sampled row, so they affect the following state transition rather than the already-sampled row.
