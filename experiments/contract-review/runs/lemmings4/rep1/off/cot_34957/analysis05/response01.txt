The key distinguishing point for the checker is that the fall-duration counter must be part of the state and must be reset asynchronously, because splatter depends on how many cycles were spent falling, not merely on the fact that a fall occurred. A model that only remembers “falling vs not falling” will agree with the reference on short falls but diverge once a fall exceeds 20 cycles and then lands. The counter must increment only while the machine is actually falling, and the splatter decision must be made at the landing edge using the accumulated count. If the counter is cleared too early—for example on the same edge that ground returns—the checker can miss splatter; if it is not cleared on reset, a later fall can inherit stale duration.

A second useful point is that the remembered walking direction must survive both falling and digging, and must be independent of the current output direction. During a fall, `walk_left` and `walk_right` are both 0 and `aaah` is 1, but the machine still needs to know which direction to resume. During digging, `digging` is 1 and walking outputs are 0, but the original direction is still stored. Bumps during fall or dig are ignored, so the checker should not update the remembered direction from `bump_left` or `bump_right` unless the machine is in a walking state and not falling or digging. The same-cycle cases are especially easy to get wrong: if `ground=0` and `dig=1` arrive together while walking on ground, fall has precedence, so digging must not start; if a bump arrives in the same cycle that ground disappears, the bump must not change direction; if a bump arrives in the same cycle that ground reappears while still falling, the bump must not change direction either.

A short worked example: suppose the machine is walking right, then `ground=0` for 21 consecutive sampled cycles, then `ground=1` with no bump. The machine falls for 21 cycles, so on landing the fall duration exceeds 20 and it splatters: all four outputs become 0 and remain 0 until reset. If the checker had reset the counter when ground returned, it would incorrectly resume walking right. If `areset` pulses during the fall, the machine immediately becomes walking left with fall count zero, and the later landing is irrelevant because the machine is no longer falling.

Finally, outputs are Moore outputs derived from state only, so the checker should sample outputs after the positive edge has settled and should not let mid-cycle input changes after sampling alter the outputs already observed for that edge. Asynchronous reset must be applied before the normal transition, and power-up should be treated as the same initialized state as reset: walking left, fall count zero, not digging, not splattered.
