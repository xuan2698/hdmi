The key distinguishing point for the checker is the landing boundary: a fall of exactly 20 cycles must resume walking, while 21 cycles must splatter. This is easy to get off by one, because the counter is incremented on each sampled cycle with `ground=0`, and the decision is made on the first sampled cycle where `ground=1`.

A short worked example: suppose the machine is walking left on ground. Then `ground=0` is sampled for 20 consecutive cycles, followed by `ground=1`. During those 20 cycles the outputs are `aaah=1` and the stored direction remains left. On the landing sample, the accumulated fall duration is 20, which does not exceed 20, so the machine resumes `walk_left=1` and clears the counter. If instead `ground=0` is sampled for 21 consecutive cycles before `ground=1`, the landing sample has duration 21, so the machine enters the splattered state: all four outputs become 0 and remain 0 until `areset`.

For the final Python checker, this means the reference model should track fall duration as a separate state variable or as part of the falling state, and it should compare the duration on the landing transition using a strict greater-than-20 test. The checker should also verify that the counter is cleared when walking resumes, so a later fall starts from zero rather than inheriting the previous duration. Another useful check is that bumps during the fall do not alter the stored direction, and that a bump on the same sampled cycle as the landing does not change the resumed direction. Similarly, a `dig=1` on the landing cycle is ignored because the machine is still in the falling state at that sample; only after resuming walking can digging begin.

The checker can also use the Moore-output invariant: in every non-splattered sample exactly one of `walk_left`, `walk_right`, `aaah`, `digging` is 1, and in the splattered state all four are 0. This catches many state-encoding mistakes, especially around the transition from digging to falling and from falling to walking. Finally, reset is asynchronous and positive-edge triggered, so the checker should confirm that `areset` immediately forces the walk-left state regardless of the current state or inputs, and that splatter is absorbing until reset.
