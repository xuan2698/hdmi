The key discipline for the checker is to separate three moments: pre-edge drive, sampled edge, and post-edge observation. Before the rising edge, the row’s `in` and `reset` are driven. At the rising edge, the FSM samples those values and enters the next state. After the edge has settled, `out` is sampled as the Moore output of the entered state. This ordering matters because the output is not a combinational function of the current input; it is a function of the state reached at the sampled edge.

For a non-reset row, the entered state is determined by the pre-edge state and the sampled `in`. For a reset row, the entered state is A and `out` must be 0 regardless of `in`. The checker should therefore evaluate reset as a synchronous override at the sampled edge, not as an asynchronous clear and not as a condition that changes the output before the edge.

A second trap is assuming an initial state. The public specification says reset resets the FSM to A, but it does not guarantee that the machine is in A before any reset is applied. The checker should either begin by asserting `reset=1` at a sampled rising edge and only then check the table, or treat all pre-reset behavior as unconstrained. Assuming A at time zero without reset is an invented condition and can cause spurious failures even when the RTL is correct.

Mid-cycle input changes must also be handled carefully. If `in` changes after the rising edge is sampled but before the opposite edge, that change must not affect the transition just taken or the output sampled after that rising edge. It is carried forward to the next sampled rising edge unless the next row drives a different value before its sampled edge. The checker must distinguish the value present at the sampled edge from any later mid-cycle change. In particular, it should not recompute the previous transition using the new mid-cycle value, and it should not expect the output to change immediately when `in` changes between edges.

Worked example: suppose the machine is known to be in B, output 0, and a row drives `in=1`, `reset=0`. At the rising edge, B with `in=1` remains B, so the post-edge state is B and the sampled output is 0. If `in` then changes to 0 after sampling, that change does not retroactively alter the edge. At the next rising edge, if `in=0` is still present, B transitions to C, and the post-edge output is 0 because C outputs 0. The checker should not expect the mid-cycle change to cause an immediate output change, and it should not derive `out` combinationally from `in`. The correct post-edge output is the Moore output of the next state selected at the sampled edge, with synchronous reset overriding the transition to force state A.

For the final Python checker, the most useful point is to latch the sampled input and reset at the rising edge, compute the entered state from the previously known state, then compare `out` only after the edge has settled. Any mid-cycle change should be stored for the next row, not used to reinterpret the current one.
