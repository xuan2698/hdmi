The most useful implementation mistake to flag for the final checker is treating the Moore output as if it were combinational with respect to the input, or sampling it before the state transition has settled. The public table defines `out` as a function of state only: A, B, and C output 0; D outputs 1. The input `in` selects the next state, but it does not directly select the output. A checker that computes `out` from the current row’s `in` and the pre-edge state, or that samples `out` immediately at the edge without allowing the newly entered state to settle, can report false mismatches even when the RTL is correct.

The correct sampling discipline is: drive the row’s `in` and `reset` before the rising edge; at the sampled rising edge, the machine enters the next state (or A under reset); after the edge has settled, sample `out` as the Moore output of that entered state. For a non-reset row, the entered state is determined by the pre-edge state and the sampled `in`. For a reset row, the entered state is A and `out` must be 0 regardless of `in`.

A related trap is assuming an initial state. The specification says reset resets the FSM to A, but it does not guarantee that the machine is in A before any reset is applied. The checker should either begin by asserting `reset=1` at a sampled rising edge and only then check the table, or treat all pre-reset behavior as unconstrained. Assuming A at time zero without reset is an invented condition and can cause spurious failures.

Mid-cycle input changes must also be handled carefully. If `in` changes after the rising edge is sampled but before the opposite edge, that change must not affect the transition just taken or the output sampled after that rising edge. It is carried forward to the next sampled rising edge unless the next row drives a different value before its sampled edge. The checker must distinguish the value present at the sampled edge from any later mid-cycle change.

Worked example: suppose the machine is known to be in B, output 0, and a row drives `in=1`, `reset=0`. At the rising edge, B with `in=1` remains B, so the post-edge state is B and the sampled output is 0. If `in` then changes to 0 after sampling, that change does not retroactively alter the edge. At the next rising edge, if `in=0` is still present, B transitions to C, and the post-edge output is 0 because C outputs 0. The checker should not expect the mid-cycle change to cause an immediate output change, and it should not derive `out` combinationally from `in`. The correct post-edge output is the Moore output of the next state selected at the sampled edge, with synchronous reset overriding the transition to force state A.
