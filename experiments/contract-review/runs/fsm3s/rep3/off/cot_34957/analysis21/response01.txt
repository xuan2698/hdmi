The state machine has four states with a single input and a Moore output that depends only on the registered state. State A is the reset state. From A, input 0 keeps the machine in A and input 1 advances to B. From B, input 0 advances to C and input 1 holds in B. From C, input 0 returns to A and input 1 advances to D. From D, input 0 returns to C and input 1 holds in B. The output is 0 in A, B, and C, and 1 only in D. So D is the sole output-asserting state, and it is reachable only via C with input 1.

The key structural point is that the next-state function is a pure function of the current registered state and the input captured at the sampled edge. The output is a pure function of the registered state alone. There is no combinational path from input to output, and no Mealy behavior. Reset is synchronous and active high, and it takes priority over the input: when reset is sampled high at an edge, the next state is A regardless of the captured input, and the output after settling is 0.

Because the output is Moore, it must be compared only after the edge has settled. Comparing the output at the edge itself, or comparing it against a value derived from the next-state logic, is a sampling error. Similarly, the input used to compute the next state must be the value captured at the sampled edge, not the value present later in the cycle. Mid-cycle input changes occur after sampling and belong to the next edge's captured input. A checker that latches the pre-edge input, or that attributes a mid-cycle change to the transition just sampled, will produce false mismatches even when the DUT is correct.

Power-up is unspecified. The spec gives no initial state and no behavior for unused state encodings, so the checker must not assume a pre-reset state or compare outputs before the first reset edge. The clean approach is to begin with an explicit reset sample, then compare only after that edge has settled. Unused encodings should be left unconstrained, and no particular state encoding should be imposed.

A short worked example: suppose the machine is in B after a sampled edge, with input 0 captured at that edge, so the next state is C. After sampling, the testbench flips input to 1 and holds it through the next rising edge. At that next edge the captured input is 1, so C advances to D and the output becomes 1 after settling. A checker that latched the earlier 0, or that treated the mid-cycle 1 as belonging to the previous transition, would instead expect C to return to A with output 0, and would flag a false mismatch. Conversely, sampling the input too early, before the driver has settled for the upcoming edge, can miss a legitimate 1 and expect the wrong next state. Both are sampling-discipline errors, not DUT errors.

For the final checker, the useful discipline is: sample input and reset at the edge, apply synchronous reset with priority over input, compute the next state from the edge-sampled input, and compare the output only after the edge has settled. Do not impose a state encoding, do not define behavior for unused codes, and do not constrain pre-reset outputs. A compact probe such as reset followed by inputs 1, 0, 1 reaches the sole output-1 state and catches both mid-cycle input leakage and incorrect reset handling.
