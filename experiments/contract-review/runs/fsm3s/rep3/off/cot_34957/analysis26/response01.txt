The key point for the final checker is edge-sampled input semantics combined with synchronous reset priority. The checker must capture `in` at the rising edge for the transition being evaluated; a mid-cycle change belongs to the next row, not the current one. Sampling too early reads the prior row's value, sampling too late reads the next row's value—both yield false mismatches. Reset must be evaluated at the same sampled edge, given priority over `in`, and force next state A. Output comparison occurs after settling, using the new current state; immediately post-reset the expected output is state A's output, 0. Do not constrain pre-reset outputs or assume a state encoding.

Worked example: in B with edge-sampled `in`=0, next state C, output 0. After sampling, `in` changes to 1 and holds; at the next edge the captured input is 1, so C→D, output 1. A checker latching the earlier 0 would wrongly expect C→A, output 0.
