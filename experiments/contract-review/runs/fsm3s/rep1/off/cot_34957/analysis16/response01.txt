The public interface is one 1-bit input `in`, one 1-bit synchronous active-high `reset`, one 1-bit output `out`, and a clock `clk`. All three non-clock signals are scalar, so the only legal values are 0 and 1; there are no multi-bit boundary cases to enumerate. The state register is internal and has four named states A, B, C, D, but the public spec exposes no state encoding, so the checker must not depend on any particular binary assignment. It should compare only the observable `out` after each sampled edge, using the reference transition table to track the expected state.

The transition table is a Moore table: output depends only on the current state, not on `in`. Outputs are 0 in A, B, C and 1 in D. Therefore the only way `out` can be 1 is for the machine to be in D. D is entered only from C when `in=1`; from D, `in=0` returns to C and `in=1` returns to B. From A, `in=0` stays in A and `in=1` goes to B. From B, `in=0` goes to C and `in=1` stays in B. From C, `in=0` goes to A and `in=1` goes to D. This means the checker's reference model needs exactly four states and a next-state function keyed by the captured `in`.

Reset is synchronous and active high. At a sampled rising edge, if `reset` is high, the next state is A regardless of `in`, and the settled output is 0. If `reset` is low, the next state comes from the current state's row using the captured `in`. The checker must not model reset as an asynchronous clear: it should not require `out` to fall to 0 before the edge just because `reset` is high, and a reset pulse that occurs entirely between edges must not affect the state until the next sampled edge. Power-up state is unspecified by the public table, so the checker should not assume an initial state unless the testbench explicitly drives reset or establishes a starting condition. The safe reference behavior is to apply the synchronous reset at the first sampled edge and compare from that point, or to initialize the reference state consistently with the testbench's stated starting condition.

Mid-cycle input changes are carried to the next sampled edge. They do not retroactively alter the just-sampled transition or the output that settled after that edge. For each row, the checker should capture `in` and `reset` before the edge, compute the next reference state from the captured values and the current reference state, then compare the DUT's settled `out` against the Moore output of that next state. Any input change after sampling belongs to the following row.

Worked example: suppose the reference state is C, `reset=0`, and `in=1` is captured at the edge. The table sends C to D. After the edge settles, the state is D and `out` must be 1. If `in` changes to 0 immediately after sampling, that change is carried to the next edge; it does not change the fact that this edge produced D and output 1. The checker should reject an implementation that reaches D but holds `out=0` until the next edge, and it should reject one that asserts `out` based on "C with in=1" rather than on being in D.
