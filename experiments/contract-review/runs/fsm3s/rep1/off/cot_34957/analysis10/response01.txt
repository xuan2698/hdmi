The public specification defines a four-state Moore machine with a single 1-bit input `in`, a 1-bit synchronous active-high `reset`, and a 1-bit output `out`, all sampled with respect to `clk`. The state set is `{A, B, C, D}`. The transition table gives, for each state, the next state for `in=0` and `in=1`, and the Moore output associated with that state: states A, B, and C output 0, while state D outputs 1. Because the machine is Moore, the output depends only on the current state, not directly on `in`. The reset is synchronous and active high, so it is recognized only at a rising clock edge; when asserted at that edge, the next state is forced to A regardless of the current state or input. The specification does not define a power-up state, so the checker should not assume any initial state before a reset has established A.

Port widths are straightforward: `in` is 1 bit, `reset` is 1 bit, `out` is 1 bit, and `clk` is the single clock. Boundary values for the 1-bit signals are therefore only 0 and 1. For `in`, both values are meaningful and must be exercised because they select different next states in every row. For `reset`, 0 means normal operation and 1 means synchronous reset at the sampled edge. For `out`, the only legal values are 0 and 1, with 1 occurring exactly in state D. There are no multi-bit ports, no don't-care encodings, and no output-enable or tri-state behavior in the public specification.

The most useful point for the final Python checker is to model the reference state and output with the correct edge semantics. At each sampled rising edge, the checker should first capture the values of `in` and `reset` that are driven before the edge. It should then compute the next reference state with reset priority: if `reset` is 1, the next state is A; otherwise the next state follows the transition table from the current reference state using the captured `in`. The expected post-edge output is the Moore output of that next reference state, not the output of the state that was current before the edge. This distinction matters at every transition into or out of D. For example, if the reference state is C and the sampled input is 1 with reset low, the next state is D, so the expected settled output after the edge is 1. A checker that compares against C's output would incorrectly expect 0. Similarly, leaving D for C must yield expected output 0 after the edge, even though the pre-edge state D had output 1.

The checker should also keep mid-cycle input changes separate from the value sampled at the edge. If `in` changes after the rising edge has been sampled but before the next rising edge, that new value is carried to the next sampled edge and must not alter the expected output for the state just entered. Reset should be applied before the transition table, and no initial state should be assumed until a reset edge has established A. With those rules, the reference model matches the public Moore specification and avoids the common off-by-one-edge and reset-priority errors.
