The public spec fixes a four-state Moore machine with a single 1-bit input `in`, a single 1-bit output `out`, and a synchronous active-high `reset`. All ports are one bit wide, so boundary values are simply 0 and 1; there are no multi-bit encodings to validate. The state set is {A, B, C, D}, and only state D asserts the output. Because this is a Moore machine, the output is a function of the settled state after the sampled edge, not of the input or the pre-edge state.

The transition table is: from A, `in=0` stays A and `in=1` goes to B; from B, `in=0` goes to C and `in=1` stays B; from C, `in=0` goes to A and `in=1` goes to D; from D, `in=0` goes to C and `in=1` goes to B. Output is 0 in A, B, C and 1 in D. The reset is synchronous and active high, so when `reset=1` is sampled at a posedge, the next state is A and the output is 0 regardless of current state or `in`. Reset asserted between edges has no effect until the next sampled posedge.

The most important checker point is the Moore-output timing. The output must be read from the state entered, not the state held before the edge. This is visible on C→D, where the output changes 0→1 on that same sampled edge, and on any edge leaving D, where the output changes 1→0 on that edge. A checker that reads the output before applying the transition, or that lags the output by one cycle, will fail exactly on these edges. The reset branch must also be applied before the table lookup and before the Moore-output read: reset sampled in D must produce A/0 on that edge, and reset sampled in C with `in=1` must produce A/0 rather than D/1.

The public spec defines no power-on state, so the checker should not assume the machine starts in A. A safe protocol is to sample one edge with `reset=1` to force A, then begin state and output comparisons from the following settled edge. Expected-state tracking before that first reset edge would rely on an initialization convention absent from the table and should be treated as don't-care.

Mid-row input changes occur after sampling and before the opposite edge. They do not trigger a transition and do not retroactively change the output just sampled; they become the input carried into the next row unless that row drives a new value. The checker should keep the sampled input for each edge separate from later mid-row changes so a mid-row toggle is not mistaken for the input that caused the sampled transition.

Worked example: state C, output 0, row drives `in=1`, `reset=0`. The sampled edge resolves C→D, so the settled output is 1. A mid-row change of `in` to 0 is carried to the next row and does not alter the C→D transition or the output 1. On the next sampled edge with `in=0`, `reset=0`, D resolves to C and the output returns to 0. This sequence exercises the only output-1 state, the one-edge transient, and the post-edge Moore-output rule, making it a strong distinguishing test for the final checker.
