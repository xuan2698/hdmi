The key point for the final checker is that this is a Moore machine with **registered (synchronous) reset**, so the output for a sampled row is determined solely by the state *before* the edge, while reset and input only affect the *next* state. In particular, reset does not asynchronously clear the output or the current state; it is sampled like any other input at the rising edge.

Power-up behavior is not specified by the public table. The table defines transitions and outputs for states A–D, but it does not state an initial state after power-up. The only defined way to force a known state is the synchronous active-high reset: when reset is high at a rising edge, the next state becomes A. Therefore the checker should not assume an implicit power-up state unless the harness explicitly drives reset before checking outputs. If reset is not asserted at the first sampled edge, the pre-edge state is whatever the simulation initialized it to, and the emitted output must be consistent with that state's Moore output. A robust checker should either (a) require reset to be sampled before any meaningful output check, or (b) treat the initial state as an explicit part of the testbench initialization rather than inferring it from the table.

Reset semantics: because reset is synchronous, asserting reset between edges has no immediate effect. At the next rising edge, if reset is high, the next state is A regardless of `in`. The output emitted for that row is still the output of the pre-edge state. For example, if the machine is in D (output 1) and reset is high at the edge, that row still emits 1, and the following row emits A's output 0. This is the most common place a checker can go wrong: it must not treat reset as an asynchronous override that changes the current state or output before the edge.

Input latching: the input is sampled at the rising edge. Any mid-cycle change after sampling must not retroactively alter the already-emitted output or the transition just taken. The checker should replay the seeded stimulus in order: drive the row's input before the rising edge, sample the pre-edge state and input, emit the pre-edge Moore output, compute the next state from (state, in, reset), then apply any mid-cycle input change before the falling edge and carry it into the next row.

Worked example: state C, output 0, row drives in=1 before the rising edge. At the edge the checker samples in=1, emits 0 (C's output), and transitions to D. A mid-cycle change to in=0 is ignored for this row. The next row samples whatever input is present at its rising edge; if it is 0, D→C and the row emits 1 (D's output); if it is 1, D→B and the row still emits 1. Thus output 1 appears on the row after entering D, not on the row that caused entry into D.

The single most useful invariant for the final checker: every emitted output equals the Moore output of the state current immediately before that row's rising edge, with reset only affecting the post-edge next state.
