The key point for the final checker is the distinction between the state that determines a row's output and the state that results from that row's transition. In a Moore machine, the output is a function of the current state alone, and the protocol samples after the posedge has settled. Therefore, for any sampled row, the observed `out` must equal the Moore output of the state that was current immediately before that row's rising edge. The input and reset values on that row determine the next state, not the present output. A checker that instead compares `out` to the output of the next state will fail on every row where the transition changes the output, and it will be especially fragile around reset and around the D state.

Reset is synchronous and active high. On a reset row, the pre-edge state still governs the sampled output; reset only forces the post-edge state to A. This means a reset row whose pre-edge state is D must still produce `out = 1`, and the following row must produce `out = 0` because the machine is then in A. If reset were treated as an asynchronous override that changes the output before the edge, that D-row `1` would be incorrectly suppressed and the state trajectory used by later rows would be corrupted. The checker should therefore apply reset to the next-state function only, after capturing the current row's output.

Mid-cycle input changes are a separate concern. The protocol says optional mid input changes occur after sampling, before the other edge, and are carried to the start of the next row. They must not retroactively change the output already emitted for the sampled row, nor the transition already taken at that edge. The final checker should associate each row's input value with the value present at that row's sampling edge, not with any later mid-cycle value. A mid-cycle change can affect the next row's pre-edge state only through the transition already selected at the sampled edge; it cannot alter the current row's output.

The most useful invariant for the final checker is: for each sampled row, `out` equals the Moore output of the state current immediately before that row's rising edge, while `reset` affects only the post-edge next state. This single invariant catches next-state output sampling, asynchronous reset misinterpretation, and mid-cycle input leakage into the current row. It also avoids requiring the checker to reason about full paths, because each row can be validated against the pre-edge state and the transition table independently.

A short worked example: suppose the pre-edge state is D, `in = 0`, and `reset = 1`. The sampled output must be `1`, because D's Moore output is 1. The transition table says D with `in = 0` goes to C, but reset overrides the next state to A. The next row's pre-edge state is therefore A, so its output must be `0`. A checker that emitted 0 on the reset row, or that expected C on the next row, would be wrong.

The initial state should be treated as explicit testbench initialization. The first row's output must be consistent with whatever state the simulation started in; the checker should not infer the initial state from the first input or from the first expected output. Power-up behavior outside reset is not specified by the public table, so the checker should rely on the testbench's initialization rather than assuming a particular power-up state.
