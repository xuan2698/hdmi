The key timing distinction is between the state that is current when a row's rising edge is sampled and the state that results from that edge. In a Moore machine, the output is attached to the current state, so the sampled output for a row must be computed from the pre-edge state. The transition function then determines the post-edge state, which becomes the pre-edge state for the next row. A checker that computes output from the post-edge state will be systematically wrong by one row whenever the transition enters or leaves the only state with output 1.

For this machine, state D is the only state whose Moore output is 1. Therefore every correct output pulse must appear on a row whose pre-edge state is D, regardless of the input on that row. If the input is 0 while in D, the next state is C and the output for that row is still 1. If the input is 1 while in D, the next state is B and the output for that row is still 1. The following row's output depends on whether the machine landed in C or B, both of which emit 0. This makes D a useful diagnostic state: any checker that reports 1 on the row that enters D, or fails to report 1 on the row that leaves D, has almost certainly sampled the wrong state.

Synchronous active-high reset must be handled with the same pre-edge/post-edge discipline. On a reset row, the output sampled for that row is still the Moore output of the pre-edge state. Reset changes only the post-edge state, forcing it to A. Thus a reset row whose pre-edge state is D must emit 1, and the next row must emit 0 because the machine is then in A. Treating reset as an asynchronous override that changes the output before the edge would incorrectly suppress that 1 and would also corrupt the state trajectory used by later rows.

Mid-cycle input changes are a separate timing concern. The protocol states that optional mid input changes occur after sampling and before the other edge, and are carried to the start of the next row. They must not retroactively change the output already emitted for the sampled row, nor the transition already taken at that edge. The final checker should therefore associate each row's input value with the value present at that row's sampling edge, not with any later mid-cycle value. A mid-cycle change can affect the next row's pre-edge state only through the transition that was already selected at the sampled edge; it cannot alter the current row's output.

The most useful invariant for the final checker is: for each sampled row, `out` equals the Moore output of the state that was current immediately before that row's rising edge, while `reset` affects only the post-edge next state. This single invariant catches next-state output sampling, asynchronous reset misinterpretation, and mid-cycle input leakage into the current row. It also avoids requiring the checker to reason about full paths, because each row can be validated against the pre-edge state and the transition table independently. The initial state should be treated as explicit testbench initialization, since the first row's output must be consistent with whatever state the simulation started in; the checker should not infer the initial state from the first input or from the first expected output.
