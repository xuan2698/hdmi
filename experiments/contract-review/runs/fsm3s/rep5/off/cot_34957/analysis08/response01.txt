The key point for the final checker is that the Moore output is a function of the **present state before the edge**, not the next state after the edge. The public table's "Output" column is attached to the state named in the "State" column, and the row describes what happens at a rising edge: the present state's output is emitted for that row, then the transition is taken. A checker that samples the post-edge state's output will shift every 1 one row early and will also mis-handle reset rows.

A concrete path illustrates the hazard. Starting in A with reset low: row 1 with in=1 emits 0 (A) and moves to B; row 2 with in=0 emits 0 (B) and moves to C; row 3 with in=1 emits 0 (C) and moves to D; row 4 with in=0 emits 1 (D) and moves to C; row 5 with in=0 emits 0 (C) and moves to A. The correct output sequence is 0,0,0,1,0. If the checker instead used the next state's Moore output, row 3 would be reported as 1 because the next state is D, even though the pre-edge state C emits 0. That single-row shift is exactly the kind of error the final checker should catch.

Reset makes the same issue sharper. Reset is synchronous and active high, so when reset is asserted at a rising edge, the pre-edge state still determines that row's output, and only the post-edge state becomes A. Thus a reset row while in D must emit 1, and the following row must emit A's 0. A checker must not treat reset as an asynchronous override that changes the output before the edge; doing so would move the 1 one row early and corrupt the transition history. Likewise, optional mid-cycle input changes occur after sampling and before the other edge, so they must be carried to the start of the next row and must not retroactively alter the just-emitted output or the transition already taken.

The final checker should therefore enforce one central invariant: every emitted output equals the Moore output of the state current immediately before that row's rising edge, with reset affecting only the post-edge next state. It should also treat the initial state as explicit testbench initialization rather than inferring it, because the pre-edge state at time zero is whatever the simulation initialized it to, and the first emitted output must be consistent with that state's Moore output. This invariant catches both next-state output sampling and asynchronous reset misinterpretation without needing to reason about the full path.
