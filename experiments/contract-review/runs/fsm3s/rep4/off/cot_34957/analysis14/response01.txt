The reset behavior is the first thing the checker should pin down, because it establishes the initial state against which every later row is compared. The spec calls for a synchronous, active-high reset that forces the FSM to state A. "Synchronous" means the reset is only honored at a rising clock edge; asserting `reset=1` between edges does not change the state until the next posedge. "Active-high" means `reset=1` triggers the reset and `reset=0` allows normal operation. The checker should therefore drive `reset=1` before a posedge, let the edge settle, and then sample `out`; the correct value is 0, because state A's Moore output is 0. It should not expect the state to change merely because reset was raised mid-cycle.

Power-up behavior is deliberately unspecified by the public table. The table defines transitions and outputs only for the four named states; it says nothing about the state of the flip-flops before the first reset edge. A conforming implementation may power up in any of A, B, C, or D, and its output before the first synchronous reset is therefore not constrained by the spec. The checker must not assume a particular power-up state, and must not sample `out` as meaningful until at least one posedge with `reset=1` has occurred and settled. Any test that reads `out` immediately after power-up, before a reset edge, is testing unspecified behavior and could reject a correct design. The safe protocol is: assert reset, clock one posedge, let it settle, then begin the directed sequence from state A.

This matters for the final checker because the reset edge is the anchor for the whole 0,0,0,1,0 envelope. If the checker begins sampling before the reset has been synchronized, it may attribute a power-up output to state A and misalign every subsequent row. The reset edge should be treated as row zero: after it settles, the machine is in A with `out=0`, and the first directed input row follows from there.

The distinction between synchronous reset and an asynchronous reset is also worth encoding. With a synchronous reset, holding `reset=1` across multiple edges keeps the machine in A on each edge; releasing reset to 0 before an edge lets the next input take effect. An implementation that resets asynchronously would still pass a simple "assert reset, clock, check A" test, so the checker gains little from probing the difference unless it specifically drives reset changes between edges and verifies the state does not move until the next posedge. That is a secondary concern; the primary concern is that the reset edge is sampled after settling and that state A's output of 0 is confirmed there.

The worked example above already shows the intended sampling discipline: reset edge → A, out 0; then in=1 → B, out 0; in=0 → C, out 0; in=1 → D, out 1; in=0 → C, out 0. The checker's job in this pass is to guarantee that the reset edge is the first sampled edge, that power-up output is ignored, and that the post-edge sample is associated with the pre-edge state. With those three conditions fixed, the 0,0,0,1,0 envelope becomes a reliable discriminator against Mealy, input-gated, and output-delayed bugs.
