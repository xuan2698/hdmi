The key point for the final checker is that this is a Moore machine whose output must be evaluated **after** the sampled posedge, using the state that the edge actually enters—not the pre-edge state and not a delayed output. The public table makes this especially important at the C→D transition: C has output 0, D has output 1, and the row that drives input 1 while in C must produce output 1 at that same settled edge. A checker that samples before the edge, or that pairs the output with the old state, will incorrectly expect 0. A checker that models the output as registered one cycle late will also expect 0 at that edge and only see 1 afterward, so it would reject a correct implementation.

A useful distinguishing walk is therefore reset-anchored and directed toward D, then observed immediately. For example, start by asserting reset and taking a posedge so the machine is in A with output 0. Then drive input 1: at the next sampled posedge the machine enters B, and after settling the output is 0. Keep input 1: B stays in B, output 0. To reach C, the table requires input 0 from B, so drive input 0: at the next sampled posedge the machine enters C, output 0. Now drive input 1: at the next sampled posedge the machine enters D, and after settling the output must be 1. This is the short worked example: the pre-edge state is C with output 0, but the correct post-edge observation is D with output 1. The checker should compare against the Moore output of the newly entered state D, not against C’s output and not against a value that appears only on the following edge.

The checker should also respect the synchronous active-high reset semantics. Asserting reset between edges does not change the output immediately; it takes effect only at the next posedge, after which the machine is in A and the output is 0. Holding reset high across multiple posedges keeps forcing A and keeps the output at 0 after each settled edge. The checker should not sample the output at the instant reset is asserted, and it should not assume a power-up state before the first reset edge. It should compare outputs only after the sampled edge has settled.

Mid-cycle input changes described by the protocol occur after sampling and before the other edge, and are carried to the start of the next row. The checker should apply each row’s input before the sampled posedge and treat any mid-cycle change as setup for the following row, never as affecting the output of the edge just sampled. This avoids a false failure in which a mid-cycle change is incorrectly expected to alter an already-sampled Moore output.

Finally, the checker should not over-constrain how quickly D is reached. From B, input 1 stays in B; from C, input 0 returns to A; from D, input 0 returns to C. The machine can remain away from D indefinitely depending on input, so the reliable discriminator is a directed, reset-anchored walk with post-edge sampling and comparison against the Moore output of the newly entered state.
