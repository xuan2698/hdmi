The most useful implementation mistake to flag for the final checker is a **Mealy-style output that leaks the current input into `out`**, because the public table is explicitly Moore and the 0,0,0,1,0 signature is precisely the probe that exposes it.

In a correct Moore implementation, `out` is a function of the registered state alone. The table says D outputs 1 and A, B, C output 0, regardless of `in`. A buggy implementation that computes `out` combinationally from `in` and the current state — or that gates the registered output with `in` — will still pass many naive tests, because the state sequence itself is correct. The failure only appears at the boundary rows where the input disagrees with the Moore output.

Consider the transition C --in=1--> D. In the correct machine, during the C row (before the edge) `out` is 0, and after the edge settles in D, `out` is 1. A Mealy-flavored bug that asserts `out` when `in=1` and state is C would show a 1 *during* the C row, one sample early. Symmetrically, sitting in D with `in=0` should still output 1 (Moore), but a bug that ties output to the input would drop it to 0 while still in D. And on D --in=0--> C, the output must fall to 0 only after the edge; a bug that clears it early would show 0 during the D row.

The 0,0,0,1,0 envelope is the compact discriminator: it forces the checker to sample `out` after the posedge has settled and to associate that sample with the *pre-edge* state. If the checker samples `out` before the edge, or samples it as a function of the new input, the Mealy bug hides. So the checker must (a) drive inputs before the edge, (b) let the edge settle, (c) sample `out`, and (d) compare against the output of the state that was current *before* that edge. The 1 must appear exactly on the row that entered D, and the following 0 exactly on the row that left D to C.

A second, smaller trap: an implementation that registers the output one cycle late (output = previous state's output) would shift the 1 by one row, producing 0,0,1,0,0 or similar. The same 0,0,0,1,0 probe catches this because the position of the single 1 is fixed by the table.

Worked example: reset-sampled edge → A, out 0. Row 1 in=1 → B, out 0. Row 2 in=0 → C, out 0. Row 3 in=1 → D, out 1. Row 4 in=0 → C, out 0. A Mealy bug would emit 1 during row 3's pre-edge interval (state C, in=1) and again would fail to hold 1 through a D row with in=0. Sampling post-edge from pre-edge state, with the 1 pinned to the D-entry row, is the distinguishing test the checker should encode.
