The most useful implementation mistake to flag for the final checker is a **Moore-output timing/attribution error**: comparing the sampled output against the output of the state that was active *before* the clock edge, rather than the state entered *after* the edge. In a Moore machine, the output is a function of the current state, and the public table gives output 1 only for state D. Because the transition into D can occur on a sampled posedge, the correct post-edge observation is D’s output (1), even though the pre-edge state (C) had output 0. A checker that latches the pre-edge state’s output, or that expects the output to change only on a later edge, will reject a correct implementation.

A short worked example makes this concrete. Start from reset in A with output 0. Drive input 1: at the next sampled posedge the machine enters B, and after settling the output is 0. Keep input 1: B stays in B, output 0. To reach C, the table requires input 0 from B, so drive input 0: at the next sampled posedge the machine enters C, output 0. Now drive input 1: at the next sampled posedge the machine enters D, and after settling the output must be 1. This is the short worked example: the pre-edge state is C with output 0, but the correct post-edge observation is D with output 1. The checker should compare against the Moore output of the newly entered state D, not against C’s output and not against a value that appears only on the following edge.

The checker should also respect the synchronous active-high reset semantics. Asserting reset between edges does not change the output immediately; it takes effect only at the next posedge, after which the machine is in A and the output is 0. Holding reset high across multiple posedges keeps forcing A and keeps the output at 0 after each settled edge. The checker should not sample the output at the instant reset is asserted, and it should not assume a power-up state before the first reset edge. It should compare outputs only after the sampled edge has settled.

Mid-cycle input changes described by the protocol occur after sampling and before the other edge, and are carried to the start of the next row. The checker should apply each row’s input before the sampled posedge and treat any mid-cycle change as setup for the following row, never as affecting the output of the edge just sampled. This avoids a false failure in which a mid-cycle change is incorrectly expected to alter an already-sampled Moore output.

Finally, the checker should not over-constrain how quickly D is reached. From B, input 1 stays in B; from C, input 0 returns to A; from D, input 0 returns to C. The machine can remain away from D indefinitely depending on input, so the reliable discriminator is a directed, reset-anchored walk with post-edge sampling and comparison against the Moore output of the newly entered state.
