The key modeling point is that only the values present at the sampled negative edge determine the next `q`. A mid-row `reset` pulse is not an asynchronous reset; it affects only a later edge if it is still high when that edge is sampled. Likewise, a mid-row `d` change must be carried into the next row’s pre-edge inputs, not applied to the row already sampled.

For the checker, capture each row’s pre-edge `d` and `reset`, wait for the negative edge to settle, then compare `q`: if captured `reset` is high, expect `0x34`; otherwise expect captured `d`. Do not compare before the first sampled edge, because power-up `q` is unspecified. Do not reset to `0x00`.

Worked example: before a negative edge, `reset=0`, `d=0x5A`; after settling, `q=0x5A`. Then, before the next negative edge, `reset` pulses high and returns low while `d` becomes `0x21`. At the next edge, sampled `reset=0`, so expect `q=0x21`, not `0x34`. An asynchronous-reset model would wrongly force `0x34` during the pulse; a row-misaligned model might apply the pulse to the wrong edge. The checker should therefore react only at settled negative edges, carry mid-row changes forward, and use `0x34` for sampled reset.
