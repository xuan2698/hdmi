The public specification defines an 8-bit register bank of eight D flip-flops, all sharing a single clock `clk`, an 8-bit data input `d`, a 1-bit synchronous reset `reset`, and an 8-bit output `q`. The input widths are `{'d': 8, 'reset': 1}` and the output width is `{'q': 8}`. Because `d` and `q` are both 8 bits wide, their legal values span `0x00` through `0xFF` inclusive, giving 256 distinct data patterns. The `reset` input is a single bit, so its only legal values are `0` and `1`. The reset is active high, meaning `reset = 1` commands the reset behavior and `reset = 0` permits normal data capture. The reset is synchronous, so it takes effect only in response to a clock edge, not asynchronously. The specified reset value is `0x34`, not zero, which is a boundary value the checker must treat as the expected `q` whenever a sampled edge occurs with reset asserted.

All eight flip-flops are triggered by the negative edge of `clk`. The sampling point is after the negative edge has settled, so the checker should compare `q` only at that settled post-edge moment. The protocol seed `20261124` is a deterministic stimulus seed and does not alter the port widths or boundary values. The key boundary cases are therefore `d = 0x00`, `d = 0xFF`, `reset = 0`, `reset = 1`, and the special reset output `q = 0x34`. There is no stated power-up value for `q`; the specification only defines behavior at sampled negative edges. Consequently, the checker should not assert any `q` value before the first sampled negative edge. After that first edge, every sampled `q` must equal either the carried `d` or `0x34` according to the carried `reset`.

The protocol adds a timing constraint that matters more than the raw widths: each row's values are driven before the sampled edge, and optional mid input changes occur after sampling, before the other edge, and are carried to the start of the next row. Thus the checker must maintain carried `d` and `reset` state. At each sampled negative edge, it should snapshot the carried inputs, compute the expected `q` as `0x34` if the snapshot `reset` is high, otherwise the snapshot `d`, and compare. Only after that comparison should it absorb any post-sample changes into the carried inputs for the next row. Reversing this order would let a mid-row change appear retroactively at the edge just sampled.

A short worked example: suppose the first sampled negative edge has carried `reset = 0` and carried `d = 0xA5`, and after sampling `d` changes to `0x3C`. The correct first expectation is `0xA5`. At the second sampled negative edge, suppose `reset = 1`; the correct expectation is `0x34`, regardless of the carried `d = 0x3C`. A checker that assumes power-up `0x34` would wrongly expect `0x34` at the first edge, and a checker that applies post-sample changes retroactively would wrongly expect `0x3C` at the first edge.

For the final Python checker, the useful rule is: maintain carried `d` and `reset`; at each sampled negative edge, snapshot them; compute expected `q` as `0x34` if snapshot `reset` is high, otherwise snapshot `d`; compare only from the first sampled edge onward; and do not assert any `q` before that edge. After computing the expected value, apply mid-row changes to the carried state for the next row. This preserves synchronous reset priority, negative-edge sampling, and the carried-input protocol without inventing an unstated initial register value.
