The public specification defines an 8-bit register bank of eight D flip-flops, all sharing a common clock `clk`, a common active-high synchronous reset `reset`, and a common 8-bit data input `d`, producing an 8-bit output `q`. The key nonstandard feature is the reset value: when `reset` is asserted at the active clock edge, every flip-flop loads `0x34`, not `0x00`. The active edge is the negative edge of `clk`. Because the reset is synchronous, asserting `reset` between edges does not immediately change `q`; the reset takes effect only when the next negative edge arrives. Likewise, deasserting `reset` between edges does not release the register until the next negative edge.

The checker must therefore treat each sampled negative edge as the sole moment at which inputs are interpreted. At that edge, the pair (`d`, `reset`) is snapshotted. If the snapshotted `reset` is high, the expected `q` is `0x34`. If it is low, the expected `q` is the snapshotted `d`. This priority matters: reset dominates data, so a high `reset` with any `d` value, including `0x34`, yields `0x34`. Conversely, a low `reset` with `d = 0x34` yields `0x34` by data pass-through, not by reset. The checker should not infer a reset event merely from the output value; it must use the sampled `reset` signal.

The protocol also distinguishes values present at the sampled edge from optional mid-row changes that occur after sampling and before the other edge. Those mid-row changes are carried to the start of the next row. The checker should snapshot the carried inputs at the negative edge, compute the expected output from that snapshot, compare against the observed `q` after the edge has settled, and only then update the carried state with any post-sample changes. Applying mid-row changes before computing the current expectation would retroactively use a value that was not present at the active edge and would create false mismatches.

A short worked example clarifies the boundary behavior. Suppose the carried inputs at the first sampled negative edge are `reset = 0` and `d = 0xA5`, and after sampling `d` changes to `0x3C`. The correct first expectation is `0xA5`. At the next sampled negative edge, suppose `reset = 1`; the correct expectation is `0x34`, regardless of the carried `d = 0x3C`. A checker that assumes power-up `0x34` would wrongly expect `0x34` at the first edge, and a checker that applies post-sample changes retroactively would wrongly expect `0x3C` at the first edge.

For the final Python checker, the useful point is to separate edge-time snapshotting from post-edge state carry. Maintain carried `d` and `reset`; at each sampled negative edge, snapshot them; compute expected `q` as `0x34` if snapshot `reset` is high, otherwise snapshot `d`; compare only from the first sampled edge onward; and do not assert any `q` before that edge. After computing the expected value, apply mid-row changes to the carried state for the next row. This preserves synchronous reset priority, negative-edge sampling, and the carried-input protocol without inventing an unstated initial register value.
