The public interface is an 8-bit register bank built from eight D flip-flops sharing a common clock, synchronous active-high reset, and a single 8-bit data input. Inputs are `d[7:0]` and `reset` (1 bit); output is `q[7:0]`. The clock is `clk`, and all state changes are triggered by the negative edge. Because reset is synchronous and active high, asserting `reset` does not immediately alter `q`; it only forces the value committed at the next sampled negative edge to the constant `0x34`. This reset constant is the single most important boundary value in the design: it is neither zero nor all-ones, and it must be applied uniformly to all eight flip-flops.

Port widths imply the following boundary behavior. `d` spans `0x00` through `0xFF`, so every 8-bit pattern is legal and no truncation or sign extension should occur. `reset` is a single control bit; only its value at the sampled negative edge matters for the commit. `q` is also 8 bits and therefore can represent exactly the same range, including the reset value `0x34`. There is no separate enable, load, or clear port, so the only two committed outcomes at a sampled edge are `0x34` when `reset` is high and the pending `d` value when `reset` is low. The checker should treat `q` as an 8-bit unsigned quantity and compare against `0x34` and against pending `d` without masking surprises.

Timing boundaries are equally important. Inputs driven before a sampled negative edge are pending until that edge is evaluated. A mid-cycle change to `d` or `reset` occurs after sampling and before the opposite edge; it must be carried forward as the pending input for the next row and must not retroactively affect the state committed at the previous edge. In checker terms, maintain pending `d` and pending `reset`, update them on drives and mid changes, and evaluate `next_q = 0x34 if reset else d` only at the sampled negative edge. Then commit `q = next_q`. Do not model reset as an asynchronous clear, and do not assert `q` before the first reset-sampled edge, since power-up state is not part of the public contract.

A short worked example: suppose committed `q` is `0x34`. With `reset` low, `d` changes to `0x7A` after a sampled edge. That change is pending only; committed `q` remains `0x34`. At the next sampled negative edge, if no newer `d` has been driven, committed `q` becomes `0x7A`. If instead the next row drives `d = 0x11` before that edge, committed `q` becomes `0x11`. If `reset` is high at that edge, committed `q` becomes `0x34` regardless of `d`.

For the final Python checker, the useful focus is strict edge-sampled evaluation with pending-input carryover. Update pending inputs on row drives and mid changes, evaluate only at the sampled negative edge, commit `q` from that evaluation, and defer all `q` assertions until after the first reset-sampled edge. This directly matches the public specification and avoids the common failures of asynchronous reset modeling, reset-to-zero assumptions, and premature or delayed sampling.
