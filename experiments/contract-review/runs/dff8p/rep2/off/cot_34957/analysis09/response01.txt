The public specification defines an 8-bit register bank of eight D flip-flops, all sharing a common clock `clk` and a common active-high synchronous reset `reset`. The data input is 8 bits wide (`d`), and the output is 8 bits wide (`q`). The reset value is not zero; it is the constant `0x34`. All state changes occur on the negative edge of `clk`. Because reset is synchronous, it is sampled at that same negative edge and is not applied asynchronously. Consequently, a change on `reset` between edges has no immediate effect on `q`; it only matters if it is present and stable at the sampled negative edge.

The checker should treat each sampled negative edge as one atomic transition. At that edge, the next state of `q` is determined by the sampled `reset` value: if `reset` is high, `q` becomes `0x34`; if `reset` is low, `q` becomes the sampled `d`. The data input is irrelevant when `reset` is high, and the reset input is irrelevant when it is low except that it must not accidentally trigger the reset path. This distinction is important because a row that drives `reset=1` and `d=0x34` is degenerate: the observed `q=0x34` would be consistent with either the reset behavior or a normal load of `0x34`. The checker should therefore include reset rows where `d` is not `0x34`, and non-reset rows where `d=0x34`, so that reset and load behavior are independently exercised.

The row protocol has three moments. First, each row has driven values at its start. Second, the negative edge is sampled after it has settled. Third, optional mid changes occur after sampling and before the other edge; those changes carry into the start of the next row unless the next row explicitly overrides them. The checker must preserve that carry. If it drops a mid change, it may drive the wrong `d` or `reset` on the following row and report a false mismatch. If the next row drives new values, those override the carried ones; otherwise the carried values persist.

A short worked example illustrates the interaction. Suppose row 1 drives `d=0x11`, `reset=0`, and samples `q=0x11`. After sampling, a mid change sets `d=0x22`. Row 2 does not override `d`, so it begins with `d=0x22`; at its negative edge, with `reset=0`, the checker expects `q=0x22`. If row 2 instead drives `reset=1` and `d=0x00`, the checker expects `q=0x34`, not `0x00`.

For the final Python checker, the useful focus is this: model the sampled negative edge as a single transition using the reset constant `0x34`, require an explicit reset to establish known state, avoid degenerate reset/data rows, and carry post-sample mid changes into the next row unless overridden. Do not add a zero-initialization assumption that the public specification does not provide.
