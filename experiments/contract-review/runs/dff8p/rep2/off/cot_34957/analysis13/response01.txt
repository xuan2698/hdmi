The critical boundary in this specification is the reset constant `0x34`. Because reset loads exactly `0x34`, a row with `reset=1` and `d=0x34` is degenerate: it cannot distinguish a correct reset from an ordinary load of the same value. Similarly, a row with `reset=0` and `d=0x34` is a valid load of the reset constant, but it does not demonstrate that the reset path works. The checker should therefore separate these cases: reset rows should use a `d` value other than `0x34`, and non-reset rows should include `d=0x34` to confirm that ordinary loading of that value is not mistaken for reset. Ordinary data boundaries such as `0x00` and `0xFF` are useful for coverage, but they carry no special semantic weight here.

The sampled negative edge is atomic. At that edge, the next value of `q` is determined solely by the sampled `reset` signal. If `reset` is high, `q` becomes `0x34` regardless of `d`. If `reset` is low, `q` becomes the sampled `d`. There is no enable, no asynchronous clear, and no zero-reset behavior. The checker must not assume any power-on value for `q`; the public specification does not define one. A known state can only be established by an explicit reset sample. Any expectation that `q` begins at zero, or at `0x34`, before a reset row is unsupported.

The row protocol has three temporal moments: values driven at row start, the sampled negative edge after settling, and optional mid changes that occur after sampling but before the other edge. Those mid changes carry into the start of the next row unless the next row overrides them. This carry is a likely source of false mismatches if the checker resets its model at every row boundary. The model should treat each row as beginning from the post-mid state of the previous row, then apply any new driven values for the current row before sampling.

A short worked example clarifies the carry. Suppose row 1 drives `d=0x11`, `reset=0`, and samples `q=0x11`. After sampling, a mid change sets `d=0x22`. Row 2 does not override `d`, so it begins with `d=0x22`; with `reset=0`, the next sampled `q` is `0x22`. If row 2 instead drives `reset=1` and `d=0x00`, the expected `q` is `0x34`, not `0x00`. The mid change from row 1 is irrelevant to that reset sample because reset overrides data, but the carry still matters for the next non-reset row.

For the final Python checker, the useful focus is therefore narrow: model each sampled negative edge as a single transition using the constant `0x34`; require an explicit reset to establish known state; avoid degenerate reset/data rows where `reset=1` and `d=0x34`; include non-reset loads of `0x34` to exercise the boundary; and carry post-sample mid changes into the next row unless overridden. The checker should compare only after the negative edge has settled, and should not infer any initial `q` value from the specification.
