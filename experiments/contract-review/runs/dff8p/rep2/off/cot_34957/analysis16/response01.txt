The public interface is an 8-bit data input `d`, a 1-bit synchronous reset `reset`, a clock `clk`, and an 8-bit output `q`. The widths are exact: `d[7:0]`, `reset` as a single bit, and `q[7:0]`. There are no enables, byte-selects, or per-bit reset controls. The reset value `0x34` is a single 8-bit constant applied uniformly to all eight flip-flops, so the checker should not infer any bit-specific behavior. The only edge that matters is the negative edge of `clk`; positive edges are irrelevant except as the boundary after which mid-row input changes may occur.

Boundary values are straightforward but worth stating explicitly. For `d`, the extremes are `0x00` and `0xFF`, with `0x34` as a special value because it equals the reset constant. For `reset`, the only values are 0 and 1. For `q`, before any reset has been sampled, the value is unknown; after a sampled reset, `q` is exactly `0x34`; after a sampled non-reset edge, `q` is exactly the active `d` value. There is no partial reset, no masking, and no saturation. A non-reset load of `0x34` is legal and must be distinguished from reset only by the `reset` input, not by the resulting `q` value.

The main checker hazard is input carry across rows. Each row begins from the previous row’s post-mid input state, then overlays any newly driven values for the current row, and only then samples the negative edge. A model that resets inputs at every row boundary, or that uses only the current row’s explicitly driven values, will diverge whenever a mid-row change is carried forward. The second hazard is initial state: `q` is unknown until a sampled reset occurs. The checker should either require the first sampled edge to be a reset or suppress comparisons until a reset has established a known `q`. After that, each sampled negative edge has exactly one transition: if `reset` is 1, `q` becomes `0x34`; otherwise `q` becomes the active `d`.

A short worked example: suppose row 1 drives `d=0x11`, `reset=0`, and the sampled edge loads `q=0x11`. After sampling, a mid change sets `d=0x22`. Row 2 does not override `d`, so the active data at row 2’s sampled edge is `0x22`; with `reset=0`, `q` becomes `0x22`. If row 2 instead drives `reset=1`, the expected `q` is `0x34` regardless of the carried `d`.

For the final Python checker, the useful focus is to implement exactly one transition per sampled negative edge using carried-then-overlaid inputs, compare only after reset has made `q` known, and include non-reset loads of `0x34` to exercise the ambiguous boundary. Avoid relying on rows where `reset=1` and `d=0x34` to prove reset behavior, since that combination cannot distinguish reset from a data load of the same value.
