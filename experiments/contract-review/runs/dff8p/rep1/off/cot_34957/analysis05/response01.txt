The public specification describes eight D flip-flops sharing a single 8-bit data input `d`, a 1-bit synchronous reset `reset`, a clock `clk`, and an 8-bit output `q`. The flops are negative-edge triggered: the state transition is sampled on the falling edge of `clk`, after that edge has settled. Reset is active high and synchronous, and the reset value is `0x34`, not zero. Therefore, at a sampled negative edge, if `reset` is high, `q` becomes `0x34`; if `reset` is low, `q` captures `d`. Because reset is synchronous, a reset pulse that rises and falls entirely between two negative edges has no effect on `q`. The checker must therefore evaluate `reset` as part of the input state present at the sampled negative edge, not as an asynchronous event that immediately forces the output.

The negative-edge trigger also means positive edges are not sampling points for `q`. Inputs may change after the sampled negative edge and before the next negative edge; such mid-row changes do not update `q` immediately. They only alter the input state that will be visible at the next sampled negative edge. The checker should treat inputs as piecewise-constant: values at row start, the values at the sampled negative edge, optional mid changes after sampling, and then the values carried into the next row. At each sampled negative edge, the expected next `q` is `0x34` if the pre-edge `reset` is high, otherwise the pre-edge `d`. The previous `q` does not affect the result except as the state being replaced.

A short worked example illustrates the deferred mid-change rule. Suppose at row start `d = 0x12` and `reset = 0`. At the sampled negative edge, reset is still low, so `q` becomes `0x12`. After sampling, before the next edge, `d` changes to `0x56` and `reset` changes to 1. Those mid changes do not alter the just-sampled `q`. At the next sampled negative edge, reset is high, so `q` becomes `0x34`, not `0x56`. This demonstrates both synchronous reset and the fact that mid changes are carried forward rather than applied immediately.

For the final Python checker, the most useful focus is to maintain an input state updated only at the specified mid-change points, and to compute expected `q` only at negative-edge sampling points using the pre-edge input state. Do not update `q` on mid changes, do not treat reset as asynchronous, and do not assume the reset value is zero. Verify that every reset-sampled negative edge produces exactly `0x34`, and that every non-reset sampled negative edge captures the current `d` rather than a stale or mid-updated value.
