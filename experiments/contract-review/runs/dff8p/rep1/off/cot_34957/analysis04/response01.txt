The public specification defines an 8-bit register bank of eight D flip-flops, all sharing a single clock `clk`, an 8-bit data input `d`, a 1-bit synchronous reset `reset`, and an 8-bit output `q`. The input widths are `d: 8` and `reset: 1`; the output width is `q: 8`. Because `d` and `q` are both 8 bits wide, the natural boundary values are `0x00` and `0xFF`, with the reset constant `0x34` lying strictly inside that range. The reset value is therefore not an all-zero or all-one pattern, which matters for the checker: a correct implementation must produce exactly `0x34` on reset, and a checker that merely tests for zero would miss a wrong reset constant. Similarly, a checker that assumes reset clears to `0x00` would falsely flag correct behavior.

The flip-flops are triggered by the negative edge of `clk`, and reset is active high and synchronous. This means `reset` is sampled at the negative edge along with `d`; a high `reset` at that edge forces `q` to `0x34`, while a low `reset` causes `q` to capture `d`. A reset pulse that begins and ends between two negative edges is invisible to the flops, so the checker must sample `reset` at the negative edge rather than reacting to changes in `reset` as events. This is the key distinction from asynchronous reset, where a high reset would force `q` to `0x34` immediately regardless of clock.

The negative-edge trigger means positive edges are not sampling points for `q`. Mid-row input changes may occur after the sampled negative edge and before the next negative edge, but they do not update `q`; they only change the input state visible at the next sampled negative edge. The checker should model inputs as piecewise-constant: row-start values, then the sampled negative edge, then optional mid changes, then the next row’s sampled negative edge. At each sampled negative edge, the expected next `q` is `0x34` if the pre-edge `reset` is 1, otherwise the pre-edge `d`. The previous `q` is irrelevant except as the state being replaced.

A short worked example clarifies the deferred mid-change rule. Suppose at row start `d = 0x12`, `reset = 0`. At the sampled negative edge, reset is still 0, so `q` becomes `0x12`. After sampling, before the next edge, `d` changes to `0x56` and `reset` changes to 1. Those mid changes do not alter the just-sampled `q`. At the next sampled negative edge, reset is 1, so `q` becomes `0x34`, not `0x56`. This shows both synchronous reset and the fact that mid changes are carried forward rather than applied immediately.

For the final Python checker, the most useful focus is to maintain an input state updated only at the specified mid-change points, and to compute expected `q` only at negative-edge sampling points using the pre-edge input state. Do not update `q` on mid changes, do not treat reset as asynchronous, and do not assume reset value zero. Verify that every reset-sampled negative edge produces exactly `0x34`, and that every non-reset sampled negative edge captures the current `d` rather than a stale or mid-updated value.
