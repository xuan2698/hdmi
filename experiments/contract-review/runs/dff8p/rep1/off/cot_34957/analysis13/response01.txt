The public specification defines eight D flip-flops sharing a single clock, `clk`, and a single active-high synchronous reset, `reset`. The data input is 8 bits wide, `d`, and the output is 8 bits wide, `q`. All eight flip-flops are triggered on the negative edge of `clk`. The reset value is not zero; when reset is sampled high at a negative edge, every flip-flop loads `0x34`. When reset is sampled low at a negative edge, each flip-flop captures the value of `d` present just before that edge. The checker samples after the negative edge has settled.

The timing language in the specification is the critical part. Each row's values are driven before the sampled edge. That means the checker must treat the row-start values of `d` and `reset` as the values that are candidates for capture at the upcoming negative edge, unless a mid input change occurs before that edge. Optional mid input changes occur after sampling, before the other edge, and are carried to the start of the next row. In other words, a mid change is not an input to the edge that has just been sampled. It is an input to a later edge, and its effect must be evaluated at the next sampled negative edge, not retroactively at the previous one.

This distinction matters most for reset. Because reset is synchronous, a reset that becomes high after the sampled negative edge does not force `q = 0x34` at that edge. Only a reset value present just before the sampled negative edge forces the reset load at that edge. A reset that rises after sampling is carried forward and affects the next sampled negative edge. The checker must therefore separate the pre-edge input state from post-sampling changes. It should not model reset as an asynchronous override, and it should not update expected `q` when a mid change occurs.

A second boundary issue is where expected `q` is updated. Since all flip-flops are negative-edge triggered, the checker should compare `q` only after the negative edge has settled, using the `d` and `reset` values that were present just before that edge. Mid-row changes must not alter the just-sampled output. They belong to the next row or next sampled edge, depending on when they occur.

A short worked example makes the boundary concrete. Suppose at the start of a row `d = 0x12` and `reset = 0`, and both are unchanged just before the sampled negative edge. The expected capture is `q = 0x12`. After sampling, before the next edge, `reset` rises to 1 and `d` changes to `0xAB`. The just-sampled `q` remains `0x12`; the reset did not act asynchronously. At the next sampled negative edge, reset is high, so expected `q` becomes `0x34`, not `0xAB`. This separates synchronous reset from asynchronous reset and separates pre-edge capture from post-sampling input changes.

For the final Python checker, the useful discipline is to track inputs at the sampling boundary separately from mid-cycle changes. The checker should maintain the row-start inputs, the inputs present at the sampled negative edge, any post-sampling changes, and the carried inputs into the next row. It should update expected `q` only at the sampled negative edge, using the pre-edge `d` and `reset`. It should not update `q` on a mid change, should not treat reset as an asynchronous override, and should not assume any particular power-up value for `q`. Any initial expected value must come from the stimulus or from an explicit reset event. Every reset-sampled negative edge must produce exactly `0x34`, and every non-reset sampled negative edge must capture the current pre-edge `d` rather than a stale or mid-updated value.
