# 第三版试运行排查

仅对第三版归档做本地仿真与分析，新增模型调用 **0 次**。所有 425 个最终 TB 的选中源码、输入拼接和逐行期望值均可重建。逐变异体复放复现了归档中的暴露、检查报警、已知位差异位置数、golden 结果和主口径 H 检出数。

## 1. 版本与流程

在 85 个题目 × 种子组内，对五种配置做了全部 850 对比较。激励差异以周期为行，比较同一周期的输入字典（包括 `mid`），额外后缀逐行计入。检查逻辑差异以源码文本行计，替换一行计一次删除和一次增加，另列 AST 差异以及共同周期的期望值差异。55/85 组的最终激励五种配置完全相同，38/85 组的最终检查器源码五种配置完全相同。只比较 A0，四种迭代配置分别在 30/85 组改变了激励，改变检查器源码的组数依次是 33、30、32、27。[850 对的差异行数](pairwise_TB_differences.csv) · [按配置对汇总](pairwise_TB_difference_summary.csv)

五种配置的 golden 结果 **84/85（98.82%）完全一致**，其中 25 组全部通过、59 组全部失败。唯一不一致的是 #75 `review2015_fsmseq`，种子 `20261121`，从 A0 到 O-O 的结果依次为通过、失败、失败、失败、通过。五个检查器源码和初稿相同。三个失败组的追加激励都把 H 暴露从 4/7 提到了 6/7，同时触发已有检查器的 golden 误报。O-O 追加后仍暴露 4/7，golden 通过。[85 组 golden 结果](golden_by_task_seed.csv) · [425 个初稿和最终 TB 的复放](TB_initial_final.csv)

## 3. Golden 误报

取首次误报周期。该周期多个输出同时失败时，以公开接口中的第一个失败输出为主分类，保留所有同时失败的位置。35 个 TB 同周期有多个输出失败，其中 10 个的输出分类不同。a 类优先看明确的复位信号，周期处于有效复位或尚未经历首次有效复位时归 a。b 类只判定同一输出在相邻周期是否匹配，在当前已知位上要求相邻值也已知。这是一项局部诊断。c 类在当前及其前后一个周期均不匹配。[298 个 TB 的首次误报和 spec 条款](false_positive_first_sites.csv) · [分类示例的数据](false_positive_examples.json)

| 类别 | TB 数 | 占比 |
|---|---:|---:|
| a 复位前或复位期间 | 0 | 0.00% |
| b 期望值匹配相邻一拍 | 170 | 57.05% |
| c 相邻两拍都不匹配 | 128 | 42.95% |

- a 类没有实例。第三版屏蔽 golden 的 X/Z 位，单凭确定期望与 X/Z 不同不会报错。
- b 类示例一为 #32 `edgecapture`，A0 第 1 次、第 3 周期。`out` 期望 `0xffffffff`，当拍是 `0x00000000`，下一拍才是 `0xffffffff`。该周期的 `mid` 把输入从全一拉到全零，发生在当前评分采样之后。示例二为 #31 `mt2015_muxdff`，B-B 第 3 次、第 3 周期。`Q` 期望为 0，当拍和前一拍为 1，下一拍为 0。
- c 类示例一为 #32 `edgecapture`，A0 第 4 次、第 31 周期。期望 `0xce6dfca9`，golden 当拍及前一拍为 `0xc20dbc21`，后一拍为 `0xc28dbc63`。对应 spec 条款要求检测输入从 1 到 0 的逐位变化。示例二为 #79 `circuit9`，A0 第 1 次、第 1 周期。期望 `q=0`，当拍及下一拍均为 `q=4`，公开波形 `5ns / clk=1 / a=1 / q=4` 给出该行为。

核对的 17 份归档官方 TB 与 AutoBench 数据集中的 `testbench` 字段逐字相同。官方评分监视器在正反两个时钟沿都运行，使用定时事件触发后的即时值，没有显式等待 NBA 更新后的稳定值。第三版只在公开 spec 对应的活跃沿后延迟一仿真单位采样。官方用 `REF === (REF ^ DUT ^ REF)` 逐位屏蔽参考 `X`。如果参考为 `Z`，右侧 XOR 结果为 `X`，官方的严格比较会失败，第三版会屏蔽该位。双方都没有统一跳过复位期间，仍检查已知值，官方还用自己的定向激励做同步和异步复位诊断。[官方评分行号与比较式](official_TB_comparison.csv)

固定原激励和期望值做反事实复放。仅跳过复位窗口救回 0 个 TB，统一前移或后移一拍救回 0 个，换成活跃沿前可救回 12 个，换成相反沿后可救回 10 个，两者合计救回 22 个不同 TB。例如 #149 `gshare` 的 A0 第 4 次在第 5 周期期望 `predict_history=0`，当拍沿后为 14，沿前仍为 0。这个 TB 改用沿前采样后整体通过。这些替代采样测试没有复现官方的整套激励与调度。由此，170 个 b 类局部匹配不能都归因于评测约定。主要问题仍是生成的参考逻辑，包括参考逻辑对输入、状态更新及 `mid` 的时序解释。

## 判断

1. 最终版本接线和评分复放一致。发现的流程缺陷发生在生成重试，10 个最终采用的重试没有携带原始反馈。#75 的实际评分差来自追加激励触发原检查器误报。
2. 误报主要来自参考逻辑及其时序实现。官方采样约定确有差异，本地替代采样只让 22/298 个 TB 整体通过，分类中的相邻值匹配也不足以推出全局一拍偏差。
3. 激励诊断能在 G 上引导局部修复，但本批次的 H 结果没有显示相对于基线的暴露收益。两项同检查侧配对的宏平均差均为负，区间均包含零。激励侧为 O 的 42 个有效 G 提升运行中，只有 8 个同步改善 H，且 H 初稿已达到 90.24% 暴露宏平均。

复放命令在实验根目录运行 `python3 pilot3_postpilot.py`，依赖 Icarus Verilog、`bwrap`、NumPy 和 SciPy。命令只使用已归档的验证文件和源码，在本地执行已有程序及仿真。
